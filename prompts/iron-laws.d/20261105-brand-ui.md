BRAND RULES (iron law, BH-9100, 2026-11-05). This repo declares its brand and UI rules in `{{BRAND_UI_FILE}}`. Every change to UI follows that file. Read `{{BRAND_UI_FILE}}` before you plan, build, fix or review a UI change.
1. Use the tokens and shared components that `{{BRAND_UI_FILE}}` names. Use no raw color (hex, rgb, a raw palette utility class) where the file names a token. Build no one-off component where the file names a shared one.
2. PLAN: carry a `## Brand tokens` section. For each new or changed screen, list the tokens and shared components it uses. Name each screen that needs a value the file does not hold, and the value it needs. A plan with no UI change writes the single line "no UI change".
3. EXECUTE and FIX: build to the plan's `## Brand tokens` list. A value the file does not hold goes in a scoped per-component override, never in a global token edit and never as a raw hex in app CSS.
4. REVIEW: check each changed UI file against `{{BRAND_UI_FILE}}`. A raw color, or a one-off component where the file names a shared one, is a `[NOTE]`. It is a BLOCK only when the REVIEW LEVELS rule makes it one, for example a core-flow screen that is visibly off-brand to a person's eye.
5. When a ticket carries a designer's prototype, the prototype rule applies as written. `{{BRAND_UI_FILE}}` fills only what the prototype does not set.
