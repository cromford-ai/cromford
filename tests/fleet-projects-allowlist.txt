# tests/fleet-projects-allowlist.txt — scripts allowed to name three or more
# fleet projects without reading bin/fleet-conf.sh.
#
# Format: <file in bin/><whitespace><one-line reason>
#
# Every line here is a promise that a human looked at the enumeration and
# decided it is either genuinely not derivable from the registry, or is owned by
# work in flight. An entry with no reason fails the guard, and so does an entry
# for a file that no longer enumerates — an exception must not outlive the thing
# it excuses. Adding a line is cheap; the point is that it is a DECISION rather
# than a default.
#
# The registry cannot answer three things today, and they are why most of this
# list exists:
#   * per-project ENV-VAR NAMES (PROJECT_1_API_BASE vs PROJECT_2_APP_BASE vs
#     PROJECT_4_API_BASE) — fleet.conf has the prod URL, not the variable that holds it
#   * ~~per-box TAILSCALE IPs~~ — CLOSED 2026-09-11: fleet.conf grew a
#     `tailnet_ip` column and bin/fleet-conf.sh --tailnet-ip{,-of-box} reads it.
#     Five files left this list outright; the ones still below are here for a
#     DIFFERENT reason now (a label→project map whose labels are on-disk keys),
#     and their reasons say so.
#   * per-board TICKET-KEY PREFIXES (PB/FR/AR/SO)
# Closing any of those in the registry would let a whole block of these lines go.
# Two columns are worth more than any amount of hand-migration:
#   * ~~tailnet_ip~~ — DONE 2026-09-11; it retired five of the nine outright
#   * token_var   — the name of each project's *_INTERNAL_API_TOKEN. Not
#     derivable from the project name (project-2 uses PROJECT_2_, project-8
#     uses IA_), which is why bin/internal-token-for.sh matches on the
#     suffix and refuses when a file defines zero or several. A per-project name
#     MAP would work too and is deliberately not used: it is a hardcoded fleet
#     project list in bin/, i.e. the thing this very guard forbids, and the map
#     that used to live in stale-owed-tickets.sh had already drifted (it said
#     PROJECT_2_INTERNAL_API_TOKEN; that env file calls it PROJECT_2_). Note when that lands: fly-dispatch.sh may be
# REMOVABLE rather than migratable — once the DB-queue wave's producers write
# rows, its ssh pull is the fallback path and it needs no IP at all, so check
# whether the entry can just go (harness-dbqueue, 2026-09-10).
