# catalog/test-impact-always.txt — suites that run on EVERY diff (BH-1203).
#
# bin/test-impact.sh already DERIVES this set from each suite's own text: a
# suite whose executable lines (not comments, case-arm patterns or quoted
# messages) run an unscoped `git … ls-files` (no pathspec, or `.`),
# `find "$DIR"`, `--tree` or `"$DIR"/tests/*` reads the whole tree, so no map
# of it is worth anything and it runs always. That detection is the primary
# mechanism. This file holds two kinds of line: the escape hatch for a suite
# whose whole-tree reach no signal can see, and the BH-4551 stability pins
# below, which keep main's classification from moving when the detector was
# narrowed (some of those suites never read the tree at all).
#
# One suite path per line, then a reason. A line naming a file that does not
# exist is ignored, so a rename cannot silently add a phantom to every run.
#
# An escape-hatch line is an admission that the detection missed something —
# say what it missed, so the next person can fix the detector instead of
# growing the list.
#
# A merge-queue batch drops the suites of catalog/test-impact-always-prepush.txt
# when every member carries a green pre-push gate record on its head (BH-7289).
# This file still feeds the gate's own list (bin/fast-lints.sh --list), so those
# suites keep their lines here.
#
# BH-1485 (review C2): tests/gh-rest-no-subshell-lint.sh walks bin/ inside a
# Python heredoc (os.walk), so none of the four text signals above see it —
# the walk is data to bin/test-impact.sh's own grep, not a `git ls-files` /
# `find "$DIR"` / `--tree` / `"$DIR"/tests/*` line in the suite's own shell
# text. Without this line a diff touching only bin/ (never tests/) does not
# select it, so a regression that reintroduces `st=$(gh_rest …)` in most of
# the 15 converted files passes CI and the pin first fires on the push-to-main
# run, as a red main.
tests/gh-rest-no-subshell-lint.sh
#
# BH-3860 / BH-3864: tests/gh-app-ratchet-test.sh walks bin/ with os.walk
# inside a Python heredoc (line ~394), the same blind spot BH-1485 documented.
# None of the four text signals see it, so a bin/-only diff did not select it,
# and a stale `raw-by-design` marker ejected #3809 / batch #3836.
tests/gh-app-ratchet-test.sh
#
# BH-5684: tests/pr-scoped-test-lint.bh-5684-test.sh runs bin/pr-scoped-test-lint.sh
# on the real tree, and the lint does the `git ls-files tests` itself. The suite's
# own text names no whole-tree read, so no signal sees it, and a tests/-only diff
# that adds an unguarded own-range read would not select it.
tests/pr-scoped-test-lint.bh-5684-test.sh
