# bin/lead-review.sh split into bin/lib/lead-review/ modules, with a growth lint (BH-6293)

Doc: MODULE-MAP, TESTING

## The gap

`bin/lead-review.sh` took edits from most tickets. It had 25 main commits and
31 conflict hits in the 24 h to 2026-10-12 17:00Z. The ticket counted 1,205
lines, the r2 attempt 2,007, and the base of this change (`dc9f7c1b`) 2,079.

## What moved

Four function groups moved byte for byte from `dc9f7c1b` into
`bin/lib/lead-review/`, one concern a module. The host went from 2,079 to 1,824
lines.

| Module | Functions |
|---|---|
| `rules-pack-inputs.sh` | `lr_rp_inputs`, `lr_rp_touched` |
| `result.sh` | `lr_detail`, `post_result`, `fail_terminal`, `claim_req`, `finish_done`, `supersede_dead` |
| `attempts.sh` | `lr_count_fail`, `lr_left_running`, `lr_fail_counted`, `lr_rate_limited`, `lr_release_rl` |
| `worker.sh` | `cleanup`, `rpool_on_result`, `lr_worker`, `lr_ring_land`, `lr_worker_exit`, `lr_slot_free` |

The top-level lines between them stay in the host: `WT=...`, `QF=...`, both
`trap` lines, `R=""`, the `LR_RING*` block and `running_at_close=...`.

Each of these is read by text (sed, awk or grep) in a suite or a script, or
shares state with the main body. To move one, a later slice must also move its
readers.

## How the host loads them

The module map pattern of `bin/lib/mc/` and `bin/lib/ms/` (docs/MODULE-MAP.md).
There is no second loader. `bin/lib/lead-review/load.sh` is
`bin/lib/mc/load.sh` with the names changed.
`bin/lib/lead-review/module-map.sh` is a git symlink to `../module-map.sh`.
`bin/lib/lead-review/MODULES` is generated by `bin/module-map-build.sh --write`,
and `--check` now reports 4 directories, `bin/lib/lead-review` among them.

The host sources the loader once, directly after `# <<< lead ci green`, after
every lib source and before the first call of a moved function:

```bash
# split-host: bin/lib/lead-review/ max-growth=40
if ! . "$H/bin/lib/lead-review/load.sh"; then
  log "bin/lib/lead-review/ did not load; lead-review tick skipped"
  HARNESS="$H" "$H/bin/alert-line.sh" --id "lead-review-modules-$(hostname)" "LEAD REVIEW MODULE MISSING: ..." >/dev/null 2>&1 || true
  exit 0
fi
```

A missing or broken module directory gives one log line, one alert line (one
row per box through `--id`) and exit 0. Exit 0 is the host's convention for a
missing required lib. The block runs before the tick lock, any claim, job,
attempt counter or spend read, so it changes no state.

One comment line above `rpool_init` names `LEAD_REVIEW_RATE_BACKOFF_S`. The
pool reads that knob under the `LEAD_REVIEW` prefix, and
`tests/lanes-registry-test.sh` section 6 needs the name in the lane script.
Before the split the name was in the doc comment of `lr_rate_limited`, which
moved to `attempts.sh`.

## The CI impact map

`ti_source_edges` (`bin/test-impact.sh`) follows `source`/`.` lines and
`# shellcheck source=` directives only, and `mm_load` names no file. New rule:
a non-comment line `mm_load "${BASH_SOURCE[0]%/*}"` (quoted or not) in script S
gives the edge S -> the directory of S. The closure then gives every suite that
reaches `bin/lead-review.sh` the row `bin/lib/lead-review/`, so a change to a
module selects every suite that a change to the host selects.

The rule is generic. `bin/lib/mc/load.sh` and `bin/lib/ms/load.sh` get the same
edge, so a change to an mc/ or ms/ module now selects more suites than before.
No selection gets smaller.

## The growth lint

`bin/split-host-growth-lint.sh [--base <ref>] [root]`, rules-pack row
`split-host-growth` (delta cmd). A host is a file under `bin/` with the line
`# split-host: <dir>/ max-growth=<n>`. The lint reads markers with `git grep`
at the merge-base and at HEAD, never the work tree. The merge-base marker wins,
so a PR cannot raise its own limit or delete the marker to pass. Net growth is
added minus deleted lines from `git diff --numstat`. Over the limit is rc 1
and one stdout line that names the module directory. The lint judges only
the hosts that the diff touches, so a bad marker already on main does not block
an unrelated PR. A HEAD marker line that does not parse is a finding, also when
the fork marker is valid, so the PR that breaks the marker goes red. A diff that
deletes the marker gets a `marker removed` note on stderr; the fork limit still
applies to that diff, and later diffs have no limit. Bad args, no work tree or
an unresolvable base is rc 2.

The limit lives in the marker line, not in a settings row: the lint runs in CI
and the PR lint job, which cannot read the jobs worker. A one-line PR changes
it, and the new value applies from the next PR.

## Fixture change in 6 suites

Six suites build a scratch harness from a hand list (bh-1950, bh-2202,
bh-2624, bh-3546, bh-3930, lane-identity bh-2537). Each one gets one line
after the `cp` that first puts `bin/lead-review.sh` in its tree:

```bash
scratch_install_closure bin/lib/lead-review/load.sh "$H" >/dev/null || ...
```

The closure is `load.sh`, `module-map.sh` (copied as a file) and the 4
modules. It copies no `MODULES`, so in those trees `mm_load` takes the order
from the module headers. The suites that already install the host's closure
get the module directory with no change.

## Lead protection

`catalog/lead-protected-paths.seed.tsv` gains `bin/lib/lead-review/**`, so the
moved code keeps the protection it had in `bin/lead-review.sh`. A seed glob
with no DB row is protected (the seed floor). To make it a console-editable
row, an operator can run `bin/lead-protected-paths-seed.sh` on the hub.

## Lessons for the next slices (blocked-resolver.sh, rb/plan.sh, mc/rebase.sh)

1. Before you move a function, grep tests/ and bin/ for readers of its body by
   text. Leave text-pinned functions in the host, or move their readers in the
   same slice.
2. Grep each lane knob that `catalog/lanes.d/` registers for the host. A knob
   named only in a moved comment fails `tests/lanes-registry-test.sh` section 6.
3. Find the suites that hand-copy the host (`cp "$DIR/bin/<host>"`). Each one
   needs one `scratch_install_closure <dir>/load.sh` line, never a `cp -r`.
4. Add the `# split-host:` marker and a lead-protected seed glob for the module
   directory in the same PR.
5. New files are invisible to `bin/test-impact.sh map` until `git add`: the
   map indexes tracked files.
6. Derive every moved body from the current base. Never copy a moved body from
   an older attempt branch: the r2 branch held a `lr_slot_free` from before
   BH-6984, and a copy would have reverted that change.
