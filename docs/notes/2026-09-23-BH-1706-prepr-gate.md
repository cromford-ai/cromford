# The build runs CI's two deterministic gates before it opens its PR

Doc: RUN-BUILD-GRAPH

## What was wrong

cromford CI runs `bin/checks-run.sh --tree .` and
`bin/test-determinism-lint.sh` on every PR. The build ran checks-run only in
diff mode (the MINED CHECKS block), and diff mode drops every `tests/` path. So a
new test that deleted a path it does not own, or read the wall clock, reached the
PR, and CI went red one round later.

## What it does now

`bin/run-build.sh` has a `# >>> prepr gate` block right after the spec artifact
commit and before the first push, the mechanical gates and the review. It
sources `bin/lib/prepr-gate.sh` and calls `prepr_gate . "$BASE" "$BUILD"`:

1. If the worktree does not ship both `bin/checks-run.sh` and
   `bin/test-determinism-lint.sh`, the state is `skipped` and nothing runs.
2. It runs both commands the way CI does, with the determinism lint pinned to
   the repo's own `catalog/determinism-lint.conf`. Findings in files that
   `git diff --name-only $BASE...HEAD` lists go to `prepr-findings.txt`.
   Findings anywhere else go to `prepr-preexisting.txt` and are only counted.
   A gate that exits 2 or more, or times out after 300 s, is `could-not-run`.
   It is never read as clean.
3. If there are no in-diff findings, the state is `clean` and no agent is
   called.
4. If there are in-diff findings and `RB_PREPR_FIX_TURNS` is 0, the state is
   `off`. The findings are recorded and nothing else changes, which is the
   behaviour before this change.
5. Otherwise the gate makes exactly one `CC fix "$FIX_MODEL" 4800` call. The
   brief is the findings verbatim. Then it re-scans once. The result is
   `fixed` only when the re-scan is clean, no tracked file is left
   uncommitted, and the turn did not edit `checks/`, `guardrails/` or
   `catalog/determinism-lint.conf`. Anything else is `red`.
6. `red` sets `PREPR_SECTION`, a `## Pre-PR gate: unresolved` section with at
   most 40 findings and the total count, which the PR body renders after the
   assumptions. It also sets `PREPR_NOTE`, ` | prepr=red`, which is appended
   to the three `PR_CREATED` RESULT lines.

Every run writes `$BUILD/prepr.txt` and one `PREPR state=<s> findings=<n>
preexisting=<m> turns=<t> fix_calls=<0|1>` line to `pipeline.log`.

`RB_PREPR_FIX_TURNS` is a `fly-pool` registry knob with default 1, min 0 and
max 1, resolved through `lane_knob`. The script carries no default of its own.
If nothing resolves (the registry is unreadable), the gate is detection only.
A value above 1 is treated as 1.

`PR_BODY_FOR` now pipes the body through `prepr_body_keywords`. For every
`Part of #N` line in `$BUILD/ticket-meta.json`'s body or `$BUILD/plan.md`, a
closing keyword (close/closes/closed, fix/fixes/fixed, resolve/resolves/resolved,
any case, optional colon) right before `#N` becomes `Part of #N`. `#16570` is
not `#1657`, and the ticket's own `Closes #<n>` stays. If there is no
ticket-meta.json or no `Part of` line, the body passes through unchanged.

The `bin/lib/rb/` stage modules are untouched. The new block sits between two
module slices, so the flatten identity holds.

## How to see it on a box

    grep 'PREPR state=' /root/harness/builds/cromford-*/pipeline.log
    cat "$BUILD/prepr.txt"
