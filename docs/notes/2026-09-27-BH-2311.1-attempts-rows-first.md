# Attempt ledger and land watermark: rows first

Doc: MERGE-CONDUCTOR

BH-2357 (BH-2311.1), the second slice of #2311. With the `pr-state-rows` flag
up, the conductor's attempt ledger answers from the `pr_attempts` rows and
`state/merge-conductor/attempts.txt` is a warm cache. The BH-870 land watermark
moves into `ledgers kind=mc_land key=<project>`. Flag down, nothing changes:
every function takes the file path it took before, byte for byte.

## What changed (`bin/lib/mc/locks.sh`)

| Function | Now |
|---|---|
| `mc_attempt_put` | row PUT first, then the file line. A failed PUT is one `mc_log` line a tick (`<tick>.pr-rows-putfail`, noclobber; once a process with no `MC_TICK_ID`), does not latch reads off, and the file line is still written. |
| `mc_attempt_has` | PR-keyed lines ask `pr_attempt_has` first. rc 0: attempted, the file is warmed if it lacks the line. rc 2: the file decides, and a file hit back-fills the row. Outage: latch the process and the tick (`<tick>.pr-rows-down`), then the FILE decides. It used to return "not attempted" on an outage. The BH-1831 miss memo stays and still reads the file. Non-PR lines, and a tail ending ` #<n>`, are file-only. |
| `mc_attempt_lines` / `_count` / `_tail` | rows first through `mc_attempt_rows`, turned back into `<kind> <key> <sha>` lines. A measured none (rc 2) is zero even with a stale file line. The file answers only when the rows cannot (flag down, not a PR key, an outage). `lines` over a `|` list is grouped by kind in the order given, oldest first inside a kind. A head with a space in it matches the whole tail. |
| `mc_attempt_put_n` | with rows in use the row sha is `<head…> #<n>`, n = 1 + `mc_attempt_count` of that head, because the route dedupes PUTs on (repo, number, kind, sha). The file line is unchanged. The readers strip the suffix. |
| `mc_attempt_rows` | kind `*` lists every kind (one GET). |
| `mc_rr_lanefail_note` / `_count` | go through `mc_attempt_put_n` / `mc_attempt_count`; the count still keys on `<head> <epoch>`. |
| `read_memo_fp` | rows of (KEY, HEAD) across every kind in one list GET, plus the file's count. The sum is deliberate: `cirerun`, `requeued`, `apread`, `mergetree`, `mergefail` and `mergifyhold` still append the file alone until BH-2311 siblings convert them, and a touch in either store has to move the fingerprint. An outage is the file's count alone. |
| `mc_land_prev` / `mc_land_record` | the ledger first. A 40-hex status is the answer. No row yet, an outage, or a status that is not a sha falls to the file, so neither the rollout nor a blink re-baselines a project. The record PUTs the ledger (rc ignored past one log line), then writes the file. |

`bin/lib/jobs/jobs.sh`: `pr_attempt_list` accepts an empty kind and leaves
`kind=` out of the query. The worker route already lists every kind then.

## Limits worth knowing

- Row sha is `str(sha, 64)` on the worker. The longest suffixed sha a PR-keyed
  writer makes today is `lanefail` (`<40-hex> <epoch> #<n>`, about 56 chars).
- `mc_attempt_has` back-fills an unsuffixed row. The counted kinds (`mergefail`,
  `lanefail`) are never asked through `has`, so nothing double-counts.
- `mc_attempt_clear` is unchanged. It does not clear a suffixed row, and no
  caller clears a counted kind.
- Two workers of one PR counting the same head in one tick compute the same n;
  the second PUT is a duplicate and the row count is one low. No lock was added
  (D33); the per-PR lock already serializes workers of one PR.
- Existing `lanefail` file lines have no rows, so the re-review lane-failure cap
  restarts once at flag-up.
- `has` now GETs on every PR-keyed ask (it used to only on a file miss), bounded
  by the tick's miss memo and outage latch. `put_n` adds one list GET; the land
  watermark one GET per project per tick.
