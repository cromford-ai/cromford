# The live cost meter and the boundary push (BH-3481.3)

Doc: COST

## What changed

This is the cost-live child of BH-3481 (ticket BH-3500). It fills the stub
bodies of `bin/lib/cost-live.sh` that BH-3481.0 added. The call sites in
`bin/agent-call.sh` are unchanged.

- `cost_live_on` decides once per claude attempt whether the live meter runs.
  It first applies the `lib.cost-live.*` settings rows (`lib_env_apply
  cost-live`, once per process). It is off, with the reason in `CL_OFF`, for:
  no root (`no-root`), `COST_LIVE=0` (`knob`), `HARNESS_TEST_SANDBOX=1`
  (`sandbox`), `PROJECT=testproj` (`testproj`), no `HARNESS_SECRET`
  (`no-secret`), no `JOBS_URL` or no jobs client (`no-jobs-url`), and any
  runner but claude (`runner=<x>`). When it is on, agent-call backgrounds the
  CLI and starts the meter beside it.
- `cost_live_meter` reads the session transcript with `bin/transcript-cost.sh`
  every `COST_LIVE_POLL_S` seconds. Every `COST_LIVE_PUSH_S` seconds it builds
  one live row (`cost_live_row`) and offers it with `cost_live_push`.
- `cost_live_row` is one JSON object with 16 fields: `box`, `row_hash`,
  `session_id`, `run_id`, `ticket`, `project`, `stage`, `model`, `input_toks`,
  `output_toks`, `cache_read`, `cache_write`, `cost_usd`, `unpriced`,
  `started_at`, `updated_at`. `row_hash` is `sha256("live|<box>|<session>")`,
  so a session has one live row, overwritten on each push. An unpriced model
  gives `cost_usd` null, never 0.
- `cost_live_push` POSTs `{box, rows: [row]}` to `/api/cost/live`, with one
  attempt and a 10 s bound. It never fails its caller. It sends nothing under
  the sandbox or for a `testproj` row.
- For a build call (`$OUT` under `builds/<dir>/`) the meter also calls
  `tw_check_build <project> <ticket> <build-dir> <live-usd>` on every poll.
  When that trips, it writes the rule and detail to `$OUT.tripwire` (first
  field is the rule, with no leading `trip`), sends TERM to the session, and
  stops. agent-call then treats the session as stopped by the tripwire.
- `cost_live_boundary_push` runs after every cost row. It spawns
  `bin/cost-rows-push.sh <box>` detached, so the row reaches the DB now rather
  than at the next 10-minute tick. It skips the spawn when the cron lane's lock
  (`locks/cost-rows-push.lock`) is held, when `COST_ROWS_PUSH_AT_BOUNDARY=0`,
  or when there is no `HARNESS_SECRET` or `JOBS_URL`. The last rule was added so
  test suites, which run with both empty, never leave a push running in their
  scratch tree.
- `cost_live_stale_s` prints `COST_LIVE_STALE_S` (default 900). That is the
  value a reader passes as `GET /api/cost/live?stale_s=`. Nothing calls it yet.

## Where it stands

BUILT, not live. `/api/cost/live` belongs to BH-3481's worker slice. Until that
deploys, every push gets a 404 and logs one line. `tw_check_build` is still the
never-trip stub until the tripwire slice lands, so the hook is inert.

## Knobs

`catalog/lanes.d/_lib.cost-live.json`, as `lib.cost-live.<env lowercase>`
settings rows. Every one has a code default, so no environment needs a value.

| env | default | meaning |
|---|---|---|
| `COST_LIVE` | 1 | 0 turns the meter off |
| `COST_LIVE_PUSH_S` | 300 | seconds between live pushes |
| `COST_LIVE_POLL_S` | 60 | seconds between transcript reads |
| `COST_LIVE_STALE_S` | 900 | the stale age a reader passes to the route |
| `COST_ROWS_PUSH_AT_BOUNDARY` | 1 | 0 turns the boundary push off |

## Log lines

- `logs/claude-cost.log`: `cost live: OFF (<why>)`, once per agent-call process.
- `logs/cost-live.log`:
  - `push FAILED session=<sid> http=<code> rc=<rc>`. A 404 reads
    `http=404 (route not deployed yet)`.
  - `could not read session <sid>; no live row this poll, meter keeps polling`,
    once per session.
  - `boundary push skipped (push in flight)`.
  - `meter off for session <sid>: ...`, when there is no transcript reader or no
    box id.

Tests: `tests/cost-live.bh-3500-test.sh`.
