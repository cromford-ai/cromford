# Flag CLI and the one-time hub seed (BH-5635.1)

Doc: OPERATING, DB-COORDINATION-SPEC

## What changed

- New entry point `bin/flag.sh`. It writes and reads the `pause_flags` rows
  for the six flag families (`paused`, `wip-limit`, `fly-pool`,
  `fly-pool-app`, `builder-fly`, `automerge-disabled`). The name check is
  `_flag_on_name` in `bin/lib/flag-on.sh`.
- New hub lane `flag` (`catalog/lanes.d/flag.json`,
  `cron/lanes/727-flag.cron`). It runs `bin/flag.sh seed` at minute 23
  of each hour, behind `hub-lease.sh check`, on the hub only.

## The verbs

- `bin/flag.sh on <flag> [<project>] [--value V] [--reason R]` and
  `bin/flag.sh off <flag> [<project>] [--reason R]` send one
  `PUT /api/flags {name, active, value?, actor: $JOBS_BOX, reason?}`.
  - The row is written first. `flags/<name>` changes only through `flag_sync`,
    and only after a 2xx whose `flag.name` and `flag.active` match the request.
  - rc 0: row written and read back. For `wip-limit` the read-back is
    `flags/<name>`. For the BH-4153 row families (`paused-*`,
    `automerge-disabled`, `automerge-disabled-*`) no file is written: the
    read-back is the cache that `flag_sync` fills, read with
    `flag_has --cached`, and the line says `cache synced`. On `off`, a legacy
    `flags/<name>` that is not newer than the row is removed.
  - rc 1: row not written (`flag.sh: row not written (<status>)`, the status
    being the HTTP code, `no-secret`, `no-url` or `curl_rc=<n>`), or the answer
    did not confirm the row. No file changes.
  - rc 2: bad usage, bad flag or project, or a routing flag. No request.
  - rc 3: the row is written, but this box does not read it back. For
    `wip-limit`, a local file newer than the row stays under
    last-writer-wins (BH-1370). For a row family, a legacy file newer than the
    row is a local hold that `flag_has` honours.
  - `on wip-limit` needs `--value <positive integer>` (1 to 6 digits).
    `--value` on any other flag, or on `off`, is rc 2.
  - `on` and `off` refuse `builder-fly`, `fly-pool` and `fly-pool-app`. Use
    `bin/jobs-client.sh routing-set` for them.
- `bin/flag.sh list [<project>]` prints one tab-separated line per row in the
  six families: name, active, value (`-` when empty), actor, updated_at. The
  worker returns at most 500 rows; a full page prints one stderr line.
- `bin/flag.sh history <flag> [<project>]` reads
  `GET /api/flag-changes?name=<name>` and prints one line per change.

## The seed

1. If `state/flags-seeded` exists, exit 0 with no request.
2. Take `locks/flag-seed.lock` with `flock -n`. If it is held, exit 0.
3. Run the lane gate (`flags/lane-off-flag`, `all-off`). Then read the
   fleet-wide marker, `GET /api/settings/flags.seeded`. A row there means a
   hub already seeded (the standby after a lease move must not seed its own
   files again): write the stamp with `marker=<value>`, one log line, exit 0.
   A failed read is rc 1 with no stamp.
4. Read the regular files `flags/wip-limit-*` only. The BH-4153 row families
   (`paused-*`, `automerge-disabled`, `automerge-disabled-*`) belong to
   `bin/flags-import.sh`, which publishes only the flags this box owns and
   keeps the rest as local holds. A hub-only pause must never become a fleet
   pause. No other file is read: `lanedown-*`, `alerted-*`, `pool-halt-*`,
   `hub-lease-renew-paused` and the routing families stay local.
5. For each file, `GET /api/flags/<name>`. A 200 skips the file: an existing
   row is never overwritten. A 404 sends a PUT with `active: 1`,
   `actor: "seed"` and `reason: "BH-5635 seed from <box> flags/"`. The PUT
   carries `value` only when the trimmed first line is 1-64 characters of
   `A-Za-z0-9._-`. Other content is seeded with no value and one
   `logs/flags.log` line.
6. Any other answer stops the pass: rc 1, one `logs/flags.log` line naming the
   file, no stamp. The next hour retries and skips the rows that now exist.
7. After a clean pass, `PUT /api/settings` key `flags.seeded` (value
   `<UTC time> box=<box> seeded=<n> skipped=<m>`). A failed PUT is rc 1 with
   no stamp. Then write `state/flags-seeded`
   (`<UTC time> seeded=<n> skipped=<m> box=<box>`, tmp + mv) and one
   `logs/flags.log` line.

Off: `flags/lane-off-flag` or `bin/harness-ctl.sh off flag`. The lane id is
`flag` because the registry requires a lane id to equal its script name
(`tests/lanes-registry-test.sh` section 2). The switch gates `seed` only;
`on`, `off`, `list` and `history` are operator commands and are not gated.
To seed again on purpose, delete the `flags.seeded` settings row and remove
`state/flags-seeded` on the hub.
