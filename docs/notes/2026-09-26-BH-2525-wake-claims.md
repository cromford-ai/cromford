# Wake claims, cursors and cooldowns: the contract

Doc: EVENTS

BH-2635 (BH-2525.0). The first slice of #2525. It ships the tables and the shell
client and nothing that uses them. Until the sibling slices land the worker
routes and wire `bin/wake-loop.sh`, nothing changes on any box.

## What changed

- `worker/jobs/schema.sql` gains three tables, all `CREATE ... IF NOT EXISTS`,
  applied by `bin/harness-sync.sh` before `wrangler deploy`:
  - `wake_claims (wake_id, box, claimed_at)`, primary key `(wake_id, box)`,
    index `(box, wake_id)`. A claim is per box, not exclusive: two boxes can
    each claim the same wake.
  - `wake_cursors (box, cursor, updated_at)`, one watermark per box.
  - `wake_cooldowns (kind, project, last_at, box)`, primary key
    `(kind, project)`, `last_at` in INTEGER epoch seconds.
- A seed copies each digits-only `settings` row `wake-cursor.<box>` into
  `wake_cursors` with `INSERT OR IGNORE`, so the first claim does not re-drain
  history and a re-apply never moves a cursor back.
- `bin/lib/jobs/queue.sh` gains four helpers.

## Wire shapes

| Helper | Request | Answer |
|---|---|---|
| `wakes_claim <box> <limit> <repos-csv> <all-kinds-csv>` | `POST /api/wakes/claim` `{box, repos, kinds_all_repos, limit}`, repos lowercased, empties dropped | `{wakes:[{id,repo,kind,key,event,at}], scanned_top}` printed as TSV rows then `#top <scanned_top>` |
| `wake_cursor_get <box>` | `GET /api/wakes/cursor?box=<box>` | `{cursor: <int or null>}`: the integer, or nothing on null |
| `wake_cursor_put <box> <n>` | `PUT /api/wakes/cursor` `{box, cursor}` | any 2xx |
| `wake_cooldown_take <kind> <project> <window_s> <box>` | `POST /api/wakes/cooldown/take` `{kind, project, window_s, box}` | `{taken: true/false}`: rc 0 / rc 1 |

Every helper answers rc 2 and prints nothing on an unusable answer: no worker,
a non-2xx (409 and 404 included), a body that does not parse, or bad arguments,
which are refused before any request. A failed request is never read as a
claim, a cursor of 0 or a taken cooldown.
