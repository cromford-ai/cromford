# Alert triage: the brake and the spools get a DB copy (BH-2344 / BH-2316.1)

Doc: DB-COORDINATION-SPEC

`bin/alert-triage.sh` keeps three "we already paid for this" records on the hub's disk: the 6h family brake (`state/alert-families.json`), the deferral spool (`state/alert-triage-deferred.tsv`) and the cliff park (`state/alert-triage-cliff-parked.tsv`). A rebuilt hub starts with none of them, so it bought a triage session again for every family it had just triaged and lost every deferred line. With `flags/alerts-db` on, the lane now writes each of them through to the generic `ledgers` table using the BH-2343 contract (`bin/lib/brake-ledger.sh`), and reads them back.

The local files stay primary. The flag is the only switch (`brake_db_on` is `alerts_db_on`). With it off, nothing new runs: no request and no file. Every DB call fails open. A read that fails is never taken to mean "the DB has none", so nothing is merged and nothing is cleared on it. Each kind of failed call writes one lane-log line per tick (`triage brake-ledger: <what> failed (rc=N)`).

## Family brake, kind `brake:triage-family`, key = the 12-hex family

- Before the splitter, the lane reads `alert_families alert-triage 21600 triaged` and `brake_read triage-family 604800`. The splitter merges both into `fams` as `max(local, db)` before the 6h check and before the tier choice. So a family the DB has seen is a repeat inside 6h, and a floor-tier re-occurrence after that. The families read asks for `state=triaged`, because this tick's own claim is a quarantined row and must not brake itself. The merged values are written to the local file as well, which heals it on a rebuilt hub.
- Each family the splitter put in `run` (the rows of `$PRESTAMP`) is marked `set` at the tick's clock. The mark goes right after the splitter's local stamp and before the sessions. Deferred, answered and settled families get no mark.
- `triage_restore_stamp` puts the DB copy back with the file: `brake_mark` at the prior epoch, or `brake_clear` when the family had none. That covers the cliff refusal, the rc-74 gate refusal, the noise budget and the marker-only evidence skip.

## Deferral spool, kind `brake:triage-deferred`, key = sha256 of the line bytes

- Only lines without `"dbrow":true` are mirrored, since those rows already live in `alerts`. Detail is `{"line": ...}`. A line over 3800 bytes, or one whose encoded detail would pass the worker's 4000-char cut, or one that is not UTF-8, stays local only, and the lane log counts it (`N deferred line(s) over 3800 bytes not mirrored`).
- The spool has seven append sites, so the mirror is not done per site. It is one reconcile on the lane's EXIT trap. The trap diffs the final spool (read under its flock) against the one `brake_read` taken at the start of the tick. It marks lines that are new and clears rows whose line the tick drained and did not put back. A line that stays deferred tick after tick costs no request after its first, so steady-state cost follows churn, not depth. Marks and clears both happen only when that read succeeded and was not `#truncated`: with no complete read to diff against, every spooled line looks new, and marking them all re-PUT the whole spool each tick (the PR #2445 lead review measured 499 PUTs for a 500-line spool under a 5xx, an HTML-200 and a truncated read). The next complete read marks whatever the outage skipped. A tick killed before the trap clears nothing.
- When the spool file does not exist at the start of a tick (an empty file is a normal drained spool, not an absent one), the rows from that read go into the tick first, where the drained spool would have put them. The dedup is by sha, and a row whose line does not hash back to its key is skipped as torn.

## Cliff park, kind `brake:triage-cliff`, key = sha256 of the line bytes

Marked on append with the same filter and key. Nothing re-queues from it, the same as the file. The daily page and the lane-log line name `kind=brake:triage-cliff` next to the file path, and they say so when the copy is incomplete.

`bin/fleet-status-push.sh` still counts the local spool and is unchanged.

Pinned by `tests/triage-brake-db.bh-2316-test.sh` and `tests/triage-spool-db.bh-2316-test.sh`, which run the real lane against a file-backed `/api/ledger` stub.
