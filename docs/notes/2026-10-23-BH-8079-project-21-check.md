# BH-8079: every build runs the project-21 dependency check

Doc: RUN-BUILD-GRAPH, ALERTS-STATE-MACHINE

## What changed

- New CLI `bin/project-21-check.sh <worktree> [--out <file>] [--head <sha>]`. It
  sends the tracked lockfiles of a worktree to
  `${PROJECT_21_BASE_URL-https://project-21.example}/v1/check` in one curl request
  (multipart, one field per file, the field name is the basename). It prints one
  line per affected dependency and a `PROJECT_21_SUMMARY <json>` line. It exits 0 on
  every check path; a usage error exits 2.
- The build lane (`bin/lib/rb/pr.sh`, block `project-21 check (BH-8079)` after the
  push) runs it once per head and puts a `## Dependency advisories (project-21)`
  section in the PR body. A result for the same head (`$BUILD/project-21.json`) is
  reused, so a build makes one call per head. A new head after a fix round is
  checked again.
- A failure (HTTP error, 429, timeout, a bad answer, no git tree, an empty
  `PROJECT_21_BASE_URL`) is `Check failed (<reason>). This is not a clean result.`
  A skip from the API (for example `partial_coverage`) or a `checked: 0` answer
  is `Partial coverage`, never `None known`.
- New self-check rule `project-21-upgrade`. Each affected row with a `fixed in` is a
  NOTE in the lead review request notes (`self_check_hold`, `lgsc_notes`). With
  `lib.project-21.project-21_review_block = 1` it is a REFUSE.
- New daily lane `bin/project-21-daily.sh` (`41 6 * * *`, every box). It counts the
  last `project-21 state=` line of each build of the last 24 h and raises the warn
  alert `project-21-check-failing` when more than 50% failed. It resolves it at or
  under 50%.
- `tests/lib/scratch.sh` exports `PROJECT_21_BASE_URL=` (empty), so no suite sends
  anything to project-21.example.

## Why

the operator, 2026-10-22: the factory must not merge a dependency with a known
advisory, and project-21 (example-org/project-21) answers that question. The check is a
tripwire (the operator's rule of 2026-10-14): it never stops a build.

## Data

The lockfile contents of every project this harness builds, client repos too,
go to project-21.example. That is the ticket's own ask, and project-21 is the operator's own
service. Set `lib.project-21.project-21_enabled = 0` to stop every call.

## Knobs and kill switches

- `lib.project-21.project-21_enabled` (1), `lib.project-21.project-21_review_block` (0),
  `lib.project-21.project-21_timeout_s` (30), `lib.project-21.project-21_rows_max` (50),
  `lib.project-21.project-21_field_max` (200), `lib.project-21.project-21_note_max` (10);
  seed rows in `worker/jobs/schema.d/202610272142-bh-8079-project-21-knobs.sql`.
- `lane.project-21-daily.project-21_daily_fail_pct` (50),
  `lane.project-21-daily.project-21_daily_window_h` (24); `flags/lane-off-project-21-daily`.
- `PROJECT_21_BASE_URL`: unset = https://project-21.example, empty = not configured.
  Nothing needs to be set on any box.
