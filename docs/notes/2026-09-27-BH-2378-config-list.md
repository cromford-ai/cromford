# /config lists every setting and flag, with audited edits (BH-2378)

Doc: DB-COORDINATION-SPEC

This is the list slice of BH-2330. It replaces the `/config` stub from BH-2375 with three tables and two modals. It adds no table and no schema.

- **SETTINGS** lists every row from `GET /api/coord/settings`, sorted by key, with a case-insensitive key filter. `lane.*` and `lib.*` rows are hidden until "show lane knobs" is ticked, and even then they carry an "edit on lane page" link (`/settings/<lane>`, or `/settings` for a `lib.*` row) and no EDIT. Every other row has EDIT.
- **FLAGS** lists every `pause_flags` row from `GET /api/coord/flags` with ON/OFF and a TURN ON / TURN OFF button. The same filter applies.
- **RECENT CHANGES — newest 50** reads `config_changes` of every kind (`GET /api/coord/config-changes?limit=50`). Each row links to `/config/<kind>/<name>`.
- EDIT asks for a value and a reason; TURN ON/OFF asks for a reason. Confirm stays disabled until both are valid (value: one line, 1..256 characters; reason: 1..512). Both modals say who last wrote the row and when, so a conductor republish shows up.
- EDIT is `PUT /api/coord/settings {key, value, reason}` with no `note`, so the row keeps its own note. TURN ON/OFF is `PUT /api/coord/flags {name, active, reason}`. A refusal shows "refused: <the worker's error>" and no success line. One busy latch disables every EDIT and toggle while a write is in flight.
- The coord proxy's PUT `settings` row now forwards `reason`. It stays optional there, because the SETTINGS page's knob writes send none.
- The pure half is `console-ui/src/lib/config.js` (`settingRows`, `flagRows`, `recentChangeRows`, `validateValue`, `validateReason`, `settingPutBody`). `useConfigChanges` in `console-ui/src/screens/Config.js` takes an optional `limit` and returns a `reload`.

The EDIT modal caps a value at 256 characters for every key, including the `conf.*` document keys the worker takes up to 4096. A longer document is still written from its own tooling.
