# The MCP server gets its read and action tools (BH-5224, part of BH-5218)

Doc: MCP

`mcp/tools/read.mjs` adds nine read tools (`project_status`, `builds`,
`pipeline`, `prs`, `alerts`, `costs`, `machines`, `logs`, `chat`) and
`mcp/tools/actions.mjs` adds seven write tools (`file_issue`,
`comment_issue`, `hold_issue`, `run_triage`, `pause_board`, `resume_board`,
`fetch_artifact`). Each file registers itself through `loadTools`, so no
shared list changed. Names and argument shapes copy the Cloud worker's
`mcp-tools.js` (moved out of this repo, BH-5239), with no `tenant`
property.

Every action is one `POST /api/dash/action` with body `{type: <tool>, ...args}`.
The schemas are closed, so an argument named `type` is refused before it could
replace the tool's own.

Routes this repo cannot confirm against the console are marked in
`docs/MCP.md`: the `builds` list, `alerts`, `logs` by project, and some query
parameters. They still forward, and a 404 answers
`console route not available: <path>`. `prs` needs `filter.project` because
the console route is per project; without it the call is refused and nothing
is sent.

`docs/MCP.md` is new: the settings, one config snippet per client, and the
19-tool table. It records that this repo's `mcp/` is the source of truth and
the console repo's copy is to be generated from it. That switch is a human
step, because the console repo is not reachable from the build box.

Tests: `tests/mcp-tools.bh-5218-test.sh` runs
`mcp/test/read-action-tools.test.mjs` against the real server process.
