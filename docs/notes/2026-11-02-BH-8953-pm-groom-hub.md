# BH-8953: pm-groom runs on the hub; a no-token send says why

## The defect

The Telegram bot token lives on the hub only. The `fleet:telegram` envelope
writes it to the hub's `env/global.env` and nowhere else. That is the design,
and this ticket keeps it.

`bin/pm-groom.sh` ran from `cron/lanes/737-pm-groom.cron` on the 8 project
boxes. Each box sent its brief through `bin/archie-tg-send.sh`, which had no
token there. The send exited rc 2 with no stderr line. Example: project-6-os
W45, 2026-11-02 11:01:15Z, `chunks=0 rc=2` (alert 53592).

## The change

1. `cron/boxes/hub.d/737-pm-groom.cron` holds the 8 weekly lines, one per
   project, at the minute each box used. They are in a `# @hub-lanes` block,
   so each line has the `hub-lease.sh check &&` prefix.
2. `cron/lanes/737-pm-groom.cron` is a comment stub with no schedule line.
   `catalog/lanes.d/pm-groom.json` `.boxes` is `["hub"]`.
3. `bin/archie-tg-send.sh` with no token prints one line on stderr and in
   `logs/archie.log`. The line names `TELEGRAM_BOT_TOKEN`, the hub-only design
   and the fix (run the send from a hub lane). It never prints a value or the
   text. rc stays 2, the documented contract that every caller handles. The
   once-a-day `archie-tg-token` ALERTS line now names the same cause.

## Why a hub.d fragment and not a `# @box hub` variant

In `REGISTRY_SOURCE=db` mode, `bin/render-cron.sh` takes lane membership from
the D1 `lane_boxes` rows. Those rows list the 8 project boxes for `pm-groom`
and not the hub, and no CLI verb changes them. A `# @box hub` variant would
then give the hub 0 lines. A hub.d fragment renders on the hub in both modes.
The stub keeps the lane fragment in place, because `render-cron.sh` refuses a
registry lane with no fragment. A box the D1 rows still list renders the
stub's default section, which has no schedule line.

## Consequences on the hub

- The hub has no `products/<project>/*/data-signals.json`; run-product writes
  it on the project box. So pm-groom runs `bin/pm-signals.sh <project>` into
  its temp dir when no local file exists, and uses that snapshot as evidence.
  The script is read-only, and its adapters read GitHub, the jobs worker,
  `logs/ALERTS.log` and `logs/cost.csv` of the hub. If it fails, the brief
  uses the stale list only (one warn line). `tests/pm-groom.bh-7261-test.sh`
  G8b pins this path.
- The box-local `flags/product-paused-<project>` no longer stops pm-groom,
  because the hub does not see box flags. A paused project still gets one
  model call a week, unless the DB switch `lane_paused run-product <P>` is set.
- A box-only `PM_MODEL` override no longer applies. The DB switches still apply on the hub:
  `lane_paused run-product <P>`, `lane-off-pm-groom`,
  `lane_model PM_MODEL product.pm <P>`.

is the gate host's scratch directory, not this diff. This diff touches no
`bin/lib/` file, no `tests/lib/` file and no file the ratchet scans.
