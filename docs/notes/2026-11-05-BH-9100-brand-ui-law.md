# BH-9100: UI changes follow the repo's brand rules file

Doc: docs/RUN-BUILD-GRAPH.md

What changed: a new law, `prompts/iron-laws.d/20261105-brand-ui.md`, rides the
system append of the `plan`, `execute`, `fix`, `review` and `lead-review`
stages when the repo declares a brand/UI rules file. The law names the file's
path and tells the model to read it. The file's content is not put in the
prompt.

Line 1 of the law file is `brand-stages: ...`, not `stages: ...`. So
`sil_text` (`bin/lib/stage-iron-laws.sh`) skips it, and the static stage laws
do not change. `bin/lib/brand-ui-law.sh` (`bul_text`) reads it instead.
`bin/agent-call.sh` appends its output after the `sil_text` laws. `PROMPT` and
`PROMPT_SHA` do not change.

How `bul_text` decides:

1. The stage must be a word of the `brand-stages:` line.
2. The path: env `BRAND_UI_FILE`, then the settings row
   `ui.brand_file.<project>`, then the row `ui.brand_file`, then
   `docs/claude/brand-ui.md`. No row falls through; an outage uses the
   default. A value that is not a repo-relative path (`..`, a leading `/`,
   a space) prints one `brand-ui:` stderr line and uses the default.
3. The repo: env `AGENT_CALL_REPO_DIR`, then `${REPOS_ROOT:-/root/repos}/<project>`,
   then the git top level of the current directory.
4. No regular file at `<repo>/<path>`: no law, and one line in
   `brand-ui-note.txt` next to the stage's out file (written once per dir):
   `brand-ui: <project>: no brand file at <path> in <repo>; brand rule not applied (BH-9100)`.
5. `review` and `lead-review` carry the law only when the diff touches UI. The
   file list is the `diff --git a/...` paths of the prompt, else
   `git diff --name-only ${AGENT_CALL_DIFF_BASE:-origin/main}...HEAD`. The
   globs are env `BRAND_UI_GLOBS`, then the row `ui.brand_ui_globs`, then the
   e2e UI globs plus `*.tsx *.jsx *.vue *.svelte *.scss *.sass *.less`. An
   unknown or empty list keeps the law.

Review severity: a raw color or a one-off component is a `[NOTE]`. The law
adds no BLOCK class; a BLOCK comes only from the REVIEW LEVELS rule.

To point a project at another file: `setting_set ui.brand_file.<project> <path>`.
The seeds are in `worker/jobs/schema.d/202611051648-bh-9100-brand-ui-knobs.sql`.

No fleet repo has `docs/claude/brand-ui.md` today. Until a repo adds it, every
stage keeps the system append it had before, and each build dir gets one note.

The 2026-10-13 prototype law is not changed.

Test: `tests/brand-ui-law.bh-9100-test.sh`.
