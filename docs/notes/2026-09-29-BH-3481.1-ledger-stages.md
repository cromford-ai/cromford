# Decomposed and superseded builds end at an honest ledger stage (BH-3481.1)

Doc: RUN-BUILD-GRAPH

## What changed

This is child 2 of 5 of BH-3481 (ticket BH-3498). Two kinds of build row used
to stop at `planning` on the console and never move again. BH-3417 is the live
example.

- **A size-gate split.** In `bin/lib/rb/plan.sh`, the `SG_DRC = 0` arm of the
  size gate now calls `BB decomposed "" "" "" false "split into <children>"`
  right before `RESULT "DECOMPOSED …"`. BB is fail-open: no beat.sh, no hub, or
  a failed POST, and the RESULT line and exit 0 are unchanged. The held arm
  (rc 3, `BUILD_DEFERRED`) and the `DECOMPOSE_FAILED` arm send no new beat.
- **A ticket that already merged.** In `bin/blocked-resolver.sh`,
  `br_resolve_ticket_merged` still marks every build dir of the ticket
  `.blocked-resolver-superseded`. Each marked dir now also gets
  `br_row_closed … superseded "superseded: <KEY> already merged via <url>"
  resolved-merged`, with three exceptions that keep the marker and get no beat:
  - the RESULT's first line starts with `PR_MERGED`;
  - the RESULT names the merged url (only checked when the url is non-empty,
    because `grep -F ""` matches every file);
  - the RESULT carries a `BUILD_DIR:` or `BUILT_AS:` line whose basename is not
    this dir's. That is a hub mirror of a pool build (`pool-<p>-<K>-*`,
    `<p>-<K>-remote<stamp>`). Its basename is no row's bkey, so a beat keyed on
    it would create a phantom `superseded` row. The real row already got its
    own terminal beat from the pool builder.

  Observe mode returns before the loop, so it sends nothing, as before. A dir
  with no RESULT is beaten `superseded`; if it is really still running, its
  next beat overwrites the stage.

Pinned by `tests/ledger-stages.bh-3498-test.sh`, which drives the shipped
size-gate block with the real `BB()` and the two resolver functions verbatim.

## Not in this change (follow-ups)

- The console still classifies `decomposed` as lane `building`
  (`console-ui/src/lib/stages.js`) and counts it in the cockpit's "building
  now" (`TERMINAL_STAGES` in `console-ui/functions/api/cockpit/[[path]].js`).
  That is what `planning` did, so nothing regresses, but no child of BH-3481
  owns the fix yet. It needs its own ticket.
- `ROLLOUT_FILED` still ends without a terminal beat.
- `br_resolve_merged` still marks its one record `.blocked-resolver-superseded`
  without a `superseded` beat. The ticket scoped this change to the
  ticket-merged loop only.
