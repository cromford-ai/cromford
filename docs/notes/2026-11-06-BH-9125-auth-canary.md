# The auth canary runs on auth.canary, once per account per UTC day (BH-9125, slice C3 of BH-9064)

Doc: AUTH-PROBE

## What changed

- New model route `auth.canary`. The seed fragment
  `worker/jobs/schema.d/202611060410-bh-9125-auth-canary-route.sql` copies
  `bootstrap.smoke` rung 0 on the claude runner (a Haiku-class model). Two
  `NOT EXISTS` guards keep an operator's edit or delete of the row.
- `bin/claude-auth-check.sh` (hub `PROBE_BODY`) and `bin/lane-probe.sh` (claude
  arm) resolve `auth.canary`. If that route cannot be read, they use `triage`.
  The new env override is `AUTH_CANARY_MODEL`. `TRIAGE_MODEL` no longer steers
  the canary, and its knob left `catalog/lanes.d/claude-auth-check.json`.
- After a day claim rc 0 with an account fp, the daily inference carries
  `AGENT_CALL_FP=canary:<runner>:<account fp>:<UTC day>`. The hub sets it in
  `local_claude_probe`; a remote box sets it in `lane-probe.sh --endpoint`.
  Only the asked model carries it, not the `auth.fallback` rung.
- `bin/lib/agent-call-ledger.sh`: `acl_precall` sends the window
  `AGENT_LEDGER_CANARY_WINDOW_S` for a stage-canary call with a caller fp. Every
  other call keeps `AGENT_LEDGER_WINDOW_S`.
- On the hub, with the day fp, the nonce is 12 hex of sha256(fp). A replayed
  answer then passes the sentinel check of the next run.
- `lane-probe.sh --endpoint` exits 0 and records nothing when the answer holds
  an `AGENT_CALL_REFUSED` line (a terminal ledger row gives back its stored rc).

## Knobs

- `AGENT_LEDGER_CANARY_WINDOW_S` (`catalog/lanes.d/_lib.agent-call-ledger.knobs.d/`):
  default 86400, min 60, max 604800, seconds. Code fallback
  `ACL_DEF_CANARY_WINDOW_S`.
- `AUTH_CANARY_MODEL` (`catalog/lanes.d/claude-auth-check.knobs.d/`): default
  empty, the DB route decides.

## Assumptions

- `<account>` in the fp is `<runner>:<cred_account_fp>`, the key of the day
  claim. A full Claude login rotates its token about every 8 h, so one login
  can buy up to 3 canary inferences on a day.
- The ledger is the second gate. The day claim stays first. The replay matters
  when the claim fails open (no `bin/lib/cred-probe.sh`) or the claim row is lost.
- `lane-probe.sh --endpoint` passes the day fp for every lane (claude, codex,
  openrouter, fireworks, grok). Only the claude model route changed.
- `lane-probe.sh` default mode (`bin/lane-reprobe.sh`) carries no fp: a reprobe
  needs fresh evidence.
