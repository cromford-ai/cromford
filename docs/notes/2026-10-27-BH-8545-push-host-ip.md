# BH-8545: hub->box pushes use the fleet.conf tailnet IP

## What was wrong

`bin/vercel-deploy-snapshot.sh` pushed `state/vercel-deploy-status.json` to
`root@<box name>`. The tailnet name `box-project-1-1` resolved to a device
that was offline for 58 days. Every push to that box timed out from
2026-10-24 20:44Z, and the box's snapshot stayed at 2026-10-23 00:56Z. The
failure showed only in `logs/vercel-snapshot.log`.

`bin/stale-owed-tickets.sh` had the same shape: its READY-QUEUE push ssh'd
`root@$IP`, and `$IP` held the box name from `bin/box-for.sh`.

## What changed

- `bin/box-host.sh <box>` (new) prints the ssh host for a box: the fleet.conf
  column 7 tailnet IP (through `bin/fleet-conf.sh --tailnet-ip-of-box`). A box
  with no IP prints its own name, as before. `local` prints `local`.
- Both pushes ssh `root@$(box-host.sh <box>)`. `bin/box-for.sh` does not change:
  its answer is a box identity for 30+ callers.
- The snapshot push keeps a fail streak per box in
  `state/vercel-snapshot-push-fail/<box>`. A success deletes the file. When the
  count reaches `VERCEL_PUSH_FAIL_STREAK` (default 3), one ALERTS line names the
  box, the host and the first ssh error line (cut to `VERCEL_PUSH_ERR_CHARS`,
  default 200). The next line needs a new streak.
- A failed push logs `push:<box>@<host>` in `logs/vercel-snapshot.log`.
- Knobs: `lane.vercel-deploy-snapshot.vercel_push_fail_streak` and
  `lane.vercel-deploy-snapshot.vercel_push_err_chars`
  (`catalog/lanes.d/vercel-deploy-snapshot.json`).

## Operator step

Remove the stale `box-project-1-1` device in the Tailscale admin console.
This is a person's step. The push no longer depends on it.
