# Box-ops lane: every box runs its own console box commands (BH-2518.2, BH-2660)

Doc: OPERATOR-SETUP

## What changed

- **New lane `box-ops`** (`bin/box-ops.sh`, `catalog/lanes.d/box-ops.json`,
  `cron/lanes/697-box-ops.cron`). It runs every minute on every box in the
  `update-runners` list, hub included. Each tick claims up to
  `BOX_OPS_MAX_PER_TICK` `box_commands` rows for this box from the jobs worker
  (`POST /api/box-commands/claim`), runs each one locally, writes one
  `logs/box-ops.log` line per command, then posts `{claimer, ok, detail}` to
  `/api/box-commands/<id>/result`. No ssh is involved.
- **Which rows a box claims.** `boxes` is the `bin/box-name.sh` name, plus
  `hub` only while `bin/hub-lease.sh check` passes. That is why the cron line
  is `# @ungated`: the lease gate is applied per row inside the script, not
  to the whole lane.
- **The ops.** `backup_now` runs `bin/state-backup.sh` and is ok only on rc 0
  and a `state/backup-last.json` stamp at or after the moment the op started.
  A held backup lock, "not configured", "off" or an ALERTS line from the run
  is posted as the fail detail. `harness_sync` maps rc 0 / 20 / 30 to ok /
  `not synced: <line>` / `refused: <line>`. `cli_update` is ok on rc 0 with
  its last stdout line. `fly_machine_stop` / `fly_machine_destroy` call
  `bin/lib/box-ops-fly.sh`, which still answers `refused: fly ops not built
  yet` until the Fly slice (#2661) lands; a target that is not
  `[0-9a-z]{8,32}` or a project/app outside `[A-Za-z0-9._-]{1,64}` is refused
  before the lib is called. Anything else is `refused: unknown type <t>`.
  Every op runs under `timeout BOX_OPS_TIMEOUT_S`; rc 124 is
  `timed out after <n>s`.

## Knobs and switches

- `BOX_OPS_TIMEOUT_S` (default 900, min 60). Keep it below the worker's
  `box_commands_claim_ttl_s` (fallback 1800), or a running op is re-offered.
- `BOX_OPS_MAX_PER_TICK` (default 3, min 1).
- A knob that is not a positive integer is one ALERTS line and exit 1,
  with nothing claimed.
- Off: `bin/harness-ctl.sh off box-ops` (`flags/lane-off-box-ops`).

## Until the worker routes deploy (#2659)

Every claim answers 404, so each box logs
`claim route not deployed (HTTP 404); nothing claimed` once a minute and
exits 0. Nothing pages. A result POST that fails after an op ran is the one
thing that does: one ALERTS line, exit 1, and the row stays claimed until the
worker re-offers it.

Tests: `tests/box-ops.bh-2518-test.sh`.
