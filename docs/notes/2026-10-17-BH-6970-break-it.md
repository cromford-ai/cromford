# The break-it verifier (BH-6970)

Doc: MERGE-CONDUCTOR, OPERATING

Part of #6544, wave 4 of 4. It builds on BH-6967 (the `review-tier:` token in
the request notes and the tier and mode columns on a verdict row).

## What changed

After the lead model's verdict is readable, `bin/lead-review.sh` calls
`bi_review` (`bin/lib/break-it.sh`). It runs only when:

- the LAST group of the request's scope notes is
  `review-tier:medium|high review-mode:full|intent` (the BH-6967 token), and
- the settings row `break_it.mode` reads `shadow` or `enforce` (trimmed, any case).

A `low` tier is `skipped:low`. No token is `skipped:unclassified`. No row, an
unreadable row or another value is `skipped:off`. A skipped run makes no call
and records nothing.

One run is ONE model call on route `review-break-it`, with no tools and the
budget from `break_it.budget_usd`. The prompt is
`prompts/lead-review.d/break-it.md`, the limits, the ticket's Acceptance tests
section (else the PR body's, cut to 8 KB) and the diff (cut to
`break_it.max_diff_bytes`). The answer is one JSON object of cases. At most
`break_it.max_tests` are kept.

The changed files pick the framework before any spend:

| Most changed files under | File | Runs |
|---|---|---|
| `worker/jobs/` | `worker/jobs/test/<key>.breakit.test.js` | `node --test` in `worker/jobs` |
| `console-ui/` | `console-ui/tests/<key>.breakit.test.js` | `node --test` in `console-ui` |
| anything else, or a tie | `tests/<key>-breakit-test.sh` (needs a `tests/*-test.sh`) | `bash` at the repo root |

`<key>` is the ticket key from the PR title (`bh-6970`), else `pr<n>`. A repo
with none of these is `could-not-run` with no call.

The file runs as the user `nobody` (`setpriv --reuid/--regid --clear-groups`,
the same drop as `bin/test-impact-gate.sh` `isolated_run`), in a `git archive`
snapshot of the head in a fresh temp dir that nobody owns. It has no inherited
environment except `PATH` and `HARNESS_TEST_SANDBOX=1`, and it runs under
`timeout` of half the time left. So a case cannot read `/etc/harness/env`,
`/root` or the gh config, and cannot write the review worktree. The network is
not closed. A probe with the run's own flags goes first. If `setpriv` or the
`nobody` user is missing, or the probe cannot switch or reach the snapshot, the
result is `could-not-run` and no case runs. The node import allowlist is a
shape check, not a security control. Only counted result lines decide:

- `clean`: rc 0 and one PASS line per case. The file is deleted.
- `failed:<k>`: k counted FAIL lines. The file is kept in `state/break-it/`.
- `could-not-run`: no framework, no route, under 120 s left, a refused call, an
  answer with no usable case, a bad import, a syntax error, a timeout, or a
  count of result lines that is not the count of cases. It never makes a BLOCK.

## Where the result goes

- The report header: `- break-it (BH-6970): <result> (mode <m>)`, above `- pr body:`.
- The result detail of the request: `break-it:<result>`, next to `golive:N`.
- `bin/lead-review-land.sh` reads it and posts `--break-it <result>` through
  `bin/lead-verdict.sh post`. The worker stores it in the new nullable column
  `verdicts.break_it` (refused 400 outside `clean`, `failed:<k>` with k 1..999,
  and `could-not-run`).

`shadow` changes nothing else. `enforce` + `failed:<k>` adds one finding to the
review and makes the verdict BLOCK:

```
- [BLOCK wrong-data] break-it: <path> failed <k> of <n> case(s): <names>. Test file committed to the PR branch as <sha12>. Output below.
```

The commit uses the contents API. It is skipped (and the line says why) when the
PR head moved or the branch is in a fork. The commit moves the head, so the next
head gets its own review.

## One attempt per head

- The box replay file `state/break-it/<owner>_<repo>-<pr>-<sha>.result` is read
  before the call and written after every paid call.
- The call guard on stage `lead-head` with fp `lead:<owner/repo>#<pr>@<sha>~breakit`
  refuses a repeat on any box before anything is bought.
- A refusal (agent-call rc 74..79) writes no replay file, so a later tick can try.
- Replay files older than `break_it.cache_days` are deleted before each run.

## Settings rows

| Row | Seed | Code fallback |
|---|---|---|
| `break_it.mode` | `shadow` | `off` |
| `break_it.max_tests` | `5` | `5` (1..20) |
| `break_it.budget_usd` | `1.50` | `1.50` (> 0, <= 20) |
| `break_it.max_diff_bytes` | `200000` | `200000` (1000..2000000) |
| `break_it.cache_days` | `14` | `14` (1..365) |

The seed is in `worker/jobs/schema.d/202610171749-bh-6970-break-it.sql`, with
route `review-break-it`: rung 0 a copy of `triage.light` rung 0, rung 1 a copy of
`lead.review` rung 0. No model literal.

## Before an operator sets enforce

A model-written case can itself be wrong, and that counts as a failure. Run
`shadow` first and read the `break_it` column of recent verdict rows: a
`failed:<k>` on a head the lead approved and that merged clean is a false
positive.
