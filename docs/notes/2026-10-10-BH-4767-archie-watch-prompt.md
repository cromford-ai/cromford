# Archie whole-factory watch prompt (BH-4767, slice 4 of #4760)

Doc: OPERATOR-SETUP

## What changed

- New prompt `catalog/prompts/archie-watch.md`. It has a fixed checklist of 10
  checks. Each threshold check names its `archie.watch.<key>` setting and no
  number. Per finding, the answer is `FINDING:`, `CAUSE:`, `LEVER:` (or
  `TICKET:`) and `SAY: none|beat|report`. A finding with no named cause gets
  `CAUSE: unknown` and `LEVER: probe <what to read>`. No findings is the one
  line `NONE`. A check whose threshold key is absent from the input is not
  judged.
- Six new settings seeds in `worker/jobs/schema.d/0002-base-rest.sql`, right
  after the `stage.archie` route seed: `archie.watch.approved_idle_min` (60),
  `archie.watch.build_fail_pct` (30), `archie.watch.build_fail_min_n` (3),
  `archie.watch.lane_silent_cadences` (2), `archie.watch.spend_pace_pct` (120)
  and `archie.watch.quota_repeat_n` (3). `worker/jobs/schema.sql` is
  regenerated by `bin/schema-build.sh --write`, and `bin/harness-sync.sh`
  applies it before a deploy.
- `afw_session` (`bin/lib/archie-fm-watch/common.sh`) sends an answer to the operator
  only when it has a line `SAY: beat` or `SAY: report`. Before, it sent every
  non-blank answer. An answer of `NONE`, or with only `SAY: none` findings,
  closes the `watch-session` row `done` and sends nothing. A blank answer is
  unchanged.
- New replay skill `catalog/prompts/replays/archie-watch` with 3 recorded
  cases: 01 fixed silently (`none`), 02 main red (`beat`), 03 unknown cause
  (`probe`). Run: `bin/archie-skill-replay.sh --root catalog/prompts/replays`.

## What this turns on

`afw_session` skips the model session while `catalog/prompts/archie-watch.md`
is absent. With this file on main, `bin/archie-fm-watch.sh` starts watch
sessions in `archie.manage=on`: at most `archie.cap.watch-session` per UTC day
(seed 12, 0 = off), on the `stage.archie` route.

## Not done here

`afw_session` passes the `## Findings this tick` rows. It does not pass the
six thresholds or the owed ledger as JSON. Until a reader passes `thresholds`,
the threshold checks are not judged: they come back `CAUSE: unknown` with a
probe lever.
