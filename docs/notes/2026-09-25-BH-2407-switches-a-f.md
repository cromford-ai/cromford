# Kill switches a-f: the contract (BH-2407, built as BH-2431)

Doc: CONFIG, VERIFICATION-MAP

Three changes that the BH-2407 children build on. No reader script changes here.

**The hatch no longer ignores a kill file.** `LANE_GATE_DISABLE=1` used to make `lane_switch`
answer rc 1 before anything else, so with the hatch on, a `flags/<name>` kill file stopped nothing.
That was fail-open. Now the hatch skips the settings rows (no refresh, no request) and goes to the
no-row step, with `LANE_SWITCH_SRC=legacy`. The file decides, which is what "runs as before" means
for the gate (agent-call.sh). A name outside `[a-z0-9_-]` is refused before the hatch, so it never
becomes a path.

**`lane_switch <name> [file|flag]`.** The second arg picks the no-row step and nothing else; a row
answers the same in both. `flag` is the default and is the BH-2320 behaviour: `flag_active` when the
jobs client is loaded, else the file. `file` reads only `[ -f flags/<name> ]` and makes no
`/api/flags` request. Any other value writes one throttled `logs/lane-gate.log` line
(`switch <name>: mode '<m>' is not file|flag, read as flag`) and is read as `flag`, never as off.

**25 more switches are registered** in `catalog/switches.d/`: agent-call-ledger-off,
alert-quarantine-disabled, alert-state-off, audit-off, batch-resolve-off, bin-self-heal-off,
blocked-resolver-disabled, builder-direct-off, call-guard-off, cliff-refuse-off, cliff-route-off,
clock-sync-off, context-gate-disabled, context-kill-off, cost-autohalt-off (a second reader,
`bin/pipeline-health.sh`, added to the existing file), cost-reconcile-off, cost-row-at-source-off,
cost-rows-from-db-off, cost-rows-push-off, dep-verify-off, extra-usage-track-off, fastpath-off,
fixpr-suppress-off, fleet-slo-off and fly-disabled. `readers` lists the files that read the flag on
a code line today; files that only name it in a comment or a message are left out. Registering is
harmless before the readers convert: `bin/switch-migrate.sh` is run by hand, and the row it writes
equals the file it copied. `bin/switch-migrate.sh --dry-run` now lists 26 switches.

**The ratchet takes per-ticket drops.** `tests/switch-ratchet.bh-2320-test.sh` keeps `FLOOR=102`
and subtracts the sum of `tests/switch-ratchet.d/*.drop`. A child that converts readers adds its own
`<KEY>.drop` holding how many bare reads it removed, and never edits `FLOOR`, so parallel
conversions do not meet on one line. The tree must still sit exactly at the effective floor, and a
drop that is not a non-negative integer fails the suite (R0).

To drive a switch with a row: `PUT /api/settings` with `switch.<name>.<box>` or `switch.<name>`
set to `1` or `0`, or run `bin/switch-migrate.sh --dry-run` on the box and then without the flag.
