# The onboarding box station: Fly pool and dedicated Fly box (BH-7975, slice BH-7939.1)

Doc: ONBOARDING, VERIFICATION-MAP

## What changed

- `obs_box` (`bin/lib/onboard-stations.sh`) reads `OBS_BOX_PATH`. Unset or
  `shared` runs the old body, byte for byte. `pool` and `dedicated` run
  `obx_run` in the new `bin/lib/onboard-box.sh`. Any other value fails with
  `unknown box path '<v>'` and makes no call. `bin/load-project.sh` does not
  set the variable, so its path does not change.
- `bin/onboard-run.sh` reads `inputs.box` once per run (`_obr_box_inputs`):
  `''` and `shared` are `shared`; `pool` and `fly` (the console picker's id)
  are `pool`; `dedicated` is `dedicated`. `inputs.have_box` is "I have a box".
  `inputs.tailscale` = `off` turns Tailscale off. On a dedicated run the clone
  station reads the project's box address from the registry
  (`fleet-conf.sh --tailnet-ip <p>`) first.
- Waits and `started_at` (the BLOCK on PR #8619, comment
  IC_kwDOTh6ir88AAAABhMfEVA): a box station wait sends NO beat. The worker's
  `running` beat rewrites the step's `started_at`, so a beat per poll made the
  box duration on SetupLine show only the last poll. Each poll now sleeps
  `onboard.box_poll_s`, then calls `obs_run_cancelled` (`bin/onboard-run.sh`):
  one `GET /api/onboarding/runs/<id>` with `JOBS_ALERT=0`. It answers
  "cancelled" only when the answer parses and `.run.state` is not `running`.
  A transport failure, a non-2xx or a bad body keeps the wait going, with no
  alert. `started_at` is written once, by the runner's first `running` beat.
  No keep-alive is needed: the cron lane holds `flock -n
  locks/onboard-run.lock` for the whole tick, so no other tick runs the stale
  check while a station waits. Each timeout counts from the station's own
  clock (read once at the start of the wait), never from a worker time.
  `bin/load-project.sh` defines no `obs_run_cancelled`, so its waits never
  probe. Pinned by `tests/onboard-run-box.bh-7975-test.sh` R3 and R5c/R5d and
  by `tests/onboard-box-pool.bh-7939-test.sh` P10.
- Path `pool`: the shared bootstrap, then one `<p> <ISO UTC>` line in
  `$ROOT/fly/onboard-queue.conf` when no line for `<p>` is there, then a wait
  for `[fly-onboard/<p>] FLY_ONBOARD <p> OK|ALREADY|FAILED:` in
  `logs/fly-pool-rollout.log` after the byte offset read before the append. OK
  and ALREADY are done. FAILED is failed and prints the last
  `onboard.box_fail_tail_lines` lines after the offset, redacted. No verdict in
  `onboard.box_pool_timeout_s` is failed, with the drain ledger
  (`state/fly-onboard/<p>.attempts`) named. The station never runs
  `bin/fly-onboard.sh`; the fly-pool-tick drain does. A project already routed
  to its pool is done with no queue write. A project the drain gave up on fails
  at once and names the two `rm` commands. If `bin/harness-sync.sh` rewrote
  `fly/` during the wait, the line is appended again (said once).
- Path `dedicated`: provision (`fm_create box-<p>` from `onboard.box_image` in
  `onboard.box_region`, then `fm_state` until `started` within
  `onboard.box_provision_timeout_s`), tailnet (`ts_join` on the machine's
  `fdaa:` address with `TS_AUTHKEY_<P>`, else `TS_AUTHKEY`; Tailscale off
  with no `have_box` is refused at `tailnet` before any Fly call, because
  `validateRegistry` takes only a dotted IPv4 `tailnet_ip` and an `fdaa:` box
  could never register), register (`bin/registry.sh add-box
  <p>-box --like <the run's default box>` and `move-project <p> --box
  <p>-box`, read back with `show`), bootstrap (the shared `obs_box` block on
  the new address). "I have a box" checks the address (an IPv4 in 100.64/10 or
  an RFC 1123 name) before any ssh and skips provision.
- Every ssh on the dedicated path (the Tailscale seam, the bootstrap and the
  clone on the box's own address) uses `-o StrictHostKeyChecking=accept-new`.
  A new machine's host key is in no known_hosts, and under cron the default
  `ask` fails as "Host key verification failed". A changed key still fails.
  The shared path keeps the default policy.
- Before any call the dedicated path refuses: a file-mode registry
  (`REGISTRY_SOURCE` is not `db`), a bad "I have a box" address, an empty
  `onboard.box_image`, no Fly token, and (Tailscale on) no Tailscale key. So a
  refused run spends nothing.
- Retry and spend: a registry row for `<p>-box` with an address skips provision
  and tailnet, so `fm_create` is not called again. A machine that was created
  and has no registry row yet is found by name: `fm_create` reads `machine
  list` first and makes no `machine run` when `<name>` exists.
- Output: each step prints `BEAT box.<sub> <running|done|failed|skipped>
  <detail>` (one line, redacted, 160 chars at most). `obx_run` ends every path
  with `== box summary ==` and the last line per sub in path order, so the
  4096-byte excerpt the runner stores always holds every sub-line. The worker
  stores the excerpt only on the step's done or failed beat, so the SetupLine
  sub-lines show when the box step ends, not live.
- `catalog/fly-idle-signals.json`: the prefix `box-` is `exempt`. Before this,
  an app with no entry answered `metrics` and could be idle-stopped.
- Settings rows (`worker/jobs/schema.d/202611101915-bh-7939-onboard-box-settings.sql`,
  INSERT OR IGNORE, no table): `onboard.box_image` `''`, `onboard.box_region`
  `iad`, `onboard.box_pool_timeout_s` `3600`, `onboard.box_provision_timeout_s`
  `600`, `onboard.box_poll_s` `30`, `onboard.box_call_timeout_s` `120`,
  `onboard.box_fail_tail_lines` `20`. Each code fallback equals its row.

## Operator steps

1. Set `onboard.box_image` to a full fleet box image before the first
   dedicated run. Until then a dedicated run fails with `no box image set`.
2. Set the GitHub Actions repo secrets `FLY_API_TOKEN`, `FLY_ORG`,
   `FLY_CONTRACT_APP`, `FLY_CONTRACT_MACHINE` and `TS_CONTRACT_HOST` for the
   contract suites. Without them the suites print `SKIP vendor:` and pass.

## Limits

- The worker still refuses `inputs.box` other than `shared` at run create, and
  the onboarding form has no pool or dedicated choice. #8266 widens both. Until
  then a pool or dedicated run exists only as a seeded run row.
- A hand run of `bin/onboard-run.sh <other-id>` (no flock) during a wait
  longer than `ONBOARD_RUN_STALE_MIN` can send one stale warn alert for the
  waiting run (once per run per UTC day).
