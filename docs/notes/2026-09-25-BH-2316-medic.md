# BH-2345 (BH-2316.2): the medic's brakes survive a dead hub

Doc: DB-COORDINATION-SPEC

Rung: BUILT. The suite below runs the real `bin/alerts-medic.sh` against a stub worker. Nothing
here has been seen on the hub yet.

## What changed

`bin/alerts-medic.sh` now writes its three brakes through to `ledgers(kind,key)` with
`bin/lib/brake-ledger.sh` (BH-2343), and reads them back as a union every pass. The local files
stay primary and are always written first.

| brake | local file | ledger kind | read window | written when |
|---|---|---|---|---|
| seen ids | `state/medic-seen.txt` | `brake:medic-seen` | 604800 s | an id's session ran (same loop as the local append) |
| 6h family stamp | `state/medic-families.json` | `brake:medic-family` | 21600 s | a family's session ran (not on an rc 74..79 refusal, not for a deferred family) |
| parked families | `state/medic-parked.json` | `brake:medic-parked` | `MEDIC_PARK_TTL` | a park is recorded this pass (`set`, `at = since`) or released (`cleared`) |

- Seen rows join both SEEN filters. Family rows are appended to the `$DBFAMS` set that
  `alert_families medic 21600` already fills. Park rows are merged into the splitter's `parked`
  map before the escalation loop, so a restored park keeps its own `since`. A local park of the
  same family wins.
- A park row's detail is `{since, ids, line}`. The worker slices `detail` at 4000 chars, so
  trailing ids are dropped from the ROW until it is 3900 chars or less. The local park keeps
  every id.
- `cleared` is written from exactly two places: the TTL releasing a park, and a new id in a
  parked family releasing it. A read never clears anything.
- The family window is 21600 s, not the ticket's 604800. `$DBFAMS` brakes any key it holds, so
  a 7-day read would stretch the 6h brake to 7 days.

## Gate and failure

All of it runs only when `alerts_db_on` (`flags/alerts-db`) is up and the library loads. With
the flag off there are no ledger requests at all. A failed read (worker down, a 200 that is not
a ledger list) logs `medic db: <name> ledger read rc=N` to `logs/medic.log`, and the pass then
decides from the local files alone. A capped read (`#truncated`) is still used, and the log says
the union is partial. A failed mark or clear is one `medic db:` log line, and the local state
stands.

`brake_read` hands the park detail over through jq `@tsv`, which doubles every backslash, so a
park whose `line` holds a `"` or `\` does not parse as it arrives. The splitter tries the raw
text first and then the text with `@tsv`'s escapes undone. Without that second try, the park
came back with no ids, the first alert in its family unparked it, and the unpark cleared the
ledger row.

outside their windows, `cleared` rows, marks after a session and none on rc 75 or over the cap,
