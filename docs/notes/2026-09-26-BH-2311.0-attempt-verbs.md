# Attempt-ledger verbs: the contract

Doc: MERGE-CONDUCTOR

BH-2354 (BH-2311.0). The first slice of #2311. It adds four verbs to
`bin/lib/mc/locks.sh`, beside the BH-1025.0 row twin, and nothing calls them
yet. Every call site still reads and writes `$MC_ATTEMPTS` with its own
`grep`/`awk`/`echo`, so nothing changes on any box.

## What changed

The verbs compute what those call sites compute today, over the file only.
The rows-first read is BH-2311 sibling 2's change, and it keeps these
signatures.

| Verb | Answer |
|---|---|
| `mc_attempt_lines <kinds> <key> <out-file>` | every matching whole line, file order, in `<out-file>`. rc 0 lines, rc 2 a measured none (a missing ledger counts as none), rc 1 bad args or an unwritable `<out-file>`. A plain command, never `$( )`. |
| `mc_attempt_count <kinds> <key> [head]` | the number of matching lines. `0` on a missing or unreadable ledger or empty args. rc 0. |
| `mc_attempt_tail <kind> <key> <head> [first\|last]` | field 4 onward of the first or last (default) match, nothing when none. rc 1 and nothing for any other mode. |
| `mc_attempt_put_n <kind> <key> <head…>` | appends `<kind> <key> <head…>` through `mc_attempt_put`: the file line byte-identical to today's `echo >>`, then the flag-gated row, rc ignored. rc 1 without kind, key and at least one head. |

`<kinds>` is one kind or a `|` list (`ejected|reejected|ejectconflict`).
Matching is string equality on `$1`, `$2` and, given a head, `$3`: `requeued`
never matches `requeued2`, `o/r#12` never matches `o/r#123`. Keys match byte
for byte, as the greps do today; nothing is case-folded here.
