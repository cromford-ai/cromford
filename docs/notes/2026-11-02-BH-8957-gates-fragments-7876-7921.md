# BH-8957: BH-7876 and BH-7921 gate sites as gates.d fragments (slice C1 of BH-8930)

Doc: RUN-BUILD-GRAPH

## What changed
- Three blocks of `bin/lib/rb/gates.sh` moved verbatim into `bin/lib/rb/gates.d/`:
  - `closed issue skip` -> `gates.d/closed-issue-skip.sh` (in `rb_gate_prelude`).
  - BH-7876's daily-ceiling check, cut out of `budget launch gate` -> `gates.d/project-ceiling.sh`
    (in `rb_gate_prelude`). It is now a marked block `project daily ceiling`. Its call line sits
    at column 0 inside the `else` arm, directly above the `ADMITTED` write.
  - `issue created-at stamp` -> `gates.d/issue-created-at.sh` (in `rb_gate_claim_and_workspace`).
- Each old place now holds one call line `. "$RB_GATES_D/<slug>.sh"`.
- The five suites that lift `budget launch gate` raw and run it under `set -u`
  (`project-ceiling.bh-7876`, `budget-caps-scopes.bh-4489`, `autohalt-boundary.bh-5526`,
  `spend-ceiling.bh-5526`, `budget-midway.bh-5526`) now export `RB_GATES_D`. Without it the
  call line cannot find the fragment and the block exits 127. A new raw runner of that block
  must export it too.
  `run-build-issue-rest.bh-1641` §3 reads the created-at region from its fragment, and its
  `gh issue` ratchet also reads `gates.d/*.sh`.

## Why
BH-7876 and BH-7921 both edited `gates.sh` and collided. A block in its own file is one file per ticket.

## Rule for the BH-7921 rebuild
- Edit `gates.d/closed-issue-skip.sh` and `gates.d/issue-created-at.sh`, not `gates.sh`, at those two sites.
- `TEST_SELECT_RESOLVE` (inside `harness suite run`) and the stack-wait read (inside
  `stacked child builds`) stay inline in `gates.sh`. They are not gates, and 20 suites read them raw.
- The tracker feature itself (`bin/lib/rb-tracker.sh`) is not built here. It stays with #7921.

## Known difference
The `rb_all` flatten differs from the old text by exactly two lines:
`# >>> project daily ceiling` and `# <<< project daily ceiling`. The other two moves flatten to the same bytes.
