# BH-10231: box-watch duty and the hourly Orgo lever check (C1 of BH-9889)

## Why

On 2026-11-21 box-small stayed dark for 5.5 hours until the operator
restarted it by hand. `bin/box-ssh-probe.sh` records each box's ssh answer, but
it never acts, and no lane called the restart lever (`bin/box-ops.sh restart`).
C0 (PR #10178) made a dead lever loud on each refused restart. This slice adds
the duty that pulls the lever, and an hourly check of the lever itself.

## What

`bin/box-watch.sh`, a hub lane (scope hub, behind `bin/hub-lease.sh check`).
Owner: the quartermaster staff agent (`staff_lanes` row
`('quartermaster','box-watch')`). Bash only, no model call.

- `tick`, every 5 min. Probes each fleet.conf box at once with
  `timeout <probe_timeout_s> ssh root@<tailnet ip> true`. Not probed: role hub
  or retired, the hub box, this box, a box with no tailnet IP. Counts the
  failed probes in a row in `state/box-watch/<box>.fails`; a rc 0 probe writes
  0. A box at `fail_probes` starts `act` detached.
- Mass dark: when `mass_dark_boxes` or more boxes fail in one tick, the lane
  restarts none and sends one warn alert (`box-watch-mass-dark`). The hub's
  own network is then the likely fault. The alert is retracted when the
  condition clears.
- `act <box>`, at most once per box per `restart_window_min`:
  1. Local stamp `state/box-watch/<box>.restart`, then the D1 claim
     `POST /api/box-watch/claim` (one `INSERT ... WHERE NOT EXISTS`). Both are
     written before the restart.
  2. `bin/box-ops.sh restart <box_id> --host <box> --apply`.
  3. Boot wait: probe every `boot_poll_s` until ssh answers or `boot_wait_s`.
  4. One recovery ssh: `bin/dns-guard.sh`, the settings refresh plus
     `lane_env_apply update-runners`, `bin/tmpfs-ensure.sh`.
  5. One re-probe, then `POST /api/box-watch/actions/<id>` with box, probes,
     restart rc, recovery rc, outcome and back-at.
- `lever-check`, hourly at :23. For each `key_env` in
  `catalog/orgo-plans.json` (fallback `ORGO_API_KEY`): unset, or a
  `GET /workspaces` that is not 2xx, is one warn alert through
  `orgo_lever_alert` (the same id `orgo-lever-<KEY>` and text as box-ops). A
  2xx retracts it. It never restarts anything and never prints a key value.

## Alerts

| id | severity | when |
|---|---|---|
| `box-watch-dark-<box>` | critical | the restart is refused (box-ops rc 2), fails, the box stays dark, or the act times out; retracted when the box is back |
| `box-watch-mass-dark` | warn | `mass_dark_boxes` or more boxes dark in one tick |
| `orgo-lever-<KEY>` | warn | the key is unset or `GET /workspaces` is not 2xx |

## Knobs

Settings rows `box_watch.<name>`, then env `BOX_WATCH_<NAME>`, then the code
fallback. A value outside its range is the fallback plus one WARN log line.

| row | fallback | range |
|---|---|---|
| `box_watch.fail_probes` | 3 | 1..100 |
| `box_watch.restart_window_min` | 120 | 5..10080 (the worker claim reads the same row) |
| `box_watch.probe_timeout_s` | 15 | 1..110 |
| `box_watch.mass_dark_boxes` | 3 | 1..1000 |
| `box_watch.boot_wait_s` | 600 | 10..3600 |
| `box_watch.boot_poll_s` | 15 | 1..600 |
| `box_watch.recovery_timeout_s` | 180 | 5..1800 |
| `box_watch.act_timeout_s` | 2400 | 60..7200 |
| `box_watch.orgo_timeout_s` | 30 | 1..300 |
| `retention.box_watch_actions.days` | 365 | the hourly `bin/d1-retention.sh` rule |

## Data

D1 table `box_watch_actions`, one row per restart attempt
(`worker/jobs/schema.d/202611261440-bh-10231-box-watch.sql`). Indexes
`idx_box_watch_actions_box(box, acted_at)` and `idx_box_watch_actions_at(acted_at)`;
the EXPLAIN at 20,000 rows is in the fragment header. 12-month size: under
1,000 rows. Rows older than 365 days are deleted (no money moves here).
The BOX WATCH section of `/staff/quartermaster` lists the newest 50 rows.

## Kill switch

`flags/lane-off-box-watch` (or `flags/all-off`), or
`bin/harness-ctl.sh off box-watch`. Every verb is gated.

## Operator commands

- Run one tick by hand on the hub: `bin/box-watch.sh tick`, then read
  `logs/box-watch.log`.
- Check the lever now: `bin/box-watch.sh lever-check`.
- Allow an early second restart of one box: delete
  `state/box-watch/<box>.restart` on the hub. The D1 claim still holds the
  window, so also wait for it, or lower `box_watch.restart_window_min`.

## Neighbors

`bin/box-ssh-probe.sh` (every 2 min) also ssh's each box; no shared state.
The Mission Control restart button and the MCP `box_restart` tool use the same
lever; this window does not see their restarts. The box-ops dedupe lock
covers the concurrent case: box-ops then prints `already running`, and the
act's boot wait and re-probe decide the outcome.

## Test fixture change: tests/route-keyed-merge.bh-5788-test.sh

`worker/jobs/test/route-table.d/bh-10231-box-watch.txt` is the first route
fragment with a five-digit ticket key. Fragments sort by file name, and
`bh-1-` < `bh-10231-` < `bh-2-` because `-` sorts before `0`. The suite's
fixture families used the keys `bh-1` and `bh-2`, so the real box-watch family
sat between them and case M1 ("zz-a directly before zz-b") went red. Every
key from BH-10000 to BH-19999 would do the same. The fixture keys are now
`bh-99998` and `bh-99999`. They sort after every real key. Every assertion
stays exact.
