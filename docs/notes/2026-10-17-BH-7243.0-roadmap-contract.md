# Roadmap contract and tracer (BH-7243.0, BH-7263)

Doc: CONSOLE, worker/jobs/README.md

Slice 1 of 5 of #7243 (the per-project roadmap and ideas backlog). This slice lays the
contract the four children import, and one end-to-end path: add an idea, read it back.
Every new name uses the word "roadmap". The existing `/ideas` screen and
`console-ui/functions/api/ideas/` are not changed.

## Data model

One schema fragment, `worker/jobs/schema.d/202610182038-bh-7243-roadmap-ideas.sql`, holds
all five tables, their indexes and four settings rows. No child adds DDL for these tables.

| Table | Rows | Key columns |
|---|---|---|
| `roadmap_ideas` | one per idea | `lane` = ideas, next or discarded; `version`; `idem_key` (UNIQUE per project); `source_ref` (UNIQUE per project, the import dedup) |
| `roadmap_idea_events` | one per change of an idea | `kind` = created, moved, edited or imported |
| `roadmap_links` | idea to filed GitHub issue | PK `(idea_id, repo, issue)`; `wave_id`; `issue_state` = open, closed_completed, closed_other or NULL |
| `roadmap_decisions` | decisions log and open questions | `kind` = log or open; `status` = open, decided or dropped |
| `roadmap_waves` | one shaping request | `status` (the CAS claim) = requested, shaping, draft, empty, failed, rejected, approved, filing or filed; `input_fp` UNIQUE per project (dedup before spend); `draft` JSON; `cost_usd` |

Now and Shipped are computed by BH-7243.2. They are never stored as a lane.
Enums are checked in JS, so a later enum change stays additive.

The `roadmap_waves.draft` JSON format:

```json
{"slices":[{"title":"","body":"","acceptance_tests":[],"spec_refs":[],"files":[],"seam_files":[],"blocked_by":[]}],"notes":""}
```

`blocked_by` holds 1-based positions of earlier slices. BH-7243.3 writes it and BH-7243.4
reads it. This slice has no writer or reader of it.

Settings rows: `roadmap.list_limit` = 200, `retention.roadmap_ideas.discarded_days` = 180,
`retention.roadmap_idea_events.days` = 730, `retention.roadmap_waves.days` = 365.

## Routes

`worker/jobs/src/routes/roadmap-ideas.js`, fragment `test/route-table.d/bh-7243-roadmap-ideas.txt`.
Both routes need the bearer.

- `GET /api/roadmap/ideas?project=&lane=&limit=` answers
  `{project, ideas, counts:{ideas,next,discarded}, truncated, as_of}`, newest `updated_at`
  first. A `limit` above `roadmap.list_limit` is lowered to it. A `limit` that is not an
  integer of 1 or more is a 400.
- `POST /api/roadmap/ideas {project, title, note?, source, link?, idem_key?, actor}`. A bad
  field is a 400 that names it in `field`. The project must be a row of `projects`. The idea
  and its `created` event are written in one D1 batch, so neither exists without the other.
  The same `idem_key` with the same title, note, source and link is a 200 replay of the
  stored idea. Anything else under that key is a 409.

Exports for the children: `ROADMAP_TABLES`, `IDEA_LANES`, `IDEA_SOURCES`,
`ensureRoadmapTables(env)` (creates all five tables from the schema.d text through
`ensureTable`) and `validateIdea(raw, {partial})`.

Statement counts, steady state:

- GET: 1 batch of 2 statements (list and counts). `settingsRows` adds 1 when its cache is cold.
- POST: 2 batches, 4 statements (project and idem lookup, then the insert and the event).
  A replay is 1 batch of 2.

`worker/jobs/test/roadmap-explain.bh-7243.test.js` proves each query uses its index on
40,000 ideas, 100,000 events and 2,000 waves.

## Retention

Three rules in `worker/jobs/src/routes/retention.js`, three keys in `ARCHIVE_TABLES`
(`worker/jobs/src/lib/archive.js`). Each rule copies the rows to the archive D1 and counts
them back before it deletes. With the archive unbound, it deletes nothing. Its
`retention_runs` row says "archive not bound" only while a row is eligible
(`quietUnbound`). The archive D1 is not bound in prod yet, and `bin/d1-retention.sh` raises
one alert for each rule error, so these rules must not raise three alerts every hour over
empty tables. `retention.dry_run` applies.

- `roadmap_ideas.discarded`: a discarded idea after 180 days. The delete repeats
  `lane = 'discarded'`, so an idea restored in between stays.
- `roadmap_idea_events.age`: an event after 730 days.
- `roadmap_waves.closed`: a rejected or failed wave after 365 days. The delete repeats the
  status test. Waves hold `cost_usd`, so they are archived.

`roadmap_links` and `roadmap_decisions` have no rule. They are the Shipped column and the
decisions log, and they grow by one row per filed slice or decision.
