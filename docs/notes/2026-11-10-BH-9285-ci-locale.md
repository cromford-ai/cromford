# BH-9285 slice C0: box suite runs use CI's locale and Postgres collation
Doc: docs/verification-map/entries/BH-9285.md

SLICE: C0 of #9285.

## Problem

A pool box ran a project's suite in the box locale (`C` on the pool image). Its
throwaway Postgres got an initdb with no `--locale`. A sort or an `ORDER BY`
came out in byte order. project-6 CI sorts with glibc `en_US` (the Postgres
image default), and PR #3661 went red in CI after the box said green.

## What changed

- `bin/lib/ci-env.sh` (new) resolves the locale. Source order:
  1. The knob `CI_LOCALE`: row `lib.ci-env.<project>.ci_locale`, then row
     `lib.ci-env.ci_locale`, then the env.
  2. The top-level `env:` `LC_ALL`, else `LANG`, of `.github/workflows/ci.yml`
     (else `harness-ci.yml`). Job-level `env:` is not read.
  3. The fallback constant `CE_FALLBACK_LOCALE=en_US.UTF-8`.
  A value must match `^[A-Za-z0-9_.@-]{1,64}$`. Any other value gives the next
  source. The collation is the knob `CI_PG_COLLATION`, else the locale.
- `HARNESS_SUITE_RUN` (`bin/lib/rb/gates.sh`) runs `npm run <script>` with
  `LANG`/`LC_ALL` set to that locale. It writes one record line to the outfile
  and to `pipeline.log`:
  - `HARNESS_LOCALE: <loc> (source: <knob|workflow|fallback>, collation <c>)`
  - `HARNESS_LOCALE: could-not-run (locale <x> not installed; source: <s>)`.
    Then npm and Postgres do not start, and the exit is
    `HARNESS_EXIT: could-not-run`.
- `pgt_start` (`bin/lib/pg-test.sh`) passes `--locale`, `--lc-collate` and
  `--lc-ctype` to initdb when the caller loaded `ci-env.sh`. It writes
  `HARNESS_PG: started (locale <l>, collation <c>)`. A missing locale is rc 3
  and `HARNESS_PG: could-not-start (locale <l> not installed)`.
- `bin/ci-local.sh` gives each step the knob's or the workflow's locale. With
  the fallback source, a step keeps the caller's `LANG`/`LC_ALL`, as before. A
  named locale the box does not have makes each step `COULD-NOT-RUN`.
- `fly/Dockerfile` installs `locales` and generates `en_US.UTF-8`.

## The image window

The pool image before this change has no `en_US.UTF-8`. Until the nightly
image rebuild (`bin/fly-image-refresh.sh`, 05:40Z) picks up the Dockerfile
change, every npm-project pool suite run records `HARNESS_EXIT: could-not-run`.
That is one record line per build: no alert, no page, no block. CI decides.

## Rollback

One settings row, no deploy: set `lib.ci-env.ci_locale` to `C.UTF-8`. Every
box has that locale, so suite runs start again (in `C.UTF-8`, as before).
