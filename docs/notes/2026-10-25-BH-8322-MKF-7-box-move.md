# Move a project box to a Fly machine: bin/box-move.sh, slice C0 (BH-8322, MKF-7)

Doc: HUB-THINNING-PLAN, RESTORE

## What changed

Parent #8315 (D2-a) moves a whole project box (first `box-project-6-os-1`) to
one Fly machine. `bin/box-move.sh` is the box variant of `bin/hub-move.sh`
(BH-7715). An operator runs it on the hub:

```
bin/box-move.sh inventory <oldbox> <newbox>
bin/box-move.sh provision [--plan] <oldbox> <newbox>
bin/box-move.sh seed <oldbox> <newbox> [<ts>|latest]
bin/box-move.sh tick <oldbox> <newbox>
bin/box-move.sh proof <oldbox> <newbox>
```

This is slice C0 of #8322. C0 is read-only for the old box, the fleet rows
and the old crontab. It writes only on the new machine (nothing reads it yet)
and in `state/box-move/<newbox>/` on the hub. Slice C1 adds `cutover --step`,
`rollback` and `tick --real`, the verbs that write rows and the old crontab:
see [2026-10-26-BH-8410-box-move-cutover.md](2026-10-26-BH-8410-box-move-cutover.md).

Files:

- `bin/box-move.sh`: the CLI, the knobs, the sandbox guard, the lock,
  `inventory`, `tick`, `proof`.
- `bin/lib/box-move/common.sh`: refusal and failure exits, the rows lookup,
  `target.json`, the remote runner `bm_sh`, the idle-exempt rule.
- `bin/lib/box-move/provision.sh`: `provision [--plan]`.
- `bin/lib/box-move/seed.sh`: `seed`, the env pipe, the swap script.
- `catalog/fly-idle-signals.json`: the prefix `box-` is `exempt`.
- `tests/box-move-provision.bh-8322-test.sh`, `tests/box-move-seed.bh-8322-test.sh`,
  `tests/box-move-tick.bh-8322-test.sh` and their fixture
  `tests/lib/box-move-fixture.bh-8322.sh`.

No cron fragment, lane file or catalog lane row names box-move. It is
operator-run.

## Rules

- Box identity and placement come from the rows: `bin/fleet-conf.sh
  --boxes-with-roles` (box id), `--tailnet-ip-of-box` (address) and
  `--projects-on-box` (projects). With `REGISTRY_SOURCE=db` these read the D1
  registry. box-move never reads a box id from a file on the old box.
- The new machine keeps the old box id. `seed` fails (exit 4) when the
  restored `state/box-id` on the new box is not the rows box id. So
  `bin/render-cron.sh <box id>` on the new box renders the old box's crontab,
  and the lane rows keyed on the box id need no change.
- Provision calls Fly only through `bin/lib/hub-move-fly.sh` (unchanged). Each
  create runs only after its find answered absent. A find that cannot read
  stops the run (exit 4) and creates nothing. A rate limit is exit 75.
- Provision refuses (exit 3) an app that is not `exempt` in
  `catalog/fly-idle-signals.json`, with the reaper's rule (an exact `apps` key
  wins, else the longest prefix that matches from the start). A box app with
  no entry gets the `metrics` signal and `bin/fly-idle-reaper.sh` can stop it.
- Env goes BOX TO BOX. One pipe: `tar -c` of the old env dir on the old box
  into `tar -x` on the new box. Each side resolves its own env dir with its own
  `bin/lib/env-path.sh`. The stream crosses the hub in memory only. No hub
  file, argv or log line holds a value. Both pipe rcs must be 0, else exit 4
  and no state restore. The new env dir must not be a symlink (exit 3).
- `seed` needs the MKF-6 backup keys on the old box: `BACKUP_S3_ENDPOINT`,
  `BACKUP_S3_ACCESS_KEY_ID`, `BACKUP_S3_SECRET_ACCESS_KEY` as set lines of a
  `*.env` file. It checks the NAMES on the old box and refuses (exit 3) when
  one is absent, commented, empty or only in a file that is not `*.env`.
- State comes from the bucket: `bin/state-restore.sh <box id> <ts> --apply`
  on the new box, into an empty tree, with no `--identity`. So env/ in the
  snapshot is not decrypted; env came from the old box. The swap moves the
  restored `state/`, `flags/`, `logs/` and orchestrator in. The old copies go
  to `tmp/box-move-prev-<run>` and are never deleted.
- After the restore, seed writes `state/box-name` = `<newbox>`, clones each
  project with `bin/bootstrap-machine.sh <p> --repos-only`, sets a LOCAL
  `flags/all-off` on the new box (never a fleet row) and writes
  `state/hub-move/target-seeded` (the marker `bin/hub-move.sh tick` needs) and
  `state/box-move/seeded` (`<ts> <oldbox> <box id>`).
- `tick` runs `bin/hub-move.sh tick` (no-write) on the new box. That tick
  renders `render-cron.sh <state/box-id>`, runs each command once under the
  no-write shim `bin/lib/hub-move-nowrite.sh`, skips the cron installers,
  refuses an unseeded box, and lifts and sets the local all-off again.
  box-move copies the table to `state/box-move/<newbox>/tick-<ts>.tsv` and the
  summary line to `tick-<ts>.summary`, also when the tick rc is not 0.
- Exit: 0 done; 2 usage or a bad knob; 3 preflight refused (one stderr line,
  one `bin/alert-line.sh --id box-move-preflight` row); 4 a step failed; 75
  Fly rate limit. `locks/box-move-<newbox>.lock` dedupes provision, seed and
  tick (held = print and exit 0). `provision --plan`, `inventory` and `proof`
  take no lock.

## Knobs

Env knobs of an operator-run CLI (the BH-7715 pattern), each with its
fallback:

| Knob | Fallback | Note |
|---|---|---|
| `BOX_MOVE_APP` | `<newbox>` | must be idle-exempt |
| `BOX_MOVE_REGION` | `iad` | the fleet's region |
| `BOX_MOVE_VM_SIZE` | `performance-4x` | parent #8315 section 4 |
| `BOX_MOVE_MEM_MB` | `8192` | project-6-os used 1 GB idle |
| `BOX_MOVE_VOLUME_GB` | `100` | project-6-os has 99 GB, 45% used |
| `BOX_MOVE_TS_HOSTNAME` | `<newbox>` | the tailnet hostname |
| `BOX_MOVE_IMAGE` | none | required for a real provision (exit 2) |
| `BOX_MOVE_TS_WAIT_S` | `300` | tailnet wait |
| `BOX_MOVE_TS_POLL_S` | `10` | tailnet poll step |
| `BOX_MOVE_SSH_CONNECT_TIMEOUT_S` | `15` | ssh ConnectTimeout |
| `BOX_MOVE_TARGET_HARNESS` | `/root/harness` | on the new box |
| `BOX_MOVE_OLD_HARNESS` | `/root/harness` | on the old box |
| `BOX_MOVE_TARGET_ORCH` | `/root/orchestrator` | on the new box |
| `BOX_MOVE_SSH_DIR` | `$HOME/.ssh` | the hub keys |
| `BOX_MOVE_PROC_LOADAVG`, `BOX_MOVE_NPROC` | `/proc/loadavg`, `nproc` | proof inputs |

`fly.env` must hold `TS_AUTHKEY_BOX`, a tagged tailnet key for project boxes.
`HUB_MOVE_REACH_HOST`, when set, is passed to the tick; else the old box
address is.

## Operator probes

Run on the hub, in this order. Each one prints names only.

1. `bin/box-move.sh inventory box-project-6-os-1 box-mkfly`
2. `BOX_MOVE_IMAGE=<hub image> bin/box-move.sh provision --plan box-project-6-os-1 box-mkfly` (calls nothing)
3. `BOX_MOVE_IMAGE=<hub image> bin/box-move.sh provision box-project-6-os-1 box-mkfly`
4. `bin/box-move.sh seed box-project-6-os-1 box-mkfly latest`
5. `bin/box-move.sh tick box-project-6-os-1 box-mkfly`
6. `bin/box-move.sh proof box-project-6-os-1 box-mkfly`
