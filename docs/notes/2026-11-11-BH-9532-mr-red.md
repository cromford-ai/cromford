# Mr Red tracer: one tick, one collector source, audit rows (BH-9532 C0, #9539)

Doc: STAFF, OPERATING

Part 1 of 5 of #9532. Mr Red is the staff agent that owns red minutes. This
slice lands the contract the four sibling slices (#9540 to #9543) build on,
and the thinnest end-to-end path:

`*/5` hub cron -> `bin/staff/mr-red.sh tick` -> kill gate -> lane gate ->
`flock -n` -> roster active -> collector (`10-drafts.sh`) ->
`POST /api/staff/findings/claim` -> lever pick -> `POST /api/mr-red/actions`
-> act -> `PATCH` -> `mrr_judge_tick`.

In C0 every lever seam matches nothing, so each finding is ONE row with lever
`observe` and state `observed`. Nothing writes to GitHub.

## What ships

- `worker/jobs/schema.d/202611111407-bh-9532-mr-red.sql`: table
  `mr_red_actions`, four indexes (`ix_mr_red_actions_created`, `_fp`,
  `_state`, and `_repo` for `GET ?repo=`), the roster row `mr-red` (lane
  `staff-mr-red`), and the core settings rows `staff.mr-red.*`.
- `worker/jobs/src/routes/mr-red.js`: `POST`, `PATCH /:key` and `GET
  /api/mr-red/actions`. The route computes `action_key =
  sha256(lever|target|fingerprint|approach)`. The same key with the same
  repo, project, target_kind, dry_run and red_check is 200 `existing:true`;
  another value is 409 `key_mismatch`. `state=cleared` needs
  `verified_red_at` and `verified_green_at` (body or row), else 400
  `unverified`. `GET` pages with `cursor=<created_at>~<id>`, `limit` 1..100.
- `bin/lib/mr-red.sh`: `mrr_killed`, `mrr_setting`, `mrr_action_post`,
  `mrr_action_patch`, `mrr_actions_get`, `mrr_dispatch`, `mrr_fingerprint`.
- `bin/staff/mr-red.sh tick | work <payload>`, `bin/staff/mr-red-collect.sh`
  and `bin/staff/mr-red-collect.d/10-drafts.sh`.
- The registry: `catalog/lanes.d/staff-mr-red.json`,
  `cron/lanes/781-staff-mr-red.cron` (behind `bin/hub-lease.sh check &&`,
  like the 157 other hub-lease lines), the two switches, the

## The seam contract, per sibling

Each seam file holds a placeholder and a `# owner: BH-9532.<n>` line.

| Seam | Placeholder | Owner |
|---|---|---|
| `bin/staff/mr-red.d/10-culprit.sh` | `mrr_culprit_match` returns 1 | BH-9532.1 (#9540) |
| `bin/staff/mr-red.d/20-mechanical.sh`, `30-codefix.sh` | `mrr_<lever>_match` returns 1 | BH-9532.2 (#9541) |
| `bin/lib/mr-red-loop.sh` | `mrr_loop_check` prints `ok` | BH-9532.2 (#9541) |
| `bin/staff/mr-red-collect.d/20-pr-red.sh` | prints nothing | BH-9532.2 (#9541) |
| `bin/staff/mr-red.d/40-freeze.sh`, `50-unstick.sh`, `60-migration.sh` | `mrr_<lever>_match` returns 1 | BH-9532.3 (#9542) |
| `bin/staff/mr-red-collect.d/40-main-red.sh`, `50-parks.sh`, `55-ttl-green.sh` | prints nothing | BH-9532.3 (#9542) |
| `bin/staff/mr-red-judge.sh` | `mrr_judge_tick` returns 0 | BH-9532.4 (#9543) |

A lever fragment `bin/staff/mr-red.d/NN-<lever>.sh` defines:

- `mrr_<lever>_match <item-json>`: rc 0 = this lever takes the finding. The
  tick walks the fragments in file order; the first match wins.
- `mrr_<lever>_approach <item-json>` (optional): prints the approach. It is
  part of the action key, so another approach is another row.
- `mrr_<lever>_act <item-json> <action-json>`: rc 0 = done, rc 3 = dispatched,
  any other rc = failed. The tick PATCHes the row to match. No `_act`
  function = failed, evidence `why=no-act`.
- `mrr_<lever>_work <payload-json>`: the pool side, run by
  `bin/staff/mr-red.sh work <payload>`. A lever dispatches with `mrr_dispatch
  <lever> <payload>` (lane `mr-red`, payload with `lever`, `action_key`,
  `project`). The lane-run queue keeps one live run per (lane, project), so a
  second dispatch for the same project in one tick answers rc 3 (already
  live).

A collector source `bin/staff/mr-red-collect.d/NN-<name>.sh` prints one JSON
line per item: the `bin/staff.sh` step-6 shape (`item`, `title`, `source`,
`observedAt`, `class`) plus `repo`, `project`, `target`, `target_kind`,
`head`, `checks`, `fingerprint` (`mrr_fingerprint`). It exits 0 only when it
read everything; any other exit drops all its lines and names it in
`incomplete=`. It may print `deferred=<n>` as its last line.

A `started` row that a killed tick leaves is not retried in C0, because no
lever acts in C0. A lever that acts must check the row's state before a retry.

## Decisions

- A4 (retention handoff). Retention is BH-9532.4 (#9543). The fragment
  carries `-- no-retention: mr_red_actions ...`.
  `worker/jobs/test/d1-retention-coverage.bh-9076.test.js` C4 refuses a
  no-retention line for a table that has a rule, so #9543 must delete that
  one comment line in the same PR that adds the rule.
- A5 (tick-all). `bin/staff.sh tick-all` runs
  `bin/staff/<agent>-collect.sh` for every active roster agent.
  `bin/staff/mr-red-collect.sh` prints nothing and exits 0 unless
  `MRR_TICK=1`, and only `bin/staff/mr-red.sh tick` sets it. So tick-all
  claims nothing for mr-red and makes no model call for it. Staff chat notes
  to mr-red still go through the generic path.
- A6. A fourth index, `ix_mr_red_actions_repo (repo, created_at DESC, id
  DESC)`, so `GET ?repo=` for a repo with no rows reads no rows.
- A10. The check runs of a closed draft whose runs are all `completed` are
  kept at `state/mr-red/checks/` (box-local cache) and read once. The tick
  deletes files older than `2 x staff.mr-red.lookback_h`.
- No push counter and no size cap in `bin/staff/mr-red.sh` (the operator, #9532,
  2026-11-11T13:49:47Z). The control is the action row and the outcome judge.
- `deferred=` counts the drafts whose check runs were not read after
  `staff.mr-red.max_items_tick` items, plus the items the tick did not reach.
  The collector reads every pulls page inside the lookback, so the count is
  exact for the lookback window.

## The summary line

`logs/staff-mr-red.log`, one line per tick:

    <ts> tick level= items= new= repeat= deferred= rows= observed= acted=
      dispatched= failed= replay= claim_failed= post_failed= dropped=
      incomplete=<list|-> timed_out=<0|1>

`rows=` counts POST answers with `existing:false`. `acted=`, `dispatched=` and
`failed=` count PATCH 2xx answers. `incomplete=` is the collector's own line.

## How to stop it

- `bin/harness-ctl.sh off staff-mr-red` (flag `lane-off-staff-mr-red`).
- Flag `staff-off-mr-red` (Archie's tripwire may set it) or
  `staff-kill-mr-red`, or `staff-off-all` / `staff-kill-all`.
- `STAFF_ENABLED=0` in `env/global.env`.
