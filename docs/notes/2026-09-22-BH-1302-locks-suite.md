# BH-1302: `bin/lib/mc/locks.sh` finally has a suite that names it

**What changed.** One new file, `tests/mc/locks-test.sh` — the sixth suite under
`tests/mc/`, beside classify, queue, rebase, settle and lib-complete. No `bin/`
file is touched by this change; `bin/lib/mc/locks.sh` is exactly what it was.

**Why there was a hole.** The BH-477 split (#1191) moved the conductor's body
into `bin/lib/mc/*.sh` and shipped five suites with it. `locks.sh` got none,
and the gap was inherited rather than introduced: the monolithic lib had no
lock-focused suite either. That left it the one mc module in
`bin/test-impact.sh`'s orphan set — the set of files no suite can be shown to
reach.

The orphan status is a property of the MAP, not of the coverage.
`tests/merge-conductor-account-fact.bh-1090-test.sh` drives half of these
functions through a whole conductor tick today. But the map is static: a suite
reaches a file only when the suite's own TEXT names that file's repo path behind
the checkout variable, closed over `source` lines the extractor can resolve. The
shim loads the modules as `. "$MC_LIB_DIR/$_mc_m.sh"` — a variable built from
`BASH_SOURCE` at run time, which no static reader can root — so every suite that
sources `bin/lib/merge-conductor-lib.sh` reaches the shim and stops there. The
one mechanism that takes a module out of the orphan set is a suite carrying the
path literally, which is what

```bash
LOCKS_SRC="$DIR/bin/lib/mc/locks.sh"
```

is doing in the new file (`bin/test-impact.sh`'s `ti_rootvars` documents that
`V="@ROOT@/bin/x.sh"` shape as naming a file rather than a root). Nothing is
committed for the orphan list itself: since #1274 it is derived at run time and
the exit shows up as a set-diff "fixed" entry in
`bin/test-impact.sh orphans --check`.

`tests/mc/expected-map.tsv` is deliberately NOT edited. That file maps
module → function → origin; it has no suite column and `bin/test-impact.sh`
never reads it, so a row for a suite would be a comment pretending to be a
mechanism.

**What the suite pins.** Ten sections, 109 assertions, all against runtime
values — printed paths, exit codes, files present or absent — never a grep over
the module's source:

- the functions under test are the ones the PRODUCTION SHIM loaded out of
  `mc/locks.sh` (`declare -F` under `extdebug`), so a fixture that quietly
  bypassed `bin/lib/merge-conductor-lib.sh` cannot read as green;
- marker path shape per account, including the five unsafe names
  (`''`, `../escape`, `.hidden`, `a/b`, `/etc/passwd`) that must land on the
  default marker and never write outside `lane-down.d/`;
- account X does not hide account Y: `mc_lane_down_note` / `mc_lane_up` /
  `mc_lane_down_for_account` isolation, the note-once rule that keeps the FIRST
  reason, and a non-fact reason writing nothing at all;
- the fleet monitor's `state/claude-auth-down.txt` line speaking for the default
  account only;
- `mc_lane_epoch` advancing exactly once per up/down transition and never
  otherwise;
- next-review account rotation: the answer follows `bin/account-pick.sh`, the
  pick is made for the model `review_model` resolves (BH-998), and a failing or
  non-executable account-pick falls back to `default`;
- `MC_LANE_EXHAUST_RE`: one realistic reason line per built-in alternative
  (the `hit your [a-z0-9 -]*limit` arm gets a phrase no neighbour matches), a
  case-insensitive variant, six adversarial negatives, and BH-1090's ADDITIVE
  composition — with `ACCOUNT_EXHAUST_REGEX` set, the override matches, every
  built-in still matches, and none of the six negatives start matching. The
  override phrase is first shown NOT to match without the override, so that
  section cannot pass vacuously;
- `MC_LANE_ROUTED_RETRY_SECS` falling back to 3600 on seven non-integer values
  and keeping a valid one, asserted on the variable AND behaviourally through
  the marker-expiry window (a junk knob keeps a 20-minute-old routed marker; a
  600s window releases it and removes the file; the default marker is never
  timed);
- the lock primitives: `mc_safe_name`, the three distinct lock paths, the
  wrapped command's rc passed through unchanged (including an arbitrary 7, so
  the 99 "no lock" code stays distinguishable), the lock actually HELD during
  the call (an inner `flock -n` on the same file is refused) and actually
  RELEASED when it returns — the property that makes a wedged PR lock
  unrepresentable;
- the claim primitives: `mc_attempted` one-shot per (kind, PR, head),
  `mc_attempt_clear` forgetting exactly one, and `mc_rr_lanefail_*` counting per
  (PR, head, lane epoch).

**`MC_LOCKS_UNDER_TEST` — the red-first hook.** The fixture copies the module
from `$LOCKS_SRC`, which defaults to the real file and can be pointed at a
deliberately broken copy. That makes the ticket's "red first against a broken
module" one repeatable command per mutation instead of a hand edit between runs,
and the evidence a real exit code. Seven mutations were run for this change —
routed marker paths flattened beside the default one; the
`ACCOUNT_EXHAUST_REGEX` override dropped from the composition; the retry-secs
`case` validation deleted; `mc_lane_next_review_account` hardcoded to `default`;
`mc_lane_up` clearing indiscriminately; the `flock` dropped from
`mc_merge_locked`; the epoch's transition test forced true — and each turned the
suite red with a named FAIL line. Nothing in `bin/` reads
`MC_LOCKS_UNDER_TEST`.

No clock dependence, no network, no `gh`, no real harness: `account-pick.sh` is
a stub, marker ageing is an explicit `touch -d @<epoch - N>` (the shape
`tests/merge-conductor-account-fact.bh-1090-test.sh` already uses), and every
write is under the scratch tree.
