# Isolation drill, then retire the Orgo box project-6-os (BH-8325, MKF-10)

Doc: HUB-THINNING-PLAN, ADDING-A-BOX

## What changed

The drill and the delete are operator actions on the hub. A build box cannot
stop an Orgo computer. This change gives the operator the tools for both.

1. `bin/box-move.sh isolation --step I1 [--confirm] <oldbox> <newbox>` starts
   the drill (lib `bin/lib/box-move/isolation.sh`).
   - It refuses (exit 3, nothing done) unless the last `B5` row of
     `state/box-move/<newbox>/steps.tsv` is `ok`, `old-rows.tsv` loads, the
     rows put no project on `<oldbox>`, and `target.json` has `ts_ip`.
   - Without `--confirm` it prints `WOULD RUN I1: ...` and the box-ops dry run.
   - With `--confirm` it writes `isolation-baseline.tsv` (line 1
     `# since=<ISO> epoch=<n> old_ip=<addr>`, then
     `<inode> <size> <head cksum> <path>` per file under `$HARNESS/logs`). Then
     it runs `bin/box-ops.sh stop <box id> --host <oldbox> --apply` and records
     `I1 ok since=<ISO> old_ip=<addr> box_id=<id> host=<oldbox>`. If box-ops
     fails, it records `I1 fail box-ops rc=<n>` and exits 4.
   - A re-run starts a new drill: a new baseline and a new `I1 ok` row.
2. `bin/box-move.sh isolation <oldbox> <newbox>` prints the drill report. It
   writes the same lines to `state/box-move/<newbox>/isolation-report-<ts>.txt`:

   ```
   isolation since=<ISO> until=<ISO> elapsed_s=<n> window_s=<W> state=running|complete old_box=<old> box_id=<id>
   count old_ip_lines n=<n|NA(..)> files=<k> verdict=pass|fail|NA
   old_ip_file <path under logs/> n=<n>
   count <p> pull_spawns_result n=<n> min=<5> verdict=
   count <p> lead_reviews n=<n> min=<1> verdict=
   count <p> conductor_merges n=<n> min=<1> mergify=<m> verdict=
   count <p> triage_dispatches n=<n> min=<1> verdict=
   count <p> fix_rounds n=<n> min=<1> verdict=
   tailnet_ip <p> answer=<addr|none> want=<ts_ip> verdict=
   tracked_old_ip ref=<sha12> files=<k> allow=<list> verdict=
   tracked_old_ip_file <path>
   isolation verdict=pass|fail|NA
   retire_ready=yes|no (<why>) clean_s=<n> need_s=<n>
   NEXT (the operator runs this, never this tool): bin/box-ops.sh retire <id> --host <old> --delete --apply
   ```

   - `old_ip_lines` (AC1) reads every hub log changed since the baseline. A
     file in the baseline is read after its baseline size. A new, rotated,
     truncated or rewritten file is read whole, and a line stamped before the
     drill start is dropped. A line counts when it names the old address with
     no digit or dot before it and no digit after it. The count covers the
     drill start to now. One line fails the drill at once.
   - `pull_spawns_result` (AC2): a `<MID>: seeded <n> file(s) for <KEY> at
     launch` line in the window in `logs/fly-pool.log`, with a later
     `reaped <KEY> from <MID>:` line.
   - AC3: `lead_reviews` (`pool lead review reaped for LR-`),
     `conductor_merges` (merged PRs of the repo in the window, GitHub search as
     in #8324), `triage_dispatches` (`[<p>] dispatched <N> shards:`, N >= 1, in
     `logs/<p>.log` on the new box), `fix_rounds` (finished rounds in the
     window, from the jobs worker).
   - AC4: `tailnet_ip` (`bin/fleet-conf.sh --tailnet-ip <p>` must equal the new
     box `ts_ip`) and `tracked_old_ip` (`git grep` of origin/main in
     `HARNESS_CHECKOUT`, no fetch; the paths in `BOX_MOVE_ISOLATION_IP_ALLOW`
     are skipped).
   - A value the report could not measure is `NA(<why>)`, never 0. While the
     window runs, every count line is `NA` except a failed `old_ip_lines`.
   - `retire_ready=yes` needs `isolation verdict=pass`, 7 days since the drill
     start and 0 old-address lines over the whole period. The report never
     deletes anything. It prints the delete command for the operator.
3. `bin/box-ops.sh stop|restart|retire <id> --host <name>` names the Orgo
   host. The new box keeps the old box id `project-6-os` (BH-8322). Without `--host`,
   `stop project-6-os` resolves the id to box-mkfly and pauses its projects.
   With `--host`, box-ops reads the projects of that host (none), and it skips
   a state file that names another host.
   - `retire <id> --host <name>` without `--delete` is refused when another
     live box has the same id: `box-register --retire project-6-os` would strip the
     lists of mkfly.
   - `retire <id> --host <name> --delete --apply` skips the
     `cron/boxes/<id>.d` check when origin/main gives the id to another live
     box (that list belongs to mkfly). The check that origin/main
     `fleet.conf` no longer names the host stays.
4. The old address is gone from the tracked prose (a comment in
   `bin/lib/build-limits.sh`, the BH-8281 and BH-8321 notes) and from
   `tests/box-register.bh-5747-test.sh` (it reads the address from
   `fleet.conf`). Two places keep it: `bin/share/mapping.py` (the redaction
   table) and the frozen plans under `.harness/specs/`. The two `fleet.conf`
   rows keep it until the fleet.conf PR of the MKF-9 runbook (step 3.2) moves
   them to mkfly. Until that PR merges, `tracked_old_ip` and `tailnet_ip` fail.

Knobs (env, operator-run, no lane reads them): `BOX_MOVE_ISOLATION_WINDOW_S`
(259200), `BOX_MOVE_ISOLATION_MIN_PULL` (5), `BOX_MOVE_ISOLATION_MIN_EACH` (1),
`BOX_MOVE_RETIRE_CLEAN_S` (604800), `BOX_MOVE_ISOLATION_PROJECTS` (empty = the
projects of `old-rows.tsv`), `BOX_MOVE_ISOLATION_IP_ALLOW`
(`bin/share/mapping.py .harness/specs/`), `BOX_MOVE_ORGO_ACCOUNT` (empty; the
box-ops `--account`).

## Runbook (on the hub, as root)

Preconditions:

1. Make sure the #8324 proof posted `proof verdict=pass` on #8324.
2. Make sure the fleet.conf PR of the MKF-9 runbook (step 3.2) is merged, so
   the rows put project-6-os and project-6-desktop on box-mkfly.
3. Load the env: `set -a; . <env dir>/global.env; set +a`, with
   `REGISTRY_SOURCE=db` and `ORGO_API_KEY` set.

Start the drill. Read the dry run before the second command:

```bash
bin/box-move.sh isolation --step I1 box-project-6-os-1 box-mkfly
bin/box-move.sh isolation --step I1 --confirm box-project-6-os-1 box-mkfly
```

Read the report every 24 h, and post the 72 h report on #8325:

```bash
BOX_MOVE_ISOLATION_PROJECTS=project-6-os bin/box-move.sh isolation box-project-6-os-1 box-mkfly
```

If a line fails, bring the old box back and stop. File a ticket for the lane
the `old_ip_file` lines name. Lift nothing else.

```bash
bin/box-ops.sh restart project-6-os --host box-project-6-os-1 --apply
```

After 7 clean days the report prints `retire_ready=yes` and a `NEXT` line.
Post that report on #8325. Then the operator, and only the operator, runs the delete. It is
permanent:

```bash
bin/box-ops.sh retire project-6-os --host box-project-6-os-1 --delete --apply
```

STOP: never run `box-ops.sh retire` for project-6-os without `--delete`. Box-ops
refuses it with `--host` (the id is shared). Without `--host`, the id resolves
to box-mkfly.

Lead review: if lead review runs on lane-run-mk only, `lead_reviews` reads 0.
Then count the lead-review rows of lane_runs for project-6-os in the window by
hand, and write the count and the query in the post.
