# Machines screen box-op buttons and BOX COMMANDS history (BH-2518.4, BH-2662)

Doc: fly-machines

## What changed

- **FLEET → MACHINES has ACTIONS columns.** Each ORGO box row has BACKUP NOW,
  SYNC and CLI UPDATE. Each Fly machine row has DESTROY, plus STOP when the
  machine is `started`.
- **Every button asks first.** It opens the in-app confirm dialog with a
  required REASON (the same `PauseReasonForm` the pause RESUME uses). CONFIRM
  stays disabled until the reason is non-blank. Cancel or Escape sends nothing.
  STOP on a machine that is building says the build will be killed. DESTROY
  is red and says it cannot be undone.
- **Nothing is guessed.** A Fly op needs the project, the app and the machine
  id. The app is the machine's own, else the project's only app. With neither,
  the buttons are disabled with the title `machine's app unknown`.
  `console-ui/src/lib/box-commands.js` `boxCommandFor` refuses a blank reason,
  an unknown type or a missing Fly field instead of filling one in.
- **The banner says what happened, and no more.** A 2xx reads
  `queued for <box>`, or `already queued (#id)` when the worker deduped it. An
  error reads `<OP> failed: <error>`. It never says done: the console only
  files the request, and the box's own lane runs it.
- **New BOX COMMANDS section** below the Fly tables: the recent commands,
  newest first, sortable by every column but DETAIL, polled every 30 s.
  The BOX cell links to `/machines?box=<name>`, which narrows the list to one
  box. A load failure shows the error with RETRY, never "no box commands yet",
  and a truncated answer says only the newest rows are listed.

## Why

BH-2518 moves box ops (backups, syncs, CLI updates, killing a stray Fly
machine) from a shell on the box to one audited request with a reason. This
slice is the console half. The worker routes (BH-2659) and the per-box lane
`bin/box-ops.sh` (BH-2660) are siblings. Until they deploy, a click reaches
the proxy and shows an honest `failed: http <n>` banner.
