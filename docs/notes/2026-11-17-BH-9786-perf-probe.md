# BH-9786: the daily perf probe tracer

Doc: STATE-STORES, TESTING

Slice C0 of #9791 (the contract section of BH-9786). The five other sections
(budget, routes, session end, statements, ticket) stay on the ticket. Each one
fills a seam file that this slice creates.

## What changed

- New hub cron lane `perf-probe` (`17 6 * * *`, `catalog/lanes.d/perf-probe.json`,
  switch `flags/lane-off-perf-probe`). It runs `bin/perf-probe.sh`.
- For each `catalog/perf-probe.d/<project>.json` in name order, the lane:
  1. checks the row (`pp_row_valid`). An invalid or disabled row is one
     `skip:` line and 0 requests.
  2. takes `locks/perf-probe-<project>.lock`, with a bounded wait
     (`PERF_PROBE_LOCK_WAIT_S`). A held lock is `skip: lock busy`.
  3. mints a session (`ppio_session`): one POST to `<base_url><session_path>`
     with `{"role": roles[0]}`. The project's internal token goes to curl on
     stdin (`-K -`), never in argv. A refused session is `skip: session <status>`.
     An unexpired jar from an earlier run is reused (0 POSTs).
  4. loads each route with one GET (`ppio_load`, no `-L`, `Accept: text/html`)
     and a `PERF_PROBE_PAUSE_MS` gap. A 401 calls `ppio_on_ended`; the tracer
     default stops the project (`stop: session ended`).
  5. writes all rows in one `jobs-client.sh perf-probe results-put` call to
     `POST /api/perf-probe/results`. The D1 table `perf_probe_results` upserts
     on `(project, route, day, kind, run_key)`, so a rerun on the same day
     replaces the rows.
  6. writes one line to `logs/perf-probe.log`:
     `<ts> perf-probe <project> routes=<n> over=<n> stmts_new=<n> ticket=<a> complete|incomplete`.
- 0 LLM calls. GET only to the app.
- Retention: `worker/jobs/src/routes/retention.d/bh-9786-perf-probe.js` deletes
  rows older than the settings row `perf_probe.retention_days` (90), through
  the hourly `bin/d1-retention.sh` lane (dry run first, `retention.dry_run`).
- Row cap per call: settings row `perf_probe.rows_max` (500).

## Formats

- Load line (writer `ppio_load`): `<status> <ttfb_ms> <total_ms> <bytes> <location|->`.
  Integer ms. Status `000` means no answer. The 5th field is the redirect URL
  of a 3xx, or `-`.
- Verdict line (writer `pp_route_verdict`): `over|under|unmeasured`, then
  optional `key=value` words (`ttfb_ms total_ms bytes status loads breaks outcome`).
  The lane fills a missing key from the last load line.
- Result row (writer the lane): `{route, ttfb_ms, total_ms, bytes, status,
  over_budget, outcome, loads, breaks}`.
- `state/perf-probe/<project>/session.json`: `{minted_at, expires_at}`. With no
  `expiresAt` in the session answer, `expires_at` equals `minted_at`, so the jar
  is not reused on a later run.
- `state/perf-probe/` is box-local (`catalog/state-paths.d/9786-perf-probe.json`).
  The jar is a secret (mode 0600), never synced and never logged.

## Seams and their owners

| File | Owner | Tracer default |
|---|---|---|
| `bin/lib/perf-probe/budget.sh` | BH-9786.1 | 1 load per route; over when 5xx, 000, ttfb or total > `PERF_PROBE_BUDGET_MS`, bytes > `PERF_PROBE_BUDGET_BYTES` |
| `bin/lib/perf-probe/routes.sh` | BH-9786.2 | the row's `routes` |
| `bin/lib/perf-probe/session-end.sh` | BH-9786.3 | `ppio_on_ended` rc 1 (stop) |
| `bin/lib/perf-probe/statements.sh` | BH-9786.4 | `stmts_new=0` |
| `bin/lib/perf-probe/ticket.sh` | BH-9786.5 | `ticket=none` |
| `tests/fixtures/perf-probe-fake.d/{board,statements,health}.py` | BH-9786.5, .4, .6 | `handle` returns None |

A later jobs-client op goes in its own fragment
`bin/jobs-client.d/<key>-perf-probe-<op>.sh` that defines `jc_verb_perf_probe_<op>`.
`perf-probe <op>` dispatches to it.

## Go-live

The only row, `catalog/perf-probe.d/project-2.json`, ships `enabled: false`,
`roles: []`, `routes: ["/"]`. Until a person changes it, the lane writes one
`skip: disabled` line per day. Go-live: a person sets `roles`, `routes` and
`enabled: true` in that file. The app must answer the session route
(`/api/internal/e2e/session`) for the internal token.
