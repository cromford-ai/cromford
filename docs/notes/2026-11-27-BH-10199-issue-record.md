# BH-10199 slice 1: the issue record

## What it is

The fleet's own copy of an issue or PR thread in the jobs D1: `issue_records` (state, title, body, labels, `rev`, `backfill_at`, `stale_at`), `issue_comments` (one row per comment, `deleted` is terminal) and `issue_record_syncs` (one row per repo: the list mark and the last complete sync). Schema: `worker/jobs/schema.d/202611270600-bh-10199-issue-records.sql`. Routes: `worker/jobs/src/routes/issue-records.js`. Helper: `bin/lib/issue-record.sh`.

## The version marks

1. Webhook. `issues`, `issue_comment` (created, edited, deleted) and the PR fields of `pull_request` and `pull_request_review` write the record inside the wake batch, under the delivery claim. 0 GitHub calls. The change mark is `issue_records.rev`, which the worker adds 1 to in the statement that changes a value. It is not the wake id, because the worker keeps one wake row per (repo, kind, key, minute): two comments in one minute share one wake id.
2. Count check. A delivery that carries `issue.comments` compares it with the stored count of comments that are not deleted. A different count on a record that holds the whole thread sets `stale_at`: a comment delivery was lost, and the later delivery's newer `updated_at` would hide it from the list backstop. An older delivery (out of order) checks nothing.
3. List backstop. `issue_record_sync <repo>` claims the repo (at most once per `issue_records.sync_every_s` = 600 s for the whole fleet), reads `issues?state=all&since=<mark>&sort=updated&direction=asc`, and posts the items. A record whose GitHub `updated_at` moved past the record's own is marked `stale_at`: a lost webhook. A complete read stamps `synced_at` with the claim's worker time. A box does not POST the claim for a repo again inside the worker's `every_s` after its last claim answer (marker `state/issue-record-claim/<owner>_<repo>`), so a shadow read makes no D1 write attempt.
4. `comments?since` with a stored ETag: next slice.

A reader trusts the record only when it is ready: a full GitHub read exists (`backfill_at`, at most `issue_records.backfill_max_age_s` = 7 days old), no `stale_at`, a complete sync at most `issue_records.sync_max_age_s` = 1800 s old, no cut body, at most `issue_records.comments_max` comments. Every age is computed on the worker clock.

## What an issue's updated_at does not show

Commit statuses, check runs and suites, workflow runs (CI), the merge queue (Mergify or GitHub), deployments and branch protection. The PR record (`pr_records`) stays the source for those. The issue record holds the thread only.

## The rules of the build comment

- A failed read is unknown. A failed jobs read writes no base rev, so no write-back follows. A failed GitHub read writes nothing. A failed list read posts nothing and moves no mark.
- A full write applies only while `rev` is the value the reader saw before its GitHub read (`base_rev`). A webhook that landed during the read wins, and the write is refused (`applied: false`).
- First seen (no row) is `base_rev` 0: a miss, and the full write creates the row.

## Steps per lane

Knob `GH_SOURCE_ISSUES` (rows `lane.blocked-resolver.gh_source_issues` and `lane.pr-state-reconcile.gh_source_issues`), default `shadow`:

- `off`: today's GitHub reads, 0 jobs calls, no PRR line. The lane's own `GH_SOURCE` step `off` makes this step `off` too.
- `shadow`: GitHub decides. A record that differs writes one `PRR_SHADOW lane=<l> key=<repo>#<n>@thread|@comments` line in `logs/prr-shadow.log`. A miss or a difference writes GitHub's answer back.
- `record`: the record decides. A hit makes 0 GitHub calls. A miss logs `PRR_MISS` and reads GitHub, then writes the answer back.

## Switch to record

1. After 48 hours in shadow, count `grep -c 'PRR_SHADOW lane=blocked-resolver key=.*@thread' logs/prr-shadow.log` and the same for `pr-state-reconcile ... @comments` on the hub.
2. If both counts are 0, post them on #10199.
3. Set the rows to `record` through the settings API.
4. 24 hours later, post `bin/gh-ledger-report.sh --per-merged-pr --by-repo --last 24h` beside the number from before the switch.
