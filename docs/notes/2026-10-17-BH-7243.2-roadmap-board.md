# Roadmap board, hand links, decisions and the ROADMAP.html render (BH-7243.2, BH-7265)

Doc: CONSOLE, worker/jobs/README.md

Slice 3 of 5 of #7243. The roadmap of a project gets a board at
`/roadmap/<project>?view=board`: four columns (Ideas, Next, Now, Shipped), the decisions
log and the open questions. A person can link an idea to a GitHub issue by hand. A hub
lane writes the board into the repo as `docs/ROADMAP.html`, through one PR per project.
No table is added: the tables and indexes are in the BH-7243.0 contract fragment.

## The column is computed, never stored

`roadmapColumn(idea, links, running)` in `worker/jobs/src/routes/roadmap-board.js`. The
first rule that matches wins:

1. `lane = discarded` → hidden.
2. One link or more, and every link `closed_completed` → Shipped.
3. A link `open`, a link not read yet (`issue_state` NULL), or a linked issue with a
   running job in this project → Now.
4. Else the hand lane (Ideas or Next).

Shipped comes before a running job: the harness closes an issue only when its PR merged.
A running job matches a link by the trailing integer of `jobs.ticket_id` (`BH-12`, `12`,
`owner/repo#12` → 12), compared exactly (`BH-72650` is not 7265). An unknown state is
neither open nor completed, so it falls to the hand lane.

A MOVE or a drag changes only the hand lane. A Now or Shipped card stays where its links
put it, and its MOVE menu says so.

## Routes

- `GET /api/roadmap/board?project=`: ONE D1 batch of 4 statements, each bound to the
  project (ideas in Ideas/Next, links, running jobs, decisions). The join is in JS. Each
  read takes one extra row, so `truncated.{ideas,links,running,decisions}` is true when a
  cap cut the list, and the board shows "Showing the newest N".
- `POST /api/roadmap/links {idea_id, project, issue}`: the repo comes from `projects`.
  201 new, 200 `replay:true` when the link exists, 404 when the idea is not in this
  project, 409 when the project has no repo. A hand link has `issue_state` NULL, so the
  idea is in Now at once; `bin/roadmap-issue-sync.sh` reads NULL links first and fills the
  state on its next tick.
- `POST /api/roadmap/links/remove`: hand links only. A wave link (`wave_id` set) is the
  filing lane's record, so it answers 409 and is kept.
- `POST /api/roadmap/decisions {project, kind: log|open, title, body?}`: a log entry is
  stored `decided`; an open question is stored `open`.
- `POST /api/roadmap/decisions/decide {id, project, status: decided|dropped,
  expected_status: open}`: a CAS on `status`. A second decide is 409 with the stored row.

Link, unlink and decide each write in one batch. Link and unlink add a `linked` or
`unlinked` row to `roadmap_idea_events` (actor and `{repo, issue}`), so the idea page
shows them. The console writes all four POSTs through the coord proxy, which stamps the
actor (`console-ui/functions/_lib/coord-writes.d/7243-roadmap-board.js`).

## Knobs (settings rows, `schema.d/202610270332-bh-7243-roadmap-board.sql`)

- `roadmap.render_projects` = `''`: the projects the render lane writes. Empty = none.
- `roadmap.board_links_limit` = `2000` (1..10000): the most link rows one board read takes.
- `roadmap.board_running_limit` = `500` (1..10000): the most running jobs one board read takes. More sets `truncated.running`.
- The board also reads `roadmap.list_limit` (BH-7243.0, 200) for ideas and decisions.

## The render lane (`bin/roadmap-render.sh`, hub, daily 06:41)

For each project in `roadmap.render_projects`: read the board, render
`docs/ROADMAP.html` (`bin/lib/roadmap-html.sh`: sections now, next, later = the Ideas
column, shipped, decisions, open; `table.sortable` with the columns Issue, Item, Status,
Label, Size, Notes; every value HTML-escaped). Line 2 is
`<!-- generated-at: <ts> -->`, and it is the only line the compare drops. Equal to the
default branch → `UNCHANGED`, no write. Else the lane writes branch
`roadmap/render-<project>` (never the default branch, `main` or `master`) and opens ONE PR,
or updates the open one. It never merges. A rate limit stops the tick. The output reads
back through `bin/roadmap-import.sh --dry-run`.

Off: an empty `roadmap.render_projects` (the seed), `flags/lane-off-roadmap-render`, or
`bin/harness-ctl.sh off roadmap-render`.

## Go-live step

An operator lists the projects whose repo gets the PR: `PUT /api/settings` with
`{"key":"roadmap.render_projects","value":"cromford"}` (comma separated for more),
or the console settings screen. Until then the lane reads one settings row a day and does nothing
else.

## Retention

No new table. `roadmap_links` and `roadmap_decisions` keep forever, by the contract's
rule (they grow at human speed). A hand unlink deletes one hand row and keeps an audit
event.
