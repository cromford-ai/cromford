# BH-5239: the Cloud control plane moved to example-org/cromford-web

Doc: OPERATOR-SETUP

## What moved

The paid Cloud control plane (`harness-cloud`) now lives in
example-org/cromford-web. The TK-28 import waves #33-#36 brought it there. the operator
confirmed the import is merged in comment 6127248473 on BH-5239. This box
cannot read cromford-web (the token gets 404), so that comment is the evidence.

The open cromford PRs for Cloud closed for their cromford-web ports:
#4761 for cromford-web#38 and #4792 for cromford-web#39.

## What this split removes

BH-5239 removes the Cloud worker from the engine in five parts. The first part
(BH-6303) removes:

- the 17 `tests/cloud-*.sh` suites, `tests/schema-fragments-cloud.bh-4987-test.sh`
  and the 25 node test files of the Cloud worker;
- the Cloud half of `tests/worker-sentry.bh-5618-test.sh`;
- the 8 Cloud notes and the 9 Cloud verification-map entries;
- the Cloud glob in `RT_HIGH_GLOBS_DEFAULT` (`bin/lib/risk-tier.sh`).

Comments and docs that named the Cloud source now say it moved here.
The four later parts delete the Cloud source itself.

## Why nothing in production changes

Nothing deploys the Cloud worker. `deploy_workers` in `bin/harness-sync.sh`
skips a worker dir with no committed `wrangler.jsonc` or `wrangler.toml`. The
Cloud worker has only `wrangler.jsonc.example`, and git history has no
`wrangler.jsonc` for it. Nothing in the engine imports Cloud source.

## The guard

`tests/no-cloud-in-engine.bh-5239-test.sh` fails when a tracked file names the
Cloud path. It allows this note and the paths listed in
`tests/fixtures/no-cloud-in-engine/allow.d/*.list`. Each later part deletes its
own list in the same PR, and the suite fails on a stale list entry. When the
last list is gone, the suite is strict, and its NC-6 case checks the public
share mirror too.
