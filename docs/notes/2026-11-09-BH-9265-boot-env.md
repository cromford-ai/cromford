# BH-9265: no long-lived Fly machine process keeps an HBUNDLE_ or SEED_ secret in its environ

Doc: FLY-BUILDER-TRIAL, FLY-POOL

## Cause

`/proc/<pid>/environ` is the env block a process got at `execve`. A later
`unset` in a child does not change it.

- `fly/Dockerfile` had `ENTRYPOINT ["/usr/bin/tini", "--", "/opt/fly-boot/entrypoint.sh"]`.
  tini started with every Fly app secret (`HBUNDLE_*`, and each `SEED_*`
  bundle of every other machine) and kept them for the life of the machine.
- `fly/entrypoint.sh` started tailscaled at step 2, before the seed block
  unset the names. tailscaled kept them too.

## What changed

- `fly/Dockerfile`: `ENTRYPOINT ["/opt/fly-boot/entrypoint.sh"]`. tini stays
  installed.
- `fly/entrypoint.sh`, block `handoff (BH-9265)`: the last step is
  `exec /usr/bin/tini -s -- "$RUNNER"`. The exec gives tini the environ of the
  entrypoint shell, after the seed block unset every name. tini keeps the same
  pid, so a stop signal reaches it as before, and tini forwards it to the
  runner. `-s` makes tini a subreaper when it is not PID 1 (Fly). If the
  parent is already tini, or tini is missing, the runner is exec'd directly.
- `fly/entrypoint.sh`, block `env scrub (BH-9265)`: tailscaled starts through
  `env -u NAME ...` for each `HBUNDLE_*`/`SEED_*` name.
- `fly/entrypoint.sh`, block `boot traps (BH-9265)`: only when the entrypoint
  is PID 1 (the docker pool, `docker run` with no `--init`). TERM exits 143 and
  INT exits 130 during boot. Without them the kernel drops the signal to PID 1.
  On Fly the entrypoint is not PID 1, so nothing changes there.
- `bin/fly-boot-env-check.sh <app> <machine-id>` (new, read-only): scans every
  `/proc/<pid>/environ` on one machine and prints names only. Exit 0 = clean,
  1 = hits, 2 = could not run.

Stop behavior: the runner traps (`fly/builder-runner.sh`) and the stop record
did not change. No `kill_signal` or `kill_timeout` changed.

Test: `tests/fly-boot-env.bh-9265-test.sh` runs the real blocks with a real
`exec` and reads the kernel environ of tini, the runner and a stub tailscaled.

## Live check (operator runbook)

The build box does not boot Fly machines. Do these steps once after the image
ships. Use a throwaway app. The secret values are fake.

1. Build and push the image: `bin/fly-image-build.sh <project>`.
2. Create a throwaway app: `fly apps create builder-bh9265-check`.
3. Set fake secrets: `fly secrets set -a builder-bh9265-check SEED_1_fake=fixture HBUNDLE_SYNCED_AT=fixture HBUNDLE_G_FAKE=fixture --stage`.
4. Boot one pool machine from the new image with `POOL_MODE=1`, as `bin/fly-pool.sh` does.
5. Run `bin/fly-boot-env-check.sh builder-bh9265-check <machine-id>`. It must exit 0 and print `clean:`. Paste the output in the ticket.
6. Repeat steps 4-5 for a builder machine (no `POOL_MODE`, with `TS_AUTHKEY`). The `ps` table must show `tailscaled`, and the check must exit 0.
7. Push one lane job to the pool machine, as the hub does.
8. While the lane runs, run `fly machine stop -a builder-bh9265-check <machine-id>`.
9. Read `fly logs -a builder-bh9265-check`. The runner must log its INT path (`cost_rows_flush`, exit 130), as before.
10. Destroy the app: `fly apps destroy builder-bh9265-check`.

If step 5 or 6 prints a `hit` on pid 1 and pid 1 is Fly's init (not tini), the
seed names come from Fly's init. This image cannot change that.
