# The clerk owns the NEEDS count, and pulls the NEEDS sweep as its lever (BH-9420)

Doc: STAFF, OPERATING

Slice C2 of #9187. The staff contract (C0, BH-9187) says each staff agent owns
ONE metric and is judged by whether that metric moved. This slice gives the
clerk its metric, `needs_count`, and its one lever, the #9117 NEEDS sweep.

## The metric

`needs_count` is `needs.total` of `GET /api/needs-sweep/count` on the console
Pages project: open alerts + failed or dead-letter commands + parked builds
(one per ticket, the newest row) + ideas at the gate. It is the same number
Mission Control NOW shows from the server. `needCounts`, `NEEDS_STAGES` and
`NEWEST_PER_TICKET` moved from `console-ui/functions/api/cockpit/[[path]].js`
to `console-ui/functions/_lib/needs-count.js`, with no SQL change. The cockpit
and the needs-sweep function both import that file.

The route uses the same `Bearer <HARNESS_SECRET>` check and the same
`CONSOLE_DB` check as `candidates` and `apply` (401 / 503 before any read). It
runs ONE statement. A method other than GET is 405. A D1 error is 502.

NOW also adds the stale builds the browser joins from the jobs worker. The hub
cannot see that part, so the metric is the server total only.

## The lane

`bin/staff/clerk-lever.sh`, hourly at :47 on the hub
(`cron/lanes/780-staff-clerk-lever.cron`). Each run:

1. Stops on `STAFF_ENABLED=0` or a kill flag (`staff-off-all`,
   `staff-kill-all`, `staff-off-clerk`, `staff-kill-clerk`), then takes
   `locks/staff-clerk-lever.lock`, then checks the clerk is active on the roster.
2. Reads `/api/needs-sweep/count`. A total that is not a whole number is
   `needs=unreadable`: no sample, no action. An unreadable count is never 0.
3. Posts one sample (`POST /api/staff/levers/metric`). That call settles every
   clerk action at least `staff.settle_hours` (24) old: `moved` = 1 when the
   count is now lower than `metric_before`.
4. Acts only at `staff.clerk.level` = `act` and NEEDS >= `staff.clerk.target`
   (300; the target text is "NEEDS < 300", so 300 is a miss).
5. Records the action FIRST (`POST /api/staff/levers/actions`), key
   `needs-sweep:<window start>`. The window is `staff.clerk.lever_every_hours`
   long (seed 6, fallback 6). Only a new row runs the sweep. An existing row or
   a 409 is `action=window-taken`. Any other answer is `action=failed`. So the
   sweep never runs without its ledger row, and runs at most once per window.
6. Runs `NS_TAG=clerk:<action key 12> bin/needs-sweep.sh`, with `--dry-run`
   unless `console.needs.sweep_dry_run` is 0. The sweep's own rules, caps,
   lock and HTTP timeout row apply unchanged.

One line per run in `logs/staff-clerk-lever.log`:

    <ts> level=act needs=903 target=300 sample=ok action=recorded dry=0 sweep_rc=0 sweep=mode=apply ... tag=clerk:2b4c0f4138ee

## The tag

`bin/needs-sweep.sh` reads an optional `NS_TAG`
(`^[a-z0-9][a-z0-9:_.-]{0,63}$`). A valid tag adds ` tag=<tag>` to the end of
its summary line, its stdout line and the detail of its ONE `needs_sweep`
ledger row. Any other value is dropped with one log line. With no tag (the
daily 05:35 lane) the summary is unchanged.

## Not in this slice

The #9187 text also lists "alerts > 6h with no new occurrence -> resolved".
#9420 narrows the lever to the #9117 sweep, which has no alert rule, and open
PR #9137 changes the alerts groom. That rule needs its own ticket.

## Defaults after merge

- `staff.clerk.level` = `observe` (C0 seed): the clerk only samples. 0 actions,
  0 extra sweeps.
- `console.needs.sweep_dry_run` = 1 (BH-9117 seed): at level act the first
  actions are dry. A dry action never settles.
- At most 24 / `staff.clerk.lever_every_hours` sweeps a day (4 at 6). Each
  sweep run makes at most `console.needs.sweep_max_reads` (300) GitHub reads.

## Go live (operator)

1. Watch `logs/staff-clerk-lever.log` on the hub for a day: one
   `level=observe needs=<n>` line per hour.
2. Set `staff.clerk.level` to `act`. The next run at or above target records a
   dry action and runs a dry sweep. Read its summary in the log.
3. Set `console.needs.sweep_dry_run` to 0. The next window applies.
4. Read `GET /api/staff/levers/scorecard?agent=clerk` after 24 h: `settled`,
   `moved`, `precision`.

Off: `bin/harness-ctl.sh off staff-clerk-lever`, or any staff kill flag above,
or `staff.clerk.level` back to `observe`.
