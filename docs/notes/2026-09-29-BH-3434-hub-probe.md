# The hub-probe lane (BH-3434, built in BH-3450)

Doc: OPERATOR-SETUP

## What changed

`bin/hub-probe.sh` is a new hub cron lane (`cron/lanes/720-hub-probe.cron`,
every 10 minutes behind `hub-lease.sh check`). It is the first caller of the
BH-3447 contract: `hp_claim`, `hp_result`, `hp_commented`, `hp_count_today`
(`bin/lib/jobs/hub-probe.sh`), `hp_run` (`bin/lib/hub-probes/common.sh`) and
`hp_on_pass` (`bin/lib/hub-probes/on-pass.sh`). Registry:
`catalog/lanes.d/hub-probe.json`, switch `catalog/switches.d/hub-probe-off.json`.

## The tick

1. `lane_gate_or_exit hub-probe`, `lane_env_apply hub-probe`.
2. The `hub-probe-off` switch. ON writes the summary line ending ` off` and
   exits before any claim or GitHub call.
3. `flock -n locks/hub-probe.lock`. A held lock skips the tick.
4. Re-drive owed comments from the spool, at most `HUB_PROBE_TICK_CAP`.
5. `hp_claim` up to `HUB_PROBE_TICK_CAP` (default 10). A failed claim logs
   `claim-failed` and ends the tick.
6. Per row: a count at or over `HUB_PROBE_DAILY_CAP` (default 20), or a count
   that could not be read, sends the row back to pending with the note
   `deferred: daily cap` / `deferred: count unknown`. Otherwise `hp_run`, then
   `hp_result` with the output capped at 4096 bytes. A failed store posts
   nothing and alerts. A stored PASS calls `hp_on_pass`. Then the comment is
   spooled and delivered.
7. One summary line in `logs/hub-probe.log`.

## The spool

`state/hub-probe/owed/<id>.json` plus `<id>.out` is written only after the
store answered rc 0. A finished row never comes back from `/claim`, so this is
what makes a failed post retry on the next tick. An entry is removed after
`hp_commented` rc 0, or when the project has no GitHub-Issues board, where the
lane logs `not-configured: comment` and leaves `commented_at` NULL.

Before every post the lane reads the thread. `<!-- hub-probe:<id> -->` already
there means only `hp_commented` runs. A thread it could not read posts nothing
that tick. Probe output inside the fence has backticks and `<!--` rewritten, so
it cannot close the fence or forge a marker.

One window can lose a comment and none can duplicate one: the lane killed
between `hp_result` and the spool write leaves a stored result with no owed
comment. The result is still in the ledger for `hp_list`.

## Defer

`hp_result` refuses `pending` and takes no note, so the defer is a direct
`POST /api/hub-probe/result` with `{"id":…,"result":"pending","note":…}`, the
body the #3448 route accepts from `claimed`. A defer that fails leaves the row
`claimed` and counts `defer-failed`; the probe never runs on it.
