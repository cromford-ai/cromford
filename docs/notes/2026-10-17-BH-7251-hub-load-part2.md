# Hub load part 2: fly-pool locks before any lib, one knob memo per lane start, one compose per catalog change (BH-7251)

Doc: FLY-POOL, OPERATING

## What changed

- `bin/fly-pool.sh`: the `env-path.sh` source and the `HENV=` assignment
  now come after the per-project `flock -n`. `mkdir -p locks logs` runs only
  when one of the two dirs is missing. A start that finds the lock held
  sources no lib. It runs `flock` and one `date` for its log line, then exits
  rc 0.
- `bin/lib/lane-gate.sh`: two memos in process memory.
  - `_lg_km_load <reg> <kind> <id>` runs ONE jq over the registry. It loads
    every knob of that lane or lib (env, settable, required, default, min,
    max, zero_means) into `_LG_KM`. It is held for the life of the process.
  - `_lg_sc_load` runs ONE jq over `state/settings-cache.json` per distinct
    file content and loads `_LG_SV` (values) and `_LG_SK` (all keys). Each
    read compares the raw text with the read builtin, so a refresh that
    rewrites the file is seen at once.
  - `_lg_settings_refresh`, `_lg_settings_state`, `_lg_setting_lookup`,
    `_lg_knob_meta`, `lane_knob_settable`, `lane_knob` and `_lg_env_apply`
    read the memos. `_lg_now` uses the `printf '%(%s)T'` builtin.
  - A command substitution inherits both memos. So after `lane_env_apply`,
    `v=$(lane_knob …)` runs no jq.
  - A required knob's registry default is exported raw. The old `@tsv` read
    escaped `\`, a tab and a newline. No required default has one today.
- `bin/lib/lanes-registry.sh` (`lanes_json_path`):
  - A fast path: when `find <lanes.d> bin/lanes-build.sh -cnewer <stamp>`
    prints nothing, the render is served with no digest. ctime is used, not
    mtime, because `cp -a`, `rsync -t` and `touch -d` can set an old mtime but
    not an old ctime.
  - The stamp mtime is the time the hash started minus 2 s
    (`_lr_stamp_put`). So an input that changed during the hash or the
    compose is newer than the stamp.
  - A hash that still matches re-stamps and composes nothing.
  - A herd lock: `flock -n` on `lock-<key>` beside the stamp. A caller that
    finds it held serves the existing render. With no render it waits up to
    60 s, then re-checks. With no `flock` or a refused stamp dir there is no
    lock, as before.
  - `lanes_stamp_write` writes its stamp with the same rule. `_lr_stamp` uses
    `$EUID` in place of an `id -u` fork.

## Why

On 2026-10-17 at 04:35Z the hub (8 CPUs) ran load about 100 with 52
`fly-pool.sh` starts, 16 `lanes-build.sh` and a jq per knob on every lane
start.

## Numbers (this box, see the PR body for the commands)

| what | before (main) | after |
|---|---|---|
| jq per `lane_env_apply merge-conductor cromford` | 38 | 2 |
| jq per `lane_env_apply fly-pool cromford` | 21 | 2 |
| jq, 20-knob fixture plus 44 knob reads | 320 | 2 |
| held-lock fly-pool start | 5.8 ms, 1 lib | 3.7 ms, 0 libs |
| loader call, valid stamp | 25.6 ms | 8.4 ms |
| composes, 8 concurrent calls on a changed tree | 8 | 1 |
