# The archivist files one ai-build ticket per cause Archie fixed by hand twice (BH-10125)

Doc: STAFF, OPERATING

Slice C4 of #9423. The staff contract (C0, BH-9187) says each staff agent owns
ONE metric and is judged by whether that metric moved. This slice gives the
archivist its collector and its one lever.

## The metric

`causes_fixed_by_hand_twice` is the count of distinct causes with at least
`staff.archivist.recur_n` (seed 2) occurrences in the last
`staff.archivist.window_days` (seed 7, 1..30) UTC days. Target: 0.

The input is Archie's hand-fix log: the `archie_actions` rows. The lane reads
and fingerprints them with the BH-4587 code, unchanged
(`bin/lib/archie-fm-improve/common.sh`: `afi_read_days`, `afi_occurrences`,
`afi_cause`, `afi_fp`). So one occurrence is one distinct dedupe key without
its `:on` / `:observe` suffix, and Archie's own `improve` rows, `watch-ticket`,
`watch-session`, `queue-solo`, `skipped` rows and a `data-lane` apply that
closed done never count.

A day that was not read in full (a failed read, a truncated page or the route
absent) makes the count `unreadable`: no sample and no action. An unreadable
count is never 0.

## The lane

`bin/staff/archivist-lever.sh`, hourly at :57 on the hub
(`cron/lanes/787-staff-archivist-lever.cron`, registry
`catalog/lanes.d/staff-archivist-lever.json`). Each run:

1. Kill checks before any request: `STAFF_ENABLED=0`, the flags
   `staff-off-all`, `staff-kill-all`, `staff-off-archivist`,
   `staff-kill-archivist`, then the lane gate.
2. `flock -n locks/staff-archivist-lever.lock`.
3. `GET /api/staff/agent?name=archivist` must say `active`.
4. Read `window_days` days of `archie_actions`, count, and sample
   `POST /api/staff/levers/metric` (this settles due actions, C0).
5. At `staff.archivist.level` = `file` or `act` only (seed `observe`): read the
   `archie-fm-improve` label list (state=all) and the open issues of
   `HARNESS_REPO`. Then, per repeated cause, highest count first:
   - dedupe: a label-list issue with the cause's marker in any state, or any
     open issue with it, is `already`;
   - cap: label-list issues created today at or over
     `staff.archivist.file_max_day` (seed 3) is `capped` (Archie's own filings
     count too, so the cap errs low);
   - record before act: `POST /api/staff/levers/actions`, lever `file-ticket`,
     key `file:<fp>:<UTC day>`. Only a new row files. `existing` or 409 is
     `taken`; anything else is `failed`;
   - file through the tracker seam (`tracker_create`). Filed only on HTTP 201
     with an `html_url`. A failed filing keeps its ledger row and is retried
     on a later UTC day under a new key.

At `observe` the lane samples the metric, logs `would=<n>`, and makes 0 action
posts and 0 GitHub calls.

## The hand-off to Archie's improve loop

The issue carries the labels `ai-build`, `archie-fm-improve` and
`staff:archivist`, the line ``Cause: `<cause>` `` and the BH-4587 marker
`<!-- archie-fm-improve:fp=<fp> -->`. So `bin/archie-fm-improve.sh` sees it in
its own label list: it comments on new occurrences, tracks the issue to its
merged PR, verifies or reopens it, and never files a second issue for that
cause. The archivist owns only the first filing at 2 occurrences; Archie's lane
files at its own `archie.improve.recur_n` (3) only when no issue exists.

`bin/staff.sh tick archivist` is not changed: there is no
`bin/staff/archivist-collect.sh`, so the model-written staff filing stays at 0
items and no cause gets two tickets.

## Settings rows

| row | seed | meaning |
|---|---|---|
| `staff.archivist.level` | observe | observe, file or act (BH-9187 seed) |
| `staff.archivist.recur_n` | 2 | occurrences that make a cause repeated (this slice) |
| `staff.archivist.window_days` | 7 | the window in UTC days, 1..30 (this slice) |
| `staff.archivist.file_max_day` | 3 | issues per UTC day (BH-9187 seed) |

Seed: `worker/jobs/schema.d/202611252047-bh-10125-archivist-lever.sql`.

## Off switches

`bin/harness-ctl.sh off staff-archivist-lever` (flag
`lane-off-staff-archivist-lever`), the staff kill flags above, or
`STAFF_ENABLED=0`. Set `staff.archivist.level` to `observe` to stop filing and
keep the metric.
