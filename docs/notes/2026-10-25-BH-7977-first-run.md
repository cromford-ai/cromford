# First-run screen for the fleet accounts (BH-7977, BH-7939.3)

Doc: DB-COORDINATION-SPEC

## What changed

A new fleet that misses a required account opens `/` on a first-run screen
with four cards (Anthropic (Claude), GitHub App, Telegram, More AI accounts),
not on the Fleet list.

- Worker route `GET /api/fleet/first-run`
  (`worker/jobs/src/routes/fleet-first-run.js`, route-table fragment
  `bh-7939-fleet-first-run.txt`). It runs ONE SELECT and answers
  `{anthropic, github_app, telegram, more_ai, complete, gate}` as booleans.
  - `anthropic`: a non-revoked `ai_accounts` row with vendor `claude`.
    `ai_accounts.vendor` has no `anthropic` value (BH-7966 CHECK).
  - `github_app`: the settings row `github_app.installed`, trimmed, exactly `1`.
    No code writes it yet; an operator sets it on `/config`.
  - `telegram`: `telegram.bot_present` trimmed `1` AND `telegram.chat_id`
    trimmed not empty (the rows `bin/fleet-telegram-chat.sh` of BH-7974 writes).
  - `more_ai`: a non-revoked row of codex, openrouter, fireworks or xai. It
    never changes `complete`.
  - `complete` = anthropic AND github_app AND telegram.
  - 503 on a D1 error; `ai_accounts schema not applied` without the BH-7966
    fragment.
- Settings row `first_run.gate` (schema.d `202610250546-bh-7977-first-run-gate.sql`).
  `1` = `/` shows the first-run screen while `complete` is false. `0` = never.
  The fragment seeds it ONCE: `0` when `jobs` or `projects` holds a row at
  apply time (the live fleet keeps its list), else `1`. With no row the route
  answers `gate:false` (code fallback). An operator changes it on `/config`.
- Console: `console-ui/src/lib/first-run.js` (path, `firstRunApi` seam for a
  later spread into `api`, `loadFirstRun`, `firstRunFrom`, `showFirstRun`,
  `FIRST_RUN_CARDS`) and `console-ui/src/screens/FirstRun.js`. `FleetScreen`
  (`/`) reads first-run once per load, in the same commit as the projects read.
  A failed read shows the list plus "could not check fleet accounts — <why>".
- The Anthropic and More AI cards open the existing AI account add sheet
  (BH-7966). GitHub App and Telegram have no setup sheet yet; each card links
  to its settings row on `/config/setting/<key>`.

## Why

- The gate row: without it, the first deploy would turn every operator's `/`
  into the first-run screen, because nothing writes the three account rows on
  the live fleet yet. The ticket names a NEW fleet.
- `console-ui/src/api.js` and `console-ui/src/api-first-run.js` are not edited:
  PR #7985 (BH-7974) owns both. When it lands, `...firstRunApi({ get, coordPath })`
  is the one-line spread.
- `more_ai` is one `vendor = '<v>'` EXISTS per vendor, not one
  `vendor IN (…)`. At 5,000 seeded rows SQLite plans the `IN` over four of five
  vendors as a full `SCAN ai_accounts`; each single-vendor EXISTS is a SEARCH on
  `ux_ai_accounts_vendor_label`.
