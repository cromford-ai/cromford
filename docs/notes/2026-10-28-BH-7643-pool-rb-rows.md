# Pool rebase rows: a per-tick limit and no machine for a closed PR (BH-7643)

Doc: FLY-POOL

## What changed

- The pool SPAWN walk of `bin/fly-pool.sh` starts at most
  `POOL_RB_MAX_PER_TICK` conductor rebase rows (`RB-<pr>-<head8>`) per tick.
  Settings row `lane.fly-pool.pool_rb_max_per_tick`, default 4, 0 = no limit.
  A value outside 0-1000 uses 4 and says one line.
- An RB row past the limit stays queued for the next tick. The walk goes on
  (`continue`, not `break`), so the ticket rows behind it still get the
  budget. After the walk, one line names the waiting rows:
  `rebase rows: <n> past pool_rb_max_per_tick=<max> wait for the next tick (<keys>)`.
- Before an RB row spawns, the pool reads its PR once
  (`GET repos/<slug>/pulls/<ticket_id>`, cached for the tick). A closed or
  merged PR closes the queue row `done` with the reason
  `empty: pr-closed (PR #<n> <closed|merged>)`, removes the queue file and
  starts no machine. A closed row takes no slot of the limit. Log line:
  `<KEY>: PR #<n> is <state> — row closed empty (pr-closed), queue file removed, no machine`.
- An unreadable PR state (no slug or gh, 4xx, 5xx, a cut read, a body with
  no known state, a row whose `rebase.slug` is not the pool's) spawns as
  before, with one `state unreadable` line per key.
- `pool_spawn_decision` runs the same closed-PR check on its RB arm, so the
  reuse handoff (`next_job_or_destroy`) also gives no machine to a closed PR.
  The limit applies to the SPAWN walk only.
- The logic is in `bin/lib/pool-rb-rows.sh`. Missing, RB rows spawn as
  before (no limit, no PR read).

## Why

The conductor queues at most 2 pool rebases per tick, but RB rows that piled
up over ticks took every budget slot, and RB rows skip the 600 s tick budget.
Ticket builds then waited. Rows of PRs merged in the meantime (project-6
#1924, #2005) still got machines.

## Not changed

- The hub rebase job file of a closed PR. The conductor still owns its
  timeout.
- RR, LR, CP and FXR rows: they do not count against the limit.

## Tests

`tests/fly-pool-rb-rows.bh-7643-test.sh`: the knob reader, the limit (6 RB +
2 ticket rows, limit 4, cap 8 gives 4 RB + 2 ticket machines), the walk's
hot-first contract with a mutated `hotfix_first` that must go red, and the
closed/merged/unreadable PR cases.
