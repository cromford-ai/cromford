# Suite ledger: run a suite once per input fingerprint (BH-5354.0 / BH-5366)

Doc: CI-RUNNERS, DB-COORDINATION-SPEC

This is the working core of the operator's 2026-10-08 dedup ask. It adds the worker
ledger, the fingerprint and the `bin/suite-reuse.sh plan|record` helper. **No
runner calls the helper yet**, so CI, the builder gate and the merge queue run
exactly what they ran before. The sibling slices wire it in.

## What changed

- **Worker tables** (`worker/jobs/schema.sql`, mirrored in `CREATED_TABLES`):
  - `suite_results`: one row per `(repo, ctx, class, suite, fingerprint)`, holding
    the status, the latest green's `run_id`/`duration_s`/`head_sha`/`ok_at`, and
    `runs`/`fails` counters.
  - `suite_reuse_runs`: one row per `(repo, run_key)` with ran, reused, total and
    `saved_s`.

  Both are additive (`CREATE … IF NOT EXISTS`). `bin/harness-sync.sh` applies
  them before `wrangler deploy`, and the routes self-create them through
  `ensureTable`.
- **Worker routes** (`worker/jobs/src/routes/suite-results.js`, in `OPEN_ROUTES`):
  - `POST /api/suite-results/lookup` `{repo, ctx, items:[{suite,fingerprint}]}`
    returns `{reuse, max_age_h, hits:[{suite, fingerprint, run_id, duration_s, class, ok_at}]}`.
    It only returns rows with `status='ok'` whose `ok_at` is within the max age
    on the worker's clock, and the `ctx` must match exactly. A green is never a
    hit while any row the caller can see holds a `fail` at the same suite and
    fingerprint, whichever class wrote it. A token caller sees `ci` rows only. The limit is 1500 items, sent as one bound JSON string read
    with `json_each`, never one bind per item.
  - `PUT /api/suite-results` `{repo, ctx, run_id, head_sha?, class?, items:[{suite,fingerprint,status,duration_s}]}`
    returns `{ok, written, contradicted:[{suite, fingerprint, prior_run_id}]}`.
    It is one upsert statement for the whole batch. Each write also prunes at
    most 500 rows untouched for 30 days.
  - `PUT /api/suite-results/runs` `{repo, run_key, ctx, head_sha?, ran, reused, total, saved_s}`
    upserts the run row. It is idempotent, and it returns 409 when the
    `run_key` belongs to the other class.
- **`bin/test-impact.sh inputs`** prints every map row, plus a
  `<suite>\t<script>` row for each function a suite names that a non-test
  script defines, plus `@infra\t<path>` for every `ti_infra_re` path.
  A named-function scan that fails is rc 2, never a list with the named edges
  missing. `ti_infra_re` now also covers `bin/suite-reuse.sh` and
  `bin/lib/suite-fingerprint.sh`, so a change to either runs the whole corpus.
- **Knobs** (`catalog/lanes.d/_lib.suite-reuse.json`):
  - settings row `lib.suite-reuse.suite_reuse`: `on`/`off`, default `on`.
  - settings row `lib.suite-reuse.suite_reuse_max_age_h`: 1..720, default 72.

  The worker reads both on every lookup. A value outside those ranges turns
  reuse **off** with a reason. It never falls back to the default. On a single
  runner, the env `SUITE_REUSE=off` skips the lookup.

## The fingerprint (`bin/lib/suite-fingerprint.sh`, `sfp_compute <rev> <suites-file> <out-tsv>`)

```
fp = sha256( "suite-fp v1\n"
           + "infra\t<infra_hash>\n"
           + sorted unique "<path>\t<git object id or ->" over the suite's inputs rows )
infra_hash = sha256( sorted "<path>\t<id or ->" over the @infra paths
                     + bin/suite-reuse.sh, bin/lib/suite-fingerprint.sh,
                       bin/ci-plan.sh, bin/test-impact-gate.sh )
```

- **Ids** come from one `git ls-tree -r -t --full-tree` of `<rev>`. A directory
  row hashes as its tree id, and a path that is absent hashes as `-`.
- **`<rev>` must be HEAD** and the tree must be clean. Untracked files count as
  dirty. A dirty tree returns rc 3 and `dirty tree`, so a local edit never gets
  a fingerprint.
- **Never reused** (fp `-`), checked in this order:
  - `always`: a suite that runs on every diff.
  - `fast-lint`: in `bin/fast-lints.sh --list`.
  - `never.tsv: <reason>`: listed in `catalog/suite-reuse-never.tsv`.
  - `out-of-tree: <token>`: a non-comment line matches
    `RATCHET_BASE|origin/main|merge-base|git[ \t]+fetch|ls-remote|gh[ \t]+api|/root/harness/(state|logs|builds)`.
  - `unknown suite`: the suite has no inputs rows.
- **`catalog/suite-reuse-never.tsv` is seeded empty.** The plan's seed grep hit
  582 suites. Every hit checked, including the 10 that remain once the grep is
  narrowed to a command position, is a stub, a shell function, a grep pattern
  or `jq -nc`. So no row would be true. The file's header carries the grep and
  the counts.

## Trust model (I1)

- **A row's class comes from the credential, never from the body.**
  - The worker bearer `HARNESS_SECRET` writes `builder` rows.
  - The header `x-suite-ledger-token` (worker secret `SUITE_LEDGER_TOKEN`)
    writes `ci` rows.
  - A body `class` that disagrees returns 403.
- **A token (CI) lookup only sees `ci` rows.** A builder can reuse a CI green,
  but CI never reuses a builder's.
- **The worker refuses when the secret is unset.** An empty header against an
  unset secret returns 401, the same rule as `bearerOk`.
- **Fail is sticky inside the upsert statement.** A concurrent `ok` can never
  overwrite a `fail`, so a fingerprint that went red runs every time until its
  inputs move or the row ages out.
- **Fail is sticky across classes in the lookup.** The class is part of the
  key, so a `fail` in one class never touches the other class's `ok` row. The
  lookup therefore drops a green when any row visible to the caller failed at
  that key. A builder fail or a CI fail hides the green from the bearer. A
  token caller sees only `ci` rows, so only a CI fail hides it from CI.
- **`contradicted` names a green that has just gone red** in any class the
  writer's lookup sees. `record` prints it as
  `suite-reuse: MISS <suite> was ok in <prior>, failed in <run>`, and as a
  `::warning::` under GitHub Actions.

## The helper (`bin/suite-reuse.sh`)

- **`plan` is fail-safe.** On any failure, `--run` is the input list, `--reused`
  is empty, exactly one `suite-reuse: off (<why>)` line prints, and the exit
  code is 0. The failures it covers:
  - the knob is off;
  - there is no credential or no URL;
  - the credential's class does not match `--class`;
  - the tree is dirty or the fingerprint failed;
  - curl failed or timed out (10 s);
  - the ledger answered non-200 or with bad JSON;
  - the server's knob is off;
  - the result would leave nothing to run.

  The ledger can never turn a run red.
- **`record` writes only from a complete gate log.** It writes from
  `--results` or from a `bin/test-trace-safety.sh --gate` log. A log that is
  not closed by its `TRACE:` summary (or `TRACE:` then `GATE:`) writes nothing.
  A failing suite's output is dumped into the log, so a `TRACE:` line anywhere
  else may belong to a nested log. A path with two `---` lines records `fail`. A suite counts as `ok` only on rc 0 with no
  `HIT`/`TIMEOUT` line for its basename. A write failure prints one stderr line
  and exits 0.
- **Lead review gets no code change.** The LEAD_REVIEW_HOST_SUITE hotfix removes
  the host-suite step. The helper is generic, so a later per-suite lead step can
  call `plan`/`record`.

## Known limit: the fingerprint follows `source`, not exec

`bin/test-impact.sh` documents this blind spot. A suite that runs a real caller,
which then execs a callee the map does not fingerprint, can be reused across a
change to that callee. So the merge-queue batch must never skip a suite on this
fingerprint alone. The sibling that wires CI must keep the full corpus there.

## Rollout (unset = reuse off)

| what | where | how |
|---|---|---|
| `SUITE_LEDGER_TOKEN` | harness-jobs worker secret | `wrangler secret put SUITE_LEDGER_TOKEN` |
| `SUITE_LEDGER_TOKEN` | GitHub Actions secret on `example-org/cromford` | repo settings → secrets |
| `SUITE_LEDGER_URL` | GitHub Actions repo variable | the harness-jobs worker URL |

- **Boxes and builders need nothing new.** They use `JOBS_URL` + `HARNESS_SECRET`.
- **Unset secrets leave CI unchanged.** Until both secrets are set, a CI caller
  gets `off (no credential)` or a 401 → `off (ledger http 401)`, and CI runs
  every suite exactly as today.
