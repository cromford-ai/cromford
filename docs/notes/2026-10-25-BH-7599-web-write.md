# web-task write mode: one approval before each write (BH-7599, slice C0)

Doc: DB-COORDINATION-SPEC

## What changed

The ticket asks for web tasks that change a website (submit a form, change a
setting), with one approval before each change. The agent loop (S1, PR #7650)
and the S5 approval path (`wh_request_human ... approve`, PR #8174) are open
PRs, not on main. This slice adds the write gate as a pure module with
injected seams and a fail-closed default, the same way BH-8125 and BH-8226
shipped their steps. Nothing on main calls it yet.

- `bin/lib/web-write-step.mjs` (node built-ins only, no top-level side effect):
  - `parseTaskMode(body)`: `write` only when the first `Mode:` line outside a
    fence reads `Mode: write` (key and value case-insensitive, spaces
    trimmed). A `>` quote, an inline "mode: write", `Mode: writer` or no line
    is `read`.
  - `isWriteAction(desc)`: a submit or image input, a button that submits its
    form, or a name or role with a write word as a whole word (submit, pay,
    purchase, buy, checkout, order, delete, remove, send, save, confirm,
    subscribe, sign up, place order, update, apply). The list is S1's
    `isSubmitLike` list plus the ticket's words.
  - `paymentReason(page)`: non-empty on a page with a card field
    (`autocomplete` `cc-number`, `cc-csc`, `cc-exp`, `cc-exp-month`,
    `cc-exp-year`, or a name `cardnumber`, `card-number`, `card_number`,
    `ccnumber`, `cvc`, `cvv`) or a URL path segment that is exactly
    `checkout`, `payment`, `pay` or `billing`.
  - `createWriteGate({ mode, project, site, issue, allowPaymentSites, approve,
    shoot, shotDir, redact, waitS, sleep })` returns `{ gate, writes,
    writesSection, n, stopped }`, one instance per agent run. `mode` is
    `read` (the default) or `write`; anything else throws `web-write: bad mode`.
  - `writesSection(writes, link)`: the result comment block.
- `catalog/lanes.d/_lib.web-write.json`: lib `web-write`, knob
  `WEB_TASK_WRITE_WAIT_S`.
- `tests/web-task-write.bh-7599-test.sh` and the fixture site
  `tests/lib/web-write-site.bh-7599.mjs` (a settings form and a card form on
  127.0.0.1 that count every POST).

## The gate

`gate(page, desc, act)` returns `{ outcome, terminal }`. In order:

1. The run is stopped (an earlier terminal outcome): refused, `act` is not called.
2. A payment page whose host is not allow-listed: refused, in every mode, for
   every action (a type on a card field too). The run stops.
3. Not a write: `act()` runs. A string result comes back as the outcome.
4. A write in read mode: refused. The run goes on (the S1 refusal).
5. A write in write mode: a screenshot `before-<n>.png` of the filled form,
   then `approve()` raced against `WEB_TASK_WRITE_WAIT_S`. Only the answer
   `approve` runs `act()`, once. Then `after-<n>.png`, and the write is
   recorded. An `act()` that throws is recorded `unknown` and is never
   retried, because a retry can write twice.

An allow-listed payment page still needs the approval: the allow-list only
lifts the refusal.

Outcomes (each through `redact`):

| Outcome | Terminal |
|---|---|
| `refused: run stopped` | true |
| `refused: payment page (<host>)` | true |
| `refused: write action in read-only mode` | false |
| `stopped: no screenshot for write <n>; nothing written` | true |
| `ok: write <n> done (<action>)` | false |
| `stopped: write <n> cancelled; nothing written` | true |
| `stopped: no approval for write <n> in <s>s; nothing written` | true |
| `stopped: approval failed for write <n> (<why>); nothing written` | true |
| `error: write <n> failed (<message>); not retried` | true |

`<action>` is `desc.action`, else `click <desc.name>`.

## The default approve

When no `approve` is injected, the gate runs S5's
`wh_request_human <project> <site> approve <prompt> --shot <png> [--issue <issue>]`
from `bin/lib/web-human.sh` beside the module, in a bash child. The argv holds
the project, the site, the prompt (`Approve write <n> on <site>: <action>`),
the shot path and the issue. It holds no typed value. rc 0 with stdout exactly
`done` is Approve, rc 3 is Cancel, rc 4 (S5 "waiting on human") is no answer.
Any other rc or stdout is an approval failure. A child still running at the
end of the wait is killed.

Until PR #8174 merges, `bin/lib/web-human.sh` does not exist. The default
answers `error: approval path not available`, so every write stops with
nothing written (fail closed).

S5's rc 4 keeps its step open for a resume run. The gate does not replay a
write on a late answer: the run stopped, so the write is not made.

## Knobs

- `WEB_TASK_WRITE_WAIT_S` (row `lib.web-write.web_task_write_wait_s`):
  default 300, equal to S5's `web_task.human_wait_s` seed. Integer 10..3600.
  A bad value throws `web-write: bad WEB_TASK_WRITE_WAIT_S`; it is never
  clamped. The `waitS` option wins over the env.
- `ALLOW_PAYMENT_SITES`: the env of the row
  `lane.web-task.<project>.allow_payment_sites` through
  `lane_env_apply web-task <project>`. A comma or space list of exact hosts,
  lower-cased, trailing dot dropped, no subdomain match. Default empty, so
  every payment page is refused. The `allowPaymentSites` option wins over the
  env. The knob is registered in S1's `catalog/lanes.d/web-task.json` in C1.
