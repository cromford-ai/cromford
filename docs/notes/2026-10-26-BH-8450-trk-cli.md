# The trk CLI and the trk watcher-prompt render (BH-8450)

Doc: trk-cli, tracker-adapter

## What changed

Slice C2 of #7920.

- New `bin/trk`: `trk list|read|comment|transition|label-add|label-remove|link-pr|close-out <project> …`.
  Each verb is one call to the tracker contract (`bin/lib/tracker.sh`). `trk
  read` puts the title + body and each comment in a `ui_wrap` block
  (`bin/lib/untrusted-input.sh`). The usage rules, exit codes and env are in
  `docs/verification-map/trk-cli.md`.
- `_obs_prompt_render` (`bin/lib/onboard-stations.sh`) asks `tracker_kind`.
  For `jira` or `linear` it puts `prompts/_template/trk-commands.md` in place
  of the GitHub Issues command block of a NEW prompt. If the template has no
  single block to replace, or the fragment is missing, it writes no prompt and
  returns 1. Every other kind renders byte for byte as before.

## Decisions (from the plan's ASSUMPTIONS)

1. The suite is `tests/trk-cli.bh-8450-test.sh`, not the `bh-7920` name in the
   ticket: a test belongs to its own ticket key (D65).
2. The two existing sandbox prompts are not converted. Their launch line,
   duplicate check and results sweep still use GitHub issue numbers, and that
   is wave 3.
3. Only a new prompt gets the trk block. An existing one is skipped as before.
4. `trk list` prints the contract JSON as is: it carries no body and no
   comment. Titles are not wrapped, as in `gh issue list`.
5. `trk` resolves the tracker and context live under `TRK_DRY=1`. The
   contract's dry rule reads no row and would route a Linear project to GitHub.
   Only the write is dry.
6. `TRK_DRY` other than empty, `0` or `1` is refused (rc 2). The contract
   treats only `1` as dry, so `TRK_DRY=true` would send a live write.
7. `TRK_LOG` defaults to `$HARNESS/logs/trk.log`, one line per write. No
   rotation exists for it yet, the same as `logs/deploy-rollback-board.log`.
8. Not verified here: whether the sandbox `tracker_adapter.*` rows use the
   fleet.conf names (`cromford-sbx-linear`) or the long names.
9. The render resolves the harness root as `${HARNESS:-$PWD}`. With no row it
   falls back to fleet.conf column 4, the GitHub render.

## What did not change

No contract verb, adapter, settings row, table, cron line or alert. The
GitHub, board and unresolved paths of the render are unchanged.
