# CI test value report: the extra sources and the report (BH-6640, BH-6618.4)

Doc: CI-RUNNERS, FLAKY-TESTS

## What changed

`bin/ci-test-value-report.sh` (BH-6636) wrote `occurrences.tsv` and a totals
JSON. This change fills the two seams it left:

- `ctv_fetch_sources <out>` (`bin/lib/ci-test-value/sources.sh`) reads three
  jobs-worker aggregates and the suite list on disk into `<out>/cache/`.
- `bin/lib/ci-test-value-render.py` adds keys to `ci-test-value.json` and
  writes two more files beside it: `ci-test-value.html` and `summary-ste.md`.

The driver, the collector lib, the rules and the worker routes did not change.

## The sources (`<out>/cache/`)

| File | Read from | Shape check |
|---|---|---|
| `suite-durations.json` | `GET /api/ci/suite-durations` | `.rows[]` with `suite` (string) and `seconds` (number) |
| `suite-passes.json` | `GET /api/suite-results/passes?repo=<repo>&since=<window from>` | `.suites[]` with `suite`, `passes`, `fails` |
| `flakes.json` | `GET /api/metrics/flakes?repo=<repo>&since=<window from>&limit=2000` | `.flakes` is an array |
| `suites-on-disk.txt` | `git ls-tree -r --name-only HEAD` of this checkout | `tests/*.sh`, `tests/mc/*.sh`, `worker/jobs/test/**.test.js`, `console-ui/**.test.*` |

- Every worker call is a GET through `_jobs_req` (`bin/jobs-client.sh`).
- Every run reads all four again. They are live aggregates, so nothing from an
  earlier run is kept: the function removes the three worker files before it
  reads.
- A failed read or a body of the wrong shape leaves its file ABSENT. One stderr
  line names it: `ctv: source <name> unread (<why>)`.
- `ctv_fetch_sources` returns 0 on every path. An unread source never stops the
  run. The report names it instead.
- An empty `JOBS_URL` (no worker on this box) reads as three unread sources.

## The JSON keys (`<day>/ci-test-value.json`)

Kept from BH-6636: `window`, `repo`, `generated_at`, `coverage`, `rules`,
`totals.occurrences`, `totals.by_class`.

New:

- `suites[]`, one row per suite. The suite set is every non-`job:` unit in
  `occurrences.tsv`, every suite in `suite-passes.json` and every line of
  `suites-on-disk.txt`, in `LC_ALL=C` order.
  - `ledger_runs`: `passes + fails` from the suite-results ledger since the
    window start. 0 when the source was read and has no row for the suite.
    `null` when the source is unread. `runs_source` says where it came from.
    The ledger mixes CI and builder runs; the route has no class filter.
  - `seen_runs`: distinct `(run_id, attempt)` pairs in `occurrences.tsv`.
  - `failures`: occurrences per class, `unknown` included.
  - `real`: `real-pr + real-main`. `false`: `test-defect + infra + flake + order`.
    Any other class counts only in `failures`.
  - `ci_seconds`: the CI median seconds × `ledger_runs`, rounded. `null` when
    either input is missing. `ci_seconds_source` is `median×runs`.
  - `last_real_catch`: the latest `day` of a real-class row, else `null`.
  - `slug`: the HTML anchor id. `on_disk`: `null` when the disk list is unread.
- `unattributed[]`: one row per `job:<name>` unit (a failed job with no suite
  named in its log): `unit`, `slug`, `occurrences`, `failures`, `last_day`.
  These never enter `suites[]` or a list.
- `totals` adds `red_runs`, `red_runs_read` (from `coverage.json`),
  `pct_by_class` (`round(100 * n / occurrences, 1)`, `{}` for 0 rows) and
  `unattributed_units`.
- `sources`: `occurrences`, `coverage`, `suite_durations`, `suite_passes`,
  `suites_on_disk`, `flakes`. Each is `{"file": <path under out>, "read": bool}`.
  `flakes` adds `rows` when read. `flakes.json` is a cross-check only; no field
  uses it yet.

## The three lists (`lists`)

Each list holds suite names. The full rows are in `suites[]`.

- `zero_real_with_false`: `real == 0` and `false >= 1`. Sorted by `false`
  descending, then suite name.
- `expensive_zero_real`: `real == 0`. Sorted by `ci_seconds` descending, `null`
  last, then suite name. At most 20.
- `never_ran`: on disk, `ledger_runs == 0` and `seen_runs == 0`. A suite not on
  disk is never listed. The list is `null`, not empty, when `suite-passes` or
  the disk list is unread: the report does not claim a suite never ran without
  the ledger.

## How to read the HTML (`<day>/ci-test-value.html`)

One self-contained file. Open it from the box, or copy it off and open it as a
file. It loads nothing from the network; the only links are the GitHub run and
job URLs.

Sections, one table each: Totals, Coverage (with the read state of every
source), Zero real with false, Expensive zero real, Never ran, All suites,
Unattributed jobs, Occurrences.

- Sort: click a column header, or focus it and press Enter or Space. The first
  sort is ascending, the next descending. The header shows ▲ or ▼ and sets
  `aria-sort`. An empty value (`—`) sorts last both ways.
- Drill down: a suite name links to its first row in Occurrences. A suite with
  no occurrence links to its row in All suites. Each Occurrences row links to
  its GitHub run and its GitHub job. A URL that is not `https://github.com/`
  prints as text.
- Every value is HTML-escaped, the `why` text included.
- On a narrow screen each table scrolls inside its own frame. The page body
  does not scroll sideways. A cell wraps only between words
  (`overflow-wrap:break-word`), so a date, a run id or a suite path stays
  whole. `word-break:break-word` split them at 375 px.

## The summary (`<day>/summary-ste.md`)

Template text in Simplified Technical English. No model call.

Line 1:

- `COMPLETE: <red_runs> red runs read` when `coverage.unread == 0`,
  `red_runs_read == red_runs` and `coverage.incomplete` is not true.
- Else `INCOMPLETE: <n> red runs unread`, with
  `n = max(red_runs - red_runs_read, unread)`. A run with an unlisted day or a
  stop reason and no unread run gives `INCOMPLETE: 0 red runs unread`; the
  coverage line names why.

Then: the window and repo, the totals, one line per class with its percentage,
the top 10 of `zero_real_with_false` and of `expensive_zero_real`
(`false=<n> runs=<ledger_runs> ci_seconds=<n|unknown>`), the `never_ran` count,
the coverage line and one line per unread source.
