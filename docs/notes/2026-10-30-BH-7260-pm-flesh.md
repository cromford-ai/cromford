# PM flesh-out of one idea, and pm-agent ideas (BH-7260, BH-7244.2)

Doc: CONSOLE, PROJECT-LANES

The whole of #7260 (BH-7244.2). Three things ship:

1. run-product's SYNTH ideas that cite data evidence land in the roadmap
   backlog as ideas with source `pm-agent`.
2. `bin/pm-flesh.sh <project> <idea-id> [--force]` turns one roadmap idea into
   a seven-section brief and drafts its PRD and mockup. The result is stored
   in the `pm_runs` row, and the idea page shows it. The idea row is not
   edited.
3. A FLESH OUT button on the idea page starts that run on the project's box.

Neither one posts to a client board, files a ticket or starts a build.

## Landing (`bin/lib/pm-ideas-land.sh`)

`bin/run-product.sh` already called the `pm_ideas_land <project> <cycle_dir>`
seam after SYNTH (BH-7258). The placeholder is now the implementation. It
always answers rc 0, and run-product ignores its rc.

- Evidence is the `ok` rows of `<cycle_dir>/data-signals.json`. With no file
  (run-product removes a failed day's file), no idea qualifies.
- An idea qualifies when a token of its `evidence_id`, `evidence_ids[]` or
  `evidence` equals an ok id exactly. A prefix, a superstring, a
  `not-configured` or `error` row, or an id only in the title does not count.
  `prompts/product-stages/synth.md` now asks SYNTH to keep `evidence_ids`.
- Each idea is one `POST /api/roadmap/ideas` with `source:"pm-agent"`,
  `idem_key:"pm-<slug>"` (a slug of at most 77 characters) and `actor:"pm-agent"`. A replay is counted as
  `replay`. A 409 (the same slug with a new summary) is counted as `changed`
  and the stored idea is not overwritten.
- `pm.land_max` (seed 20, 0..100, 0 = off) caps the ideas landed per cycle.
- One summary line goes to the run-product log:
  `pm-land: project=<p> candidates=<n> evidence=<n> landed=<n> replay=<n> changed=<n> errors=<n> skipped=<n> capped=<n>`.

`worker/jobs/src/routes/roadmap-ideas.js` `IDEA_SOURCES` accepts `pm-agent`.
The console's source picker does not list it: a person does not pick it.

## The flesh-out (`bin/pm-flesh.sh`)

The script header documents every step. In short:

- run-product's switch and `flags/product-paused-<project>` stop it (rc 0).
  `locks/<project>-product.lock` held is rc 75. No `product.pm` model route
  is rc 75 with no read.
- It reads the idea and the newest `data-signals.json`, and hashes the idea
  (title, note, source, link), the evidence snapshot and the prompt.
- CLAIM BEFORE THE SPEND: `POST /api/pm/claim` on
  `pm_runs UNIQUE(project, idea_id, input_hash)`. A claim API that does not
  answer is rc 75 with no call. A done row prints its stored result with no
  call. An answered row is finished from its stored result with no call
  (`draft=unknown`). A claimed or failed row is billed: only `--force` by a
  person re-claims it. An answered or done row is never re-claimed.
- ONE `bin/agent-call.sh` call, stage `pm`, lane `run-product`, role
  `product.pm`, no tools, with
  `prompts/product-stages/pm-flesh.md`. The answer must hold exactly the seven
  `## ` headings in order, cite no Evidence id whose status is not `ok`, and
  fit `pm.flesh_result_max_chars`. Otherwise the run is `failed` (billed) with
  one ALERTS line, rc 1.
- `POST /api/pm/result {status:answered, result}` stores the result at once.
  If it fails, the row stays `claimed` (billed) and one ALERTS line is
  written.
- `bin/draft-proposal.sh` drafts the PRD and the mockup (Mission Control
  assets only). Its outcome is the `draft` column: `ok`, `skipped` (rc 75),
  or `failed`. A failed draft does not stop the run. The draft's `prd.md` is
  sent with the done POST and kept in the `prd` column, so the paid PRD
  outlives the run's temp dir. A PRD over `pm.flesh_prd_max_chars` (131072)
  is cut, and its last line says so. The idea page opens the PRD under the
  brief and links the desktop and mobile screenshots at
  `prop:<p>:pmflesh-<run12>`.
- `POST /api/pm/result {status:done, result_ref, draft, prd, cost_usd}`. The row is
  `done` only when this answers 200. If it fails, the row stays `answered`,
  and a re-run finishes it with no call and `draft=unknown`.
- `result_ref` is `<console>/roadmap/<p>/idea/<id>#pm-flesh`.
- The script writes nothing under `state/`. Temp files live in one
  `mktemp -d` dir that a trap removes. The `pm_runs` row is the only state
  across runs.
- `cost_usd` is the sum of the `logs/cost.csv` rows of the project whose
  `run_id` is `pm-flesh:<run id>`. The call and the draft run with
  `COST_RUN_ID=pm-flesh:<run id>`. A build, review or triage of the same
  project in the same window has another `run_id` and is never counted.
- Exit codes: 0 done or already done or billed, 1 a failure after the claim
  (or no such idea), 2 usage, 75 refused before any spend.
- The spend runs under `AGENT_CALL_LANE=run-product`: pm-flesh runs under
  run-product's switch and lock, and `LLM_USD_CAP_DAY` of that lane binds it.
- Log: one line per run in `logs/pm-flesh.log`.

Cost stage `pm`, lane `run-product`: `catalog/llm-sites.d/7260-pm-flesh.json`.

## The table, the routes, the retention

`worker/jobs/schema.d/202610301916-bh-7260-pm-runs.sql`: `pm_runs` with
`ux_pm_runs_key`, `idx_pm_runs_project_created`, `idx_pm_runs_idea_created`
and `idx_pm_runs_created`, and five knob seeds (`pm.retention_days` 180,
`pm.runs_shown` 50, `pm.flesh_result_max_chars` 32768,
`pm.flesh_timeout_s` 900, `pm.land_max` 20). The statuses are `claimed`,
`answered`, `done` and `failed`. The allowed moves are claimed → answered,
claimed → failed, answered → done and answered → failed.
`pm.error_max_chars` (BH-7261) is reused.

`worker/jobs/src/routes/pm.js`: `POST /api/pm/claim`, `POST /api/pm/result`
and `GET /api/pm/runs`. Every statement binds the project. The coord proxy
forwards the GET; the two writes have no proxy row, so they are 405 from a
browser.

Retention: `retention.d/bh-7260-pm-runs.js` rule `pm_runs.age` runs in the
existing hourly `bin/d1-retention.sh` lane. A row older than
`pm.retention_days` is copied to the archive D1, then deleted. `cost_usd` is
money, so an unbound archive deletes nothing. `retention.dry_run` (seed 1)
applies, and each run writes one `retention_runs` row. This replaces the
`bin/pm-retention.sh` and weekly lane that the ticket scope named: two
schedulers over one table is a double run, and a bash delete cannot archive.

## The console

The idea page (`/roadmap/<p>/idea/<id>`) has a PM FLESH-OUT section
(`console-ui/src/screens/roadmap/flesh-section.js`). Its read
(`console-ui/src/lib/roadmap-api/pm-flesh.js`, `GET /api/coord/pm/runs`)
starts at mount in parallel with the idea read, and the section has its own
skeleton. It sits below HISTORY so it can render before the idea read answers.
It shows the newest answered or done run as seven labelled blocks (text,
never HTML) and every run in a sortable table (WHEN, STATUS, DRAFT, COST,
MODEL).

## The FLESH OUT button

The section starts with FLESH OUT and RELOAD. FLESH OUT asks in the in-app
dialog, then sends ONE command through `POST /api/dash/action`:
`{type: run_script, project: <p>, script: pm-flesh-launch.sh, args: [<p>, <id>]}`.

1. The console worker refuses `run_script` with 400 'unknown action'. The
   Pages proxy then checks the session with the worker's authed probe, and
   queues the row only for that exact shape
   (`console-ui/functions/_lib/pm-flesh-command.js`). No other script, no
   other project and no `--force` gets through.
2. The hub's `run_script` arm (`bin/poll-commands.sh`) forwards the row to the
   box that owns the project. No hub allow-list changed.
3. `bin/cmd-run-script.sh` runs `bin/pm-flesh-launch.sh` because
   `catalog/run-script-allowlist.d/bh-7260-pm-flesh.json` lists it.
4. `bin/pm-flesh-launch.sh` checks the project and the id, answers `busy` when
   the product lock is held, and else starts `bin/pm-flesh.sh` detached. It
   returns at once, inside the 300 s run_script bound.

The claim before the spend still decides: inputs that already have a result
make no call. A queued click locks the button while the screen is open.
RELOAD reads the runs again. A re-run of a billed or failed run stays a
person's step: `bin/pm-flesh.sh <p> <id> --force` on the box.
