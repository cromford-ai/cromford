# Why merge-queue batches go red: the daily red-batch report (BH-8048)

Doc: MERGE-CONDUCTOR

## The problem

On 2026-10-22 about 50 % of the harness-ci.yml merge-queue batch runs concluded
failure (13 of 26 in 24 h at 17:10Z). Each red batch is about 265 runner-minutes
that merge nothing. The pre-queue gate had passed every one of those heads.

## What shipped

- `bin/ci-batch-red-report.sh [--days N] [--dry-run]`: one TSV row per failing
  suite in `state/ci-batch-red/latest.tsv`, and one line in
  `logs/ci-batch-red.log`:
  `ci-batch-red: repo=<r> days=<d> red=<n> green=<n> red_rate=<pct> unread=<u> deferred=<k> case=<A|B|A+B|C> share_a=<pct> share_b=<pct> pruned=<p> ignored=<i>`
- The daily hub lane `ci-batch-red-report`
  (`catalog/lanes.d/ci-batch-red-report.json`,
  `cron/lanes/730-ci-batch-red-report.cron`, 06:37 UTC). Kill switch:
  `bin/harness-ctl.sh off ci-batch-red-report`. The lane id is the script
  name, because `tests/lanes-registry-test.sh` maps every cron script to the
  lane with its basename; the ticket's `ci-batch-red.json` name could not hold.
- Tests: `tests/ci-batch-red-report.bh-8048-test.sh`.

## The decision rule

The case is decided per red batch, over the readable red batches (red, not
`unread`):

- EXPLAINED-A: the batch has at least one suite failure (`rc` or `trace`),
  every member PR's pre-queue gate run was readable, and no failing suite is in
  the suites a member gate ran.
- EXPLAINED-B: the batch has at least one suite failure, and a green batch ran
  on the same `head_commit.tree_id` (no code change).
- `case=A` when more than 50 % of the readable red batches are EXPLAINED-A,
  `case=B` when more than 50 % are EXPLAINED-B, `case=A+B` when both, else
  `case=C`. 0 readable red batches is `case=C`.

"The suites a member gate ran" are the `impact-gate: done <suite> rc=` and
`impact-gate: reused <suite> from` lines (and any `--- <suite> rc=` line) of the
gate job's log. The verdict annotation's `suites=` field is NOT used: in
`.github/workflows/prequeue-gate.yml` it is the gate's FAILED suites, and it is
empty on a green verdict. Suites that only `bin/prequeue-invariants.sh` ran are
not printed per suite, so they count as not run by the gate.
