# Cut over project-6-os and project-6-desktop to box-mkfly, with a 24 h proof (BH-8324, MKF-9)

Doc: HUB-THINNING-PLAN, RESTORE

## What changed

Two code changes support the MKF-9 cut-over. The cut-over itself is an
operator action on the hub (the runbook below). A build box cannot run it.

1. `bin/box-move.sh proof <oldbox> <newbox>` now compares the 24 h after the
   cut-over with the 24 h before. The lib is `bin/lib/box-move/proof.sh`. The
   lines it printed before stay the same. After them it prints:

   ```
   window before=<ISO>..<ISO> after=<ISO>..<ISO> width_s=<W> after_state=complete|partial
   count <project> <counter> before=<n|NA(..)> after=<n|NA(..)> verdict=pass|fail|NA
   count <project> lane_silent after=<n|NA(..)> verdict=pass|fail|NA
   rollback_drill elapsed_s=<n|none> budget_s=<B> verdict=pass|fail|NA
   proof verdict=pass|fail|NA
   ```

   - The before window is the W seconds that end at the last `B2 ok` row of
     `state/box-move/<newbox>/steps.tsv` (the old cron stopped). The after
     window is the W seconds that start at the last `B5 ok` row (the new cron
     started). When the last B5 row is not `ok`, proof prints
     `window: none (<why>)`, the `rollback_drill` line and `proof verdict=NA`,
     and reads nothing remote for the window.
   - The counters per project of `old-rows.tsv`: `triage_ticks` (`[<p>] rc=`
     lines in `logs/<p>.log`, the old box for before and the new box for
     after), `pool_spawns` (`launch→first push` lines in the hub
     `logs/fly-pool.log`), `lead_reviews` (`pool lead review reaped for LR-`
     lines in the same log), `fix_rounds` (rows of
     `GET /api/fix-rounds?status=done` and `status=adopted` with `finished_at`
     in the window), `merges` (GitHub REST search
     `repo:<r> is:pr is:merged merged:A..B`, with a `mergify_*` count of the
     PRs that a `mergify*` login merged), and `lane_silent`
     (`[jobs-watchdog] LANE SILENT: <p>@` lines in the hub `logs/ALERTS.log`
     in the after window).
   - A counter verdict is `pass` when after >= before - `BOX_MOVE_PROOF_SLACK`.
     `lane_silent` passes at 0. A value proof could not measure is `NA(<why>)`,
     never 0: a missing log, a log whose oldest line is after the window
     start, a truncated worker list, a gh failure, an unreachable box. While
     the after window is not over, every verdict is `NA`.
   - `proof verdict=pass` needs every counter measured on both sides, a
     complete after window, 0 lane-silent lines and a rollback drill under
     budget. One `fail` makes it `fail`. Else one `NA` makes it `NA`.
   - Proof stays read-only and exits 0.
2. `bin/box-move.sh rollback --confirm` records its own time. The
   `rollback ok` row of steps.tsv and the `Rollback done.` line carry
   `elapsed_s=<n>`. Proof prints the newest one against the budget.

New knobs (env, operator-run, no lane row, as every box-move knob):
`BOX_MOVE_PROOF_WINDOW_S` (86400), `BOX_MOVE_PROOF_SLACK` (1, 0 is allowed),
`BOX_MOVE_ROLLBACK_BUDGET_S` (900). A bad value is exit 2.

## Runbook (operator, on the hub)

The order is: preconditions, the drill, the real cut-over, 24 h, the proof,
and the results table on #8324.

### 1. Preconditions

1. Make sure the MKF-8 results table is on #8323. On 2026-10-28 the #8323
   thread had only the merge comment. If the table is not there, stop.
2. Make sure the newest no-write tick is under 24 h old. If it is older, run
   `bin/box-move.sh tick box-project-6-os-1 box-mkfly`.
3. Make sure state-backup on project-6-os writes a snapshot (MKF-6).
4. Set `REGISTRY_SOURCE=db`, `REGISTRY_ADMIN_TOKEN` and `HARNESS_SECRET` in
   the shell. Proof also reads `JOBS_URL` for the fix rounds.
5. Pick a quiet hour: no claimed build for project-6-os or
   project-6-desktop.
6. Do not touch `flags/automerge-disabled-project-6-os`.

### 2. The rollback drill (AC3)

1. Run the cut-over, one step at a time:
   `bin/box-move.sh cutover --step B1 --confirm box-project-6-os-1 box-mkfly`,
   then the same with `--step B2`, `B3`, `B4` and `B5`.
2. Run `bin/box-move.sh rollback --confirm box-project-6-os-1 box-mkfly`.
3. Read `elapsed_s=<n>` on the `Rollback done.` line. It must be 900 or less.
4. Check that project-6-os runs its crontab again and that the rows put both projects
   on project-6-os.
5. Run a fresh no-write tick:
   `bin/box-move.sh tick box-project-6-os-1 box-mkfly`.

### 3. The real cut-over

1. Run B1 to B5 again, as in step 2.1. The after window starts at this B5.
2. If the fleet.conf files must follow the rows, open that PR only after B4.
   A committed fleet.conf that names mkfly before the rows move is a split
   brain at the next registry seed.
3. STOP before `bin/box-ops.sh retire ... --apply`. The ticket names
   `retire project-6-os --to mkfly --apply`. Its box id argument is the short id
   (`^[a-z][a-z0-9]*$`), not the box name. The new machine keeps the old box
   id `project-6-os` (BH-8322: `render-cron.sh project-6-os` renders its crontab). The retire
   step runs `bin/box-register.sh --retire project-6-os`, and that step removes
   `cron/boxes/project-6-os.d`, `cron/boxes/project-6-os.order` and `project-6-os` from
   `catalog/lanes.d/*.json`. That would empty the crontab of the new machine
   at its next render. Run only the dry run:
   `bin/box-ops.sh retire project-6-os --to mkfly --ip <project-6-os ip> --root /root/harness-checkout`.
   Read its PLAN lines. If they remove `cron/boxes/project-6-os.d` or a lanes entry,
   do not run `--apply`. Post the PLAN on #8324 for a decision.

### 4. The 24 h proof

1. Wait 24 h after the B5 of step 3.1.
2. Run `bin/box-move.sh proof box-project-6-os-1 box-mkfly`.
3. Post the results table on #8324: one row per `count` line, the
   `rollback_drill` line and the `proof verdict` line.
4. If the verdict is `fail`, run
   `bin/box-move.sh rollback --confirm box-project-6-os-1 box-mkfly`
   and post the table with the rollback line.
5. If the verdict is `NA`, post the table with each `NA(<why>)`. Fix the
   source and run proof again. `NA` is not a pass.
6. Known limit: `GET /api/fix-rounds` has no time filter. It lists the
   oldest 500 rows of a status (`LIST_MAX`) and says `truncated`. A project
   with more than 500 done or adopted rounds reads `fix_rounds NA(truncated)`.
   Count those rounds from the worker D1 table by hand for the table, and
   say so in the post.

### 5. Not in MKF-9

MKF-9 does not stop the Orgo computer and does not run `--delete`. That is
MKF-10 (#8325).
