# Seam file per sibling, `Owns:` lines, owns-overlap lint, HUB_MODULE (BH-6384)

Doc: PLAN-CONTRACT

## What happened

On project-6-os on 2026-10-12/13, siblings of split parents lost 6 approved
PRs in about 3 hours to conflicts with each other (HOME-1 142.x, AW-2 138.x,
workflows 60.x; add/add on `board.tsx`, `run.ts`, `edit-slot.tsx`). The
siblings were filed as one parallel wave, and each edited the same file. One
pattern worked: TK-138.0 created one empty seam file per later part, and the
conflict on #196 was mechanical to resolve.

## What changed

- `prompts/plan-contract.md` §15: the contract child creates one seam file per
  later child, with a one-line owner comment. A later child edits only its own
  seams and files no sibling lists. A shared list is a registry folder. Two
  children that must edit the same existing file are linked hard
  (`DEPENDS: #<earlier> hard — same file <path>`).
- `bin/run-decompose.sh`: the spec prompt carries that rule ("ONE SEAM FILE
  PER LATER CHILD") and a new optional spec field, `owns` (a JSON array of
  paths). The hard fallback is the existing `after` field, written as
  `"<position>: same file <path>"`, so the filer needs no new field for it.
  The legacy model-filed board prompt carries the same rule in one sentence.
- `bin/lib/file-children.sh` `fc_owns_line`: both filers (`fc-issues.sh`,
  `fc-board.sh`) write `Owns: <path>, <path>` after the footer when the spec
  has `owns`. A spec without `owns` files bodies byte-identical to before. The
  issues lane logs `child <n> declares no owns` for a decompose child without it.
- `bin/decompose-lint.sh` (new): after the filing, `bin/run-decompose.sh` runs
  it over the filed bodies and logs each line to the split's `pipeline.log`:
  `DECOMPOSE_LINT owns-overlap <path> <A> <B>` for two children that own the
  same path (or a directory and a file in it) with no hard link from B to A,
  `DECOMPOSE_LINT no-owns <id>` for a child it could not judge, and
  `DECOMPOSE_LINT ok <n> children` only when it judged every child and found
  no overlap. It never changes the split's result.
- `bin/hub-module-warn.sh` (new): once a day per project (stamp in
  `state/hub-module/<project>.day`, written before the read), it reads the
  pre-plan index and logs `HUB_MODULE <path> <n> tickets (<keys>)` to
  `logs/<project>.log` for each file that exists at HEAD and that 3 or more
  pre-planned tickets plan. `bin/preplan-tick.sh` calls it with `--box` just
  after its lane gate, before the tick's early exits, under `timeout 60`, with
  its output discarded and its rc ignored.
- `bin/decompose-overlap-report.sh` (new): the metric. `before` reads the
  merged PR files of each sibling of the last 20 split parents. `after`
  replays the same parents through the new prompt in dry run (one model call
  per parent, only with `--yes`, and a replay dir with a `children.json` is
  reused).

## Known limits

- On an in-app board that advertises `dependencies`, a sibling-to-sibling
  `after` link rides only in `dependsOn`, not in the body text. The lint reads
  body text, so it can warn on such a pair although the board orders them.
- The `HUB_MODULE` threshold (3) is a code constant from the ticket. The line
  gates nothing.

## Commands

    bin/decompose-lint.sh <id>=<body-file> [<id>=<body-file>...]
    bin/hub-module-warn.sh <project> [--index FILE] [--repo DIR] [--now EPOCH]
    bin/hub-module-warn.sh --box
    bin/decompose-overlap-report.sh before --last 20
    bin/decompose-overlap-report.sh after --last 20 --yes
