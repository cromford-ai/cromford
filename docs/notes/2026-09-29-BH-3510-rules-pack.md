# The rules pack engine: local runner and built-in checks (BH-3510, BH-3477.1)

Doc: test-impact

## Why

BH-3477 exists because merge batches kept dequeuing on the same dozen repo
ratchets (lib-root, alert-writers, jobs-client-modules, the grep-q flake shape,
model id literals, the determinism lint and friends), each one found only by CI
after a build had already pushed. The rules pack runs that set before the push,
in about 20 seconds. BH-3509 shipped the contract as a stub; this change fills
in `bin/rules-pack.sh` and adds `bin/lib/rules-pack-checks.sh` for the two
built-in checks. Nothing calls the pack yet: BH-3513 wires it into the builder
gate. `--runner isolated` still answers 125 until BH-3511 fills in
`bin/lib/rules-pack-snapshot.sh`.

## The pre-existing split

A `delta` component already judges only this diff, so its red is a finding.
A `tree` component judges the whole tree, so when it is red at HEAD the pack
re-runs it once on a tree of the fork (a `git archive` of the merge-base,
committed into a scratch repo). Red there too means main already had it: the
lines go to stderr as `rules-pack: pre-existing: ...` and to
`preexisting.txt`, never to stdout, and the run can still answer rc 0. Green
at the fork means this diff broke it, and it is a finding.

## What could-not-run means

A component that could not run is never green and never red. It is listed in
`summary.json`'s `could_not_run`, and a run where every selected component
could not run answers rc 125. The causes:

- a `needs` binary is not on PATH;
- it timed out at twice the budget (rc 124), or answered 125;
- a `cmd` exited 2 or more, the lints' "could not scan";
- local mode as root beside a live harness without `HARNESS_TEST_SANDBOX=1`:
  `tests/lib/scratch.sh` refuses to start there and the pack never sets that
  variable, so every `suite` component is could-not-run (builtins and cmds
  still run);
- `route-fragments` when `bin/lanes-build.sh --write` cannot render the
  git-ignored `catalog/lanes.json` the worker imports (a `git archive` tree
  never has it, so the pack renders it first);
- in isolated mode, a failed snapshot probe or build: every component.

## Blind spots

- The split is per component, not per line. A tree component that is red on
  main and red on HEAD for a new reason reads as pre-existing.
- Delta ratchets see a renamed file as new, the same blind spot
  `tests/lib/ratchet-delta.sh` documents.
- `rp_model_id_delta` diffs the working tree against the fork, as
  `tests/alert-triage-runners.bh-2544-test.sh` R6 and
  `tests/triage-route-off-grok.bh-3224-test.sh` S7 do. Local mode judges the
  tree as it stands and warns on stderr when a tracked file has uncommitted
  changes.
