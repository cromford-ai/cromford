# Fleet cooldown knobs are settable, the guard is capped at the lane TTL, old tombs are collected (BH-2498)

Doc: DB-COORDINATION-SPEC

Three follow-ups from the r2 review of #2476 (BH-2353). All of them live in `bin/lib/fleet-cooldown.sh` and `catalog/lanes.d/_lib.fleet-cooldown.json`.

- **Settable knobs.** `FLEET_COOLDOWN_DB`, `FLEET_COOLDOWN_CACHE_S` and `FLEET_COOLDOWN_CLEAR_GUARD_S` are now `settable:true`. Their settings keys are `lib.fleet-cooldown.fleet_cooldown_db`, `lib.fleet-cooldown.fleet_cooldown_cache_s` and `lib.fleet-cooldown.fleet_cooldown_clear_guard_s`, so `PUT /api/settings` accepts them. A row outside the registry's min/max is clamped by `lane_knob`. `FLEET_COOLDOWN_STORE` is a path. It stays `settable:false` and a row for it is ignored.
- **Resolve order.** Operator row, then the same row from the box settings cache (`state/settings-cache.json`) when the worker does not answer, then env, then the code default (DB on, 20 s cache, 600 s guard). `_fcd_knobs` runs `lib_env_apply fleet-cooldown` from `bin/lib/lane-gate.sh` in a subshell on the first `fcd_*` call of a process, the same way `bin/lib/lane-caps.sh:_lc_knobs` does. Sourcing the seam still reads, writes and prints nothing. Nothing is exported into the caller. If the read fails (no lane-gate, no registry, no jq, exit 75), the env value is used, so a settings outage never changes behaviour and never reaches a picker running under `set -e`. A row that is not a number falls through to env.
- **Guard cap.** The reseed guard is `min(FLEET_COOLDOWN_CLEAR_GUARD_S, LANE_DOWN_TTL_S)`. `LANE_DOWN_TTL_S` is read from env only: unset, 0 or not a number means 7200, the fallback BH-2359 (#2472) gives it. At the defaults the cap does nothing (600 < 7200). With the TTL below the guard, a re-down after the TTL now shows instead of staying hidden for the rest of the guard.
- **Tomb GC.** Every lane clear first removes each `$HARNESS/state/fleet-cooldown/cleared.lane.*` (else `$H/...`) whose mtime is older than 2x the guard AND whose hide mark (field 3) is past or unreadable. A tomb still hiding a row is kept however old it is, and so is one whose mtime cannot be read. The GC also runs when the guard is 0, so turning the guard off still drains the old tombs. Cache and lock files are never touched. With neither `HARNESS` nor `H` set there is no state dir: the GC globs nothing, removes nothing, and the knobs skip the settings read (env, then default), since `lane-gate.sh` would fall back to `/root/harness`. Every `rm` in the seam ends in `|| true`.
