# BH-8098: the always set is cut to whole-repo reads (slice C1 of #8050)

Doc: TESTING, MERGIFY

Measured on this build box on 2026-10-23, main 8bed51d1 against branch
`ticket/bh-8098`, the same corpus (2,749 suites on main, 2,750 with this
suite). "main" is main's `bin/test-impact.sh` on a main worktree; "branch" is
this branch's script on this tree.

## What changed

- `TI_ALWAYS_AWK` drops a `git -C <X> ls-files`, `--tree <X>` or `find <X>` hit
  when X starts with a variable the suite proves scratch. It reads that
  suite's bindings with `getline`, only for a suite with such a hit.
- `find` matches its root name as a whole identifier: `find "$DEST"` is no
  longer `find "$D"`.
- 8 BH-4551 catalog pins that read no real tree path are deleted.
- One escape-hatch line is added for `tests/generated-not-tracked.bh-5518-test.sh`.
  It lists every tracked file through `git "${g[@]}" ls-files`, which no
  signal sees. On main it was in the set only through a scratch
  `git -C "$S" ls-files` line.
- `catalog/test-impact-always-prepush.txt` loses the 27 lines that left the
  always set (65 to 38).
- Env `TI_ALWAYS_NARROW=0` is the detector before BH-8098. `inputs` (the
  suite fingerprint) always builds with it, so no fingerprint moves for the
  detector suites.

## Real-tree reads in the removed suites

After the build, every removed detector suite was read for a line that runs
a checker on the real checkout. Three have one:

- `tests/tier-wording-lint.bh-4582-test.sh` L4 runs
  `bin/lint-tier-wording.sh --all` on the checkout.
- `tests/agent-call-no-tools-lint.bh-7276-test.sh` N15 lints the checkout's
  diff against origin/main.
- `tests/discipline-dupes.bh-5788-test.sh` D2 checks
  `prompts/build-discipline.md` only, a scoped read.

The first two lints are `delta` components of the rules pack
(`catalog/rules-pack.tsv`), and the rules pack runs on every PR
(`bin/fast-lints.sh`), so a PR that adds a finding is still red. The suites
still run when their own map rows change.
