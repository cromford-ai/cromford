# BH-7836: the rebuild-fresh rung releases the malformed-plan hold

Doc: BLOCKED-RESOLVER

What changed:

- New fragment `bin/blocked-resolver.d/bh-7836-pm-release.sh` defines
  `br_pm_release <p> <rkey> <reason> <tkey>`.
- `br_rebuild_fresh` in `bin/blocked-resolver.sh` calls it once, after the
  observe-mode return and `br_head_gate`, and before `br_close_pr`.
- When the ticket's last `state/plan-malformed.txt` row (field 3) or its
  `plan_malformed` ledger row says `held` or `skipped`, the resolver appends
  `<p> <key> released <ISO stamp> blocked-resolver:<rkey>` to the file and
  writes `job_ledger_put plan_malformed "<p> <key>" released`. Then the rung
  closes the PR and enqueues the rebuild as before.
- If the file append or the ledger put fails, the rung is deferred: nothing
  closed, nothing enqueued, no counter spent. The park is offered again on the
  next tick.
- Off switch: `BR_OPT_OFF=bh-7836-pm-release`.

Why: the rebuild that the rung bought reached the hold gate in
`bin/lib/rb/plan.sh`, logged `PLAN skipped`, and exited 4. The resolver read
PLAN_MALFORMED again and spent the next rung. TK-1163 spent three rungs this
way and went ABANDONED. A `released` row is the hold's documented way out
(last row wins). A later malformed plan still holds the ticket again, so the
hold still limits plan sessions.

Tests: `tests/blocked-resolver-pm-release.bh-7836-test.sh`.
