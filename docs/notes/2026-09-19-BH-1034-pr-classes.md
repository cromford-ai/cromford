# The first two wake classes: `pr-closed` and `pr-ci`

Doc: EVENTS

**What changed.** BH-1059 shipped the wake-class contract and wired no class to
it. This is the first pair of classes that plug into that loader, plus the
backstop paste in the six lanes they launch.

- **NEW `bin/lib/wake-class-pr-closed.sh`.** `wc_pr_closed_row` sets one bit
  when a `pr` row carries the event `pull_request.closed`, and nothing on any
  other action, on a bare `pull_request`, on a `-`, or on any other kind.
  `wc_pr_closed_dispatch` launches the three hub-wide lanes a closure gives new
  work to, then clears the bit.
- **NEW `bin/lib/wake-class-pr-ci.sh`.** `wc_pr_ci_row` collects the project of
  every `checks` row and of every `pr` row whose action is `opened`,
  `synchronize`, `reopened` or `ready_for_review`, deduped; separately it sets a
  snapshot bit for any `pr` or `issue` row, which is why `pull_request.closed`
  reaches this class as a snapshot and never as a review.
  `wc_pr_ci_dispatch` sends `review-prs` to the box `bin/box-for.sh` names,
  launches `review-autopilot` once, launches the ticket snapshot when the bit is
  set, then clears both accumulators.
- **The backstop paste in six lanes.** Three lines after each lane's own lock,
  sourcing `bin/lib/wake-lanes.sh` and calling `wake_backstop_skip <lane>
  <project>` on the lib's own 1800s default window. A cron tick that fires
  within 1800s of a wake launch of the same lane stands down; anything unclear
  runs.

**The two classes, row by row.**

| Class | Row it matches | Lanes it launches | Machine | Cooldown | Class flag | Backstop window |
|---|---|---|---|---|---|---|
| `pr-closed` | `pr` + `pull_request.closed` | `bin/reconcile-prs.sh` | hub | 120s | `wake-lanes-pr-closed` | 1800s |
| `pr-closed` | `pr` + `pull_request.closed` | `bin/check-migration-prs.sh` | hub | 120s | `wake-lanes-pr-closed` | 1800s |
| `pr-closed` | `pr` + `pull_request.closed` | `bin/alerts-groom.sh` | hub | 300s | `wake-lanes-pr-closed` | 1800s |
| `pr-ci` | every `checks` row, and `pr` + `pull_request.{opened,synchronize,reopened,ready_for_review}` | `bin/review-prs.sh <project>` | the owning box (`bin/box-for.sh`), over ssh with `WAKE_LAUNCH=1` | 120s per project | `wake-lanes-pr-ci` | 1800s |
| `pr-ci` | the same rows, once per drain | `bin/review-autopilot.sh` | hub | 3600s | `wake-lanes-pr-ci` | 1800s |
| `pr-ci` | any `pr` or `issue` row | `bin/tickets-snapshot-push.sh` | hub | 300s | `wake-lanes-pr-ci` | 1800s |

**One flag per class, and it arms both halves.** `bin/lib/wake-lanes.sh` keys
the backstop on the CLASS a lane belongs to (`wake_class_of`), not on the lane:
`wake-lanes-pr-closed` covers `reconcile-prs`, `check-migration-prs` and
`alerts-groom`, `wake-lanes-pr-ci` covers `review-prs`, `review-autopilot` and
`tickets-snapshot-push`. So one flip both launches those lanes on a wake and
lets their next cron tick stand down; a lane-keyed flag file arms nothing
(`tests/wake-lanes-lib.bh-1034-test.sh` asserts that). `flags/wake-lanes-off`
beats the class flag — with that file present no class hook runs and every
backstop falls open.

**What is inert until an operator acts.** Nothing in this change flips a flag.
Until `wake-lanes-pr-closed` and `wake-lanes-pr-ci` are set the loop's
`CLASS_ON` is 0 for both classes, neither hook is ever called, and every pasted
backstop falls open, so all six lanes keep today's cron cadence byte for byte.
The operator steps are:

```
bin/jobs-client.sh flag-set wake-lanes-pr-closed on "BH-1034"
bin/jobs-client.sh flag-set wake-lanes-pr-ci on "BH-1034"
```

**The window is one knob, and it is the contract's.** No paste here pins its
own window: each calls `wake_backstop_skip <lane> <project>` and lets
`bin/lib/wake-lanes.sh` apply `${WAKE_BACKSTOP_S:-1800}`. So `WAKE_BACKSTOP_S`
in `env/global.env` moves all six lanes at once, there is no second env name
for the same dial, and no lane script gains a knob the lanes registry would
have to carry.

**What this does not change.** `bin/review-prs.sh`'s CI debounce is untouched:
the wake only makes its first CI read happen sooner, and its reviewed-sha ledger
still decides what it spends. `bin/tickets-snapshot-push.sh` stays hub-side,
because it holds the board tokens. `bin/wake-loop.sh`, `bin/lib/wake-lanes.sh`
and the webhook receiver are not edited here. The merge conductor and the merge
sweep are neither launched nor throttled by these classes.

**Cost shape.** `cooled` writes its stamp on the same call that grants a launch,
so a drain with fifty closed PRs buys one `reconcile-prs` run, not fifty. A
launch that fails to exec leaves the cooldown taken and no run, which costs one
window of delay and never a lost run, because every one of these lanes still has
its cron line.

**Proof.** `tests/wake-pr-closed-drives-lanes.bh-1034-test.sh` and
`tests/wake-ci-drives-review.bh-1034-test.sh` drive both classes through the
real `bin/wake-loop.sh`, and their second halves drive the real
`bin/reconcile-prs.sh` and `bin/tickets-snapshot-push.sh` across the backstop
truth table (fresh stamp, stale stamp, flag off, `WAKE_LAUNCH=1` re-stamp, env
window override).
