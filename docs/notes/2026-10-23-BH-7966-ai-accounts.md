# AI accounts: rows, routes, the add sheet, the fleet table and the project choice (BH-7966, BH-7937.2)

Doc: DB-COORDINATION-SPEC

## What changed

This is the third slice of BH-7937 (onboarding UI wave 4). An operator can now
add an AI account from Mission Control, see every account on the fleet, and
choose which account a project bills. The token never reaches the jobs worker
in plain text: the browser seals it to the hub's public key and sends only the
ciphertext as a BH-7964 envelope.

- **Table** (`worker/jobs/schema.d/202610232044-bh-7966-ai-accounts.sql`):
  `ai_accounts` (id, vendor, label, plan, use_kind, envelope_id, created_by,
  created_at, revoked_at). There is no token column and no state column.
  Indexes: `ux_ai_accounts_vendor_label` (unique) and `ix_ai_accounts_label`.
  Rows are operator history and are never deleted; revoke stamps `revoked_at`,
  and a revoked label stays taken.
- **Settings rows** (knobs, BH-7945): `ai_accounts_list_limit` = `500` (1..5000,
  else 500), `ai_account_status_poll_s` = `3` (1..60, else 3) and
  `ai_account_status_wait_s` = `90` (5..900, else 90).
- **Jobs routes** (`worker/jobs/src/routes/ai-accounts.js`, main bearer, the
  seam BH-7964 left empty):
  - `GET /api/ai-accounts`: one `db.batch` of 5 reads. Each row has
    `projects` (the `account.<project>` pins that hold its label), `today`
    (`cost_rows.auth_account` since 00:00Z of the request day), `boxes` (distinct
    `registry_box_accounts` login boxes, `null` when none reported) and `state`.
    The answer is `{accounts, limit, truncated}`.
  - `POST /api/ai-accounts {vendor, label, plan, use_kind, envelope_id}`: 400 on
    a bad field or a label that looks like a token, 400 when the envelope's
    `stored` scope is not exactly `ai-account:<vendor>:<label>:<use_kind>[:<project>]`,
    409 when the (vendor, label) exists (revoked too). 200 `{id, state:'pending'}`.
  - `POST /api/ai-accounts/:id/revoke`: stamps once; a repeat is `{already:true}`.
  - `GET /api/secrets/envelope/:id/status`: `{state}` from the newest event
    (`pending`, `consumed`, `applied`, `apply_failed`, `expired`). Never the
    ciphertext or the scope.
- **State** is the newest `secret_envelope_events` row of the account's
  envelope: stored or consumed = `pending`, applied = `active`, apply_failed =
  `failed`, expired = `expired`, no event = `unknown`; `revoked` wins. Only the
  hub apply (BH-7937.1, PR #8149) writes `applied`, so until it lands every new
  account shows `pending`.
- **Console**: `ACCOUNTS ON THE FLEET` on the Settings hub tab, under
  `PROJECT ACCOUNTS`. `+ ADD ACCOUNT` and `ROTATE` open the add sheet. The sheet
  reads the settings once per page load, seals with WebCrypto RSA-OAEP SHA-256
  (`console-ui/src/lib/envelope.js`), posts the envelope, posts the account,
  clears the token, then polls the status every `ai_account_status_poll_s` for
  at most `ai_account_status_wait_s` and says PROVED, FAILED or STILL WAITING.
  With an empty `hub_envelope_public_key` it says the hub key is not set and
  sends nothing. Rotate adds a new label and revokes the old one only after the
  new one saved. Each PROJECT ACCOUNTS row has `CHOOSE…`: the fleet pool, an
  active account, or the project's own new account; the pin goes through the
  existing confirm and `PUT /api/settings`.
- **Console proxy rows** (`console-ui/functions/_lib/coord-writes.d/7966-ai-accounts.js`):
  `POST secrets/envelope`, `POST ai-accounts` (created_by stamped as
  `console:<actor>`) and `POST ai-accounts/<uuid>/revoke`. No row forwards the
  hub token, so the console can store an envelope and never read one back.

## Why

The fleet runs more than one AI vendor, and each project may bill its own
account. The token must reach the boxes without passing through the worker,
the console or a log in plain text.

## Rules and commands it touches

- The label rule for a new account is the hub consumer's rule (PR #8149
  `bin/lib/envelope.sh`): `^[a-z0-9._@-]{1,48}$`, no `..`, no leading `.`, not
  `sk-` / `sk_` / `xai-` / `fw_` / `or-` in any case, and not `shared`.
- The hub key comes from `bin/envelope-keygen.sh` on the hub (BH-7937.1).
- Verify: `HARNESS_TEST_SANDBOX=1 bash tests/ai-accounts.bh-7966-test.sh`;
  `npm run build && node tests/drive/ai-accounts.bh-7966-drive.mjs --shots <dir>`
  in `console-ui` (prints `SKIP: no chromium` where playwright is absent).
