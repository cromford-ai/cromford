# BH-9586: rule U14-MERGED settles an ejected ticket whose PR merged

Doc: PR_UNBLOCK_AGENT_PLAN

## The gap

BH-9460 sat in phase `ejected` for 1409 minutes after its PR #9508 merged, and
the `merge-queue` label stayed on the PR. No unblock rule matched it:
U14-REQUEUE takes only an open, unmerged PR, so the ticket fell to the U12
card. The worker also refused the move: `ejected -> merged` was not a legal
transition, so no actor could settle the ticket.

## What changed

- `worker/jobs/src/lib/lifecycle.js`: `ejected` may now move to `merged`. The
  owner is `lifecycle` (the re-entry rule). The conductor's own move from
  `ejected` now answers `wrong_owner` instead of `illegal_transition`.
- `bin/lib/unblock/collectors/lifecycle.sh`: the ejected record carries
  `merge_sha` (the pull's `merge_commit_sha`, 40 hex, else null) and
  `base_ref` (the pull's `base.ref`, else null). 0 new reads.
- `catalog/unblock-rules.d/U14-MERGED.json` (priority 139, class
  `lifecycle-settle`): kind `ticket-ejected`, PR `closed`, `merged == true`,
  head, merge sha and base ref known. A null field never matches.
- `bin/lib/unblock/act.sh` action `settle_merged {ticket_key, merge_sha,
  base_ref}`, in this order:
  1. Re-read the PR. It must still be merged, with the same merge sha and base.
  2. GitHub compare `<merge_sha>...<base_ref>` must answer `identical` or
     `ahead`. `behind` or `diverged` is `refused merge-sha-not-on-base:<status>`.
  3. `lifecycle_transition <p> <key> merged lifecycle`. A 409 whose current is
     `merged` counts as done. A 409 `illegal_transition` from `ejected` is
     `refused phase-illegal` (the worker is not deployed yet).
  4. If the fresh PR has the `MC_MERGIFY_LABEL` label (default `merge-queue`),
     DELETE it through `prr_write`. A failed DELETE is
     `failed label-remove-failed after phase merged`.

## Deploy order

Deploy the jobs worker first. Until then, the rule answers
`refused phase-illegal` and writes nothing. Shadow mode answers
`would WOULD_SETTLE_MERGED`.

## First case

BH-9460 (PR #9508, head 428b6712) is still ejected. The first unblock tick
after the deploy settles it. Nothing is settled by hand in this change.

`worker/jobs/test/ticket-lifecycle-merged.bh-9586.test.js`.
