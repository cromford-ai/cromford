# BH-6025: size gate fallbacks move to 1200 lines / 30 files

Doc: OPERATING, RUN-BUILD-GRAPH

## Why

`bin/split-chain-report.sh --days 14` ran on 2026-10-11 (window 2026-09-27 to
2026-10-11). Split tickets: n=82, median lead 30.9h. Unsplit tickets: n=243,
median lead 4h. Merged split children (n=350) had p90 578 product lines and p90
10 files. The report proposed 1200/30 (BH-5520).

On 2026-10-14 the operator set the hub rows `size_gate.lines` = 1200 and
`size_gate.files` = 30 by hand on /config. The code fallbacks and the
fresh-install seed still said 700/20. A box with no worker, no cache, a corrupt
cache or `LANE_GATE_DISABLE=1`, and a fresh settings table, got the old numbers.

## What changed

- `bin/size-threshold.sh`: `DEF_LINES=1200`, `DEF_FILES=30` (resolution step 5,
  the documented fallback of the two rows).
- The junk-value guards and default args move to 1200/30 in `bin/size-gate.sh`,
  `bin/run-decompose.sh`, `bin/lib/rb/plan.sh` (`# >>> size threshold call`) and
  `bin/lib/rb/pr.sh` (the diff size note).
- `worker/jobs/schema.d/0001-bh-4985-size-gate.sql`: the seed values are now
  `'1200'` and `'30'`. The statement stays `INSERT OR IGNORE`, so the hub rows
  and any operator edit are not touched on re-apply.
  The VALUES are edited in place, not added as a new statement (the operator's
  comment 6173075132 asked for "a new statement or migration"). The reason:
  `bin/schema-build.sh` sorts fragments by name, so a new fragment applies
  after this one. On a fresh table this statement inserts first, and a later
  `INSERT OR IGNORE` of 1200/30 is ignored. An `UPDATE` is refused by
  `tests/schema-additive.bh-1000-test.sh`. Only an edit in place gives a fresh
  table 1200/30.
- Comments and docs that stated the default: `catalog/size-thresholds.conf`,
  `prompts/plan-contract.md`, `docs/OPERATING.md`, `docs/RUN-BUILD-GRAPH.md`,
  `bin/share/overlay/AGENTS.md`, `bin/share/overlay/CONTRIBUTING.md`, the
  hotfix seed comment.
- Tolerance band (15%): the gate now trips at 1380 lines / 34 files.

## What did not change

- The hub: its rows already answer 1200/30 and outrank every fallback.
- Per-project rows `size_gate.<axis>.<project>` and the hotfix tier (1500/30).
- The resolution order.

  `tests/size-gate-test.sh`, `tests/size-threshold-settings.bh-4985-test.sh`,
  `tests/size-threshold-hotfix-tier.size-hotfix-test.sh`.
