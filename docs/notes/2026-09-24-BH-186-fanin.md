# The merge conductor and reconcile-prs account for every PR they enumerate

Doc: MERGE-CONDUCTOR

## What changed

BH-186. Two lanes now check that every PR they enumerate comes out with exactly
one accounted outcome: `bin/merge-conductor.sh` (the per-PR worker fan-out in
`tick_project`) and `bin/reconcile-prs.sh` (the per-row loop over the console's
unmerged list). If a run enumerated more than it accounted, it says so. The
ticket first named `bin/merge-sweep.sh`. That lane no longer runs on cron, so
the 2026-09-24 scope note moved the check to these two, the lanes that start PR
work now. merge-sweep is not wired.

- **One lib, `bin/lib/fanin.sh`.** Each run keeps a scratch ledger at
  `state/fanin/<lane>/<scope>.<pid>`: one `E <id>` line per enumerated PR and
  one `A <id> <outcome>` line per accounted one. The per-PR body only ever runs
  inside `fanin_run` (reconcile-prs, same shell) or `fanin_run_sub` (the
  conductor, a nested subshell). The wrapper writes the `A` line after the body
  returns, so every `return` is accounted without bookkeeping at each one.
- **What it catches.** A body that `exit`s the lane, or a worker or tick that is
  SIGKILLed, writes no `A` line. `fanin_end` names those ids as `missing:`. If
  the whole run died, the next run of the same lane and scope finds the dead
  ledger (its pid is gone), alerts once with `(run died before fan-in)` and
  deletes it. A dead ledger that is fully accounted is deleted silently.
- **Outcomes.** Conductor: `skipped:draft`, `skipped:unverifiable`, otherwise
  the PR's `pr-state.tsv` state after its worker (`skipped:no-row` when it has
  none), plus ` rc=N` on a non-zero status. reconcile-prs: `merged`, `closed`,
  `skipped:open`, `skipped:unread`, `skipped:no-url`,
  `skipped:closed-unsettled`, `merged:no-project`, `merged:no-slug`. A return
  that sets no outcome is still accounted, as `unlabelled`.
- **reconcile-prs body.** The loop body is now `rcr_one_pr`. Its former
  `continue`s are `return 0` with an outcome set. It must hold no `continue`,
  `break` or `exit`.

## What an operator sees

- `logs/merge-conductor.log`: one
  `FANIN merge-conductor <slug>: enumerated N accounted M (<outcome> <n>, …)`
  line per project tick that listed PRs.
- `logs/reconcile.log`: one `FANIN reconcile-prs fleet: …` line per tick whose
  console list was not empty.
- On a mismatch: one
  `ALERT FANIN <lane> <scope>: enumerated N accounted M missing: <id>… [double: <id>…]`
  through `bin/lane-alert.sh --severity warn`. If the lane-alert script is
  absent, the line is appended to `logs/ALERTS.log`. A healthy run and an empty
  run send nothing.

A box without `bin/lib/fanin.sh` runs both lanes exactly as before: no-op
fallbacks, no ledger. Suite: `tests/fanin.bh-186-test.sh`.
