# web-task sign-in step on an allow-listed site (BH-8226, slice C0)

Doc: DB-COORDINATION-SPEC

## What changed

This slice follows `docs/notes/2026-10-23-BH-7891-type-secret.md` (the
`type_secret` action `createTypeSecret`). It adds the sign-in step of the
web-task lane as a module. The web-task agent does not call it yet: the agent
loop (S1, #7594, PR #7650) is not on main, so slice C1 of #8226 wires it in.

- `bin/lib/web-signin-step.mjs`: `createSignIn({ site, allowed, secrets,
  selectors, timeoutS, maxAttempts })` returns `{ signIn, attempts }`. One
  instance per agent run. `secrets` is the run's one `createTypeSecret`
  instance, so its redact set and mask list cover the sign-in. Each
  `signIn(page)` call:
  1. Past the attempt cap: `refused: sign-in refused (attempt cap <n>)`,
     terminal. No vault read, no fill.
  2. The host gate on `page.url()`: `https:` (or `http:` only on `127.0.0.1`,
     `localhost` or `::1`), no userinfo, the host (lower-case, trailing dot
     stripped) equals the run's vault site exactly, and the site is an entry
     of the allow-list. A subdomain or another listed host is refused. Else
     `refused: sign-in not allowed on <host>`, not terminal, no read, no
     attempt used.
  3. Finds the password input and a username input (default selectors, or
     the `selectors` overrides). Neither: `error: no sign-in form on <host>`,
     no attempt used.
  4. Counts the attempt. Types the username, then the password, through
     `typeSecret` (vault fields `username` and `password`). A two-step form
     (username first) is submitted once before the password page.
  5. Submits: clicks the submit control, else presses Enter on the password
     input. Waits for `load`.
  6. No password input left on the page and the page still on the run site:
     `ok: signed in (<host>)`. A form still there: `error: sign-in failed
     (the sign-in form is still on the page)`. A page on another host:
     `error: sign-in failed (the page left <site> for <host>)`, never ok.
  The host gate runs again before each `typeSecret` and inside its fill,
  after the vault read. A page that left the run site (a two-step submit to
  another host, a JS redirect) gets no value typed (review D14).
  The host gate also runs on the submit target: the action of the field's
  form before each `typeSecret`, and the submit control's `formaction` (else
  its form's action) before the click. A form that posts off the run site
  gets `refused: sign-in not allowed on <host>`: no value is typed into it
  and no request goes to that host (BH-8226 lead review).
- Other outcomes: a non-ok `type_secret` outcome is returned as is, with its
  terminal flag. `error: sign-in failed (no password field after the username
  step)`. `error: sign-in timed out after <n>s` (a `TimeoutError`).
  `error: sign-in failed (<message>)` (another submit or wait throw). Every
  outcome goes through `secrets.redact`. The step never logs.
- Knobs (`catalog/lanes.d/_lib.web-signin.json`, lib id `web-signin`):
  - `WEB_TASK_SIGNIN_TIMEOUT_S` (settings row
    `lib.web-signin.web_task_signin_timeout_s`): default 20, range 5..120.
  - `WEB_TASK_SIGNIN_ATTEMPTS` (settings row
    `lib.web-signin.web_task_signin_attempts`): default 1, range 1..3. A
    second wrong password can lock a real account.
  - A bad value makes `createSignIn` throw `web-signin: bad <ENV>`. It is
    never clamped.
- `tests/lib/web-signin-site.bh-8226.mjs`: a fixture sign-in site on
  127.0.0.1 (one-page form, two-step form, a page with no form). It reads its
  credentials from a mode-600 file and logs method and path only.
- `tests/web-signin-step.bh-8226-test.sh`: the gate table, the sign-in paths
  on a fake page, the knobs, and an e2e that signs in on the fixture site
  through the default `wv_read` provider and the jobs worker fake. No fixture
  password is in any log, result, stdout, stderr or child argv.
