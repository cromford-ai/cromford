# Mission Control flag columns and toggles (BH-5635.4)

Doc: DB-COORDINATION-SPEC

## What changed

- The coord proxy (`console-ui/functions/api/coord/[[path]].js`) admits `value`
  on `PUT flags`. It still stamps the actor and drops every other key.
- `api.setFlag(name, active, value, reason)` writes one flag row. It sends
  `value` as a string, and no `value` key when there is none. The proxy stamps
  the actor. `api.routingAll()` reads every `routing` row (`GET /api/routing`).
- New `console-ui/src/lib/flagrows.js`. `shapeProjectFlags` makes one
  `{ paused, wip, route }` per project. Each cell is a value, `false` (readable,
  none) or `null` (not readable). `null` shows "—". It never shows "off".
- The Fleet PROJECTS table on `/` has three new sortable columns after FLAGS:
  - PAUSED: the `paused-<p>` row. PAUSE or RESUME opens the in-app modal and
    needs a typed reason. Then one PUT, then a re-read of the flags.
  - WIP: the `wip-limit-<p>` value. A number input (1..9999) and SAVE write
    `active 1` with the value. A bad number is refused with no request.
  - ROUTE: the `routing` row, as text. It links to `/p/<p>`, where the ROUTING
    section shows RoutingPanel.
  - The FLAGS column (box-file PAUSED and the BH-1672 pause rows) is unchanged.
- The `/config` FLAGS table has a VALUE column.

## Why the console reads what it reads

- The worker contract was already on main (BH-5635.0): `PUT /api/flags` takes
  an optional `value`, `GET /api/flags` returns it, and `GET /api/routing`
  returns every row. This slice touches no worker code.
- A failed flags read, a payload with no `flags` list, a row whose `active` is
  not 0 or 1, and a payload of 500 rows or more (the worker's LIMIT) are all
  "not readable". A full page cannot prove that a row is absent, so the cell
  shows "—" and not a guessed "off". The routing read uses the same 500 rule.
- An active `wip-limit-<p>` row whose value is not a whole number shows "—".
  The console does not invent a number.
- The cell never changes on a click. It shows only the re-read after the PUT.
  A PUT that fails shows the worker's error, and the re-read still runs.
- One flag write at a time. The latch covers the dialog and the PUT, so a
  double click sends one request.

## Decisions taken without a ticket answer

- The tests are in `console-ui/tests/` (`npm test` runs only that directory),
  named for this ticket. The ticket named `console-ui/test/...bh-5635.test.js`.
- PAUSE and RESUME need a typed reason (`PauseReasonForm`, the BH-2509 rule).
- The PAUSED button works both ways: PAUSE when off, RESUME when on.
- WIP SAVE always writes `active 1`. To clear a limit, use TURN OFF on `/config`.
- ROUTE is a link to `/p/<p>`. It does not open RoutingPanel on `/`.
- `tests/fleet-flag-columns.bh-5643-test.sh` names the new lib by path for the
  orphan check (D41) and runs both node suites.
