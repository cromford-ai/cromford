# Scheduled D1 retention (BH-6750, slice 2 of BH-6727)

Doc: OPERATING

## The gap

The harness-jobs D1 kept every row for ever in its busiest tables. On
2026-10-14 it read 100-160M rows an hour and answered "overloaded" 875 times in
5 hours (BH-6727). The only cleanup was the wakes prune in
`bin/doorbell-coverage-check.sh`: once a day, at most 5,000 rows, below the
webhook inflow, so `wakes` never drained.

## What changed

- `POST /api/retention/run` (`worker/jobs/src/routes/retention.js`) runs six
  rules. Each reads the eligible ids oldest first through an index, deletes
  them by id in batches of `retention.batch` (500), stops at
  `retention.max_rows` (5,000) per rule, and writes one `retention_runs` row.

| Rule | Removes | Window (settings row, default) |
|---|---|---|
| `wakes.age` | any wake older than the window | `retention.wakes.days` (30) |
| `wakes.acked` | an acked wake older than the window | `retention.wakes.acked_days` (3) |
| `job_heartbeats.closed` | the beat of a job that is not running, or has no jobs row | `retention.job_heartbeats.days` (30) |
| `stage_events.closed` | events of a job that is not running; summed into `stage_events_daily` in the same D1 batch first | `retention.stage_events.days` (90) |
| `lane_ticks.stale` | a (lane, project, box) with no tick in the window: a retired lane or box | `retention.lane_ticks.days` (30) |
| `retention_runs.age` | this table's own audit rows | `retention.retention_runs.days` (90) |

- `cost_rows` and `ledgers` carry money and history. No rule touches them.
  Archiving them is a later slice.
- `retention.dry_run` is seeded `1`: a run counts (capped at
  `retention.count_cap`) and writes the audit rows, and deletes nothing. Read a
  dry run, then set the row to `0`.
- `lane_ticks` is a state table (one row per lane, project and box), not an
  event log, so it has no daily summary. A stale row is a lane or box that no
  longer runs.
- The hub lane `bin/d1-retention.sh` calls the route every hour at :41
  (`cron/lanes/731-d1-retention.cron`). Hourly, because a run is bounded: a
  backlog drains in steps instead of one burst.
- New indexes: `stage_events(created_at)` and `lane_ticks(last_tick_at)` serve
  the cutoff reads; `retention_runs` has `(rule, started_at)` and
  `(started_at)`.

## Operate

- Read the last dry run: `logs/d1-retention.log` on the hub, or
  `SELECT * FROM retention_runs ORDER BY id DESC LIMIT 6`.
- Turn deletes on: settings row `retention.dry_run` = `0`.
- Turn one rule off: its window row = `0`.
- Stop the lane: `bin/harness-ctl.sh off d1-retention`.
- The doorbell wakes prune still runs. It is now redundant and can be removed
  after the first real retention runs.
