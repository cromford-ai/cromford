# PyYAML is on every machine the corpus runs on, and missing it is red in CI

Doc: CI-RUNNERS, REMOTE-GATE

## What was wrong

The mergify-template suites parse YAML with python3 + PyYAML. Neither the bh-ci
runner image nor the test host image had it, so
`tests/hotfix-mergify-template-test.sh` printed `python3 PyYAML missing —
skipping` and exited 0. CI read that as green for YAML assertions that never ran.

Separately, G9 in `tests/test-impact-gate.bh-1524-test.sh` checked a two-second
budget against a suite that slept three seconds on the real clock, so a loaded
runner could spend the budget early and fail it.

## What it does now

- `bin/ci-tool-present.sh --python-module <name>` answers "can python3 import
  this?": rc 0 yes, rc 1 no (or no python3), rc 2 misuse, including a name that
  is not a dotted python identifier.
- `decisions-shard` and `harness-safety-shard` install `python3-yaml` behind
  that guard and then run it unguarded, before the suite and trace steps.
- `fly/Dockerfile` and `fly/testhost/Dockerfile` install `python3-yaml`.
- `tests/hotfix-mergify-template-test.sh` fails with exit 1 under `CI=true` when
  PyYAML is missing, and still skips outside CI.
- G9 runs the gate on a stub `date +%s` that only the slow fixture advances, so
  the budget cut-off is exact. G9b moves it by less and checks the last suite
  starts.

## Still owed

The test host image has to be rebuilt and redeployed (docs/REMOTE-GATE.md,
"Deploying the test host image"). The bh-ci runner image is built outside this
repo, and until it bakes PyYAML the job-time install covers it.
