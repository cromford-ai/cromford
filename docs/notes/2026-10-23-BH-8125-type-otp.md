# web-task type_otp action and its retry rule (BH-8125, slice C0)

Doc: DB-COORDINATION-SPEC

## What changed

This slice follows `docs/notes/2026-10-22-BH-7596-web-totp.md` (the TOTP
generator and the vault provider `wt_totp_code`). It adds the behavior of the
`type_otp()` tool action as a module. The web-task agent does not call it yet:
slice C1 of #8125 wires it into the agent loop.

- `bin/lib/web-otp-action.mjs`: `createTypeOtp({ project, site, codeFor,
  stepFor, sleep, now, maxAttempts })` returns `async typeOtp(fill)`. One
  instance per agent run. Each call:
  1. Past the attempt cap: `refused: otp refused`, terminal. No vault read.
  2. Reads the site's step once per instance (`wt_totp_step`).
  3. On a retry in the same TOTP window as the last typed code, waits for the
     next window (`secondsToNextStep` of `bin/lib/totp.mjs`).
  4. Makes the code after the wait (`wt_totp_code`). A reply that is not 6-10
     digits is a failure.
  5. Gives the code to `fill(code)` and counts the attempt.
- Outcomes (the text the model sees, never the code or the secret):
  - `ok: otp typed (attempt <n> of <cap>)`, not terminal.
  - `refused: otp refused`, terminal.
  - `error: otp unavailable (<provider line>)`, terminal. No fill, no attempt
    used. A retry cannot fix a missing secret or a vault refusal.
  - `error: otp fill failed (<message>)`, not terminal. The attempt is used.
    The code and every digit run of 6 or more in the message are masked.
- Every call after a typed one is a retry of a refused code. The site shows
  the refusal on its page, and the model calls `type_otp` again.
- `bin/lib/web-totp.sh`: new `wt_totp_step <project> <site>`. It prints the
  vault field `totp_step`, or 30 when the site has no row. A stored value that
  is not an integer >= 1 is rc 2 `web-totp: bad totp_step`. `wt_totp_code`
  does not change.
- Knob `WEB_TASK_OTP_ATTEMPTS` (`catalog/lanes.d/_lib.web-otp.json`, settings
  row `lib.web-otp.web_task_otp_attempts`): default 2 (the first try plus one
  retry), range 1..5. A bad value makes `createTypeOtp` throw
  `web-otp: bad WEB_TASK_OTP_ATTEMPTS`. It is never clamped.
