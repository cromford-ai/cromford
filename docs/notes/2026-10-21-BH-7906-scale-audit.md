# Scale envelope audit of the harness itself (BH-7906)

Doc: docs/scale/ENVELOPES.md, docs/scale/LANDMINES.md, docs/scale/baseline.json, docs/scale/inventory.tsv

## What changed

- `docs/scale/ENVELOPES.md`: one block per load path (9 vendors, 5 poll
  loops, the cron lanes, the D1 tables, 2 fan-out blocks, 2 human-rate
  blocks), plus a row for each of the 186 lane ids, 206 D1 tables and 28 vendor
  seam files.
- `docs/scale/inventory.tsv`: the frozen list of lanes, tables and seams the
  audit covers (as_of 2026-10-21, base 8a1d9bc7c4ad).
- `docs/scale/baseline.json`: the measured `NOW` numbers as data.
- `docs/scale/LANDMINES.md`: 2 paths that break at or below 10x, each with a
  skipped test in `tests/scale-landmines.bh-7906-test.sh`.
- `tests/lib/scale.sh`: `scale_wrap` (counts calls and peak concurrency) and
  `scale_fake_gate` (the `SCALE_FAKE_LATENCY_MS` and
  `SCALE_FAKE_RATE_LIMIT_EVERY` knobs).
- The knobs are in three shared fakes: `tests/lib/gh-rest-stub.sh` (GitHub),
  `tests/lib/fake-jobs-attempts.bh-4156.sh` (jobs worker) and
  `tests/lib/pool-reap-fixture.sh` `write_fly_stub` (flyctl). With both knobs
  unset the hook does not run and each fake answers the same bytes as before.

No production code changed. No lane, script, schema or console file changed.

## What was measured (source, date)

- Cron lane runs/day for every lane, from the `cadence` and `boxes` fields of
  `catalog/lanes.d/*.json`, counted over the 2026 calendar: 138,346 runs/day on
  all boxes, 29,858 on the hub (2026-10-21).
- The overlap guard of each lane, from its script: 185 of 186 call
  `lane_gate_or_exit` (single run per lane and project, BH-7422); `orc-monitor`
  shows none.
- Indexes and retention for every D1 table, from `worker/jobs/schema.d/` and
  `worker/jobs/src/routes/retention.js`: 137 of 206 have a named index, 36
  have a retention rule, 144 have neither a rule nor a `DELETE` in the worker.
- PR merges and tickets shipped, from `git log origin/main --first-parent`
  over 2026-10-14..2026-10-20 UTC: 333 PR merges (47.57 a day), 294 distinct
  `ticket/bh-*` branches (42 a day), 1.13 PRs per ticket.
- GitHub REST load: 5,700 calls/h against a 6,600/h bucket, as recorded in the
  `bin/lib/gh-rest-ledger.sh` header (2026-09-22).
- D1 overload: 875 "overloaded" answers in 5 h, as recorded in `CLAUDE.md`
  and `retention.js` (2026-10-14).

The tables were generated at build time by a script kept in the build
directory (`gen-scale.py`), not in the repo. A later audit can regenerate them
the same way; this one is a snapshot.

## What could not be measured, and why

- Every live D1 count (rows/day per table, lane durations from `lane_runs`,
  builds in flight from pool state). The build box is a pool machine. Its
  egress proxy denied `harness-jobs.operator.workers.dev:443` on each try
  (`transport rc=56` in `logs/jobs-client.log`, 2026-10-21 22:39Z).
- Every GitHub read (the current `rate_limit`, GraphQL points, issue counts,
  Actions runs): `gh api rate_limit` answered `Forbidden` from the proxy.
- Model and Fly dollars per day: the cost ledger (`state/cost/` from
  `bin/cost-rollup.sh`) lives on the hub. This box holds 3 rows of its own
  `logs/cost.csv`, which is not the fleet.
- Telegram and Slack volumes, review capacity per project: no ledger records
  them, and the hub logs are not on this box.

Each of these is `not measured (needs: …)` in ENVELOPES.md and
`"not measured"` in baseline.json, never a zero. `HUB_PROBE: d1-count` covers
only 4 tables (`jobs`, `ledgers`, `split_watchdog_actions`,
`hub_probe_requests`), so it cannot fill the table rows.

## Design decisions

- **The inventory is frozen.** The ticket asks a test to check that every lane
  and table in the repo is in ENVELOPES.md. Read literally, each later PR that
  adds a lane or a table goes red and must append to one shared doc. So the test
  requires full coverage of `inventory.tsv` (written at audit time), and prints
  `NOTE: new since audit: <kind> <name>` for a later name. A re-audit
  regenerates the inventory.
- **Seam globs.** The ticket's `bin/lib/*github*` and `bin/*telegram*` match
  no file. The inventory also takes `bin/lib/gh-*.sh` and `bin/*tg-send*`.
- **No Telegram knob.** `tests/lib/` has no shared Telegram fake (each suite
  stubs `curl` inline), so there was no fake to add the knobs to. The gap is
  in the Telegram block.
- **The fly 429 shape is assumed.** No fly reader in `bin/` classifies a 429;
  `bin/fly-pool.sh` reads any non-zero flyctl rc as a failed call. The fake
  prints `Error: request failed with status 429 Too Many Requests (rate
  limited)` on stderr and exits 1. There is no live capture of that text.
- **The GitHub and jobs shapes are the production shapes.** GitHub: a 403
  with `x-ratelimit-remaining: 0` and a "rate limit" body, which
  `_gh_rest_sniff` reads as `rate-limit` (rc 75). Jobs: the
  `d1OverloadGuarded` 503 body, which `_jobs_req` retries as an overload.
  `tests/scale-fakes.bh-7906-test.sh` drives both through the real readers.
- **Two landmines, not three.** Only the GitHub REST bucket and the D1
  overload have a measured `NOW` and `CEILING` with the ceiling at or below
  10x. Reviewer throughput (the project-10 review-lane bottleneck) has no recorded
  number in this repo, so the audit could not rank it.
