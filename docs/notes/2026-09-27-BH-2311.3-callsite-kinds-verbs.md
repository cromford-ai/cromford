# Conductor, queue and tier2 attempt kinds go through the verbs

Doc: MERGE-CONDUCTOR

BH-2360 (BH-2311.3). The PR-keyed attempt sites in three files stop grepping
and appending `$MC_ATTEMPTS` by hand and call the BH-2311.0 verbs in
`bin/lib/mc/locks.sh` instead. `locks.sh` itself is unchanged.

## What changed

| Site | Before | Now |
|---|---|---|
| `bin/merge-conductor.sh` red strike count | `grep -c "^red $KEY "` | `mc_attempt_count red "$KEY"` (every head) |
| `bin/merge-conductor.sh` Mergify hold (count + two writes) | `grep -c "^mergifyhold $KEY $HEAD$"`, `echo >>` | `mc_attempt_count mergifyhold "$KEY" "$HEAD"`, `mc_attempt_put_n` |
| `bin/merge-conductor.sh` enqueue / merge failure (count + write, twice) | `grep -c "^mergefail $KEY $HEAD"`, `echo >>` | `mc_attempt_count mergefail "$KEY" "$HEAD"`, `mc_attempt_put_n` |
| `bin/lib/mc/queue.sh` `mc_eject_strikes` | `grep -cE` / `awk` over the file | `mc_attempt_count "ejected\|reejected"` with `MC_EJECT_REBASE=0`; otherwise the same awk over the lines `mc_attempt_lines` copies to a per-call temp file |
| `bin/lib/tier2-autoenqueue.sh` `_ae_once` (`aeskip`, `aewould`) | `grep -qxF`, `echo >>` | `mc_attempt_has`, `mc_attempt_put` |

The `identityalert` block in `merge-conductor.sh` is not PR-keyed and stays
file-only, under its own lock.

With `pr-state-rows` down the file bytes and every count are what they were.
The one difference is that a missing ledger now reads `0` on the
`MC_EJECT_REBASE=0` branch, where the old `grep -c … || true` printed nothing.
With the flag up, `mergifyhold`, `mergefail`, `aeskip` and `aewould` are now
also written as `pr_attempts` rows through `mc_attempt_put`: the file line first,
then the row, with the row's rc ignored and BH-1831's per-tick latch after an
outage. Reads stay file-only. The rows-first read is BH-2311 sibling 2's change.

`mergefail` has exactly two writers (both in `merge-conductor.sh`), and each
writes `mergefail <key> <head>` with nothing after the head, so the field-exact
count reads the same lines the prefix grep did.

`tier2-autoenqueue.sh` gets the verbs from `locks.sh`, which
`merge-conductor-lib.sh` sources before the conductor sources the tier2 file.

## Verified by

`tests/attempt-kinds-rows.bh-2360-test.sh` drives two real
`bin/merge-conductor.sh` ticks on a Mergify PR whose queue never answers
(mergifyhold), two on a no-queue PR whose merge fails and two on a
native-queue PR whose enqueue fails (both `mergefail` sites). With the
flag down it compares the resulting ledger byte for byte against the same ticks
run on a pre-BH-2360 conductor. The suite rebuilds that baseline itself: it
takes today's three files and puts the old call-site text back, so the check
needs no git history and does not go vacuous once this is on main. It also
checks the eject strikes and the tier2 lines against the pre-BH-2360 functions,
sees the flag-up row PUTs and the outage latch, and runs an exact-allowlist
static guard over the three files.
`tests/tier2-autoenqueue-test.sh` stubs the two verbs it now needs.
