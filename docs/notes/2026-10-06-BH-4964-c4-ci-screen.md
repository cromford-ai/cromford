# Merge-queue batches on /ci (BH-4972, C4 of BH-4964)

Doc: MERGIFY, COST

## What changed

- `/ci` has a new MERGE-QUEUE BATCHES section under CI HEALTH. It reads
  BH-4971's ledger through the coord proxy,
  `GET /api/coord/ci-batches?[repo=]&since=<today-30d>&limit=5000`, polled
  every 60s like the other /ci reads. `?repo=` on the page scopes it.
- One row per batch run, newest first: RUN (links to
  `https://github.com/<repo>/actions/runs/<run_id>`), WHEN, MODE,
  SELECTED / TOTAL, ESCALATION, DURATION, BILLED min, CONCLUSION. Every header
  sorts on the shown value. A value the ledger did not record is "—", never 0.
- Above the table: `7-day median batch minutes: before X (n) · after Y (n)`.
  The cutover is the earliest `batch-selected` batch in the loaded rows. Both
  sides count every mode (an escalated `full` batch after the cutover is part
  of the after cost) and only rows with a billed minute. A side with none reads
  "not enough batches yet", or "before the loaded window" when the 30-day read
  or a truncated read cut the before side short.
- A failed read is the ErrorBox (an unapplied table shows "ci_batches schema not
  applied"); an empty read is "no merge-queue batches recorded yet".
