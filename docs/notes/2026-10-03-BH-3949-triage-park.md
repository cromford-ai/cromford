# A ticket the call-guard keeps refusing is parked, and an open PR skips the paid session (BH-3949, part 2 of BH-3943)

Doc: CALL-GUARD, TRIAGE-STATE

## What changed

New `bin/lib/triage-park.sh`. When `bin/triage-shard.sh` gets a
`call-guard repeat` refusal (only that one: not `counter-unreadable`, not
`context-kill repeat`), it calls `triage_park_on_refusal` after the shard's
TRIAGE-STATE stamp. That reads `call_guard_list <p> triage-shard 24` and takes
the row for `<KEY>:<fp>`. When `refused_since_reset` is at least
`TRIAGE_REFUSED_PARK_AFTER` (settings `lib.triage-park.triage_refused_park_after`,
default 3, 0 = off), it does one `triage_state_put`:
`verdict=hold`, `waiting_on=team`, `verdict_hash=<the row's input_hash>`,
`next_recheck_at = now + TRIAGE_PARK_RECHECK_S` (default 604800), reason
`call-guard-exhausted: paid <n>/<max>, refused <r>, last repeat`.

- An unreadable call-guard list, no call-guard row, no triage_state row or no
  `input_hash` parks nothing and writes one `triage-park: <KEY> not parked: ...`
  line to the project log.
- A row already parked on the same hash is not PUT again.
- Only after a 2xx PUT is the marker `state/triage-park/<p>/<KEY>.<fp>` written,
  and only when it was absent does `bin/lane-alert.sh --severity warn` send one
  alert. A failed PUT writes no marker, so the next refusal retries.
- The last line of `rt_scope` (`bin/lib/rt/scope.sh`) calls
  `triage_park_tick_line`, so it runs before `rt_shards` (BH-3418 keeps
  `bin/lib/rt/shards.sh` unedited, and `bin/run-triage.sh` is at its line
  ceiling):
  one `triage-park: N parked (KEYS)` line (rows with `verdict=hold`, reason
  `call-guard-exhausted...`, `input_hash == verdict_hash`), nothing when N is 0.
  After a good read it deletes the markers of keys no longer parked.

Unparking needs no code: a board change moves `input_hash`, and
`bin/triage-state.py decide` answers `llm changed`.

Open-PR checks, through `open_pr_for_key` (`bin/lib/open-pr-precheck.sh`, BH-3948):

- `split_chain_gate` asks before offering a due child. A hit writes the remind
  watermark, logs `SPLIT_DEFER <KEY> open-pr #N - paid_avoided`, writes
  `last_decision` only, and skips the key; nothing is printed when every key is
  skipped. The 2 reads are charged against the pass's `SPLIT_CHAIN_MAX_LOOKUPS`.
- A launch-only triage shard (launch-queue section, no board or finished-build
  section) for a key with an open PR logs `BUILD_DEFER <KEY> open-pr #N -
  paid_avoided` and exits 0 before the ledger claim and the model call.
- rc 1 (verified none) and rc 2 (unreadable) keep today's path.

## Why

project-4 TK-2117 sat in the TRIAGE-STATE "to the model" list on every tick from
2026-10-01 (81 log lines), refused by the call-guard each time. project-4 TK-2125 paid
a split-ready session to learn "PR #1787 already covers the scope".
