# BH-9556 slice C0: lanes that act (2026-11-24)

## What changed

- `bin/needs-sweep.sh`: a missing `console.needs.sweep_dry_run` row is apply
  (fallback 0). A value other than 0 or 1 is 0. The row `1` is the kill flag
  (dry). A settings outage is exit 4, one log line and ONE alert
  `needs-sweep-settings`, before any candidates read and with no ledger row. No
  jobs client or an empty `JOBS_URL` is not-configured (exit 0, no alert).
- `bin/scheduler.sh`: the `scheduler.mode` read keeps its rc. An outage is exit
  1, one `SCHED-TICK error=settings-unreachable` line and ONE alert
  `scheduler-settings-unreachable`. No input read, no POST, `.last` not
  stamped. A missing row stays shadow.
- `bin/unblock.sh`: an unreadable `unblock.enabled` is exit 1 and ONE alert
  `unblock-settings-unreachable` (it was a quiet rc 0).
- `catalog/lanes.d/unblock.json`: `UNBLOCK_ACT` registry default 1. The lane
  scripts keep their `${UNBLOCK_ACT:-0}` reads: lane_env_apply exports a
  knob only when a settings row exists, and prod has the row
  `lane.unblock.unblock_act=1` (operator, 2026-10-26).
- `worker/jobs/src/lib/seed-moves.js` (new), called by `GET /api/settings` and
  `GET /api/settings/<key>`: once per DB binding, one guarded batch moves
  `console.needs.sweep_dry_run` 1 -> 0 and `scheduler.mode` shadow -> enforce,
  each only while value and actor `seed` are unchanged. Moved rows carry actor
  `seed:BH-9556`. It never throws. `PUT /api/settings` refuses actor `seed`.
