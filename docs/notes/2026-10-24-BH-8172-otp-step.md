# web-task OTP step: pass a TOTP page on an allow-listed site (BH-8172, slice C0)

Doc: DB-COORDINATION-SPEC

## What changed

This slice follows `docs/notes/2026-10-23-BH-8125-type-otp.md` (the code
maker `createTypeOtp`) and `docs/notes/2026-10-24-BH-8226-sign-in-step.md`
(the sign-in step `createSignIn`). It adds the page half of the `type_otp()`
tool action as a module. The web-task agent does not call it yet: the agent
loop (S1, #7594, PR #7650) is not on main, so slice C1 of #8172 wires it in.

- `bin/lib/web-otp-step.mjs`: `createOtpStep({ site, allowed, otp, selectors,
  timeoutS })` returns `{ passOtp, attempts }`. `otp` is the run's one
  `createTypeOtp` instance. One `passOtp(page)` call is one attempt:
  1. The host gate of the sign-in step on `page.url()`. Else
     `refused: otp not allowed on <host>`, not terminal, no code made.
  2. Finds the one-time-code input: `selectors.otp`, else the first match of
     `input[autocomplete="one-time-code"]`, `input[name="otp"]`,
     `input[name="totp"]`, `input[name="code"]`, `input[inputmode="numeric"]`.
     None: `error: no otp field on <host>`, no code made.
  3. The target gate: where the input's form submits, and the submit
     control's `formaction` (else its form's action). Off the run site:
     refused as in 1, no code made.
  4. Calls `otp(fill)`. `createTypeOtp` makes the code at this moment (after
     the wait for the next window on a retry). `fill` runs the host gate again
     after the vault read, then types the code. A non-ok outcome of `otp`
     (`refused: otp refused`, `error: otp unavailable (...)`, `error: otp fill
     failed (...)`) is returned as is, with its terminal flag. Nothing is
     submitted.
  5. Submits: the submit control (its target gated again before the click),
     else Enter on the input. Waits for `load`.
  6. No OTP input left and the page still on the run site: `ok: otp passed
     (<host>)`. The OTP input still there: `error: otp not accepted (the otp
     form is still on the page)`, not terminal; the caller calls `passOtp`
     again, and `createTypeOtp` waits for the next window or answers
     `refused: otp refused` past its cap (`WEB_TASK_OTP_ATTEMPTS`). A page on
     another host: `error: otp failed (the page left <site> for <host>)`,
     never ok.
- Other outcomes: `error: otp timed out after <n>s` (a `TimeoutError`) and
  `error: otp failed (<message>)` (another submit or wait throw; every digit
  run of 6 or more masked). The step never logs and no outcome holds the code.
- `bin/lib/web-signin-step.mjs` now exports `gate`, `normHost` and
  `allowList`. Their bodies did not change. The OTP step imports them, so both
  steps use one host gate.
- Knob (`catalog/lanes.d/_lib.web-otp-step.json`, lib id `web-otp-step`):
  `WEB_TASK_OTP_STEP_TIMEOUT_S` (settings row
  `lib.web-otp-step.web_task_otp_step_timeout_s`): default 20, range 5..120,
  the wait after the code submit. A bad value makes `createOtpStep` throw
  `web-otp-step: bad WEB_TASK_OTP_STEP_TIMEOUT_S`. It is never clamped.
- `tests/lib/web-otp-site.bh-8172.mjs`: a fixture site on 127.0.0.1 that asks
  for a TOTP code after the password. It checks the code against the current
  30 s window only, at the time in a clock file the suite moves. `reject=<n>`
  refuses the first n code posts. It reads its credentials and the base32
  secret from a mode-600 file and logs method and path only.
- `tests/lib/web-fake-page.bh-8172.mjs`: the fake Playwright page of the
  #8226 suite as one importable file.
- `tests/web-otp-step.bh-8172-test.sh`: the gate table, the step paths on the
  fake page, the knob, the fixture site, and an e2e: `createSignIn` then
  `passOtp` on the fixture site through the default `wv_read`, `wt_totp_code`
  and `wt_totp_step` providers and the jobs worker fake. A first refused code
  passes on the retry in the next window. A site that refuses every code
  stops with `refused: otp refused` after 2 posts. No secret, password or
  code is in any outcome, log, result, stdout, stderr or child argv.
