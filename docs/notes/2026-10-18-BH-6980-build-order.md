# BH-6980 (BH-6547.4): the build order in Mission Control

`/build-order?project=<p>` shows the order the scheduler builds a project's
tickets in. It is read-only: edges are not edited from the console.

## The three reads

The screen makes three independent GETs in ONE `Promise.allSettled`, every 30 s.

| Read | Route | Answer | Bound |
|---|---|---|---|
| R1 | `/api/coord/scheduler/ready?project=` (worker `scheduler.js`, BH-6979) | the newest tick: `at, mode, candidates, complete, verdicts[]` | 1001 rows |
| R2 | `/api/coord/ticket-edges?project=` (worker `ticket-edges.js`, BH-6977) | `edges[]` (`parent, child, kind`) | 500 rows |
| R3 | `/api/dash/kanban/pipeline?project=` (the Kanban read) | build cards per column | the pipeline's own bounds |

A failed read prints `<read> unavailable: <error>`. A failed R1 renders no
graph at all, never an empty or all-unknown one. A failed R2 renders the nodes
with `—` for their parents, never "no parent". 500 edges prints "showing the
first 500 edges". `complete: false` adds `partial` to the tick line.

## The node state rule (`console-ui/src/lib/build-order.js`)

Nodes are the verdict tickets plus every edge end. A verdict's `ticket` is the
issue number; a card's `ticket` is `<PFX>-<n>`; they join on the trailing
digits, and only this project's build cards count. First hit wins:

1. A build card. The most advanced column wins: `merged_deployed` → merged,
   `merge_queue` → queued (in the merge queue), `review` → review, `building` →
   building, `queued` → queued (waiting for a build slot). `dead_failed` sets
   nothing.
2. A verdict: `yes` → ready; `no` → waiting (label `waiting on #N` only for
   `parent #N open`); `in-flight` → building (build in flight); `unknown` →
   unknown.
3. Neither → unknown, "not in the ready set and no recent build".

The reason is the verdict's text whenever it has one, then the card's
`stage_why`, then the default above.

Depth is the longest path from a root. An edge back into the current walk
closes a cycle: it is skipped and both ends say `cycle in the edges`. The key
prefix comes from this project's own cards; with none, a node prints `#n` and
links to `/p/<p>`.
