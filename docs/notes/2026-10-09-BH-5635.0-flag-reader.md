# One flag reader, fail-closed on a failed read (BH-5635.0)

Doc: DB-COORDINATION-SPEC

## What changed

- `pause_flags` has a new nullable column, `value TEXT`. `worker/jobs/schema.sql`
  creates it on a fresh database. `ADDED_COLUMNS.pause_flags` in
  `worker/jobs/src/lib/core.js` adds it to a live table on the first request.
  It is never backfilled. NULL means an empty flag file.
- `PUT /api/flags` accepts an optional `value`: a string of up to 64 characters
  of `A-Za-z0-9._-`. Any other value, a number included, is a 400 and writes
  nothing. Absent, null or `""` is stored as NULL. The audit row diffs `value`
  only when the old or the new row has one, so a value-less write keeps its
  `{"active":N}` audit JSON. A value change alone writes one audit row. A
  same-value write writes none.
- `GET /api/flags`, `GET /api/flags/<name>` and `PUT /api/flags` call
  `ensureColumns(env, "pause_flags")` first.
- `flag_sync` in `bin/lib/jobs/flags.sh` is now the GET plus `_flag_apply_row`.
  Its rc is unchanged. An active row with a value writes the value as the file
  content (tmp + mv, mtime = the row's `updated_at`). Different content is
  rewritten only when the row is not older than the file (the BH-1370 rule). A
  value outside the alphabet is refused with one `jobs-client.log` line, and the
  box is left alone.
- New `bin/lib/flag-on.sh`, sourced, with no caller yet (#5641 and #5642 add them):
  - `flag_on <flag> [<project>]`: rc 0 ON, 1 OFF, 2 bad name or no root.
  - `flag_value <flag> [<project>]`: prints the value when ON. Same rc.
  - `flag_file_on <flag> [<project>]`: the file only, never a request.
  - `<flag>` is one of `paused wip-limit fly-pool fly-pool-app builder-fly
    automerge-disabled`. Only `automerge-disabled` may omit the project.
  - The root is `${HARNESS:-${H:-}}`. No root is rc 2.

## Read order (paused, wip-limit, automerge-disabled)

1. `JOBS_URL` empty: the file answers.
2. `GET /api/flags/<name>` with a readable row: `_flag_apply_row` reconciles
   `flags/<name>`, `state/flags-cache/<name>.json` is written, a
   `state/flags-cache/.outage` marker is removed with one `logs/flags.log` line
   (`[flags] outage ended (<name> read ok)`), and the file answers.
   If the reconcile fails (`flags/` unwritable, disk full), the answer is ON
   when the row says active 1 OR the file exists. The value is the row value
   when it is set, else the file content.
3. 404: the file answers. The cache and the marker do not change.
4. Any other result is an outage. The first caller creates `.outage` with
   noclobber and writes one ALERTS line through `bin/alert-line.sh --id
   flags-outage`:
   `[flags] harness-jobs flag read failed for <name> on <box> (<why>): pause,
   automerge and WIP gates now answer from state/flags-cache and flags/,
   fail-closed. Check the worker/jobs deploy and HARNESS_SECRET.`
   The answer is ON when the cache says `active` 1 or the file exists. The
   value is the cached value when there is one, else the file content. The
   cache is not written.

The routing families (`builder-fly`, `fly-pool`, `fly-pool-app`) run
`routing_sync` (no request while `routing_rows` is off) and the file answers.
They have no cache entry and no outage marker.

## Why

A failed flag read must never answer "not paused" when the last known answer
was paused. The cache keeps the last good row, so a removed file does not
un-pause a box during an outage.
