# Skip a CI dispatch a PR run already covers; push once per build attempt; `FULL_CI_LABEL=off` (BH-8049)

Doc: COST, MERGE-CONDUCTOR, RUN-BUILD-GRAPH

## Why

Runner minutes. project-6's `ci.yml` declares `workflow_dispatch:` with no
inputs, so each dispatch is the full lane (about 42 min). Two conductor lanes
dispatched it on a PR head with no look at the runs already on that head. The
builder also pushed after execute and after each fix round. On a branch that
already has a PR, each push starts the PR's CI (project-6: `ci` + `e2e`) and
cancels the run before it.

## What changed

1. **Dispatch skip.** `bin/lib/ci-dispatch-skip.sh` defines `cds_check <slug>
   <head> <wf> [runs-json]`. Two lanes call it before their
   `workflow_dispatch` POST:
   - `mst_ci_nostart` (`bin/lib/mc-stuck-timers.sh`, CI never started). It
     reads `ci.yml` first, sends `ref=<PR head branch>`, no inputs. One GET of
     `actions/runs?head_sha=` per dispatch decision.
   - `mc_block_ci_step` (`bin/lib/mc/block-ci.sh`, CI-only BLOCK). It uses the
     runs it already read. No new read.

   If a `pull_request` or `merge_group` run of the same workflow file on the
   same head SHA is green or not finished, the lane does not dispatch. It logs
   `ci-dispatch: skip <sha12>: <wf> run <id> is <status>`. A skip writes no
   `cikick` or `blockci` row and sends no `CI_NEVER_STARTED` alert. A head with
   no such run (a DIRTY head GitHub never ran), or with only red or cancelled
   runs, still gets its dispatch. An unreadable run list dispatches as before
   and logs `ci-dispatch: runs unreadable for <sha12>; dispatching as before`.
2. **Push once per build attempt.** `bin/lib/push-once.sh` and the knob
   `BUILD_PUSH_ONCE` (lane `fly-pool`, settings row
   `lane.fly-pool.build_push_once`, default `pr`):
   - `pr`: when the branch already has a PR (`SQUASH_OK=0` or `RB_PR_OPEN`
     set), `PUSH_BRANCH` defers its backup pushes, `CKPT_START` starts no
     checkpoint watcher, and pr-push sends the commits in one push. An attempt
     that ends before pr-push sends them from the EXIT trap
     (`PO_FLUSH_ON_EXIT`) through `hold_push`. `YIELD_CHECK` sends them before
     it measures origin. A retry attempt pushes once more. A first build with
     no PR keeps its backup pushes.
   - `always`: defer every backup push. `off`: the old behavior.
   - Log lines: `push-once: deferred push after <stage> ...`,
     `push-once: end-of-attempt push <sha12> (<why>)`,
     `push-once: end-of-attempt push not pushed (<rc>) ...`.
3. **Counts.** `bin/ci-minutes-watch.sh` logs one
   `ci-counts repo=<slug> dispatches_24h=<n> (<wf>=<n>,...) pushes_per_pr prs=<n> median=<m> max=<x> (<branch>) of <N> run(s) read`
   line per repo, before its estimate line. `state/ci-minutes/latest.json`
   repo objects gain `dispatches_24h`, `dispatches_by_workflow` and
   `pushes_per_pr`. The ci_health payload gains `dispatches_24h` and
   `pushes_per_pr`. The counts come from the runs the lane already reads.
4. **`FULL_CI_LABEL=off`.** `fcl_apply` (`bin/lib/rb-full-ci-label.sh`)
   returns before the classifier when the value is `off` (any case, spaces
   trimmed), the same as empty. A settings row cannot hold an empty value, so
   `off` is the row's off state. `offline` and `full-ci-off` are still labels.

## Operator steps after deploy

1. Set `lib.rb-full-ci-label.project-6-os.full_ci_label` to `off`. Do this
   only after the change is on the boxes: the old `fcl_apply` would add a
   label named `off` to every project-6 PR.
2. Delete the `ci-impact` label from example-org/project-6.

## Not changed

- `mrqd_self_dispatch` (`bin/lib/main-red-queue-dispatch.sh`): `ref=main`,
  once per freeze episode, the thaw path.
- The BH-5795 traced-hold dispatch: it sends `inputs[scope]`, which project-6
  `ci.yml` refuses, and it already skips an unfinished PR run.
- The E2E preview push and the preview-QA fix push: each needs the pushed tree
  for a preview.
