# 2026-11-12 — BH-9580: human gate ask from the planner block

Doc: CUSTODY, GATES-VS-REPORTS, MERGE-CONDUCTOR

## What changed

- New jobs D1 tables `human_gates` and `human_gates_archive`
  (`worker/jobs/schema.d/202611121730-bh-9559-human-gates.sql`), with the 4
  indexes, the 12 gate-class rows, 4 knob rows and 4 kill flags.
- New route `POST /api/human-gates` (`worker/jobs/src/routes/human-gates.js`):
  one upsert on `(repo, key, lane, question_fp)`. 400 with no default, no
  recommended answer, or 0 or more than 3 reasons. An unknown reason is
  irreversible.
- New retention rule `human_gates.archive`: a resolved row past
  `human_gate.retention_days` (90) is copied to `human_gates_archive`, then
  deleted, in one batch.
- New `bin/lib/human-gate.sh` (`hg_ask`, `hg_class`, `hg_plan_blocked`,
  `hg_release`), the jobs-client verb `human-gate-put`, and
  `bin/lib/human-gate-release.d/plan.sh` (`hgr_plan`).
- `bin/lib/rb/plan.sh`: the plan blocked gate calls `hg_plan_blocked` before
  the `plan_blocked` beat. RESULT, the exit code and the beat do not change.
- `bin/lib/plan-blocked.sh` `pb_notice`: when `<build>/human-gates.md` exists
  and scrubs clean, the comment carries it instead of the plain cq text.

## Why

BH-9559 part A: a question to a person gets a deadline, a default and a
record, so a later lane can default or chase it.

## Limits of this slice

- Only the planner block at the plan blocked gate is wired. The spec intake
  hold and the replan escalate have no recommended answer or default to ask.
- The board sweep path (`bin/client-questions.sh`) still posts the plain cq
  text without a deadline.
- A reworded question on a re-plan is a second row. The old row stays open
  until the defaults sweep (BH-9559.3) resolves it.
- The sibling seams (`human-gate-release.d/conductor.sh`, `tackler.sh`,
  `needs-human.sh` and the 6 stub docs) hold no code yet.
