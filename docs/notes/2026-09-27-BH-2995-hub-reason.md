# /hub SEED REGISTRY and CHAT BINDINGS writes require a reason (BH-2995, BH-2992.1)

Doc: CONSOLE

## What changed

- **Coord proxy** (`console-ui/functions/api/coord/[[path]].js`): the two
  WRITES rows BH-2521 added, `POST settings/seed-registry/apply` and
  `PUT telegram-topics`, list `reason` in their body allowlist and carry
  `reasonRequired: true`. After the JSON-object check, a flagged row whose
  `reason` is not a string with non-blank text answers
  `400 {"error":"reason required"}` and forwards nothing. A good reason is
  forwarded as sent, with the stamped actor. The telegram-topics validator
  now reads "thread_id must be an integer, every other field a string", so
  the reason survives it and a string `thread_id` is still dropped. No other
  row is flagged: `hub/promote`, `hub/restore-lab` and the rest behave as
  before, and `pickBody`/`writeRoute` are unchanged.
- **api.js:** `seedApply(plan_fp, reason)` and
  `telegramTopicSet(project, thread_id, reason)` send the reason.
- **Libs:** `requestApply` (`lib/registry-seed.js`) and `saveEdit`
  (`lib/chat-bindings.js`) open the confirm dialog with a per-click
  `form = {reason: ''}`, `confirmBlocked: true` and, when the panel passes
  `renderForm`, a form body. `submitApply` sends nothing unless the dialog
  confirmed AND the reason is non-blank; it sends the trimmed reason.
  `saveEdit` returns `{refused: 'a reason is required'}` for a confirmed
  blank reason and sends nothing.
- **Panels:** SeedRegistry and ChatBindings render the existing
  `PauseReasonForm` (`ui/PauseForms.js`) inside the in-app Modal: the old
  dialog copy, then a REASON input. APPLY / MOVE in the dialog stays disabled
  while the reason is blank or whitespace.

## What did not change

- The worker. `routes/settings.js` (seed apply) and `routes/telegram-topics.js`
  ignore the extra `reason` field. Storing it belongs to a sibling slice of
  #2992.
- No schema change, no new env var.

## Tests

- `console-ui/tests/hub-write-reason-proxy.bh-2995.test.js` (new): the real
  `onRequest` refuses `""`, `"   "`, `null`, `42` and a missing reason on both
  rows with zero upstream fetches, forwards a good reason with the stamped
  actor, still forwards `hub/restore-lab` without one, and keeps a telegram
  reason while dropping a string `thread_id`.
- `console-ui/tests/hub-reason-panels.bh-2995.test.js` (new): the lib flows.
- The BH-2521 suites that sent these writes without a reason now send one,
  and the mounted-panel suites type into the dialog's REASON field and check
  the confirm button is disabled until they do.
