# BH-8339: the resolver's ABANDONED terminal belongs to one PR, and a fix round works only an open PR

Doc: MERGE-CONDUCTOR

## Problem

On 2026-10-25 the resolver abandoned PR #8294 (ticket BH-8062). The record is
one per ticket (`br_cap_key`), so it became ABANDONED for the ticket. The
rebuilt PR #8301 then got a lead BLOCK, and `br_one` answered rc 3 for it on
every tick: no fix round came. A round that was queued for #8294 also pushed to
that closed PR's branch (`ticket/bh-8062`). The first round on a branch whose
own CI lint was red was briefed without the lint lines, and the PR body was
rewritten before a round that then pushed nothing.

## What changed

The new logic is in `bin/blocked-resolver.d/bh-8339-pr-record.sh`. Each driver
call site is one line. `BR_OPT_OFF=bh-8339-pr-record` restores the old
behaviour of every call site except the body write (item 5).

1. `br_abandon` stamps `abandoned_url` (the PR it closed) on the record.
   `br_save` mirrors it into `ledgers(kind=br_record)` and `br_load` restores it.
2. The pre-pass (`br_finished`) retires an ABANDONED record's rows only when
   the record has no `abandoned_url`, the row has no PR url, or the row is the
   abandoned PR. `br_record_index` column 2 is `abandoned_url` for an
   ABANDONED record.
3. `br_one` calls `bpr_scope` before the ABANDONED check. When the row is
   another PR of the ticket and `br_pr_state` answers `open`, the record is
   reset for that PR in one `br_save`: outcome `""`, `mechanicals`, `regens`,
   `fixrounds`, `fixround_bonus` to 0, one `pr-reset` attempt, `pr_reset`
   `{from,to,at}`, `pr_resets` +1, then one `resolver_pr_reset` event. The
   rebuild counters and adjudications are kept, so the rebuild cap still bounds
   the ticket. A legacy record (no `abandoned_url`), an operator ABANDON, a
   `rebuild-*` row, a closed, merged, absent or unreadable PR, and observe mode
   keep the terminal.
4. `br_fix_round` calls `bpr_fix_target` right after the `br_pr_ref` read. A
   closed, merged or absent PR gets no round (no worktree, no agent, no push,
   no rung). An unreadable state is retried next tick. This runs on the
   owning box in `--fix-here` too. `br_fix_adopt` adopts another PR's `done`
   row with no record save and no rung (`bpr_adopt_other`).
5. The fix round runs the worktree's own `bin/ci-local.sh` before the agent
   (`bpr_lint_brief`, into `$ST/<p>/<ck>.ci-local-pre`). A red result puts its
   finding lines in the prompt. A clean result prints nothing. Skipped, off,
   could-not-run or a conflicted merge keep the last-round paragraph.
6. `br_preflight` no longer writes the PR body on the "the round runs" path.
   `br_preflight_after_push` writes it after a push that landed, as before.
   The re-review and evidence routes still write it (they run no round).

## Not changed

The rebuild cap, the operator's "ticket says ABANDON" terminal, the
`abandoned` jobs-ledger row a watcher reads, and the `fix_round_jobs` key (one
round per ticket at a time). The lead-review side is out of scope.

Tests: `tests/blocked-resolver-pr-record.bh-8339-test.sh`.
