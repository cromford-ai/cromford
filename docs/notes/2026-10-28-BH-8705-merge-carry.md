# The lead word carries across a pure merge of main before the CI wait (BH-8705)

Doc: OPERATING

## Why

A "merge main into the PR" push moves the head. Gate 10
(`bin/lib/lead-gates.d/10-builder.sh`) held the new, unapproved head (rc 11)
until CI was green. Only then could gate 50 replay the lead word. A diff that
did not change waited 20 to 40 min. On 2026-10-27/28 about half of the
project-6-os fix rounds were only merges of main.

## What changed

- New gate `bin/lib/lead-gates.d/07-merge-carry.sh` runs before gate 10. It
  calls `lead_carry` (`bin/lib/lead-carry.sh`, the BH-6291 / BH-8028 path) with
  `LC_MERGE_ONLY=1`. A carry is rc 12: no review, no CI wait. Any other answer
  is rc 0, and the chain runs as before. The gate never holds a head.
- `lead_carry` merge-only mode:
  - Only `patch_same` `main-merge` carries: every new commit since the reviewed
    head is a two-parent merge whose tree equals `git merge-tree` of its
    parents, with no conflict, and the rest is on origin/main. A rebase
    (patch-id), a hand-resolved conflict, a new commit or a merge of another
    branch does not carry.
  - A BLOCK is carried as BLOCK, never as MERGE. A BLOCK does not ask
    `la_decide` (`bin/lead-verdict.sh` publishes a BLOCK as failure in every
    mode). A MERGE asks it first, as before.
  - A not-retracted lead, human or risk-tier row on the new head stops the carry.
  - The default mode (the merge conductor's `mc_lead_ready` and
    `rebind_patch_id`) does not change.
- The carried row is source `lead`. The note is
  `lead-replay:<G12> how:main-merge ref:#<id> by:lead-review carried_from:#<id> reason:merge-carry:<H12>`.
  It names both shas. `bin/lead-verdict.sh show` prints it as
  `MERGE (lead, #<n>, carried from #<id>)`. The ticket asked for source
  `carry`; the worker accepts no such source, and every standing reader would
  need a change, so the note marks the carry instead.
- CI still runs on the new head. The conductor still needs green CI to merge.

## Knob, state and rollback

- `LEAD_REVIEW_MERGE_CARRY` (lane lead-review, default 1, 0 = off). A value
  other than 0 or 1 reads 0, with one log line. Set the row to 0 to return to
  the old path with no deploy.
- Ledger `state/lead-review-enqueue/merge-carry.tsv`, rows `<epoch>\t<line>`.
  `bin/lib/lead-gates.d/99-state-sweep.sh` trims it with the
  `LEAD_REVIEW_GATE_STATE_KEEP_DAYS` window.
- Test: `tests/lead-merge-carry.bh-8705-test.sh`.
