# Onboarding checks browser-QA wiring, and a daily lane alerts until it is wired (BH-6254)

Doc: OPERATOR-SETUP, onboarding-a-repo

A project could enrol and merge for days with no browser QA. project-6-os merged 47+ PRs with no `vercel.conf` row, prod `-`, no env file on the hub and `deploy.project-6-os.kind=none`. No alert fired.

- New `bin/qa-wiring-check.sh <project>` checks five items: the `vercel.conf` row, the prod URL, the QA account (`QA_TEST_USER_ID`, `QA_CLERK_SECRET_KEY`, a role in `state/qa-accounts.json`), the deploy kind, and the Clerk prod origin. It prints one `ok:`, `OWED:` or `UNKNOWN:` line per item. rc 0 all ok, 1 an OWED line, 3 only UNKNOWN lines, 2 usage. It never prints a key value.
- The settings row `qa_wiring.<project>.exempt=<reason>` exempts a project with no web UI. The default is no row, so every project is checked.
- `bin/load-project.sh` prints the check as a `== browser QA ==` block after `== LOADED`. The block is never fatal.
- New hub lane `qa-wiring-sweep` (`bin/qa-wiring-sweep.sh`, daily `55 5 * * *`, flag `lane-off-qa-wiring-sweep`) runs the check for every project in `fleet.conf`. On an OWED line it writes one ALERTS line through `bin/alert-line.sh` and one `fleet_alert` beat with akey `qa-wiring:<project>`, once per project per UTC day (latch `flags/alerted-qa-wiring-<project>-<YYYYMMDD>`). An UNKNOWN line is logged to `logs/qa-wiring.log` and does not alert.
