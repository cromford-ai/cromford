# Flags in the DB: paused-*, automerge-disabled* and lanedown-* are rows (BH-4153)

Doc: jobs-client, fleet-pauses, verification-map

## What changed

- New worker table `harness_flags(scope, name, value, set_by, reason, set_at,
  cleared_at)`, PRIMARY KEY `(scope, name)`, shipped in `worker/jobs/schema.sql`
  with an idempotent backfill from `pause_flags` (applied by
  `bin/harness-sync.sh` before `wrangler deploy`). D1 has no RLS: the table sits
  behind the worker's bearer like every other one.
- `GET/PUT /api/flags` read and write it for the ported names
  (`FLAG_PORTED_RE`, `worker/jobs/src/lib/harness-flags.js`), and the new
  `DELETE /api/flags?name&scope&reason` clears a row (soft: `cleared_at`).
  A fleet-scope write also upserts the `pause_flags` row in the same batch, so
  `checkPause` and the other worker readers keep working unchanged. Every other
  name is still `pause_flags` only.
- `bin/lib/flags.sh` is the public entry for `flag_has` / `flag_set` /
  `flag_clear` / `flag_list` (implemented in `bin/lib/jobs/flags.sh`). For a
  ported name on a box with a worker configured they are DB-first, write no
  `flags/` file, keep a last-good cache in `state/flags-cache/<scope>/<name>`,
  and answer rc 2 when the worker cannot be read and nothing is cached.
  `flag_active` reads rc 2 as ON for `paused-*` and `automerge-disabled*` (a
  stop switch fails closed) and logs one `jobs-client.log` line.
- `flag_set --hold-local` (cost-local-brake, the lanedown marks) writes a
  local hold when the PUT fails; a row written after the hold wins (BH-1370's
  recency rule).
- `flag_set --local-only` writes ONLY the local hold, never a row, and
  `flag_clear --local-only` drops it. `bin/quiesce-for-resize.sh` pauses with
  it, because a resize stops one box: a `paused-<p>` row would stop every box
  and the worker's claim-time check. `bin/quiesce-for-resize.sh --resume`
  lifts those holds and leaves any pause written as a row alone. A legacy `flags/<name>` that cannot be
  imported yet also counts as a local hold, and removing the file removes it.
- With the worker unreachable and nothing cached, `paused-<p>` reads as ON, so
  `run-triage.sh` stands down for the whole tick, including result staging
  that runs after its pause gate. A box that has read its flag once answers
  from the cache instead.
- Readers that tested `flags/paused-<p>` or `flags/automerge-disabled*`
  directly now go through `flag_active`/`flag_has`. `lanedown-*` marks are
  rows scoped to the box that writes them (`JOBS_BOX`).
- `bin/flags-import.sh` moves the legacy files into rows and deletes them; it
  runs daily from `bin/update-runners.sh`, by hand, and lazily from `flag_has`.
  It only publishes a file this box OWNS: `paused-<p>` and
  `automerge-disabled-<p>` for a `<p>` fleet.conf puts on the box, the fleet
  `automerge-disabled` on the hub, and `lanedown-*`. A file only ever paused
  the box it sat on, so any other one (a stray from a failed PUT, an old
  quiesce) is reported `kept-local` and stays a local hold on that box. A row
  at or after its mtime still wins and removes it.
- `bin/fleet-status-push.sh` builds the snapshot's `pause_flags` from the rows
  (`flag_list` / `flag_has`), and keeps its last pushed list when it cannot
  read them; `bin/poll-commands.sh`'s "auto-merge enabled" reply reads the
  fleet kill switch row.
- The console's COST BREAKER card reads `/api/flags?prefix=paused-`, so
  `lanedown-*` rows cannot push a trip off the 500-row list.
- Console: a `/flags` screen (SETTINGS tab) lists every flag with SET and CLEAR.

## What did not change

A box with no worker configured (`JOBS_URL` or `HARNESS_SECRET` empty) keeps
the file semantics exactly. Non-ported names keep BH-1370's reconcile.

## Rollback

Revert the PR. The rows stay (additive table); `pause_flags` was kept in step
for fleet-scope names the whole time, so the old reconcile reads the same pauses.
Imported files are gone, but the old reconcile re-creates `flags/paused-*` and
`flags/automerge-disabled*` from their `pause_flags` rows on the next read.
`lanedown-*` marks would restart as files on the next canary failure.
