# Conductor markers and detached jobs as pr_attempts rows

Doc: MERGE-CONDUCTOR

BH-2358 (BH-2311.2), part of #2311 ("move file state to DB so nothing is lost
when a box dies"). Two files change: `bin/lib/mc/classify.sh` and
`bin/lib/mc/rebase.sh`. No table, no migration, no lock, no cron lane.
`pr_attempts.kind` is free text, and every new kind fits in 32 characters.

## The gate

Every new line below is written and read only when the `pr-state-rows` flag is
up (`mc_rows_twin_on`, which is `pr_rows_on` from the jobs client). With the
flag down the path is today's: the same `attempts.txt` bytes, the same empty
stuck marker, no `/api/pr-attempts` request.

## What changed

| Record | Written when | Read when | Forgotten by |
|---|---|---|---|
| `handoff <key> <head>` | `mc_handoff_record`, before the marker file. It first clears any `handoff-rel` for that head. | `mc_handoff_sticky`, when the marker file is missing | `mc_handoff_gc` (the marker's own url and head) |
| `handoff-rel <key> <head>` | `mc_handoff_release`, for the head in the marker file or else the row's head field. Nothing is written for no head. | `mc_handoff_sticky`, after the release file check | a new park on the same head, `mc_handoff_gc` |
| `stuck <key> <state> <head>` | `mc_stuck_check`, before the marker and before the alert. The marker now holds this line. | `mc_stuck_check`, when the marker is missing. A hit writes the marker back and does not page. | `mc_stuck_gc` (the line inside the marker; an empty marker has no row) |
| `rbjob <key> <head> done` | `mc_rebase_run`, after the job file says done | `mc_rebase_spawn`, when the job file is missing: rc 4, nothing spawned | the stuck re-kick, the release label, and the land and eject arms before their own spawns |
| `rrjob <key> <head> done` | `mc_rereview_run`, only for a verdict. Lane-failed, deferred and failed runs are retried by design, so they record nothing. | `mc_rereview_spawn`, when the job file is missing: rc 4. `headbound_review` logs it and hands the budget back. | nothing: a verdict for a head is final |

The call sites for `cirerun`, `requeued`, `apread` and `mergetree` now use the
BH-2354 verbs: `mc_attempt_tail … first` for cirerun and requeued,
`mc_attempt_tail … last` for apread, `mc_attempt_put` for the writes, and
`mc_attempt_put_n` plus `mc_attempt_count` for mergetree. The file lines are
the same bytes as before. With the flag up, each one is now also a row.

## Why the land and eject arms forget `rbjob`

Both arms rebase the SAME head again on purpose, when main moves or the queue
ejects it. Each has its own dedupe mark (`landrebase <key> <main sha>`,
`ejectrebase <key> <head>`). A rebase that finished without pushing, such as
a conflict or a no-op, leaves its `rbjob` line on that head. `mc_lane_gc`
deletes the job file after three days. Without the clear, the next landing
would get rc 4 and log LAND_DEFER on every tick. So the two arms clear the
line first, the same way the stuck re-kick and the release label do.

## An outage

`mc_attempt_has` answers rc 1 on an outage and latches the tick off
(BH-1831). Every new fallback therefore reads an outage as "no row", and the
files decide exactly as they did before. An outage never counts as parked,
released, paged or finished.

## Left for the rows-first sibling

- `mc_attempt_put` still writes the file line before the row. The ticket asks
  for row first, but that order belongs to `bin/lib/mc/locks.sh`, which this
  change does not touch. For the markers, the row and ledger line go before the
  marker file.
- A failed row write is not logged here. `mc_attempt_row_put` swallows its rc,
  and the per-tick latch is the only signal.
- The held-page flush in `bin/lib/mc/log.sh` still writes an empty stuck
  marker and no row. If `MC_STUCK_DIR` is wiped, that one flushed page can go
  out again once.
- `mc_handoff_owns` classifies a reason word and reads no file, so it is
  unchanged. The row fallback the ticket asks for is in `mc_handoff_sticky`,
  the per-PR park check.
