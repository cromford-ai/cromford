# BH-10124: Millwright's metric, collector and bake-rerun lever (C3 of #9423)

Doc: STAFF, OPERATING

## What changed

Millwright, the maintenance staff agent, now owns the metric
`failed_bakes_and_broken_boxes`. It has a collector for the staff tick and an
hourly lever lane.

- `bin/lib/millwright-read.sh` reads the four fault kinds (`mw_bakes`,
  `mw_probe_cmd`, `mw_boxes`, `mw_metric`).
- `bin/staff/millwright-collect.sh` is the collector. `bin/staff.sh tick
  millwright` (cron 729, every 15 min) claims what it prints. At level `file`
  or `act` the tick files a ticket. At level `observe` (the seed) it files
  nothing.
- `bin/staff/millwright-lever.sh` (cron 787, hourly at :37, hub, behind the
  hub lease) samples the metric. At level `act` it re-runs each failed bake
  once.
- `bin/fleet-propagate.sh` keeps a new top-level key `.pool_fail` in
  `state/fleet-propagate.json`.

## The metric

`value = bakes + boxes`.

- `bakes`: failed pool image bakes. A pool counts when
  `.pool_fail.<p>` exists, `flags/fly-pool-app-<p>` is a non-empty file, and
  `state/fly/<p>.image` is missing or not newer than the entry's `at`. Every ok
  bake writes `.image` (propagate, the 05:40Z nightly or a hand
  `bin/fly-image-build.sh`), so a newer `.image` means the pool was fixed.
- `boxes`: distinct boxes with at least one of these faults:
  - `resolv-broken`: `/etc/resolv.conf` does not exist through its link, or
    has no `nameserver <address>` line (a commented line does not count).
  - `tmp-full`: `/tmp` block use% at or above `MW_TMP_FULL_PCT` (90).
  - `stale-bin`: the `box_status` row has `harness_lag_min` above
    `harness_version.max_lag_min` (fallback 30) and `lag_checked_at` younger
    than `MW_LAG_FRESH_MIN` (60) minutes. `bin/fleet-version-check.sh` writes
    the lag; Millwright reads it with one `GET /api/boxes`.

The resolv and /tmp reads come from one read-only ssh probe per registry box
(tailnet IP, not `hub`, not retired), all in parallel, each under `timeout
MW_SSH_TIMEOUT_S` (15). The hub runs the same probe locally. A box that does
not answer is `unreachable`: unknown, never a fault. The sample's detail names
each count, `unreachable` included.

An unreadable record, registry or `GET /api/boxes` makes the metric
unreadable: no sample, no action. It is never 0.

## `.pool_fail`

`.pool_fail.<p> = {sha, at, reason}`. The bake step of `bin/fleet-propagate.sh`
sets it for a pool whose bake failed (any status but `ok`, `debounced`, `busy`
and `known-fail`) and deletes it on an `ok` bake. Every record write of a run
(the sync record, the skip record and the hub-refused record) carries the
previous value through `fp_pool_fail`, because each run rebuilds the record
from scratch. `.pools` does not change.

## The lever

The bake id is `<project>:<sha12>`. The lever writes one
`staff_lever_actions` row per id, key `bake-rerun:<p>:<sha12>`, BEFORE it acts.
Only a new row acts. An existing row or a 409 is `taken`, so the same id never
re-runs twice. The act writes `state/fly/<p>.image-dirty` with the 40-char sha
(tmp file and `mv -n`, never over a mark that is already there). The next
`bin/fleet-propagate.sh` tick drains that mark as one bake under its own bake
lock, debounce and retry counter. The lever makes no Fly call.

Before each row the lever reads the record again. A pool that is fixed or has
a retry queued meanwhile is `skipped=<p>:fixed|queued`. A bake whose
propagate retry is still queued is never re-run, and the collector does not
file it.

Cap: `staff.millwright.bake_rerun_max_day` (seed 2, fallback 2) minus the
scorecard's `actions` for the last day. An unreadable scorecard is
`cap-unreadable` and no action.

One line per run in `logs/staff-millwright-lever.log`:
`level=<L> value=<n|unreadable> sample=<ok|failed|-> action=<none|recorded:<n>|taken:<n>|failed:<n>|cap-reached|cap-unreadable> marks=<n> detail=<..>`.

## Knobs and switches

- Settings rows: `staff.millwright.level` (seed observe), `staff.millwright.bake_rerun_max_day` (seed 2).
- Lib rows `lib.staff-millwright.*` (`catalog/lanes.d/_lib.staff-millwright.json`):
  `MW_TMP_FULL_PCT` 90 (50..100), `MW_SSH_TIMEOUT_S` 15 (1..120),
  `MW_LAG_FRESH_MIN` 60 (10..1440), `MW_BOXES_MAX` 200 (1..500). Out of range
  is one warn line in `logs/staff.log` and the default.
- Off: `flags/lane-off-staff-millwright-lever`, `STAFF_ENABLED=0`, and the
  flags `staff-off-all`, `staff-kill-all`, `staff-off-millwright`,
  `staff-kill-millwright`.
