# Pool routing and the WIP limit read through flag-on.sh (BH-5635.3)

Doc: DB-COORDINATION-SPEC

## What changed

The 14 raw `[ -f flags/(builder-fly|fly-pool|fly-pool-app)-<p> ]` tests now call
the BH-5635.0 reader. The WIP-limit content read now calls `flag_value`.

| Site | Now |
|---|---|
| `bin/fleet-propagate.sh` `fp_has_pool` else branch | `flag_on fly-pool-app "$1"` |
| `bin/fly-results-ingest.sh` remote-result loop | `flag_on fly-pool "$p"` |
| `bin/split-watchdog.sh` route pick | `flag_on fly-pool "$p"` |
| `bin/fly-machine-state.sh` no-client branch | `flag_on fly-pool-app "$PROJ"` (the `cat` of the app name stays) |
| `bin/fleet-status-push.sh` `.projects.<p>.pool` | `POOL=false; flag_on fly-pool "$P" && POOL=true` |
| `bin/pr-owner-sweep.sh` `pos_pool_routed` else branch | `flag_on fly-pool "$1"` in a subshell |
| `bin/fly-dispatch.sh` `dispatch_project` (2 sites) | `flag_on builder-fly`, `flag_on fly-pool` |
| `bin/healthcheck.sh` no-client branch | `flag_on builder-fly "$PROJECT"` |
| `bin/fly-pool-tick.sh` pool skip | `flag_on fly-pool` and `flag_on builder-fly` |
| `bin/blocked-resolver.sh` `br_pool_routed` else branch | `flag_on fly-pool "$1"` in a subshell |
| `bin/free-slots.sh` fly early return | `flag_on builder-fly "$P"` |
| `bin/free-slots.sh` WIP limit | `flag_value wip-limit "$P"` |
| `bin/harness-sync.sh`, `bin/pipeline-health.sh` publishers | `flag_file_on builder-fly`, `flag_file_on fly-pool` |

Result: `wip-limit-<p>` written as a `pause_flags` row with a value reaches
`bin/free-slots.sh` with no ssh and no file. The routing families answer from
the file after `routing_sync`, as the contract says. With the `routing_rows`
switch off (today), the routing sites send no request.

The publishers use `flag_file_on`. They publish the file state to the hub, so
they must not read the row back into the row.

## The source line

Each script sources the lib beside its `env-path.sh` line, in the same shape:

    . "$H/bin/lib/flag-on.sh" 2>/dev/null || . "$(dirname "${BASH_SOURCE[0]}")/lib/flag-on.sh" 2>/dev/null || flag_on() { [ -f "$H/flags/$1-$2" ]; }

The handler defines a file-only reader, which is the behavior before this
change. It is not `|| exit 1`, because many existing suites copy one of these
scripts into a scratch tree without `bin/lib/flag-on.sh`.

`bin/blocked-resolver.sh` has its own `flag_on <full-name>` (one argument), used
for `blocked-resolver-observe`, `automerge-disabled` and
`review-rescue-disabled`. A top-level source would replace it. So
`br_pool_routed` sources the lib in a subshell, and the script's own `flag_on`
stays. `pos_pool_routed` in `bin/pr-owner-sweep.sh` uses the same subshell
form, because `tests/routing-sweep-readers.bh-1027-test.sh` runs that one line
outside its script.

## A fix in bin/lib/flag-on.sh

`_flag_on_bind` sourced `bin/jobs-client.sh` with no check. When
`bin/lib/jobs/` is missing, the client runs `exit 1` while it is sourced, and
that ended the caller. `tests/routing-dispatch-readers.bh-1371-test.sh` found
it: `bin/free-slots.sh` printed nothing. `_flag_on_bind` now returns 1 when
`bin/lib/jobs/` is missing, which is the same check the callers use. The answer
then comes from the file. Cases D4 and M2 of
`tests/flag-callsites-pool.bh-5635-test.sh` cover it.

## Not changed

- Glob enumerations of `flags/`, the `cat flags/fly-pool-app-*` reads,
  `bin/pool-cap.sh` and `bin/fly-pool.sh`.
- `bin/concurrency-plan.sh` still reads `flags/wip-limit-<p>` with `cat`. The
  ticket names only `bin/free-slots.sh`. A `flag_value` call in free-slots
  reconciles the file from the row, so concurrency-plan sees the row value
  after the next free-slots run.
