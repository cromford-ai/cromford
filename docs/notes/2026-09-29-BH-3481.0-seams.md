# The live-cost and build-tripwire seams: stub libs and their call sites (BH-3481.0)

Doc: RUN-BUILD-GRAPH

## What changed

This is child 1 of 5 of BH-3481 (ticket BH-3497). It adds the interface the
other children fill in. Runtime behavior does not change: `cost_live_on`
answers off, `tw_check_build` never trips, `tw_paused` answers not-paused, and
nothing writes a tripwire marker.

- `bin/lib/cost-live.sh` (sourced, root `${HARNESS:-${H:-}}` only), all stubs:
  - `cost_live_on` sets `CL_OFF=stub` (`CL_OFF=no-root` with no root) and
    returns 1.
  - `cost_live_row <box> <sid> <tc-line>` prints nothing and returns 1.
  - `cost_live_push <json-row>`, `cost_live_meter <cli-pid> <sid> <cwd>` and
    `cost_live_boundary_push` return 0 and do nothing.
- `bin/lib/build-tripwire.sh` (sourced, same root rule), all stubs:
  - `tw_expected <project> <build-dir>` prints nothing and returns 1.
  - `tw_eval <csv> <live-usd> <expected> <mult> <repeat-max>` prints
    `ok<TAB>stub` and returns 0.
  - `tw_trip <project> <key> <build-dir> <verdict-line>` returns 0 and writes
    nothing.
  - `tw_paused <project> <key>` returns 1.
  - `tw_check_build <project> <key> <build-dir> <live-usd>` returns 1, prints
    nothing and writes nothing.
- `bin/agent-call.sh`:
  - Sources both libs fail-open (sibling `lib/` first, then
    `$HARNESS/bin/lib/`). Without them, fallbacks answer the same as the stubs
    for `cost_live_on` (`CL_OFF=absent`), `cost_live_meter` and
    `cost_live_boundary_push`.
  - Claude attempt: the CLI runs backgrounded when a context ceiling is set OR
    `cost_live_on` answers 0. `context_meter` still runs only with a ceiling.
    `cost_live_meter <cli-pid> <sid> <cwd>` runs beside it only when live cost
    is on and the attempt has a session id, and is killed and reaped after the
    wait. The foreground branch is unchanged.
  - `ac_cost_row_write` calls `cost_live_boundary_push` once, after the row is
    emitted and, for a build call, teed into the build's `cost.csv`.
  - `$OUT.tripwire` (per call, cleared at the start of every claude attempt):
    after the `$OUT.ctxkill` check, the claude branch turns rc 0 into 143,
    appends `TRIPWIRE: <stage>/<project> session stopped by the harness build
    tripwire (<first line>) — output above is TRUNCATED` to `$OUT`, logs a
    failovers.log policy line and stops the model ladder. `run_attempt` sets
    `TW_STOP` and `BUDGET_STOP`, so grok tier-2, the configured fallback,
    OpenRouter and Fireworks do not engage. `TW_STOP` keeps it out of
    `KILL_STOP` and out of the BUDGET FLAG INERT check, and the stage-end arm
    writes a `TRIPWIRE:` line to failovers.log, not a `BUDGET STOP` ALERTS line.
    The cost row is still written, with note `tripwire:<first word>`.
  - Precall, before the repeat-kill and call-guard checks: when `$OUT` is under
    `*/builds/*/*` and `$(dirname "$OUT")/TRIPWIRE` exists, it writes
    `AGENT_CALL_REFUSED tripwire <stage> <first line>` to `$OUT` and
    `$OUT.err`, a failovers.log line and the zero-cost refused row
    (`refused:tripwire`), and exits 74. No runner is called.
- `bin/lib/rb/plan.sh` sources `build-tripwire.sh` fail-open. `CC()`, when
  `$BUILD` is set: if `$BUILD/TRIPWIRE` is absent it calls
  `tw_check_build "$PROJECT" "$KEY" "$BUILD" 0`. If the file exists then, it
  writes `BB tripwire_paused` (detail: the file's first 1200 bytes) and
  `RESULT "BUILD_REFUSED TRIPWIRE_PAUSED <first line>"` and exits 3 without
  calling agent-call. It checks again after the call and ends the same way.
  Otherwise CC returns agent-call's rc as before.

## Left for the siblings

- Every stub body above.
- Release semantics for `$BUILD/TRIPWIRE`. Nothing here removes it.
- `LENS_CALL "$LENS" &` in `bin/lib/rb/review.sh` runs CC in a background
  subshell, so there a tripwire `exit 3` ends that lens's subshell, not the
  build. The next foreground CC call (fix, re-review) then ends the build.
  Several RESULT lines are possible on that path once something writes the
  marker.
