# Push and flaky wake classes: the first two BH-1034 lanes wired

Doc: EVENTS

**What changed.** BH-1061 is the first BH-1034 child to wire a wake class. It
adds two class files and backstop skips in the three lanes they drive:

- `bin/lib/wake-class-push.sh` — `push` wakes now drive `rebase-train.sh` per
  project (locally or over ssh), and also drive `fleet-propagate.sh` and
  `prompt-eval.sh --cron` when the push is to `cromford` and touches
  `prompts/`. Pushes are deduped by project; `cromford` pushes remember the
  sha so `prompts_touched` can inspect the right commit.
- `bin/lib/wake-class-flaky.sh` — `check_suite.completed` wakes drive
  `flaky-detect.sh <project> --days 1` per project. `check_run.completed` is
  ignored, and suites are deduped by project.
- `bin/rebase-train.sh`, `bin/fleet-propagate.sh`, and `bin/flaky-detect.sh`
  each gained a `wake_backstop_skip` region inside their own lock (or before
  any work, for flaky-detect), keyed to the class flag
  (`flags/wake-lanes-push` / `flags/wake-lanes-flaky`) and a per-lane stamp.
  `WAKE_LAUNCH=1` overrides the stamp; `flags/wake-lanes-off` suppresses both.

**Inert until armed.** Both class flags are off by default, so the new files
change nothing until an operator runs:

```
bin/jobs-client.sh flag-set wake-lanes-push on "BH-1061"
bin/jobs-client.sh flag-set wake-lanes-flaky on "BH-1061"
```

That step is intentionally manual and must wait until the BH-1059 contract
child's worker deploy is live, because `worker/jobs/src/index.js` is what stores
`push` and `check_suite.completed` wakes in the first place.

**What it touches.** `bin/lib/wake-class-push.sh`,
`bin/lib/wake-class-flaky.sh`, `bin/rebase-train.sh`, `bin/fleet-propagate.sh`,
`bin/flaky-detect.sh`, the two new integration suites under `tests/`,
`docs/verification-map/entries/BH-1061.md`, `docs/verification-map/README.md`
(regenerated by `bin/verification-map-build.sh`), and this note.
