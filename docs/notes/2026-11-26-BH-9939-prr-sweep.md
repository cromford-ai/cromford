# BH-9939: the slow safety sweep of the PR record

Ticket #9939, wave 7 of 7 of #9926. Lane `prr-sweep`, script `bin/prr-sweep.sh`.

## What it does

The lanes read PR facts from the PR record, and webhooks write the record. If a webhook is lost, a field stays wrong. The sweep compares the record with GitHub for the open PRs of each fleet repo and repairs each difference.

The cron line fires every 5 minutes on the hub. `tick` starts one `bin/prr-sweep.sh project <project>` run for each fleet project through the per-project runner (`pl_dispatch`). The knob `PRR_SWEEP_INTERVAL_MIN` (60) decides. If the last sweep of the repo is that old, the run sweeps the repo.

| Step | GitHub calls | What it compares |
|---|---|---|
| Open list | 1 for each 100 open PRs | `head_sha`, `head_ref`, `base_ref`, `draft`, `title`, `labels`. A PR that the record lacks. |
| Gone | 1 for each PR | A PR that the record calls open and GitHub's complete list does not hold. |
| Checks | 1 for each 100 runs, 3 pages at most | The newest run of each workflow on an open PR head, against `checks["workflow:<name>"]`. |
| Statuses | 1 for each PR read | `commits/<head>/status` against `statuses`, for a bounded set of PRs. |
| Sync | 0 | `pr_record_list_sync` renews the list sync stamp. |

Measured in `tests/prr-sweep.bh-9939-test.sh` (A2): 5 GitHub calls for a repo with 50 open PRs and no change. They are 1 list, 1 runs page, 2 status reads and 1 `rate_limit` read. The `rate_limit` read is the budget memo of `bin/lib/gh-budget.sh`. If another lane filled the memo, the sweep makes 4 calls.

## The status compare is bounded

GitHub has no list read for commit statuses. A status read for each open PR is 50 calls for 50 PRs. So each sweep reads:

1. each PR whose record holds a `pending` status on its head,
2. each PR that changed since the last sweep (its `updated_at`, or a workflow run on its head),
3. then `PRR_SWEEP_STATUS_ROTATE` (2) other PRs by rotation.

The total of per-PR reads is `PRR_SWEEP_PR_READS_MAX` (10) at most. A quiet PR gets a status read one time in 25 sweeps for a repo with 50 PRs. Raise `PRR_SWEEP_STATUS_ROTATE` to make that shorter. The cost is 1 call for each PR in each sweep.

`PR_RECORD_FIELD_MAX_AGE_S` measures the row age (`refreshed_at`). A write of the whole PR makes the row young, and that hides a lost `status` or check webhook. The sweep is the repair for that case.

## Newer only

Each write carries the sweep start time. The worker replaces a field only if its stored time is not newer. The answer names the applied fields. An applied field is a fix: one `PRR_SWEEP_FIX` line in `logs/prr-shadow.log` and one row in `state/prr-sweep/fixes.tsv`. A refused field is one `PRR_SWEEP_STALE` line.

## The trust window and the interval

`pr_record_list` trusts the record list while the sync stamp is at most `PR_RECORD_LIST_MAX_AGE_S` old. This change moves the default of that knob from 900 to 3900 (60 minutes plus `PRR_SWEEP_LIST_SLACK_S`, 300 s). The code fallback in `bin/lib/pr-record.sh` moved with it.

If the settings row of the window is below the interval plus the slack, the sweep uses the window minus the slack as its interval and logs `PRR_SWEEP_WINDOW`. The hub row `lib.pr-record.pr_record_list_max_age_s` is 2400 today, so the sweep runs each 35 minutes there until an operator sets the row to 3900 or deletes it.

## The alert

If a repo has more than `PRR_SWEEP_FIX_ALERT_24H` (20) fixes in 24 hours, the lane fires one alert with the id `prr-sweep-fixes:<repo>`. The first sweep that counts the limit or less resolves it.

## The raise

`bin/prr-sweep.sh raise [--dry-run]` also runs as the last step of each tick. For each lane with a seam file in `bin/lib/prr-shadow.d/`, all of these must hold:

- the step of the lane is `record`,
- the first sweep on the box is `PRR_SWEEP_QUIET_DAYS` (7) days old,
- each repo that the lane tried has a completed sweep in each of the last 7 24-hour windows (`state/prr-sweep/sweeps.tsv`),
- the ledger holds 0 fixes in that window,
- the registry has the knob `CADENCE_BACKSTOP_MIN_<LANE>`,
- the lane had no raise in that window.

The third condition is there because 0 fixes from a sweep that did not run is not evidence. If the lane was off, or the list read of one repo failed for a day, no raise occurs. `bin/prr-sweep.sh report` prints `swept=<owner>_<repo> days=<n>/7` for each repo.

Then the lane's row `lib.cadence-backstop.cadence_backstop_min_<lane>` gets its value times `PRR_SWEEP_RAISE_FACTOR` (2), to the knob's max at most. Today `merge-conductor` (60, max 120) and `blocked-resolver` (30, max 240) have such a row. The other 7 seam lanes have no interval row, and `raise` prints `no interval row` for them. Nothing lowers a row. To go back, set the row.

## Operator commands

```
bin/prr-sweep.sh report            # fixes for each repo, step and interval row for each lane
bin/prr-sweep.sh raise --dry-run   # what the raise rule does now
grep -c 'PRR_SWEEP_FIX repo=<repo>' logs/prr-shadow.log
bin/harness-ctl.sh off prr-sweep   # stop the lane
```
