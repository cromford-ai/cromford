# BH-10531.0: MCP closed schema checks own keys only

Defect: `unknownKey()` in `mcp/lib/tools.mjs` used `k in props` to find a declared property. The `in` operator reads the prototype chain. So on a closed schema (`additionalProperties: false`), the keys `constructor`, `toString`, `hasOwnProperty` and an own `__proto__` key (from `JSON.parse`) passed as declared. The handler then ran with those keys.

Fix: the check is now `Object.hasOwn(props, k)`. The same line serves nested object schemas, because `unknownKey()` recurses.

Test: `mcp/test/closed-schema-own-keys.bh-10531.test.mjs` drives `callTool()`, the validator the server dispatcher calls. It proves the refusal for the four inherited names and for a nested `o.toString`. It also proves a declared key and an open schema still run the handler.

No live tool schema declares a property with an `Object.prototype` name, so no real call changes result. No knob. No user-facing entry point.
