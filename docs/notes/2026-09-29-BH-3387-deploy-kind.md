# deploy-verify reads deploy.<project>.kind before it polls (BH-3387)

Doc: EVENTS

## What changed

cromford has no GitHub "Production" deployment. Every merge still went
through `bin/deploy-request.sh` into `bin/deploy-verify.sh`, which polled
`repos/<slug>/deployments` for 20 minutes, found nothing and paged
`deployfail:cromford:<sha>` (79ef9558, b58a59ba and 90953299 on 2026-09-28).

A settings row now says how a project's merges reach prod:

| `deploy.<project>.kind` | What deploy-request / deploy-verify do |
|---|---|
| `github-deployment` | Today's path: poll the Production deployment, then smoke prod. |
| `none` | One line, `deploy-verify SKIP: <project> has no GitHub production deployment (deploy.kind=none)`, in the build's `pipeline.log`. No gh call, no ALERTS line, no beat, rc 0. |
| `smoke-only` | No deployments call and no deploy hook. The prod smoke curl is the whole check, and a dead prod still FAILs. |
| no row, an unknown value, a settings outage | Today's path, unchanged. An unknown value writes one stderr line naming it (it lands in `deploy-verify.log`). |

`bin/lib/deploy-kind.sh` (`deploy_kind <project>`) is the one reader. It
lowercases the project before building the key.

`worker/jobs/schema.sql` seeds `deploy.cromford.kind = none` with
`INSERT OR IGNORE`, so `bin/harness-sync.sh` applies it and an operator edit
survives a re-apply. No other project is seeded.

## Closing the old pages

`bin/deploy-kind-resolve.sh <project>` closes open console alerts whose akey
starts with exactly `deployfail:<project>:`, with the reason
`not a deploying project`, and logs a count to `logs/alerts-groom.log`. It does
nothing unless the row reads `none`. Both scripts launch it on every `none`
merge, so the first cromford merge after the seed is applied clears the
backlog. By hand:

```bash
bin/deploy-kind-resolve.sh cromford
```

## Setting the row for another project

```bash
. /root/harness/bin/jobs-client.sh && setting_set deploy.harness-console.kind none "no GitHub deployment"
```

That is `PUT /api/settings` under the hood, and the console Settings page shows
the row as a raw key. Use `smoke-only` for a project that has a prod URL in
`fleet.conf` but no GitHub deployment.
