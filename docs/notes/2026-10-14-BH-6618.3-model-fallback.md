# CI test value report: the model fallback (BH-6639, BH-6618.3)

Doc: CI-RUNNERS, FLAKY-TESTS

## What changed

`ctv_model_pass` in `bin/lib/ci-test-value/model.sh` was a no-op seam. It is now
the model pass of `bin/ci-test-value-report.sh`. It reads only the
`occurrences.tsv` rows that no rule decides (`unknown U1.undecided`). It asks one
model stage, `ci-test-value`, through `bin/agent-call.sh` for a class. It
rewrites columns 11 (class), 12 (rule) and 15 (why) of those rows only. Every
other byte of the file stays the same.

The classes are the six of the report (`real-pr`, `real-main`, `test-defect`,
`infra`, `flake`, `order`) plus `unknown`. The prompt is
`catalog/prompts/ci-test-value-classify.md`. The log excerpt goes in fenced as
`=== UNTRUSTED INPUT <fp> ===` ... `=== END UNTRUSTED INPUT <fp> ===`, and the
prompt tells the model never to follow instructions in it.

The call runs with `AGENT_CALL_NO_TOOLS=1`, because a PR author writes the log text in the prompt. claude then has no tools, and a non-claude route is refused with rc 78 (nothing billed, the row stays undecided).

## The route

The model is `model_routes` role `stage.ci-test-value`, read with
`lane_role_model`. The seed
`worker/jobs/schema.d/202610151430-bh-6639-ci-test-value-route.sql` copies triage
rung 0 on the claude runner, so no model name is in the code. Change it on the
Models page. No route, no harness root or no readable prompt means no call: the
rows stay `U1.undecided` with an empty why, and stderr gets one line:
`ctv: no model route stage.ci-test-value; N row(s) left undecided`.

## The knobs

| Knob | Default | What it does |
|---|---|---|
| `CTV_MODEL_BATCH` | 20 | Rows per call. |
| `CTV_MODEL_MAX_CALLS` | 20 | Calls per run. A row past the cap stays `U1.undecided`, why `model call cap N`. |
| `AGENT_CALL_BUDGET_USD_CI_TEST_VALUE` | 0.50 | agent-call's USD cap per call. |

A bad value (not a whole number >= 1, or a budget of 0 or not a number) stops
the pass with one stderr line. The driver then exits 1 and writes no report. The
worst case for one run with the defaults is 20 x 0.50 = 10 USD.

## Dedup before spend

`fp = sha256("<run_id>|<attempt>|<job_id>|<unit>|<sha256 of the excerpt file>")`.
The excerpt file is the one the driver wrote, `<out>/cache/excerpt/<job>-<n>.txt`.
The pass finds `n` the way `read_job` does: the unit's line in the job log's list
of failed units. A row with no excerpt file is not asked (why `no excerpt`).

The ledger is `<out>/cache/model/<fp>.attempt` and `<fp>.json`. The driver's
lock on `<out>/.lock` serializes the pass.

| State | Outcome | Terminal |
|---|---|---|
| `<fp>.json` exists | the row takes it, no call | yes |
| `<fp>.attempt` and no `.json` (a billed call crashed) | `unknown M1.unparseable`, why `no answer recorded` | yes |
| an `.attempt` write fails | no call, why `cache write failed` | no |
| agent-call rc 74..79 (nothing billed) | `.attempt` removed, why `model refused rc=N` | no |
| any other non-zero rc (billed) | `unknown M1.unparseable`, why `model failed rc=N` | yes |
| rc 0, a valid line for the fp | `<label> M1.model <why>` | yes |
| rc 0, no valid line for the fp | `unknown M1.unparseable`, why `empty or invalid answer` | yes |

The pass writes `.attempt` for every row of a batch before the call. It writes
the `.json` before it removes the `.attempt`. A valid answer line is one JSON
object with a string `fp`, `label` and `why`. The `fp` must be in the batch and
the label must be one of the seven, in lower case. The first valid line per fp
wins. The why loses tabs, CR, LF and the 0x1f byte and is cut to 20 words.

The pass prints one summary line on stderr:
`ctv: model pass undecided=U cached=C asked=A calls=K labelled=L unparseable=P refused=R`.

## How to run it

```bash
bin/ci-test-value-report.sh --days 1 --out /tmp/ctv
```

Without `--no-model` the pass runs. The labels are in `/tmp/ctv/occurrences.tsv`
and the answers in `/tmp/ctv/cache/model/`. A second run on the same `--out`
makes no call for a row it already answered. No cron runs this report.
