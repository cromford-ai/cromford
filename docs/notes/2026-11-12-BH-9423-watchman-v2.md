# Watchman v2: a path allowlist, the DUMMY VALUES header and the live_unrotated_secrets metric (BH-9423)

Doc: STAFF, OPERATING

Slice C0 of #9423, the watchman part of the #9187 second wave.

## Why

The 11-06 hand triage found 132 of 133 watchman findings were test fixtures.
Each one still made a finding, a claim and a beat. Watchman also had no
metric, so the staff contract could not judge it.

## What changed

- `bin/lib/watchman-allow.sh` (new) holds the path allowlist and the rotation
  register reader. It holds no state and makes no request.
- `bin/staff/watchman-collect.sh` keeps every gitleaks location in the leak
  cache, as before. An allowlisted location makes no beat, does not count
  toward `WM_FIRST_SCAN_MAX`, and is not printed. A changed allowlist takes
  effect on the next tick with no rescan. A baseline whose non-allowlisted
  count is now at or under `WM_FIRST_SCAN_MAX` prints those locations one by
  one, and its baseline finding stops. The collector writes one
  `allowlist skipped=<n> path=<n> dummy=<n>` line a tick in `logs/staff.log`.
  It still makes no request on a quiet tick.
- `bin/staff/watchman-metric.sh` (new hub lane `staff-watchman-metric`,
  hourly at :52, `cron/lanes/782-staff-watchman-metric.cron`) samples the
  metric. It takes no lever action and files nothing.
- `prompts/staff/watchman-soul.md` has a new prose section. It tells the model
  to end each secret or rotation issue with a six-line rotation checklist. The
  MAY, NEVER and REPORT lists did not change.

## The allowlist

Settings rows (lib knobs in `catalog/lanes.d/_lib.staff-watchman.json`):

| Row | Default | Meaning |
|---|---|---|
| `lib.staff-watchman.wm_path_allowlist` | `tests/,__tests__/,e2e/,fixtures/,.harness/specs/,*.md` | Comma-separated patterns. `x/` = a whole path segment anywhere. `*.ext` = a suffix. Anything else = one exact path. A pattern with a character outside `[A-Za-z0-9_./*-]` is dropped with one warn line. Empty = the default. |
| `lib.staff-watchman.wm_dummy_lines` | `5` | A file whose first N lines at the leaking commit say `DUMMY VALUES` (any case) is allowlisted. 1..50. |

`test/` (singular) is not on the list, because the ticket does not list it.
A file the collector cannot read (a gone commit, a missing repo) is never
allowlisted.

## The metric

`live_unrotated_secrets` = A + B.

- A: the non-allowlisted locations in `state/staff/watchman/leaks/*.jsonl` and
  `base/*.jsonl` whose agent-core fingerprint is an open watchman finding, or
  that the collector never printed (`printed.tsv`). A printed location with no
  open finding is closed. Closing the filed issue as completed is the rotation
  signal.
- B: the register credentials (`catalog/staff-rotations.d/`) past due + 1 day,
  the collector's own rotation-due rule.

The lane reads `GET /api/staff/findings?agent=watchman` once. A failed read,
an answer that is not a list, or `truncated: true` logs
`live_unrotated_secrets=unreadable` and posts no sample. Otherwise it posts
one sample through `POST /api/staff/levers/metric` and logs
`live_unrotated_secrets=<n> history=<A> rotation=<B> allowlisted=<n> sample=<ok|failed>`
in `logs/staff-watchman-metric.log`.

Off: `flags/lane-off-staff-watchman-metric`, or the staff kill flags
`staff-off-all`, `staff-kill-all`, `staff-off-watchman`, `staff-kill-watchman`.
