# Pool VM size per project is a settings row (BH-8318, MKF-3)

Doc: FLY-POOL, LANES

## What changed

- `spawn_one` in `bin/fly-pool.sh` launched every pool machine with the
  literal `--vm-size performance-8x --vm-memory 16384`. The `fly machine run`
  line now takes `--vm-size "$PVM_SIZE" --vm-memory "$PVM_MEM"`. The same
  line serves the push path and the pull path (BH-7430), so both read it.
- Two new fly-pool lane knobs, as fragments in
  `catalog/lanes.d/fly-pool.knobs.d/`:
  - `VM_SIZE`, row `lane.fly-pool.<project>.vm_size`, default `performance-8x`.
  - `VM_MEMORY_MB`, row `lane.fly-pool.<project>.vm_memory_mb`, default `16384`.
  `lane_env_apply fly-pool <project>` exports the row as the env var. No new
  reader.
- `bin/lib/pool-vm-size.sh` (`pool_vm_resolve`) checks the pair:
  - The size must be exactly one of `performance-1x`, `performance-2x`,
    `performance-4x`, `performance-8x`, `performance-16x`.
  - The memory must be a whole number of MB, a multiple of 1024, and between
    2048 and 8192 MB per CPU of the size (performance-16x: 32768..131072).
  - An empty value takes its own default. Blanks and newlines are trimmed.
  - Any failed check sends the WHOLE pair to `performance-8x`/`16384`, because
    a good size with the default memory can be a pair flyctl refuses.
- A refused row writes one line per spawn in `logs/fly-pool.log`:
  `<key>: VM size row refused (<why>) — launching performance-8x/16384`.
  No alert. The spawn goes ahead.
- No row, or no lib in the tree: the argv is byte-identical to the one before.
  No row is seeded for any project.

## Why

MKF-3 of #8315: a project that needs a bigger builder must get one with a
row, not a code change. Every limit is a knob (BH-7945).

## Operator commands

```
bin/harness-ctl.sh set fly-pool VM_SIZE performance-16x project-6-os
bin/harness-ctl.sh set fly-pool VM_MEMORY_MB 32768 project-6-os
```

Set both rows together when the new size's range does not hold 16384.

Probe after one pool tick (not run from a build box):
`fly machine status <id> -a pool-<project>` shows the guest size, and
`grep "VM size row refused" logs/fly-pool.log` is empty.

## Known gap

`bin/pool-budget.sh` still prices a machine-hour at 8 CPU / 16384 MB
(`POOL_BUDGET_VM_CPUS`, `POOL_BUDGET_VM_MEM_MB`). A project on a bigger row
gets a low budget estimate. The cost rows read the real guest config.
