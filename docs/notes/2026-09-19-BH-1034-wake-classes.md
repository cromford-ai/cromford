# Wake classes: the shared contract before any lane is wired

Doc: EVENTS

**What changed.** BH-1034 will split the GitHub-webhook wake stream into five
classes (pr-closed, pr-ci, push, deploy, flaky) and let each child ticket wire
one lane. This contract child lands the shared parts so every sibling imports
the same library and the same hooks:

- `worker/jobs/src/index.js` stores the action-suffixed event name
  (`pull_request.closed`, `check_suite.completed`, `deployment_status.created`,
  etc.) in the `wakes.event` column and returns it in the webhook response.
  `push` carries no `action` and stays literally `push`; malformed actions fall
  back to the bare event name. `kind`, `key`, and the `(repo, kind, key, minute)`
  idempotency index are untouched.
- `bin/lib/wake-lanes.sh` is the shared backstop library: `wake_class_of`,
  `wake_stamp`, `wake_backstop_skip`. It has no side effects when sourced —
  `bin/jobs-client.sh` is sourced lazily inside `wake_backstop_skip`, the only
  function that needs `flag_active` — and every gate fails open (runs) when a
  dependency is missing.
- `bin/wake-loop.sh` sources the library, loads any `bin/lib/wake-class-*.sh`
  files, builds a `CLASS_ON` associative array once per invocation (one `wake
  classes armed: …` line in `logs/wake-loop.log` when any class is on), and
  calls each active class's `wc_<class>_row` hook per fleet row and its
  `wc_<class>_dispatch` hook once per drain. A class call that fails does not
  abort other classes or the existing dispatches. It also adds `lane_runs_here`
  and `remote_launch` for classes that launch a lane on the box that owns the
  project, and `launch()` now runs every child with `WAKE_LAUNCH=1` in its
  environment.

**The two lines a lane script pastes**, right after its own flock:

```bash
[ -r "$H/bin/lib/wake-lanes.sh" ] && . "$H/bin/lib/wake-lanes.sh"
command -v wake_backstop_skip >/dev/null 2>&1 && wake_backstop_skip <lane> [project] [window] && exit 0
```

`wake_class_of` is keyed on the LANE, not on the event: `reconcile-prs`,
`check-migration-prs`, `alerts-groom` → `pr-closed`; `review-prs`,
`review-autopilot`, `tickets-snapshot-push` → `pr-ci`; `rebase-train`,
`fleet-propagate`, `prompt-eval` → `push`; `deploy-train`,
`migration-autopilot`, `apply-migrations` → `deploy`; `flaky-detect` →
`flaky`. Any other lane gets rc 1 and never skips a tick.

**The knobs.** One flag per class, off until a sibling wires that class:

```bash
bin/jobs-client.sh flag-set wake-lanes-pr-closed on   # and -pr-ci, -push, -deploy, -flaky
bin/jobs-client.sh flag-set wake-lanes-pr-closed off
touch flags/wake-lanes-off        # kill switch: every class off, every backstop open
```

- Stamps: `state/wake-ran/<lane>[-<project>]`, epoch seconds, written only by a
  run that carried `WAKE_LAUNCH=1`.
- Window: `WAKE_BACKSTOP_S` (default 1800s), or a third argument per lane.
- Skips: one line per skipped tick in `logs/wake-backstop.log` —
  `<lane>[<project>]: cron tick skipped — wake-driven run <age>s ago (backstop <window>s)`.
  An empty file means no lane has skipped anything.

**No lane is wired yet.** With no `bin/lib/wake-class-*.sh` files on disk and
no `flags/wake-lanes-*` flag on, the loop is byte-for-byte unchanged for the
existing dispatches. Each BH-1034 child will drop one class file and one flag.

**Follow-up, after the classes are live:** remove a cron line only when
`doorbell-coverage-check.sh` reports that repo ringing for a full cycle. The
backstop makes a cron tick cheap; the cron line is still the thing that runs the
lane when the doorbell is silent, and it is the last resort this whole design
rests on.
