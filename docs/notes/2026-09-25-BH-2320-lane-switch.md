# Kill switches read as settings rows (BH-2320, contract + pilot)

Doc: CONFIG

`bin/lib/lane-switch.sh` adds `lane_switch <name>`. rc 0 means the switch is ON, so the thing it
names is off. The order is:

1. `LANE_GATE_DISABLE=1` answers off.
2. The box row `switch.<name>.<box>` (box = `JOBS_BOX`, else the hostname, lowercased), then the
   fleet row `switch.<name>`. Both come from `state/settings-cache.json`, the same 60 s cache
   `lane_knob` fills, so there is no extra request. `1|on|true` is on and `0|off|false` is off.
   When a row answers, `flags/<name>` does not decide. A file that contradicts a `0` row gets one
   throttled `logs/lane-gate.log` line: `switch <name>: row says 0 (<key>), flags/<name> ignored`.
   Any other value is logged and read as no row.
3. No row: `flag_active <name>` when the jobs client is loaded, else `[ -f flags/<name> ]`. A switch
   with no row answers what its file answered before.

Switch names are `[a-z0-9_-]`. Dots are refused because `switch.a.b` would be both switch `a.b` and
switch `a` on box `b`.

Every switch read this way has `catalog/switches.d/<name>.json` (`name`, `readers`, `box_scoped`,
`what`), one file per switch. The only one so far is `dora-digest-off`: `bin/dora-digest.sh` reads
it through `lane_switch`.

`bin/switch-migrate.sh [--dry-run]` writes `switch.<name>.<box>=1` (`PUT /api/settings`, actor
`switch-migrate`) for each registered switch whose file exists on this box and that has no box or
fleet row. It leaves the file in place. It exits 1 on a refused registry file or a failed write,
and 75 when the settings table cannot be read, in which case it writes nothing. Nothing runs it on
a schedule yet. Merging writes no row.

`tests/switch-ratchet.bh-2320-test.sh` holds the count of bare `[ -f …flags/<x>-off|-disabled ]`
reads in `bin/` and `fly/` at 102 or fewer. Lower its `FLOOR` with each converted reader.
