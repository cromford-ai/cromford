# BH-8067 (slice C0): the fleet's own PR record

Doc: DB-COORDINATION-SPEC

What changed:

- New D1 table `pr_records`, fragment
  `worker/jobs/schema.d/202610221947-bh-8067-pr-records.sql`: one row per PR,
  keyed `UNIQUE(repo, number)` with the repo lowercased. Columns for state,
  draft, head and base ref and sha, mergeable state, labels, checks, review
  decision, queue state and last comment id. `fields_at` holds the time of
  each stored value. Indexes `ux_pr_records_repo_number`,
  `idx_pr_records_state_refreshed`, `idx_pr_records_refreshed`.
- New gated routes `PUT /api/pr-records` (per-field upsert: a value is
  replaced only when its time is >= the stored time) and
  `GET /api/pr-records` (`{row, age_s}`, row null when absent).
- New client `bin/lib/pr-record.sh` with `pr_record_put` and `pr_record_get`.
  `pr_record_get` reads GitHub (one REST GET of the PR) only when the jobs
  read fails, the PR has no record, a requested GitHub-filled field is null,
  or the record is older than `PR_RECORD_MAX_AGE_S`. It then writes what it
  read into the record. One `logs/pr-record.log` line per GitHub read.
- `gh_pr_create_ladder` writes the record after it opens or adopts a PR
  (state open, refs, the local head sha). Best effort: its stdout and rc do
  not change.
- Knob `PR_RECORD_MAX_AGE_S` (default 900, 0 = always read GitHub) in
  `catalog/lanes.d/_lib.pr-record.json`.
- Retention rules `pr_records.closed` (14 days after the last write) and
  `pr_records.age` (90 days), settings rows
  `retention.pr_records.closed_days` and `retention.pr_records.days`.

Not in this slice: the other write sites (C1), webhook updates (C2), and the
lanes that move onto `pr_record_get` (C3 and later). No lane reads the record
yet.
