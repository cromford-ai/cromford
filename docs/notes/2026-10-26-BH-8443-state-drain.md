# A dry-run-first lane that drains dead state/ entries, and the hub report (BH-8443)

Doc: STATE-STORES

Slice C1 of #4159 (the rest of #4159, issue #8443).

## What changed

- New box lane `bin/state-drain.sh`, daily at `37 4 * * *` on the same 10
  boxes as `tmp-sweep` (`cron/lanes/775-state-drain.cron`,
  `catalog/lanes.d/state-drain.json`).
- It drains a top-level `state/` entry only when the entry is not in
  `catalog/state-paths.json` (any class) and is not `gh-policy-cache`, is not a
  link or on another mount, no key of its name appears in the deployed `bin/`,
  `catalog/` or the box crontab, and nothing inside it was written for
  `STATE_DRAIN_MIN_IDLE_DAYS` (30). The C0 plan said "zero `bin/` writers".
  The writer census misses function-built paths (`state/alerts` counts 0 and is
  live), so the lane uses the stricter test.
- `STATE_DRAIN_DRY_RUN` defaults to 1: the lane logs `would-drain` lines and
  deletes nothing. A real run archives each entry to
  `archive/state-drain/<stamp>/<name>.tgz`, reads the archive back, then
  removes the entry. Archives older than `STATE_DRAIN_ARCHIVE_KEEP_DAYS` (90)
  are pruned. At most `STATE_DRAIN_MAX_PER_RUN` (20) entries per run.
- `bin/state-drain.sh --report` prints the files under `state/` whose first
  segment is not allowlisted. Every run logs the count as
  `unallowlisted_files=<n>` and writes it in the `state_drain` ledger row.

## What did not change

- The hub count is not 0. The rollout families still have writers and catalog
  rows. The lane keeps them. They drain after their writers and catalog rows
  are removed by other tickets.
- No knob is flipped. A person reads a dry run in `logs/state-drain.log` and
  then sets `lane.state-drain.state_drain_dry_run` to 0.
