# flags/ config files read as settings rows (BH-2411, BH-2320.C5)

Doc: CONFIG, SCHEDULER, ALERTS-STATE-MACHINE, LEDGER-HYGIENE

`bin/lib/conf-row.sh` adds `conf_rows <file>`, `conf_row <file> <key>` and
`conf_row_note_file`. Nine resolvers read a settings row directly above
`flags/<file>`, so whatever beat the file before still beats it:

| file | row | where it is read |
|---|---|---|
| scheduler.conf | `conf.scheduler.<var lowercased>` | `sched_conf` (env still wins) |
| cost-caps.conf | `conf.cost-caps.budget.<project>` = `<per_pr> [min]`, `.default`, `.ceiling` | `_cb_load`, after the chosen file |
| lane-caps.conf | `conf.lane-caps.lane.<lane>` = `<usd\|off> [bytes]`, `.default`, `.noise.<lane\|default>` | `_lc_load`, after the chosen file (env caps still win) |
| ledger-ttl.conf | `conf.ledger-ttl.ttl.<class>`, `conf.ledger-ttl.set.<knob>` (`/` as `.`, `*` as trailing `_`) | `bin/jobs-watchdog.sh`, before every file |
| slo.conf | `conf.slo.<key lowercased>` (first word) | `conf` in `bin/fleet-slo.sh` |
| alerts.conf | `conf.alerts.<name lowercased>` (`set` scalars only) | `alert_cfg` (env still wins) |
| dora-digest.conf | `conf.dora-digest.<key lowercased>` | `bin/dora-digest.sh`, same namespace and charset check as the file |
| determinism-lint.conf | `conf.determinism-lint.{rule,opt,scope}.<id>` | `bin/test-determinism-lint.sh` replaces the file's line of the same name |
| readiness-levels.json | `conf.readiness-levels` holding the whole JSON table | `bin/readiness-report.sh` |

Every key also has a box row, the same key plus `.<box>` (box = `JOBS_BOX`, else the hostname,
lowercased), which wins over the fleet row. The value is the rest of the line the file would carry,
and it goes through the resolver's own validator. A row the validator refuses does not override:
cost-caps and lane-caps name it in `cost_budget_legacy_rows` / `lane_caps_legacy_rows` as
`row:<key>`, and the file's value stands. Since BH-2478 scheduler and alerts do the same: a
refused `conf.scheduler.*` / `conf.alerts.*` row logs
`conf <file>: row conf.<file>.<key>='<value>' refused, flags/<file> used` (once an hour) and the file
answers, not the code default. A value holding a newline or tab is logged and read as no row.

Each resolver is called as `$(…)`, so the rows are loaded once into the calling shell first
(`conf_rows_preload <file>`, BH-2478): `alert_state_enabled` / `alerts_db_on`, `bin/fleet-slo.sh` and
the four scheduler scripts (overlap-guard, overlap-schedule, rebase-train-ahead, lane-reaper) do it
before their reads, so a process runs one jq over the settings cache instead of one or two per knob.

No row is read when the resolver's fixture variable is set (`COST_CAPS_CONF`, `LANE_CAPS_CONF`,
`LEDGER_TTL_CONF`, `SLO_CONF`, `ALERTS_CONF`, `DETERMINISM_LINT_CONF`, `READINESS_LEVELS`), or under
`LANE_GATE_DISABLE=1`. Rows come from `state/settings-cache.json` (the cache `lane_knob` and
`lane_switch` fill). When the worker is down, the last cache answers at any age. With no cache, the
file answers.

When rows answered and `flags/<file>` exists, `logs/lane-gate.log` gets one line an hour:
`conf <file>: settings rows override flags/<file> for: <keys>`. `cost_budget_source`,
`lane_caps_source`, `test-determinism-lint.sh --rules` and `readiness-report.sh --print-levels` name
the rows as a source.

The worker takes up to 4096 characters for `conf.readiness-levels[.<box>]`. Every other key stays at
256. The PUT for a readiness row over 256 characters answers 400 until the jobs worker is deployed.

Merging writes no row, so every box behaves as before until someone writes one
(`PUT /api/settings {"key":"conf.scheduler.overlap_threshold","value":"5"}`). The alerts rule tables
and `parked` list, and determinism-lint's `pin`/`file`/`skip` lists, have no key and stay file-only.
No script writes any of the nine files. `tests/conf-rows.bh-2411-test.sh` N1 fails if one starts to.
