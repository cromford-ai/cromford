# BH-9262: owner and human-only decisions refuse the fleet credential (C0, shadow)

Doc: worker/jobs/README.md, CONSOLE

Slice C0 of #9262. C1 gives the two chat callers a proof and then flips the mode.

## Why

`HARNESS_SECRET` is on every box. Before this change an owner command
(`POST /api/box-commands`, the BH-5750 Orgo and Fly pool types) passed on the
body `actor` alone, and the human-only staff decisions passed on any actor that
was not an agent name. Any box could post `actor=<owner email>`.

## What changed

- New `worker/jobs/src/lib/owner-proof.js`. `ownerProof(req, env)` accepts
  exactly two proofs:
  1. the Mac human token: `x-human-verdict-token` = `HUMAN_VERDICT_TOKEN`
     (`humanTokenOk`, unchanged);
  2. the Pages proof: `x-box-ops-token` = `BOX_OPS_TOKEN` (SHA-256 of both
     sides, then a constant-time compare) AND `x-box-ops-identity`, the
     Access-verified email, in `BOX_OPS_OWNERS` (trimmed, lower-cased).
  A `BOX_OPS_TOKEN` that is blank or equal to `HARNESS_SECRET`,
  `LEAD_VERDICT_TOKEN` or `HUMAN_VERDICT_TOKEN` proves nothing.
- `humanGate` gates these routes, only in the direction that raises authority:

  | Route | Gated | Open to the bearer |
  |---|---|---|
  | `POST /api/box-commands` | the OWNER_ONLY types | the BH-2518 types, claim, result |
  | `POST /api/staff/agents/autonomy` | a raise | a lower or the same level |
  | `POST /api/staff/classes/delegation` | `delegate` | `ask_first` |
  | `POST /api/staff/promotions/decide` | `approve` | `void` |
  | `POST /api/staff/suppressions/decide` | `approve` | `decline` |
  | `POST /api/staff/suppressions` | always | - |
  | `POST /api/archie/classes/delegation` | `delegate` | `ask_first` |

- The mode is the protected settings row `owner_proof_mode` (added to
  `PROTECTED_HUMAN_KEYS`: only the human token writes it, and the worker signs
  it). `protectedMode` takes an optional force variable.
  - No row or `shadow`: the request goes through. A request with no proof logs
    one `[owner-proof] would-refuse route=<r> actor=<a> why=<why>` line. A
    box-commands owner type still needs an owner `actor` in shadow, as before.
  - `enforce`: box-commands answers `403 {error:"owner_only"}` with one
    `box_command_refused` audit row (outcome `refused:owner_proof`). The staff
    and archie routes answer `403 {error:"human_proof_required"}`. Nothing else
    is written.
  - The settings read fails: 503, nothing written.
  - Worker env `OWNER_PROOF_ENFORCE=1` forces enforce. `HUMAN_VERDICT_ENFORCE`
    does not.
- A box-ops proven box command records the proven identity as `requested_by`.
- Pages (`console-ui/functions/api/coord/[[path]].js`): a write row flagged
  `boxOps: true` gets the two headers from `functions/_lib/box-ops-proof.js`
  `boxOpsHeaders`, only when Access verified the identity and `BOX_OPS_TOKEN`
  is set. Flagged rows: `box-commands`, `staff/agents/autonomy`,
  `staff/classes/delegation`, `staff/promotions/decide`. The human verdict
  token is never read under `console-ui/functions`
  (`console-ui/tests/coord-box-ops.bh-9262.test.js` G1 walks every file).

## Env to set

- `BOX_OPS_TOKEN`: a new random value. Set it as a jobs worker secret
  (`wrangler secret put BOX_OPS_TOKEN`) and on the console Pages project,
  production and preview. Never on a box, the hub or in an env bundle.
- `BOX_OPS_OWNERS`: jobs worker secret, already set by BH-5750.
- `CF_ACCESS_TEAM_DOMAIN`, `CF_ACCESS_AUD`: on the Pages project (BH-2515).
  Without them Pages sends no proof.

## Rollout

1. Deploy. With no `owner_proof_mode` row the mode is shadow and no answer
   changes.
2. Provision the env above.
3. C1: `bin/archie.sh` delegate and `bin/box-request.sh` get a proof or the
   pending-approval fallback.
4. After C1 merges and one day with no unexplained `would-refuse` line in
   `wrangler tail`, the owner sends a human-token
   `PUT /api/settings {key:"owner_proof_mode", value:"enforce"}`.
