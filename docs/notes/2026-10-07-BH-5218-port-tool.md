# Port merged changes to cromford-ai/cromford as a PR (BH-5227, part of BH-5218)

Doc: PUBLISH-CROMFORD

## What changed

- New `bin/port-to-cromford.sh`. It takes one merged upstream range and opens a
  PR with it on the public copy. It never pushes to the target's default branch.
- New `bin/share/port.py plan <upstream> <from> <to> <staging>`. It curates the
  range file by file with the tables `bin/share/sanitize.py` already has
  (`rewrite`, `rewrite_path`, `dropped`, `PATCHES`, the overlay), and writes
  `port-manifest.json` next to the staging tree.
- New `port_cursor` table in `worker/jobs/schema.sql`, served by
  `GET|PUT /api/port/cursor` (`worker/jobs/src/routes/port-cursor.js`), with
  the client in `bin/lib/port-cursor.sh`. It holds the last upstream sha ported
  to each target and the PR that carried it.
- `bin/share/sanitize.py` keeps `bin/port-to-cromford.sh` and
  `tests/port-to-cromford.bh-5227-test.sh` out of the whole-tree publish.

## Usage

Run it from the upstream checkout:

```
bin/port-to-cromford.sh [--dry-run|--apply] [--repo owner/name] <from>..<to> | <PR-number>
```

- `--dry-run` is the default. It prints the range, every stripped path with
  its reason, the dollar amounts it redacted and the diff against a shallow
  clone of the target. Everything happens in a `mktemp -d` dir that is
  removed on exit.
- `--apply` pushes `port/<to12>`, opens the PR against the target's default
  branch, then moves the cursor to `<to>`.
- `--repo` defaults to `cromford-ai/cromford` and must be an exact line of
  `catalog/share-publish-targets.conf`.
- A PR number must be MERGED. It ports `<merge>^1..<merge>`.
- `PORT_TARGET_URL` overrides the clone and push URL. The default is
  `https://github.com/<repo>.git`.

Exit codes: 0 ported, or nothing to port. 1 refused, failed, or the cursor
compare-and-set was lost. 2 could not run.

## The cursor rule

With C the stored cursor for the target:

| State | Result |
|---|---|
| cursor unreadable (worker down, `JOBS_URL` unset, table not deployed) | exit 2, never read as "no cursor" |
| no row | the range as given |
| `<to>` is C or behind it | `nothing to port`, exit 0 |
| commits in `C..<from>` | `would skip N commit(s)`, exit 1 |
| C is not an ancestor of `<to>` | exit 1 |
| otherwise | the range becomes `C..<to>` |

The cursor only moves with a PR URL in hand, by compare-and-set on C. If a
sibling moved it first, the run prints an `ALERT port-to-cromford:` line on
stderr and exits 1. The PR stays open. A range where every changed path is
stripped opens no PR and leaves the cursor where it is.

If a run dies between creating the PR and writing the cursor, re-run it. It
finds the PR for `port/<to12>` with `gh pr list --state all` and goes straight
to the cursor write.

## What is stripped

The first matching rule wins, and the path is listed with its reason in the
output and the PR body (under its public name):

- internal record: `.harness/`, `tasks/`, `docs/notes/`
- fleet setup: `fleet.conf`, `vercel.conf`, `cron/`, `fly/warm-env/`,
  `catalog/share-publish-targets.conf`
- publisher machinery: `bin/share/`, `bin/publish-share.sh`,
  `bin/port-to-cromford.sh`, `tests/port-to-cromford.*`
- anything the public overlay replaces
- anything `sanitize.dropped()` drops

Directory rules match whole path segments, so `docs/notes-ish/` and
`tasks-list.md` are ported. In `*.md` files only, dollar amounts such as
`$12,500` or `$3.5 M` become `$N`. `$PATH`, `${VAR}` and `$N` are left alone.

`bin/share/leakcheck.py` and `bin/share/gitleaks-gate.py` scan the staged files
in both modes, and in `--apply` `leakcheck.py` also scans the PR body. A hit
exits 1. A gate that could not run exits 2. Either way nothing is pushed.

## Use one channel per target

Use this tool or `.github/workflows/publish-cromford.yml` for a target, never
both. The workflow force-publishes the whole sanitized tree onto main, which
does not know about the cursor or about any open port PR.

## Two human steps before the first `--apply`

1. Deploy the jobs worker. `bin/harness-sync.sh` applies `schema.sql`, which
   creates `port_cursor`. Until then both modes exit 2 `cursor unreadable`.
2. `--apply` needs a `gh` and git credential with push and PR-create rights on
   `cromford-ai/cromford`.
