# web-task TOTP codes from the vault (BH-7596, slice C0)

Doc: DB-COORDINATION-SPEC

## What changed

A web-task lane run must pass a site's 2FA step without the model seeing the
TOTP secret or the code. This slice adds the code generator and the vault
provider. It does not add the `type_otp()` tool action, the retry on a
refused code or the fixture-site TOTP page. Those need the web-task agent and
fixture site of #7594 (web-task S1) and are slice C1, owed on #7596.

- `bin/lib/totp.mjs`: RFC 6238 TOTP, node:crypto only.
  - `node bin/lib/totp.mjs code [--digits N] [--step S] [--algorithm A]`
    reads the base32 secret from stdin and prints the code with no newline.
    Defaults: 6 digits, 30 s step, sha1. Digits 6..10, step an integer >= 1,
    algorithm `sha1`, `sha256` or `sha512`. These are the bounds of the
    format, not tunable limits.
  - `node bin/lib/totp.mjs next-window [--step S]` prints the seconds left
    in the current step. C1's retry waits this long for the next code.
  - Bad input: rc 2 and one stderr line `totp: bad <parameter>`. The line
    never holds the value.
  - The secret may be in groups, in lower case, with `-` and trailing `=`.
    Spaces, `-` and trailing `=` are removed and the text is upper-cased.
  - Clock: env `TOTP_NOW` (unix seconds), else the system clock.
- `bin/lib/web-totp.sh`: `wt_totp_code <project> <site>`, sourced.
  - Reads `totp_secret` (required) and `totp_digits`, `totp_step`,
    `totp_algorithm` (optional) through `wv_read`, so it runs only inside a
    claimed web-task lane run on its claiming machine.
  - An optional field with no vault row (`refused no_entry`) takes the
    default. Any other refusal stops with rc 1.
  - rc 0: the code on stdout, no newline. rc 1: `web-totp: no totp_secret`
    or the vault refusal. rc 2: a stored value the generator refuses
    (`web-totp: bad totp_<field>`). A stored value is never clamped.
  - The secret goes to `totp.mjs` on stdin only. It is never on an argv, in
    a file or in a log. The code is only on stdout.

## Operator step

Get the base32 secret from the site's "can't scan the QR code" text when you
turn on 2FA. Store it with the value on stdin:

```bash
bin/web-vault.sh set <project> <site> totp_secret
```

If the site uses other settings, store them the same way (one value each):
`totp_digits` (6..10), `totp_step` (seconds), `totp_algorithm`
(`sha1|sha256|sha512`). Most sites use the defaults, so do not set them.

## What C1 adds

- S1's otp seam calls `wt_totp_code` at the moment of typing.
- The `type_otp()` tool action in S1's agent loop. The model sees neither the
  secret nor the code.
- A refused code: wait `next-window` seconds, retry once, then stop with
  "otp refused".
- The fixture site TOTP page and its test, and the real-site proof on a site
  the operator names.

Tests: `tests/web-task-totp.bh-7596-test.sh`.
