# BH-4658 (BH-4656 part 1): the PR snapshot, and lead-review-enqueue reads heads through it

Doc: GH-REST, VERIFICATION-MAP

## Why

`bin/lead-review-enqueue.sh` runs every 5 minutes on the hub and, for every
open non-draft PR on every repo in `LEAD_REVIEW_AUTO_REPOS`, made one live
`GET pulls/<n>` to learn the head. On a quiet hour almost none of those heads
had moved. BH-4656 puts those reads behind one shared on-disk snapshot; this
part ships the library and converts this one lane. The conductor,
batch-resolve, stuck-work and mc conversions, and the wakes file, are sibling
tickets.

## What changed

- **`bin/lib/pr-snapshot.sh`** (new, sourced). Store:
  `state/pr-snapshot/<owner_repo>/` with `open.json` + `open.meta` +
  `open.lock`, `base-<ref>` (`<epoch>\t<sha>`), and `pr-<n>.json` +
  `pr-<n>.key` + `pr-<n>.lock`.
  - `prs_open_list <slug> <out>`: the open list, reused inside
    `PR_SNAPSHOT_TTL_S` (or `PR_SNAPSHOT_QUIET_TTL_S` when `prs_wake_seen`
    says no wake arrived since it was cached). A refresh takes `flock -n
    open.lock`, writes by tmp + `mv`, then rewrites `open.meta`.
  - `prs_base_tip <slug> <base>`: one `GET git/ref/heads/<base>`, cached for
    `PR_SNAPSHOT_TTL_S`, re-read early on a `push` wake for that base.
  - `prs_pr_get <slug> <n> <head> <updated_at> <base> <out>`: the `pulls/<n>`
    body, cached under the key `(n, head, updated_at, base tip)`.
  - `prs_gc`: deletes `pr-*` files older than 3 days. The lane calls it once a
    tick, so closed PRs do not pile up.
  - `prs_wake_seen`: answers 2 (unknown). `bin/lib/pr-snapshot-wakes.sh`, a
    sibling ticket, replaces it when the file is present.
- **`catalog/lanes.d/_lib.pr-snapshot.json`** (new): the four knobs, all
  `required` with registry defaults (`PR_SNAPSHOT` 1, `PR_SNAPSHOT_TTL_S` 60,
  `PR_SNAPSHOT_QUIET_TTL_S` 300, `PR_SNAPSHOT_FEED_STALE_S` 900). They
  resolve through `lib_env_apply pr-snapshot` in a subshell, as
  `bin/lib/gh-budget.sh` does: settings row > cached row > env > registry
  default. No TTL literal is in code. `PR_SNAPSHOT_FEED_STALE_S` is resolved
  here and acted on by nothing yet; the wakes sibling reads it.
- **`bin/lead-review-enqueue.sh`**: the list read asks for `headRefOid` and
  `updatedAt` too (still the REST path of `harness_pr_list`, no extra read).
  The head read is `prs_pr_get`, and each repo logs
  `<owner/repo> PR-SNAPSHOT hit=<n> miss=<n>`. The 40-hex check, the compare
  read and everything after are unchanged.

## The cache key, and why a hit is still the live head

A hit needs every one of these:

- head, `updated_at` and base tip all non-empty and not `-`;
- `pr-<n>.key` equal to the key byte for byte;
- the cached body's `.head.sha` equal to the head;
- no `pr` wake for `<n>` since the key was written.

A body is stored only when GitHub answered 2xx, its `.head.sha` is the list's
head, `mergeable` is not null and `mergeable_state` is not `unknown`. A null or
`unknown` means GitHub is still computing the merge; caching it would freeze
that answer. A push moves the head and `updated_at` on the list, so the key
stops matching. A push to the base moves the tip. Either way the next read is
live. So the head a hit returns is the head GitHub last reported live.

## Never wait, never serve stale

Both locks are `flock -n`. A lane that loses the open-list lock reads the list
for itself and writes nothing. A lane that loses a `pr-<n>.lock` skips the
store. A refresh that fails (44 or 75) leaves `open.json` and `open.meta` as
they were, empties the caller's output, and returns the code; a cache past its
TTL is never served. Losing any file costs one live read, never correctness.

## Kill switch

`PR_SNAPSHOT=0` (settings key `lib.pr-snapshot.pr_snapshot`): every function
calls GitHub straight through and nothing under `state/pr-snapshot` is read or
written. `PR_SNAPSHOT_TTL_S=0` does the same for all three caches. An empty or
non-numeric value means off. A box without the lib file runs the lane's
fallback, today's live `pulls/<n>` read, and still logs `hit=0 miss=<n>`.

## Cost

The lane adds one `GET git/ref/heads/<base>` per repo per tick (TTL 60s
against a 5-minute tick, so it is read every tick). It saves one `pulls/<n>`
per open PR per tick whose head and base did not move.
