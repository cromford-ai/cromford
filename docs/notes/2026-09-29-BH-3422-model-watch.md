# The model-watch lane (BH-3422, built in BH-3429)

Doc: OPERATOR-SETUP

## What changed

`bin/model-watch.sh` is a new hub cron lane (`cron/lanes/720-model-watch.cron`,
daily at 05:47Z behind `hub-lease.sh check`). It is the first caller of the
BH-3422 contract: `bin/lib/model-watch.sh` (#3425), the `model_watch` routes
(#3426) and `bin/lib/model-watch-suggest.sh` (#3427).

Each run:

1. Gate, then the `model-watch-off` switch, then `MODEL_WATCH_ENABLED`, then
   `flock -n`. All four come before any network call.
2. Fetch OpenRouter `/api/v1/models`. When `anthropic` is watched and
   `ANTHROPIC_API_KEY` is set, it also fetches Anthropic `/v1/models`. The key
   goes in a header file, never in argv or a log. A list with fewer than
   `MODEL_WATCH_MIN_LIST` entries, a 5xx or junk counts as an outage. That means
   one warn alert with id `model-watch-fetch` and nothing recorded.
3. Build the known set from `GET /api/model-prices`, `catalog/model-prices.json`
   and `catalog/model-slugs.json`, all through `mw_norm_id`. If any of the three
   is unreadable, or the `model_watch` list is, the lane sends one warn alert
   with id `model-watch-known` and records nothing.
4. Record every watched-vendor model whose `(vendor, mw_norm_id)` is unknown and
   has no row yet.
5. Announce up to `MODEL_WATCH_MAX_NEW` unannounced `new` rows, oldest first.
   Each one is a critical `lane-alert` with id `model-watch:<vendor>:<id>`,
   sent first, and then the row is stamped with `announced_at`, `status` and
   `suggestion`. An anthropic row is probed only when a hub route could take
   it. `mw_probe_run` stamps `probe_attempted_at` before it spends.
6. Write one summary line to `logs/model-watch.log`. Warnings go to
   `logs/model-watch.notes.log`.

The lane never writes a route. The `Approve:` line in the message names
`bin/model-watch-approve.sh`, and only a human runs it.

## Knobs

`catalog/lanes.d/model-watch.json`, settings rows `lane.model-watch.<env lowercased>`:
`MODEL_WATCH_ENABLED` (1), `MODEL_WATCH_VENDORS` (`anthropic`),
`MODEL_WATCH_PROBE_USD_CAP` (0.25), `MODEL_WATCH_MAX_NEW` (5, 1..20),
`MODEL_WATCH_MIN_LIST` (5). An out-of-range value gets one warn line and the
default. It is never clamped.

## Off

Use the `switch.model-watch-off` settings row, `flags/model-watch-off`,
`MODEL_WATCH_ENABLED=0`, or `bin/harness-ctl.sh off model-watch`.

## Choices a reader might not expect

- The vendor name is its own OpenRouter prefix (`anthropic`, `x-ai`). There is
  no hand-kept vendor map.
- Only the hub ladders (`GET /api/model-routes`) are matched. Project overrides
  are not read.
- `stats.cost_stage` is null, not `probe`, for two reasons. The probe runs with
  `AGENT_CALL_LEDGER=0`, and `bin/bootstrap-machine.sh` also uses the `probe`
  stage, so its cost would have been attributed to this lane.
- CLI versions are read as the raw `GET /api/metrics/cli-versions?limit=200`
  body, because `mw_cli_lag` takes JSON. The `metric-cli-versions-list` verb
  prints TSV.
