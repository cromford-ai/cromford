# BH-7164: three harness-jobs read shapes under 5,000 rows a call

Doc: docs/OUTSIDE-DEADMAN.md

## What changed

- `GET /api/progress/stamps`, cost section. It no longer sums every priced
  `cost_rows` row of the widest window on each call (129,155 rows a call
  live on 2026-10-16). `worker/jobs/src/lib/cost-hourly.js` folds the rows
  above a rowid watermark (`cost_fold_mark`) into hourly buckets
  (`cost_project_hourly`, one row per project and hour) in one D1 batch. It
  then reads 3 things in parallel: the raw rows from the short cut or the
  current hour (per stage), the raw rows of each window's partial first hour,
  and the whole-hour buckets. The response fields and values do not change.
  If the fold or a bucket read throws, the section logs one line and runs the
  old single query.
- A watermark above `MAX(rowid)` (the table emptied or renumbered) clears the
  buckets and refolds from 0.
- `GET /api/artifacts`: new index `idx_artifacts_kind_updated` on
  `job_artifacts(artifact_kind, updated_at)`. The route walks one kind newest
  first and stops at the LIMIT, with no sort. The route SQL does not change.
- Retention rule `cost_project_hourly.age`, settings row
  `retention.cost_project_hourly.days` (400). The buckets are a cache:
  `cost_rows` keeps every row. Keep the window at 31 days or more, because the
  route reads up to 30 days of buckets.

## Numbers (seeded volume, BH-6727 fixture, VOLUME_SCALE=1)

- Cost section, second call: fold 100 rows, raw recent 129, edges 29 and 28,
  buckets 2,171. The old single read covered 22,331 rows on the same fixture.
- Artifacts, `kind=pr_url&project=alpha&limit=100`: 1,293 index entries
  walked. The old plan read and sorted 9,834. With `since=` 24 h: 164.
- Live after-numbers need the deploy and 24 h of D1 analytics.

## Rounding

`spend_long` is now summed per project and rounded once. The old code rounded
after each (project, stage) row, so a project with several stages can differ
by a cent from the old value. `spend` (per stage) is unchanged.
