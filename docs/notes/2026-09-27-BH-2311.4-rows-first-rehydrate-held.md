# Rows first: every-tick pr-state rehydrate and the held-page read

Doc: MERGE-CONDUCTOR

BH-2361 (BH-2311.4), the last slice of #2311. Both halves close the same hole:
a rebuilt hub, or a pager with no local mark, paged again about something the
worker already knew was paged or held. Flag down (`pr-state-rows` off) nothing
changes on any box.

## What changed

**`mc_rows_rehydrate` (`bin/lib/mc/settle.sh`).** A non-empty `pr-state.tsv` used
to return before any request. With the flag up it now reads the `pr_state` view
on every `mc_init` (`mc_rows_rehydrate_view --merge`) and, only on a COMPLETE read
(rc 0, not capped, not cursor-broken, not empty), merges it into the file in
`mc_rows_merge`:

- keys match with the repo case-folded, number exact (BH-1841);
- a local row with no view row is kept;
- a local row whose numeric `since` is newer than the view's is kept (a
  transition whose event write failed);
- on the SAME state and `since` the local row is kept too. `mc_transition`
  refreshes head, reviewed and reason in the file with no event write, and a
  mark whose event POST failed is in the file alone, so the view is behind
  there. Only the view's `alerted` mark can land: where the file has `-`, or an
  earlier mark for the same entry (`STATE@since@day`, a later day). Taking the
  view's head there made a page held for the current head release as "moved"
  (review D12);
- otherwise (the view's `since` is newer) the view's columns land under the
  local key spelling;
- view-only rows are added.

The fetch runs outside any lock. The merge re-reads the file under
`mc_row_put`'s own `$MC_ROWS.lock` and holds it only for one awk and one `mv`,
so a row written during the fetch survives. An outage, a truncated view or an
empty one leaves the file as it is and never asks the ledger. The BH-1831
`<tick>.pr-rows-down` latch skips the read for a caller that exports
`MC_TICK_ID` before `mc_init`; merge-conductor.sh sets its tick id later, so
there it never fires. An EMPTY file keeps its old path:
view first, then `ledgers(kind=pr_state)` on rc 1. One log line per merge:
`pr-state rehydrate(merge): N from view, K local kept newer, A added`.

**The held check (`bin/lib/mc/log.sh`, `bin/lib/jobs/conductor.sh`).**
`mc_hold_cached`, the pre-send check `mc_stuck_check` and `mc_budget_check` run
before `mc_alert` (and `mc_hold_page` before a PUT), now asks the worker's
whole held list first. `held_pages_whole` returns the rows only when their
count equals `n_total` (rc 3 truncated, rc 1 unparseable). `mc_hold_rows_load`
reads it once per tick into `<tick>.held-rows.tsv` in `MC_TICK_DIR`;
`mc_hold_tick_begin` loads it after its flush, so the fan-out subshells find
it, and a path that never ran tick_begin loads it lazily. The rows can only add
a "held" answer (repo case-folded); not listed falls to the local tick cache as
before. Any failure latches `<tick>.held-rows.down` with one log line
(`held rows unreadable (rc=N) — local held marks decide`, quiet on a 404) and
the local cache decides for the rest of the tick.

The order of mark and send in both pagers is unchanged.

## Limits

The held route deletes a row on release, so it answers "held", never "already
paged". A STUCK page flushed and released on a box whose marker file then died
is not recoverable from it. BUDGET marks do come back, through the rehydrate.
