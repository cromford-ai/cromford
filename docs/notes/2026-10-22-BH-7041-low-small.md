# A low-small risk class: small code heads skip the lead review (BH-7041)

Doc: OPERATING

## What changed

Before this change the risk tier gave `low` only to docs, console screens and
new test files. 0 of 777 cached heads were low, so the tier skipped no lead
review.

`bin/lib/risk-tier.sh` has two new functions, `rt_low_small` and
`rt_low_small_apply`. `rt_classify` does not change. Both callers of
`rt_classify` (the hub enqueue `bin/lead-review-enqueue.sh` and the worklist
gate `bin/lib/lead-gates.d/60-risk.sh`) call `rt_low_small_apply` right after
it, on a head classified in that call. The two callers share
`state/lead-review-enqueue/risk.tsv`, so a head gets the same answer from the
lane that sees it first.

A `medium` head is low-small when all of these are true:

- Its own lines (additions + deletions, `.harness/specs/*` left out) are 1 or
  more and less than `min(risk_tier.low_small_lines, 250)`. Rule 3
  (`high_lines`) still counts every line.
- No path is in the constant floor `RT_LOW_SMALL_DENY`, the current high or
  sensitive rows, or the lead protected paths. A settings row can not remove a
  floor path. The floor adds `worker/jobs/schema*`, `worker/*/schema.d/*`,
  `.github/*`, `.mergify.yml`, `catalog/lanes.d/*`, `bin/lead-*`,
  `bin/lib/risk-tier.sh`, `bin/lib/lead-*`, `rules/*` and `cron/*` to the high
  and sensitive defaults.
- Every existing test file is modified in place (not a helper or a fixture). Its
  patch loses no assertion line (`RT_LOW_SMALL_ASSERT_RE`: a call of `ok`,
  `bad`, `eq`, `check`, `want`, `same`, `fail` or `pass`, or any `assert`,
  `expect` or `FAIL`), and gains no `exit 0` and no `skip`.
- Every read is whole. A read that fails is never low-small.

Under `enforce`, a yes becomes `low` with reasons `low-small: ...` (risk.tsv
column 8 `low-small`), and the existing low path signs it off. The REQFOR
(BH-5630) and silence (BH-5797) refusals still hold, and a lead-authored head
is still reviewed. Under `shadow`, a yes writes one
`risk-tier WOULD sign off (low-small: ...)` line, and the head stays medium. A
no writes one `low-small no (<why>); medium` line.

## The knobs

- `risk_tier.low_small_mode`: `off`, `shadow` or `enforce`. No row = `shadow`.
  Any other value, or a row that can not be read, is `off` for the tick, with
  one `<repo> risk tier: ...` log line.
- `risk_tier.low_small_lines`: no row = 250. A value over 250 reads as 250. A
  value that is not an integer turns low-small off for the tick.

Only `enforce` (and its line limit) is in `RT_RULES_SIG`. Shadow and off never
change a cached tier, so the deploy keeps every cached tier. A flip to or from
enforce, or a lines change under enforce, reclassifies each open head once.
Under shadow, a head already cached before the deploy gets no WOULD line until
its head moves.

## How to flip to enforce

1. Read one day of shadow lines on the hub:
   `grep 'WOULD sign off (low-small' /root/harness/logs/lead-review-enqueue.log /root/harness/logs/lead-review.log`.
2. Read the replay result in `.harness/specs/BH-7041/replay.md`, or run the
   replay again on the hub (see below), and read each `BLOCK low-small:` line.
3. If both are acceptable, run on the operator's Mac:
   `bin/protected-setting.sh risk_tier.low_small_mode enforce "BH-7041: low-small sign-off"`.
4. To go back, run the same command with `shadow` or `off`.

## The replay

`bin/risk-tier-replay.sh <heads.tsv> [--compare-dir DIR]` is read only. Each
input line is `<owner/repo>\t<pr>\t<head>\t<verdict>[\t<base>]`. It prints one
row per head, the line
`replay: heads=N low_before=A low_small=L blocks=B blocks_low_small=K unreadable=U`,
and one `BLOCK low-small:` line for each BLOCK that it would sign off.

On 2026-10-17 the operator ran it on the hub over 400 lead verdicts:
`low_small=18 blocks=70 blocks_low_small=1` (#7177). The reason that one
BLOCK is acceptable is in `.harness/specs/BH-7041/replay.md`.
