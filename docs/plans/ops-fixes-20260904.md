## 0. Ground rules for every fix

- **DB over files.** The harness-jobs worker + D1 (`worker/jobs/`, client
  `bin/jobs-client.sh`) is the coordination truth. Where a fix replaces a file
  (done marker, lock, pgrep, STATE.md prose, plan marker), the D1 row is primary and
  the file is the documented degraded fallback used only when `_jobs_req` returns
  rc 1 (worker unreachable — the `transport rc=28` case of 2026-09-03 18:01:52Z).
- **Schema is additive and re-applied on every deploy** (`worker/jobs/schema.sql:4-8`).
  New tables only, every statement `IF NOT EXISTS`, seeds `INSERT OR IGNORE`. A
  column on an existing table is allowed only via the `ensurePrCostsColumns`
  pattern (`worker/jobs/src/index.js:646-677`) AND the CREATE list, kept in sync.
- **Every write idempotent** (PK upsert / `ON CONFLICT`), **every read bounded**
  (`limit` clamped server-side, 1..1000, like `/api/metrics/extra-usage`).
- **No secrets in any row, `meta` included.** Tokens are exported from
  `/root/harness/env/*.env` with `set -a; . file; set +a`, never placed in argv.
- **Client contract stays fail-open**: one curl, `JOBS_TIMEOUT=5`, rc 0/2/9/1, one
  ALERTS line per day (`bin/jobs-client.sh:46-89`).
- **Worker tests**: `worker/jobs/test/index.test.js` stubs D1 by SQL pattern. Every
  new SQL shape needs a `fakeDB` branch or the handler reads `undefined`. Run with
  `cd worker/jobs && npm test`; `tests/jobs-worker-test.sh` bridges it into CI.
- **Shell tests**: `tests/<name>-test.sh`, `set -uo pipefail` (never `-e`),
  `ok()/bad()` counters, `$T=$(mktemp -d)`, fake `curl`/`claude`/`gh` on a
  `$T/fakebin` PATH, `HARNESS=$T` override, last line `[ "$FAIL" -eq 0 ]`.
  Template: `tests/with-job-test.sh`. CI globs `tests/*.sh` (`harness-ci.yml`
  `decisions` job) and runs `bash -n` + `shellcheck --severity=error` on `bin/*.sh`.
- **Stage names** passed to `agent-call.sh` are `^[a-z][a-z0-9_]*$` and must have a
  row in `catalog/context-budgets.json` (`tests/context-budget-manifest-test.sh:406-473`
  enforces both directions).
- **Console**: if a browser must read a new endpoint, widen the GET allowlist in
  `console-ui/functions/api/coord/[[path]].js:72-74` (out of scope unless named).
- **Deploy is NOT part of any PR here.** A PR whose D1/worker change is merged is
  inert until the orchestrator runs the `console-deploy` skill (schema apply +
  `wrangler deploy`) and `harness-sync.sh`/`update-runners.sh` land `bin/` on the
  boxes. Each PR body states which of those it needs.

## Fix 3 — Lane liveness + STARTED marker (`bin/lane-launch.sh`, `bin/lane-status.sh`)

### Problem (evidence)
- 2026-09-02 ~20:5xZ: the PR #192 deploy lane was reported RUNNING by the
  orchestrator from an unanchored `pgrep -f` that matched its own prompt text; the
  lane had never started (STATE.md turn "cost-rows-deploy lane … still RUNNING").
- 44 launchers in `/root/orchestrator/orc-*.sh` and 13 `builds/*/run.sh` call
  `claude` directly: no D1 row, no heartbeat, no cost row, no stage/budget, no
  STARTED marker, `.done` file written by the process that can be SIGKILLed
  (`bin/orc-job.sh:6-11` names exactly this failure, 2026-08-27 17:48Z).
- `bin/orchestrate.sh:280,299,304` put the orchestrator token in argv:
  `env IS_SANDBOX=1 ${ORC_TOKEN:+CLAUDE_CODE_OAUTH_TOKEN=$ORC_TOKEN} claude …`, and
  `bin/disk-clean.sh:22` / `bin/preplan-tick.sh:16` run `pgrep -af` on every box.
- Unanchored `pgrep -f` liveness: `bin/preplan-tick.sh:10,12,16`,
  `bin/quiesce-for-resize.sh:14,19`, `bin/disk-clean.sh:22`. The anchored fix
  already exists once: `bin/count-builds.sh:11`.

### Design
**Primary record: a D1 `lane_runs` row keyed to a `jobs` row (kind=`lane`).**
The launcher never returns "started" until it has observed the claude child pid.

`bin/lane-launch.sh` (single canonical wrapper, hub + boxes):
```
lane-launch.sh --name <slug> --stage <stage> --prompt <file>
               [--project <p>=orchestrator] [--model <m>=$EXECUTE_MODEL|claude-opus-5]
               [--timeout <s>=14400] [--expected-by <ISO8601|+NNm|+NNh>=+4h]
               [--cwd <dir> | --worktree <branch> [--base origin/main]]
               [--env <name>.env ...] [--done-marker <path>] [--budget-usd <n>]
```
Behaviour, in order:
1. Validate `--name` (`^[a-z0-9][a-z0-9_-]{2,40}$`), `--stage` (`^[a-z][a-z0-9_]*$`
   AND present in `catalog/context-budgets.json .lanes[].stage`; refusal text lists
   the known stages — the fix-8 half of this), `--prompt` readable, `--expected-by`
   parses. `--cwd /root/harness-checkout` (or any path under it) is REFUSED:
   "lanes work in worktrees; use --worktree <branch>" (fix-4 enforcement).
2. `--worktree`: `git -C /root/harness-checkout worktree add /root/wt-orc/<name> -b <branch> <base>`
   (prune first; refuse if the dir exists and is dirty).
3. Env: `set -a; . env/global.env; [. env/<x>.env …]; set +a`. Nothing on argv.
   `GH_TOKEN` is exported from `github-admin.env` the same way when `--env github-admin.env`.
4. Write the local fallback record `state/lanes/<name>.json`
   `{name,stage,project,host,box,launcher_pid,spec,cwd,expected_by,started_at:null,claude_pid:null,status:"launching"}`.
5. `setsid bash lane-launch.sh --_inner <same args> </dev/null &` — the inner runner:
   a. `job_lane_open "<stage>/<project>/claude" "<name>" lane '{label,spec,cwd,host,expected_by,launcher_pid}'`
      (rc 9 refusal → inner writes `status:"refused"` + reason to the state file and
      exits 3; the launcher relays it and exits 3). rc 1 → no row, continue (fail-open).
   b. `lane_run_put` (new verb) → `PUT /api/lane-runs` with
      `{job_id,name,host,box,pid:$$,spec_path,cwd,expected_by,status:"launching"}`.
   c. Runs `agent-call.sh <stage> <project> <model> <timeout> builds/<name>/run.txt "@<prompt>"`
      in the background (cwd = `--cwd`/worktree). `agent-call.sh` gives the budget
      from the catalog, the cost.csv row, `$OUT.model/.runner`, and a `job_phases`
      row because `JOB_ID` is exported by `job_lane_open`.
   d. Verifies the claude child: up to 90s, walk `pgrep -P` from the agent-call pid
      down (never `pgrep -f`), accept a process whose `comm` is exactly `claude`
      (or `node` whose argv[1] basename is `claude`). On success: `lane_run_put`
      `{status:"running", claude_pid, started_at}` + `job_event <job> lane STARTED "pid=<n> host=<h>"`
      + write `builds/<name>/STARTED` (fallback marker) + state file `status:"running"`.
      On timeout: `lane_run_put {status:"launch_failed"}`, `job_event … LAUNCH_FAILED`,
      one ALERTS line `[lane-launch] <name> NEVER STARTED (no claude child after 90s) — read builds/<name>/run.txt.err`,
      kill the agent-call subtree, close the job `failed`, exit 1.
   e. Waits for agent-call; closes with the real rc: `lane_run_put {status: done|failed, rc, finished_at}`,
      `job_lane_close <rc>`, writes `--done-marker` (default `builds/<name>/DONE` containing `rc=<n> <ts>`).
      TERM/INT trap closes with 143 exactly like `with-job.sh:80-88`.
6. The launcher polls the state file for `status` ∈ {running, refused, launch_failed}
   (max 120s) and exits 0 only on `running`, printing `STARTED <name> job=<id> pid=<n> expected_by=<ts>`.
   Any other outcome is a non-zero exit with the reason on stderr — a launcher that
   returns 0 has proven a live claude pid.

`bin/lane-status.sh [<name>|--all] [--json]`:
- Reads `GET /api/lane-runs?name=<n>` (or `?open=1`) — the DB is the answer.
- Falls back (rc 1 from `_jobs_req`) to `state/lanes/<name>.json` + `kill -0 <claude_pid>`
  and says so: `source=file (worker unreachable)`.
- Never uses `pgrep -f`. Prints `name status host pid started_at expected_by overdue=<yes|no> last_beat_age_s`.

`bin/jobs-watchdog.sh` addition (hub, `*/5`, already exists): after the job-orphan
loop, `GET /api/lane-runs?overdue=1` → one ALERTS line per overdue lane, latched in
D1 (`lane_runs.alerted_at`), cleared with `LANE DONE` when it closes — "nothing waits silently".

**Token-on-cmdline**: `bin/orchestrate.sh:162,280,299,304` → read the token in a
subshell and `export CLAUDE_CODE_OAUTH_TOKEN` before `claude`; remove `${ORC_TOKEN:+…}`
from all three invocations; keep the three `--max-budget-usd "$ORC_BUDGET"`
occurrences (`tests/turn-budget-test.sh:43-45` asserts exactly 3). Replace
`cut -d= -f2` with `cut -d= -f2-`.

**pgrep hygiene**: anchor `bin/preplan-tick.sh:10,12,16`, `bin/quiesce-for-resize.sh:14,19`
with the `count-builds.sh:11` pattern (`^[^ ]*bash /root/harness/bin/run-build\.sh`);
`bin/disk-clean.sh:22` keeps `-af` but filters with the same anchored regex.

### D1 (additive; `worker/jobs/schema.sql`)
```sql
CREATE TABLE IF NOT EXISTS lane_runs (
  job_id TEXT PRIMARY KEY,        -- jobs.id (kind=lane)
  name TEXT NOT NULL,             -- the --name slug; one open row per name
  host TEXT, box TEXT,
  pid INTEGER,                    -- inner runner pid
  claude_pid INTEGER,             -- verified child; NULL until observed
  spec_path TEXT, cwd TEXT,
  status TEXT NOT NULL,           -- launching | running | done | failed | launch_failed | refused
  rc INTEGER,
  expected_by TEXT,
  started_at TEXT, finished_at TEXT,
  alerted_at TEXT,                -- overdue latch (watchdog)
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_lane_runs_name ON lane_runs(name, updated_at);
CREATE INDEX IF NOT EXISTS idx_lane_runs_open ON lane_runs(status, expected_by);
```

## Fix 4 — Hub checkout hygiene (`bin/hub-checkout-guard.sh`, named offender)

### Problem (evidence)
- 2026-09-03 02:00/02:10/02:20Z `harness sync REFUSED: checkout dirty uncommitted: bin/triage-gate.sh`; 2026-08-31 the hub checkout was left on a PR branch (STATE.md:39-41); `harness-sync.sh:37-38` syncs against `origin/<whatever HEAD is>` so a checkout parked on a branch reads "fresh".
- The alert says "a human must resolve it" but never says WHICH lane did it.

### Design
- `bin/harness-sync.sh --check` gains a branch check: HEAD must be `main` (or the
  branch named in `flags/harness-sync-branch`, a deliberate pin); otherwise
  `echo "on branch <b> (expected main)"; return 30`.
- `bin/hub-checkout-guard.sh [--fix]` (hub cron `*/10`, beside `fleet-status-push`):
  1. Runs the same dirty/branch classification as `harness-sync.sh --check` (share
     the function: move `check_freshness` into `bin/lib/checkout-state.sh`, sourced by both).
  2. On a violation, identifies the offender from D1: `GET /api/lane-runs?open=1`
     rows whose `cwd` is under `/root/harness-checkout`, plus `GET /api/jobs?status=running&box=<hub>`
     with `meta.cwd` under it. Fallback: `state/lanes/*.json` with the same test.
     If nothing claims it: `offender=unregistered (no lane_runs row names /root/harness-checkout — a session launched outside lane-launch.sh)`.
  3. Writes ONE latched ALERTS line (latch = `ledgers` row kind=`hub-checkout`, key=`<hub-box>`, status=`dirty`, detail=`{files,branch,offender}`; cleared with a `RECOVERED` line):
     `[hub-checkout] /root/harness-checkout dirty: bin/triage-gate.sh on branch fix/x — offender: lane ts75-unblock (job build-…, pid 4242, started 01:20Z) — lanes must use worktrees (bin/lane-launch.sh --worktree)`.
  4. `--fix` (manual only, never cron): if the offender lane is terminal in D1 and
     the dirty files are exactly those a merged PR already contains upstream, `git checkout -- <files> && git switch main && git reset --hard origin/main`
     after backing up the diff to `state/hub-checkout-backup-<ts>.patch`. Otherwise refuses.
- `bin/lane-launch.sh` already refuses `--cwd` under the checkout (fix 3).
- `docs/OPERATOR-SETUP.md` + `README.md`: "The hub checkout is READ-ONLY, main-only.
  Work happens in `/root/wt-orc/<lane>` worktrees. `harness-sync.sh` refuses a
  dirty or off-main checkout and the guard names the lane."

## Fix 2 — TEST-CHANGE in the plan + resume provenance/pause

### Problem (evidence)

### Design

## Fix 7 — Budget blind spots (meter backoff + stale-once alert; OpenRouter key-limit probe)

### Problem (evidence)
- `EXTRA-USAGE METER DOWN: no successful poll for 6h/8h/32h (429 for every credential)` fired
  2026-08-30 13:58Z, 08-31 22:58Z, 09-01 00:58Z, 09-02 00:58Z, 09-03 06:58Z, 09-03 21:58Z —
  daily re-alerts (`bin/extra-usage-track.sh:194-224`, `STALE_H=6`, day flag), no backoff
  (a 429 is classified permanent, `:172-180`), and the last good number is not in the alert.
- OpenRouter: probed live 2026-09-04 00:52Z via the provisioning key —
  `box-hub` limit $1,000 usage $1,000.00 (0 remaining), `box-project-2` $242.7/$250 (97%),
  `box-project-4` $328.6/$400 (82%), account credits $10,695 total / $10,552.68 used (~$142 left).
  Nothing in `bin/` reads `/api/v1/keys`, `/api/v1/auth/key` or `/api/v1/credits`; the survival
  lane just tells a human to "check account credits/limits" (`agent-call.sh:1047-1065`).

### Design
**A. Meter (`bin/extra-usage-track.sh`)**
- In-run retry for 429/5xx only: 3 attempts, 5s → 20s → 60s (bounded, 85s worst case).
- Cross-run exponential backoff recorded in D1 first, file second: `ledgers` row
  kind=`meter-backoff`, key=`extra-usage:<box>`, status=`backoff`, detail
  `{attempt, next_try_at, last_http}`; the hourly cron reads it and skips the poll while
  `now < next_try_at` (1h, 2h, 4h, 8h cap; reset on a 200). Fallback file `state/extra-usage-backoff.json`.
- **Stale alert fires ONCE**: threshold `EXTRA_USAGE_STALE_HOURS` default 2 (was 6); the latch is a
  `ledgers` row kind=`meter-stale`, key=`extra-usage:<box>`, status=`alerted`, detail = the last
  good row (`GET /api/metrics/extra-usage?box=<box>&limit=1`, fallback: last CSV line). Alert text:
  `[hub] EXTRA-USAGE METER STALE: last good poll 2026-09-03T15:58Z (weekly 41%, extra_used $1,234.56); 429 on every credential since 17:58Z, backoff attempt 3 next 04:00Z — nothing is watching the bill.`
  Recovery writes `METER RECOVERED` once and sets the row to `clear`. The per-day flag files
  (`flags/alerted-extra-usage-stale-<day>`) are retired.
**B. OpenRouter (`bin/openrouter-limit-probe.sh`, new; hub cron hourly `:40`)**
- Hub (holds `OPENROUTER_PROVISIONING_KEY` in `env/openrouter.env`): `GET /api/v1/keys?include_disabled=false`
  (every key: name, limit, usage, limit_remaining) + `GET /api/v1/credits` (account). Boxes
  (only `OPENROUTER_API_KEY`): `GET /api/v1/auth/key` for their own key, hourly from the same
  `extra-usage-track.sh` cron line (`--openrouter` flag) — limit may be `null` there; then no pct.
- Rows → D1 `provider_key_snapshots` (CSV first: `logs/provider-keys.csv`):
  ```sql
  CREATE TABLE IF NOT EXISTS provider_key_snapshots (
    provider TEXT NOT NULL,         -- openrouter | fireworks | xai
    key_name TEXT NOT NULL,         -- OpenRouter key name, or "_account" for the credit balance
    ts TEXT NOT NULL,
    limit_usd REAL, usage_usd REAL, remaining_usd REAL, pct REAL,
    limit_reset TEXT, disabled INTEGER,
    box TEXT,                       -- who observed it
    PRIMARY KEY (provider, key_name, ts)
  );
  CREATE INDEX IF NOT EXISTS idx_provider_key_ts ON provider_key_snapshots(provider, key_name, ts);
  ```
  `POST /api/metrics/provider-keys {rows:[…]}` (≤200, upsert), `GET /api/metrics/provider-keys?provider=&key=&limit=`
  (newest first; `?latest=1` = one row per key). Client verbs `metric_provider_keys_put`, `provider_keys`.
- **Alert BEFORE exhaustion**: levels 80/90/100 % per key and for `_account`
  (`remaining/total_credits`), latched per (key, level) in `ledgers`
  (kind=`provider-key-alert`, key=`openrouter:<name>:<level>`), cleared when pct drops below
  the level (a raised limit). Text:
  `[openrouter] box-project-4 at 82% of its $400 key limit ($71.43 remaining, ~2.1 days at the 7d rate) — raise the key limit in openrouter.ai/settings/keys or expect the survival lane to fail closed`.
  The 7-day rate comes from the snapshots (bounded query, `limit=200`). First run will
  alert on box-hub (100%), box-project-2 (97%), box-project-4 (82%) and `_account` (98.7%) — state that in the PR body.
- `bin/claude-auth-check.sh` openrouter lane canary (`:151-180`): when the D1 latest row for
  the box's key shows `remaining_usd <= 0`, the `LANE DOWN` alert says `key limit exhausted` instead of a generic lane failure.

## Fix 6 — Orchestrator working memory → D1 (`orc_threads`, `orc_owed`, `bin/orc-ledger.sh`, `bin/orc-context.sh state`)

### Problem (evidence)
- `/root/orchestrator/STATE.md` is 102,971 bytes / 1,502 lines (≈26K tokens) and is inlined
  whole on every turn (`bin/orchestrate.sh:174`, `cat … STATE.md`, no cap) against a declared
  "turn-maintained, capped" budget (`catalog/context-budgets.json` orchestrator-turn) and a
  CLAUDE.md contract of ~12K tokens. 34 of its 60 `##` sections are append-only "Turn …" logs
  from 2026-08-31→09-04. Each probe turn costs $1.3–1.6.
- The OWED ledger (`## OWED TO OPERATOR`, 8 bullets) and thread status live in prose that only the
  model edits, with no validation and no survival-lane update (`orchestrate.sh:402-425`).

### Design
**Tables** (`worker/jobs/schema.sql`, additive):
```sql
CREATE TABLE IF NOT EXISTS orc_threads (
  id TEXT PRIMARY KEY,            -- slug, e.g. pr192-cost-rows-deploy
  title TEXT NOT NULL,
  status TEXT NOT NULL,           -- open | closed
  rung TEXT,                      -- started | built | merged | deployed | live (claim discipline)
  owner TEXT,                     -- orchestrator | lane:<name> | operator | box:<box>
  expected_by TEXT,
  last_evidence TEXT,             -- <=600 chars, the checkable trail; never a secret
  closed_at TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_orc_threads_open ON orc_threads(status, updated_at);
CREATE TABLE IF NOT EXISTS orc_owed (
  id TEXT PRIMARY KEY,
  promise TEXT NOT NULL,          -- <=400 chars
  thread_id TEXT,                 -- orc_threads.id when one exists
  made_at TEXT NOT NULL, expected_by TEXT,
  rung TEXT, closed_at TEXT, evidence TEXT,   -- rung-5 evidence that closed it
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_orc_owed_open ON orc_owed(closed_at, expected_by);
```
**Endpoints**: `PUT /api/orc/threads` (upsert by id; `status` allowlisted; `last_evidence`
truncated server-side to 600 chars), `GET /api/orc/threads?status=open&limit=N` (N clamped
1..100, newest `updated_at` first), `POST /api/orc/threads/:id/close {evidence}`;
`PUT /api/orc/owed`, `GET /api/orc/owed?open=1&limit=N`, `POST /api/orc/owed/:id/close {rung, evidence}`
(refuses `rung != live` unless `{force:true, reason}` — claim discipline in the write path).
Client verbs `orc_thread_put/orc_threads/orc_thread_close`, `orc_owed_put/orc_owed/orc_owed_close`.

**`bin/orc-ledger.sh`** (the turn contract's write tool; idempotent upserts):
```
orc-ledger.sh thread <id> [--title T] [--status open|closed] [--rung R] [--owner O] [--expected-by TS] [--evidence "…"]
orc-ledger.sh owed <id> --promise "…" [--expected-by TS] [--thread <id>]
orc-ledger.sh close-thread <id> --evidence "…" | close-owed <id> --rung live --evidence "…"
orc-ledger.sh list [threads|owed] [--all]
```
Fallback when rc 1: append the same op as a JSON line to `/root/orchestrator/ledger-fallback.jsonl`;
the next `orc-context.sh state` render replays unflushed lines to D1 first (idempotent), then renders.

**`bin/orc-context.sh state`** (new subcommand; hard caps): renders
`## OPEN THREADS (newest 25, of N)` — one line each `[<rung>] <id> — <title> (owner, expected-by, updated) :: <evidence ≤240 chars>`;
`## OWED TO OPERATOR (open, oldest first, max 12)` with an `OVERDUE` prefix when `expected_by < now`;
`## DURABLE FACTS` from `/root/orchestrator/FACTS.md` (a hand-curated static file, `tail -c 6000`).
Total output is truncated at `ORC_STATE_MAX_BYTES` default 24,000 (~6K tokens) with a
`[state truncated: N more open threads — orc-ledger.sh list threads]` trailer. Falls back to
`tail -c 24000 /root/orchestrator/STATE.md` with a `(D1 unreachable — showing the last 24KB of the generated snapshot)` header.

**`bin/orchestrate.sh:174`**: `state=$("$HARNESS/bin/orc-context.sh" state)` replaces the
`cat STATE.md`; after the turn (after `:498-500` append), `orc-context.sh snapshot` regenerates
`/root/orchestrator/STATE.md` from D1 (header: `# GENERATED from harness-jobs D1 at <ts> — read-only; edit with bin/orc-ledger.sh`)
so grep and the survival lanes still have a file. `tests/orchestrator-diet-test.sh` gains the assertions.

**One-time import `bin/orc-state-import.sh --dry-run | --apply`** (hub, run once by the orchestrator):
- `## OWED TO OPERATOR` bullets → `orc_owed` (id = `owed-<sha1 of first 64 chars, 8 hex>`, `made_at` =
  the leading `YYYY-MM-DD HH:MMZ`/`~HH:MxZ` token normalised, `expected_by` from `expected-by|Expected-by ~<time>` when present, promise = bullet text ≤400).
- Bullets under `## Immediate status`, `## Product/build work`, `## Alert work still open`,
  `## Grok 4.6`, `## PR review learning lane` → `orc_threads` status `open`, `rung` parsed from the
  first of MERGED|DEPLOYED|LIVE|BUILT|STARTED|RUNNING in the bullet (RUNNING→started), title = first
  sentence ≤120, evidence = rest ≤600.
- Bullets under `## Turn …` sections → threads with status `closed` unless the bullet contains
  `NEXT|owed|pending|RUNNING|expected-by|still` (then `open`). `## Durable operating facts` →
  `/root/orchestrator/FACTS.md`.
- `--dry-run` prints a table (id, status, rung, title) and counts; `--apply` upserts and writes
  `STATE.md.pre-import-<ts>` beside the file before the first `snapshot` overwrites it.
**`/root/orchestrator/CLAUDE.md` turn-contract text** (hub-only file; the PR ships the exact
replacement as `docs/orchestrator/turn-contract.md` and the deploy step is a hand edit):
replace "Before your final reply, UPDATE STATE.md …" with: "Working memory is the D1 orchestrator
ledger, rendered into your prompt by `orc-context.sh state` (open threads + OWED, capped). Before
your final reply, record what changed with `bin/orc-ledger.sh` (thread/owed upserts, closes with
rung-5 evidence only). Never edit STATE.md — it is a generated snapshot. A thread not in the
ledger does not exist next turn." OWED rule text (`CLAUDE.md:64-65`) rewritten to name `orc_owed`.
