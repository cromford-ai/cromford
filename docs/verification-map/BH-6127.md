# Mission Control LANES: lane-run metrics and the queue-wait alert (BH-6127)

**What it is:** the console page for lanes that run on Fly machines (BH-6124).
It shows per lane and per machine run counts, the queue wait, the cost per lane
and the hub load. A hub lane alerts when a lane's queue waits too long.
Details: [the note](../notes/2026-10-12-BH-6127-lane-run-metrics.md).

- Nav path: bottom nav **LANES** → `/lane-runs`. A lane name opens
  `/lane-runs/lane/<lane>`. A machine name opens `/lane-runs/machine/<id>`. A
  run number opens `/lane-runs/run/<id>`. On a run, the claimer opens its
  machine list and the back link opens its lane.
- Selectors: `table.tbl th[aria-sort]` (every table is the shared
  SortableTable), `a[href^="/lane-runs/lane/"]`, `a[href^="/lane-runs/run/"]`.
- Precondition: `lane_runs` rows exist. With none, the page shows "No lane runs
  in the last 24 h. Every lane runs on the hub until a lane_placement row says
  fly." A failed read shows the ErrorBox with RETRY instead.
- Routes (harness-jobs, `worker/jobs/src/routes/lane-runs-metrics.js`):
  `GET /api/lane-runs?lane=&machine=&status=&limit=` (newest first, limit 200,
  max 500, `truncated` at the cap), `GET /api/lane-runs/<id>`,
  `GET /api/lane-runs/metrics?hours=` (default 24, 1..168),
  `POST /api/lane-runs/wait-tick {box, load1}`, `POST /api/lane-runs/wait-ack {lane}`.
- Alert: `bin/lane-run-wait-alert.sh`, hub only, every minute. Settings row
  `lane_run.wait_alert_min` (seed 10, 1..1440; any other value uses 10). Alert
  id `lane-run-wait:<lane>`, severity warn. A failed tick writes one
  `lane-run-wait-alert:unreachable` alert. Off:
  `bin/harness-ctl.sh off lane-run-wait-alert`.

**How to drive it:**

| what | how |
|---|---|
| the routes alone | `cd worker/jobs && node --test test/lane-runs-metrics.bh-6127.test.js` |
| the alert script over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/lane-run-wait-alert.bh-6127-test.sh` |
| the console views | `cd console-ui && node --test tests/lane-runs.bh-6127.test.js` |
| the metrics on a live worker | `curl -sS -H "authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/lane-runs/metrics"` |
| on the hub | `tail logs/lane-run-wait-alert.log` (`<ts> over=<n> fired=<n> acked=<n> resolved=<n> load1=<x\|null>`) |

**What must never regress:**

- One over tick never alerts (W3). A lane alerts once per breach, on its 2nd
  consecutive over tick, and not again until its wait drops under the limit
  (W1, W2, T1).
- A wait equal to the limit is not over (W4).
- No hub load report is `hub: null` and "hub load: no report yet", never 0 (M5, C6).
- A failed cost read is `cost_available: false` and a chip, never a silent 0 (M5, C6).
- The list says `truncated` at its cap, and the page says "showing the newest
  <n> runs" only then (L1, C3).
