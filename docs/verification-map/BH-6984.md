# Lead review: the tick lock is not held across the wait (BH-6984)

**What it is:** a lead-review tick holds `locks/lead-review-tick.lock` (fd 7)
only while it decides and starts reviews. When its starts close, it releases
the lock, launches the rerun a skipped tick owed, and then waits for its
running reviews. A later tick or doorbell ring therefore starts more reviews
while the first ones run. Before this change, each box ran about one review
at a time, because every later tick logged `tick skipped: the previous tick
still holds locks/lead-review-tick.lock` until the running reviews ended.

- Slot count (`bin/lead-review.sh` `lr_slot_free`): `rpool_box_running`, the
  tick's own live workers plus the live workers of other ticks on this box,
  against K and the fleet-wide `lead_review.concurrency` row.
- Box count (`bin/lib/review-pool.sh`): with `RPOOL_LIVE_DIR` set
  (lead-review: `state/lead-review/pool`), each worker holds the file
  `<tickpid>-<id>` (its pid) while it runs. `rpool_others` counts the files
  of other ticks whose pid is alive and removes the rest. The memory and tmp
  terms of K add those workers back, because they already use their share.
- One request, one worker: the per-key lock `locks/lead-review-<key>.lock`
  and the DB claim (`job_open`, 409 = `skip <key>: ...`) stay as they were.
- Early end: `rpool_finish` removes nothing while a worker of the tick still
  runs. The worker keeps its TMPDIR and heartbeat, and records its result.

**How to drive it:**

| what | how |
|---|---|
| the acceptance cases (L1-L5) | `HARNESS_TEST_SANDBOX=1 bash tests/lead-review-tick-lock.bh-6984-test.sh` |
| on a live box | `grep -E 'starts closed\|tick skipped\|tick seen=' logs/lead-review.log` and `ls state/lead-review/pool` |

**What must never regress:**

- A tick started while another tick's review runs is not skipped, and starts
  a second review when a slot is free (L1).
- With the box cap reached, a tick starts nothing and exits 0 (L2).
- One request is never claimed by two ticks (L3).
- A tick that ends early never takes a running worker's scratch (L4).

**Metric to watch:** lead verdicts per box per hour at steady demand (about 3
before the change). Read `logs/lead-review-land.log` on the hub and each box's
`logs/lead-review.log` over the 6 hours after deploy.
