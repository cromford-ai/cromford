# Ticket edges and holds as rows (BH-6977)

**What it is:** every dependency line a plan or a split child declares, and
every person HOLD or RESUME comment, is also a D1 row. Nothing dispatches on
the rows yet. Details: [the note](../notes/2026-10-15-BH-6977-ticket-edges.md).

- Routes (harness-jobs, `worker/jobs/src/routes/ticket-edges.js`, bearer-gated):
  - `POST /api/ticket-edges {project, parent, child, kind, source, planned_files?}`:
    200 `{ok, id, kind, verified_at}`.
  - `GET /api/ticket-edges?project=&parent=|child=`: 200 `{edges:[...]}`.
  - `POST /api/ticket-holds {project, ticket, state, by, at, comment_id}`:
    200 `{ok, id, state}`.
  - `GET /api/ticket-holds?project=&ticket=`: 200 `{holds:[...]}`, newest first.
  - 400 for a bad field, 503 when a table is not applied.
- Shell client `bin/lib/ticket-edges.sh`. Writers: `bin/run-preplan.sh`,
  `bin/run-decompose.sh`, `bin/dep-verify.sh`, wake class
  `bin/lib/wake-class-ticket-holds.sh` (flag `wake-lanes-ticket-holds`, off).
- Kill switch `flags/ticket-edges-off`.

**How to drive it:**

| what | how |
|---|---|
| routes, writers and wake class, over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/ticket-edges.bh-6977-test.sh` |
| routes, upsert rules, retention and EXPLAIN plans | `cd worker/jobs && node --test test/ticket-edges.bh-6977.test.js` |
| the edges of one ticket on a live worker | `curl -s -H "Authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/ticket-edges?project=cromford&child=6978"` |

**What must never regress:**

- The same edge or the same comment never makes a second row (E4, E3, W2, W3).
- A planner or decompose write never undoes a dep-verify verdict (W2).
- dep-verify's stdout line and exit code are the same with the worker up,
  down or answering 503 (F1, N1).
- A writer never prints to stdout and never changes its caller's exit code (E1, F2, E5).
- A bot comment never makes a hold row (H3, E3).
- Every statement uses its index, never a scan (W6).
