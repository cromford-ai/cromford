# D1 overload relief (BH-5781)

**What it is:** four changes that cut the D1 reads behind the
`D1_ERROR: D1 DB is overloaded` answers (about 230 an hour on the hub on
2026-10-09, all at minute :00/:15/:30/:45). Details:
[the note](../notes/2026-10-09-BH-5781-d1-overload.md).

- `_jobs_req` (`bin/lib/jobs/req.sh`) sends a request again ONCE when the answer
  is a 503 whose payload contains `overloaded`, after `JOBS_OVERLOAD_SLEEP`
  (2) plus 0..`JOBS_OVERLOAD_JITTER_S` (2) seconds. `JOBS_OVERLOAD_RETRIES=0`
  switches it off. No other answer is sent again.
- `setting_get` (`bin/lib/jobs/settings.sh`) answers from
  `state/settings-cache.json` when the file is younger than
  `JOBS_SETTINGS_CACHE_S` (default `LANE_GATE_CACHE_S`, 60 s), with no request.
  Signed keys (`human_verdict_mode`, `human_verdict_sig_mode`, `*.sig`,
  `lead_authority.*`, `risk_tier.*`) always go to the worker. `setting_set` sets `fetched_at` to 0 after a 2xx.
- The worker answers `GET /api/settings` and `GET /api/settings/<key>` (non-lead
  keys) from one snapshot per isolate (`worker/jobs/src/lib/settings-cache.js`).
  TTL: row `settings_cache_ttl_s`, else wrangler var `SETTINGS_CACHE_TTL_S` (30),
  else 0 (off); integer 0..60 only. Every settings writer clears the snapshot.
- `lane_gate_or_exit` (`bin/lib/lane-gate.sh`) first sleeps
  `lane_start_offset <id>`: cksum of the box name mod (spread+1), only at a
  quarter-hour minute, only for a lane whose registry cadence minute is a
  number, a list or `*/N` with N >= 5, capped at N*30 s. Spread: row
  `lane_start_spread_s` (read from the cache file, never refreshed), else
  `LANE_START_SPREAD_S`, else 120; integer 0..600; 0 = off.

**How to drive it:**

| what | how |
|---|---|
| overload retry | `HARNESS_TEST_SANDBOX=1 bash tests/jobs-client-overload.bh-5781-test.sh` |
| box settings cache (+ the worker test) | `HARNESS_TEST_SANDBOX=1 bash tests/settings-get-cache.bh-5781-test.sh` |
| worker snapshot alone | `cd worker/jobs && node --test test/settings-cache.bh-5781.test.js` |
| start offset | `HARNESS_TEST_SANDBOX=1 bash tests/lane-start-offset.bh-5781-test.sh` |
| this box's offset for a lane | `HARNESS=/root/harness LANE_GATE_NOW=1800000000 bash -c '. bin/lib/lane-gate.sh; lane_start_offset <lane-id>'` |
| on a live box | `grep 'after overload retry' logs/jobs-client.log`; `grep 'start offset' logs/lane-gate.log`; `jq .fetched_at state/settings-cache.json` |

**What must never regress:**

- A 503 that does not say `overloaded`, a 500, a 4xx and a 200 are never sent again.
- A stale, future-dated or unreadable cache file goes to the worker, never rc 2.
- A signed key is never answered from either cache.
- A minutely or `*/2`..`*/4` lane, and any minute that is not 0/15/30/45, never waits.
