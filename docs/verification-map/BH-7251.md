# Hub load part 2: fly-pool lock first, one knob memo per lane start, one compose per catalog change (BH-7251)

**What it is:** three changes that cut the hub's short-lived forks.

- fly-pool (`bin/fly-pool.sh`): the per-project `flock -n` comes before the
  first lib source. A start that finds the lock held writes one
  `already running` line to `logs/fly-pool.log` and exits rc 0. It sources
  nothing.
- Knob memo (`bin/lib/lane-gate.sh`): `_lg_km_load` reads the registry knobs
  of one lane or lib with one jq. `_lg_sc_load` reads
  `state/settings-cache.json` with one jq per distinct content. Every knob read
  after `lane_env_apply` or `lib_env_apply` uses them.
- Registry loader (`bin/lib/lanes-registry.sh` `lanes_json_path`): when no file
  in `catalog/lanes.d` or `bin/lanes-build.sh` has a ctime newer than the
  stamp, the render is served with no digest. Otherwise the hash decides. A
  compose holds `lock-<key>` beside the stamp; a caller that finds it held
  serves the existing render.

**How to drive it:**

| what | how |
|---|---|
| the acceptance cases | `bash tests/fly-pool-lock-first.bh-7251-test.sh`, `bash tests/lane-knob-memo.bh-7251-test.sh`, `bash tests/lanes-registry-compose-once.bh-7251-test.sh` |
| fly-pool overlaps on the hub | `grep -c 'already running' logs/fly-pool.log` |
| jq per lane start | put a jq shim that counts calls first on PATH, then run `bash -c '. bin/lib/lane-gate.sh; lane_env_apply merge-conductor cromford'` |
| the stamp and the herd lock | `ls -l --time=ctime ${TMPDIR:-/tmp}/harness-lanes-$(id -u)/` |

**Kill knobs:** none. `LANE_REGISTRY=<path>` still bypasses the loader.
`LANE_GATE_DISABLE=1` still turns the gate off.

**What must never regress:**

- A held-lock fly-pool start sources no lib (L1).
- A lane start with 20 knobs runs at most 2 jq, and every exported value is
  the same as before (M1, M2).
- A settings cache rewritten under a running lane is read at once (M5).
- Two loader calls with no change compose once; an edit with an old mtime, a
  deleted file, a new knob fragment and a renderer edit each compose (C1-C8).
- 8 concurrent calls on a changed tree compose once (C10).

**Metric to watch:** hub `uptime` load5 every 5 minutes for 1 hour (target:
under 50 on the first deploy, then under 24), `state/hub-load/<date>.tsv` from
`bin/hub-load-sample.sh`, and `pgrep -fc` for `fly-pool.sh`, `lanes-build.sh`
and `jq`.
