# Lane runs on Fly: batch enqueue (BH-6886)

**What it is:** for a lane placed `fly`, `pl_dispatch` enqueues every eligible
project in one `POST /api/lane-runs/batch` per 500 projects, not one POST per
project. A tick costs the hub the same few forks for 10 projects or 1000.
Details: [the note](../notes/2026-10-15-BH-6886-lane-runs-batch.md).

- Shell (`bin/lib/lane-placement.sh` `lp_enqueue_batch`): one `jq` call builds
  every payload, one more reads every answer. `LP_BATCH_MAX=500`.
- Dispatch (`bin/lib/project-lanes.sh` `pl_dispatch`): an answer row
  `enqueued` with an id counts `fly`; `already_live` counts `already live`.
  Every other project runs on the hub, counts `enqueue failed -> hub`, and the
  dispatch writes ONE alert, id `lane-placement:<lane>`. A 404 (no batch
  route) sends the projects not yet placed through the per-row `lp_enqueue`.
- Route (harness-jobs, `worker/jobs/src/routes/lane-runs-batch.js`):
  `POST /api/lane-runs/batch {lane, box?, rows: [{project, args}]}`, 1..500
  rows, one statement with `ON CONFLICT` on the index `lane_runs_live`. A bad
  row, a duplicate project or 501 rows is a 400 that writes nothing.

**How to drive it:**

| what | how |
|---|---|
| the tick budget, the answer handling and the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/hub-load-budget.bh-6886-test.sh` |
| the route alone | `node tests/lib/lane-runs-batch.bh-6886.mjs` |
| on a live worker | `curl -sS -X POST -H "authorization: Bearer $HARNESS_SECRET" -H 'content-type: application/json' -d '{"lane":"<lane>","rows":[{"project":"<p>","args":["bin/<script>"]}]}' "$JOBS_URL/api/lane-runs/batch"` |
| on a live box | `grep 'placed:' logs/<lane>-cron.log` |

**What must never regress:**

- 1000 projects cost at most 3 HTTP calls and 40 forks per tick (B1).
- Only an answer row makes a project fly or live. A failed or partial answer
  runs the project on the hub (L2, L4, L5, E3).
- A worker with no batch route still enqueues through the per-row path (L3, F8).
