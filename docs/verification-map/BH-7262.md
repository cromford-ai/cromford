# Product stage fleet enablement and per-run USD cap (BH-7244 slice 4, BH-7262)

**What it is:** seven projects get the weekly product cycle
(`bin/run-product.sh <project>`, Monday 09:0x UTC at the fleet.conf offset):
project-6-os, project-5, project-2, project-4, project-3, project-9 and
project-8. A project gets the cron line when
`prompts/product-<project>.md` exists (`cron_project_block` in
`bin/lib/cron-lines.sh`).

- Context files: `prompts/product-{project-6-os,project-5,project-9,project-8}.md`
  are new. The project-2, project-4 and project-3 files are unchanged.
- Registry: `catalog/lanes.d/run-product.json` `.boxes` adds `project-6-os`,
  `project-9`, `small` and `project-5`.
- Per-run USD cap: `product_run_cap_check <stage>` in
  `bin/lib/product-run-cap.sh`. It sums this run's `logs/cost.csv` rows (this
  project, since the run start, stages map/signals/ideate/synth/prd/mockup/pm,
  column 13). At or over `PRODUCT_RUN_USD_CAP` it writes one
  `logs/<project>.log` line and one ALERTS line (through `bin/alert-line.sh`)
  and returns 1. `cap_stop` in
  run-product.sh then ends the cycle with rc 0.
- Knob: `PRODUCT_RUN_USD_CAP` on lane `run-product`, default 0 = unlimited,
  in `catalog/lanes.d/run-product.knobs.d/PRODUCT_RUN_USD_CAP.json`.
  An invalid value is unlimited.

**Preconditions:** none for the suite. A real cycle needs `/root/repos/<p>`,
the stage prompts and a model route.

**How to drive it:**

| what | how |
|---|---|
| context files, cron lines, registry, cap decision table, run-product end to end (stub agent-call) | `HARNESS_TEST_SANDBOX=1 bash tests/product-fleet-enable.bh-7244-test.sh` |
| one box's weekly line | `bin/render-cron.sh project-6-os > /tmp/b && bin/render-crontab.sh --base /tmp/b project-6-os \| grep run-product` |
| set a 5 USD cap for one project | `bin/harness-ctl.sh set run-product PRODUCT_RUN_USD_CAP 5 <project>` |
| a cap stop on a box | `grep 'run USD cap reached' /root/harness/logs/ALERTS.log` |
