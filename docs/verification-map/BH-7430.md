# Fly pool machine pull (BH-7430, BH-6896 S3)

**What it is:** with the lane knob `POOL_MACHINE_PULL=1` on a project,
`bin/fly-pool.sh` `spawn_one` ends at ONE `fly machine run`. The machine
fetches the pinned harness sha itself (`fly/harness-fetch.sh`), composes its
env from the pool app's `HBUNDLE_*` Fly secrets plus the seeded
`global.override.env`, and finds its job and relays in `/run/harness-seed`
(`fly/entrypoint.sh`, blocks `seed (BH-7430)` and `harness pull (BH-7430)`).
At 0 (the default) the spawn is byte-identical to the push path.

**How an operator reaches it:** `bin/fly-pool-secrets-sync.sh <project>
[--dry-run]` on the hub, then the settings row
`lane.fly-pool.<project>.machine_pull=1`. The steps, project-6-os first, are in
`docs/notes/2026-10-19-BH-7430-pool-secrets-sync.md`.

**How to drive it:**

| what | how |
|---|---|
| 3 spawns on the pull path: 3 `machine run`, 0 sftp, 0 console, 0 box ssh, 0 sleep; the decision table; knob 0 equals the base script | `bash tests/fly-pool-machine-pull.bh-7430-test.sh` |
| the machine fetch helper against a local bare repo | `bash tests/fly-harness-fetch.bh-7430-test.sh` |
| the entrypoint seed move, env compose, fetch and row stamp (8-row table) | `bash tests/fly-entrypoint-seed.bh-7430-test.sh` |
| the operator sync verb | `bash tests/fly-pool-secrets-sync.bh-7430-test.sh` |
| the live probe's preconditions and its four checks against a stubbed fly (0 network calls; the live run against Fly is still manual) | `bash tests/fly-pool-probe-pull.bh-7430-test.sh` |

**What it writes:**

- `logs/fly-pool.log`: `machine pull: on (...)` once per tick;
  `<key>: push path (<why>)` per spawn that falls back;
  `<mid>: seeded N file(s) for <key> at launch; ...` and
  `spawned <mid> for <key> (pull, live=...)` per pull spawn.
- On the machine: `seed: placed N file(s)`, `env: composed global.env ...`,
  `harness-fetch: <slug> <sha12> into /data/harness`, `row <p>/<key> stamped`.
- On a failed fetch: the ledger row `pool-result <p>/<key>` with
  `BUILD_DEFERRED harness-fetch: <why>`.

**What must never regress:**

- Knob 0 changes nothing: the shim log equals the base script's (B1).
- No `HBUNDLE_*` variable reaches the runner; no token is on argv of git.
- A missing precondition is a push spawn and one log line, never a dead spawn.
