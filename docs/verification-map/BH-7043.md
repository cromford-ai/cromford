# Builder APPROVE carry and the replay fetch retry (BH-7043)

**What it is:** a builder APPROVE on head A stands on head B when B carries
exactly A's patch (`bin/lib/builder-carry.sh` `bc_carry`, over `patch_same`).
Then the BH-5294 lead replay runs on B with no model call. The replay fetch
(`patch_same_fetch`) retries by sha and by the PR ref before it gives up, and
names the redacted git error.

**How a user reaches it:** there is **no UI route**. It runs in the hub cron
lane `713-lead-review-enqueue` (`bin/lead-review-enqueue.sh tick`, every 5
minutes) and in the box worklist gates 10 and 50 of `bin/lead-review.sh tick`.

**What to look at:**

- `logs/lead-review-enqueue.log`: the tick line carries `replayed=<n>
  builder_replayed=<n> fetch_failed=<n>`. Per PR: `builder APPROVE carried
  from <A12> (how:<how>)`, or `builder APPROVE on <A12> not carried: <why>`.
- `logs/lead-review.log`: the same two per-PR lines from gate 10 and gate 50.
- `state/lead-review-enqueue/builder-carry.tsv` (7 days) and the
  `builder-replay` rows of `state/lead-review-enqueue/modes.tsv` (30 days).

```bash
grep -o 'replayed=[0-9]* builder_replayed=[0-9]* fetch_failed=[0-9]*' /root/harness/logs/lead-review-enqueue.log | sort | uniq -c
```
