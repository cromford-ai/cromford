# Hub lane CPU rank (BH-7252 C0)

**What it is:** the hub lane `bin/lane-cpu-rank.sh` measures CPU seconds per
hour per lane over one 1 h window (`bin/lane-cpu-sample.sh --cpu-s`) and posts
the ranked table once to issue `lane_cpu_rank.issue` (code default 7252). The
method and the table format are in
[the note](../notes/2026-10-17-BH-7252-lane-cpu-rank.md).

- Cron: `5 14 * * *` in `cron/lanes/735-lane-cpu-rank.cron`, behind
  `bin/hub-lease.sh check`. Registry: `catalog/lanes.d/lane-cpu-rank.json`.
- State: `state/lane-cpu-rank/state-<issue>` and `state/lane-cpu-rank/report.md`.
- Log: `logs/lane-cpu-rank.log`, one `rank=<outcome> issue=<n>(row|default)
  rows=<n> load5=<start>-><end>` line per run.
- Off: `flags/lane-off-lane-cpu-rank`.
- Target (BH-7406): the table goes to the issue in the `lane_cpu_rank.issue`
  row, seeded 7406. A failed run ends its log line with `why=<cause>`.

**How to drive it:**

| what | how |
|---|---|
| fresh token at post time, `why=` on failures, the 7406 row | `HARNESS_TEST_SANDBOX=1 bash tests/lane-cpu-rank-token.bh-7406-test.sh` |
| the `--cpu-s` column, rounding, default output unchanged | `HARNESS_TEST_SANDBOX=1 bash tests/lane-cpu-sample-cpu-s.bh-7252-test.sh` |
| post once, marker, attempts, gave-up, lock, knobs | `HARNESS_TEST_SANDBOX=1 bash tests/lane-cpu-rank.bh-7252-test.sh` |
| the CPU column on the hub, 60 s, no post | `/root/harness/bin/lane-cpu-sample.sh --seconds 60 --interval 5 --cpu-s --lane lane-cpu-sample --max-pct 100` |
| the last runs on the hub | `tail -n 3 /root/harness/logs/lane-cpu-rank.log` |
| the posted table | the comment on #7406 that holds `<!-- lane-cpu-rank:7406 -->` |

# Lane move to lane-run (BH-7252 C1)

**What it is:** the hub lane `bin/lane-move.sh` moves one lane's project runs
to Fly lane-run after proof gates, checks the hour after the move, and moves
the lane back to the hub when the counts do not hold. One module per lane in
`bin/lib/lane-move/`; the first is `pipeline-health`. The gates, the check
rule and the state file are in
[the note](../notes/2026-10-17-BH-7252-pipeline-health-move.md).

- Cron: `6,16,26,36,46,56 * * * *` in `cron/lanes/736-lane-move.cron`, behind
  `bin/hub-lease.sh check`. Registry: `catalog/lanes.d/lane-move.json`.
- Publisher: `8,18,... bin/lane-snapshot-publish.sh --lane pipeline-health` in
  `cron/lanes/579-lane-snapshot-publish.cron`.
- State: `state/lane-move/<lane>`, `<lane>.before.tsv`, `<lane>.report.md`.
- Log: `logs/lane-move.log`, one `lane=<lane> step=<step> why=<...>` line per
  lane per run.
- Off: `flags/lane-off-lane-move`. Kill row: `bin/jobs-client.sh setting-set
  lane_placement.pipeline-health hub`.

**How to drive it:**

| what | how |
|---|---|
| gates, flip, check, rollback, kill row, post once | `HARNESS_TEST_SANDBOX=1 bash tests/lane-move.bh-7252-test.sh` |
| the row routes `--dispatch` to lane-run and back; the hub cron lines | `HARNESS_TEST_SANDBOX=1 bash tests/pipeline-health-placement.bh-7252-test.sh` |
| the repo-invisible alert on a machine | `HARNESS_TEST_SANDBOX=1 bash tests/gh-repo-invisible-machine.bh-7252-test.sh` |
| the publisher runs for the lane (hub) | `tail -3 /root/harness/logs/lane-snapshot-publish.log \| grep 'pipeline-health placed'` |
| the move state (hub) | `tail -5 /root/harness/logs/lane-move.log`; `cat /root/harness/state/lane-move/pipeline-health` |
| the placement row (hub) | `/root/harness/bin/jobs-client.sh setting-get lane_placement.pipeline-health` |
| the posted report | the comment on #7252 that holds `<!-- lane-move:pipeline-health:<flip epoch> -->` |
