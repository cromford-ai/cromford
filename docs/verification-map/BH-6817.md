# Lane-run machines run current code; a non-zero run is `failed` (BH-6817)

**What it is:** a lane-run machine pulls `main` of the harness repo before its
claims, a run with rc != 0 is reported `failed` with a reason, and the
conductor runs a PR on the hub when its machine run failed. Details:
[the note](../notes/2026-10-15-BH-6817-lane-run-fresh-code.md).

- Code sync (`bin/lib/lane-run-code.sh`, on a machine only:
  `LANE_RUN_CODE_SYNC=1` from `fly/lane-run-entrypoint.sh`, no `.git`, no
  populated `builds/`, row `lane_run.code_sync` not `0`): at most once per
  `lane_run.code_check_s` (120). See it: `flyctl logs -a lane-run` shows
  `code <old12|unknown> -> <new12>` after a swap, `code current <sha12>` when
  main is unchanged, `code sync failed: <why>` on a failure (tree unchanged,
  one `lane-run-code-sync` warn alert per hour). `cat /opt/harness/HARNESS_COMMIT`
  on the machine (`flyctl ssh console -a lane-run`) is the commit it runs.
- Failed runs: `GET /api/lane-runs/by-prefix?lane=<lane>&project_prefix=<p>`
  lists a row with rc != 0 as `status:"failed"` and `reason`
  `command-missing` (126/127) or `exit-nonzero`. Its `prof_line` ends
  ` rc=<n> reason=<r> err=<first stderr line>`. D1 and `/api/lane-runs`
  (the console LaneRuns screen) still show `done` + rc.
- Command missing: the worker does not start an `args[0]` that is not an
  executable file in its harness; it reports rc 127 and writes one
  `lane-run-command-missing-<lane>` warn alert per lane per
  `lane_run.command_missing_alert_s` (3600) per machine.
- Conductor: `logs/merge-conductor.log` shows
  `<slug>#<n> fallback=machine-failed (command-missing at <key>)` or
  `(rc=<n> at <key>)`, and that PR runs on the hub that tick.
- Image: `logs/lane-fleet.log` on the hub shows
  `image <id> registry.fly.io/lane-run:latest digest=sha256:… harness_commit=<sha|unknown>`
  once per started machine and digest, and
  `start <id>: machine run image=<lane_fleet.image>` or
  `start <id>: machine start image=<ref> digest=… harness_commit=…`.
- Proof after merge (ticket): arm `conductor_workers_on_fly`; 10 consecutive
  merge-conductor-pr rows answer `done` rc 0 on the by-prefix read, and the
  hub `merge-conductor` process count drops.
