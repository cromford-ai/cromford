# Lane-run image: flyctl, harness tree and Fly token for a pool tick (BH-7516)

**What it is:** the lane-run image and its boot supply three of the four things
`bin/fly-pool-project.sh --preflight <project>` (#7515) checks: `fly-binary`,
`harness-src` and `fly-token`. `env-bundle` is BH-6896 S3. Details:
[the note](../notes/2026-10-19-BH-7516-lane-run-pool-prereqs.md).

- flyctl (`fly/lane-run.Dockerfile`, block `bake-flyctl`): the build arg
  `FLYCTL_VERSION` comes from the row `bake.flyctl.version`. It has no default:
  an empty arg FATALs. See it: `fly version` on the machine prints the pinned
  release; `ls -l /root/.fly/bin` shows `flyctl` and the `fly` link.
- Harness tree: `/opt/harness` holds `bin catalog fleet.conf prompts rules fly`,
  and `POOL_HARNESS_SRC=/opt/harness`. The code sync (`lrc_sync`) swaps all six
  paths, each optional one only when the fetched commit has it. See it:
  `ls /opt/harness` on the machine; `flyctl logs -a lane-run-mk` shows
  `code <old12> -> <new12>`.
- Fly token: `fly/lane-run-entrypoint.sh` writes `$ENVD/fly.env` (mode 600)
  from the `FLY_API_TOKEN` / `FLY_API_TOKEN_<P>` secrets, `%q`-quoted. Stage the
  secret with the stdin command in `fly/lane-run.toml`. See it:
  `stat -c %a /opt/harness/env/fly.env` is `600`; never `cat` it.
- The check: on a lane-run-mk machine (`flyctl ssh console -a lane-run-mk`),
  `/opt/harness/bin/fly-pool-project.sh --preflight project-6-os` answers
  `preflight project-6-os: missing env-bundle`.

Verified by `tests/lane-run-image.bh-7516-test.sh`.
