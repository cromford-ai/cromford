# Lead review after an in-build APPROVE, in the daily digest (BH-9501)

**What it is:** one line in Archie's daily digest. It gives the share of PRs
with an in-build APPROVE that the lead review then blocked, over the
`DAILY_DIGEST_APPROVE_BLOCK_DAYS` days (default 14) that end with the digest
day. Details: [the note](../notes/2026-11-11-BH-9501-approve-then-block.md).

- Route (harness-jobs, `worker/jobs/src/routes/approve-then-block.js`, lib
  `worker/jobs/src/lib/approve-then-block.js`, bearer-gated, read-only):
  `GET /api/metrics/approve-then-block?day=YYYY-MM-DD[&days=1..60]`: 200
  `{ok, day, from, to, days, cohort, blocked, share, repos:[{repo, cohort, blocked, share}]}`;
  400 on a bad `day` or `days`, before any read.
- Lane: `bin/daily-digest.sh` block `# >>> approve-then-block (BH-9501)` merges
  the answer as `.approve_then_block` in `state/daily-digest/<D>.json`. A 404
  is one note line in `logs/daily-digest.notes.log` and no key; any other
  failure is `{ok:false}`. No alert.
- Render: `bin/lib/daily-digest-render.sh`, the last line of the digest.
- Knob: `DAILY_DIGEST_APPROVE_BLOCK_DAYS` in `catalog/lanes.d/daily-digest.knobs.d/DAILY_DIGEST_APPROVE_BLOCK_DAYS.json`.

## Check after deploy

```bash
jq .approve_then_block /root/harness/state/daily-digest/$(date -u -d yesterday +%F).json
```

`ok` is `true`, and `cohort` and `blocked` are numbers. The sent digest text
(`state/daily-digest/<D>.txt`) has a line that starts with
`Lead review after in-build APPROVE`.
