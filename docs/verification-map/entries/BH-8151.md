| PR record webhooks (BH-8151, BH-8067 slice C2): a signed GitHub delivery writes the fleet's PR record; case 2 of the read rule (a field a named change did not carry is stored NULL, so the next get reads GitHub) | [entries/BH-8151.md](entries/BH-8151.md) | No screen. Route `POST /webhooks/github` (`worker/jobs/src/routes/webhooks.js`) calls `recordPrRecord` (`worker/jobs/src/lib/pr-record-intake.js`) after the signature check and before `wakeOf`; the status and body do not change. Writes `pr_records` rows (source `webhook`, `last_source`, `webhook_at`, `fields_at.<f>`) for `pull_request` (PR fields, `mergeable_state`), `pull_request_review` (`review_decision`), `issue_comment` on a PR (labels, state), `check_run` / `check_suite` / `workflow_run` (`checks` entries `{status, conclusion, sha, at}` keyed `<check name>`, `suite:<app slug>`, `workflow:<name>`) and a default-branch `push` (`mergeable_state` NULL on open rows of that base). Check, comment and push writes do not move `refreshed_at` on an existing row. `PUT /api/pr-records` accepts `mergeable_state: null`. Client `bin/lib/pr-record.sh`: GitHub `mergeable_state: "unknown"` is stored null. A failed write is one `[pr-record-intake]` warn.
