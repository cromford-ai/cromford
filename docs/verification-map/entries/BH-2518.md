| Box and Fly machine ops from the console, plus the BOX COMMANDS history | [fly-machines.md](fly-machines.md) | Nav FLEET → MACHINES (`/machines`; `/machines?box=<name>` filters the history to one box). Buttons: ORGO BOXES ACTIONS column (BACKUP NOW, SYNC, CLI UPDATE) and each FLY · &lt;project&gt; table's ACTIONS column (STOP on started machines only, DESTROY on every row, disabled with title `machine's app unknown` when the app cannot be resolved). Every button opens the in-app confirm with a required REASON; CONFIRM stays disabled until it is non-blank, Escape cancels. Routes `POST /api/coord/box-commands` (the request) and `GET /api/coord/box-commands[?box=]` (history, polled every 30 s); source `console-ui/src/lib/box-commands.js`, `console-ui/src/screens/Machines.js`. Executor: the per-box lane `bin/box-ops.sh` is sibling BH-2660 and is not part of this slice; its knobs `BOX_OPS_TIMEOUT_S` and `BOX_OPS_MAX_PER_TICK` are that sibling's, and the claim TTL is `settings.box_commands_claim_ttl_s` (worker sibling BH-2659, 1800 s fallback). Verify: pick an ORGO box → BACKUP NOW → type a reason → CONFIRM → banner `queued for <box>` (or `already queued (#id)` on a repeat, or `BACKUP NOW failed: http <n>` while the worker route is undeployed) → the row shows in BOX COMMANDS with STATUS REQUESTED. BH-5750 box controls (owner only: the worker answers 403 `owner_only` unless the Access-verified actor is in the worker secret `BOX_OPS_OWNERS`, and the warn banner shows it). ORGO BOXES: every row with an Orgo box id gets RESTART, RESIZE, STOP and RETIRE beside the three above; the id is the row name without the prefix every non-hub row shares and without a trailing `-N` (`<prefix>-project-3-2` → `project-3`), and the `hub` row and an all-number rest (the hub's own fleet name) get no Orgo buttons. All four are queued for box `hub` with the Orgo id as target. RESTART and STOP open the reason confirm; STOP says it never lifts the pause. RESIZE opens a form (ACCOUNT, a select over the Orgo read's accounts, preset to the computer's own; VCPUS, MEMORY GB, DISK GB, blank keeps a size; REASON) → GET PRICE posts `orgo_resize_quote` → the `orgo-quote` dialog says `pricing… queued for hub (quote #id)` and polls `GET /api/coord/box-commands?box=hub` every 5 s for 180 s at most (stopped when the dialog closes) → it shows the quote's `PLAN cost +$N/mo …` / `COST: resize …` or `NEEDS PURCHASE: …` field verbatim; CONFIRM (RESIZE) is enabled only on an ok quote and posts `orgo_resize` with `quote_id` = the quote row id and `confirm_monthly_usd` = the figure from that line (the worker's rule; an ok quote with no cost line is `0`); a failed quote or 180 s with no answer (`no price yet`) leaves it disabled and posts nothing more; a worker 409 `stale_quote` / `open_command_differs` shows in the banner. RETIRE (danger) has REASON, MOVE TO, IP and a delete checkbox; delete needs the box id typed into `TYPE <id> TO DELETE` and focus stays in that field. New columns ORGO STATE (`running`, `stopped`, … from `GET /api/coord/orgo-computers` matched on computer name = row name; `unknown` with no record, `gone <age>` for a `gone_at` row, `<state> · stale <age>` when `seen_at` is over 15 min old, `not available` when the route answers 404/503, `read failed` on any other error) and SPECS (`4c/16gb/100gb`), both sortable. LAUNCH BOX section (`data-testid=launch-box`; BOX ID, PROJECT, ACCOUNT, VCPUS, MEMORY GB, DISK GB, REASON): GET PRICE stays disabled until every field is set (0 or 2.5 is refused) → posts `orgo_launch_quote` → the dialog shows the `capacity: …` and `box-launch: … usd_mo=N …` fields verbatim → LAUNCH enabled only on an ok quote with `usd_mo`, posts `orgo_launch` with the token. Each FLY · &lt;project&gt; section ends in `data-testid=fly-pool-controls`: a project on the pool (a `pool-<p>` or `<p>-pool` app, or a `pool` machine; the payload has no pool flag) gets POOL CAP + SET (`fly_pool_cap`, a whole number above 0), one off it gets ONBOARD TO POOL (`fly_onboard`); both confirm with `Fly bills per running machine; no fixed monthly price.` and no quote. BOX COMMANDS: a DETAIL `NEXT:` field renders on its own line in a `<code>` block; a `fail` row whose detail has `WAITING:`, `NEEDS PURCHASE:` or `refused:` shows WAITING, NEEDS PURCHASE or REFUSED as its STATUS tag. Executor: `bin/box-ops.sh` on the hub (BH-5750 C2/C5/C6); the Orgo read is `bin/orgo-state.sh` (C4).
