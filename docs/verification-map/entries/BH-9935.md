| PR record fields (BH-9935, wave 3 of #9926): the record holds each PR's commit statuses, the newest Mergify queue payload, the head commit time and the changed-file list; one shell reader per field, and a label list from the stored labels | [entries/BH-9935.md](entries/BH-9935.md) | No screen. Four added `pr_records` columns `statuses`, `mergify_queue`, `head_commit`, `files` and the indexes `idx_pr_records_repo_head_sha`, `idx_pr_records_repo_head` (`worker/jobs/src/lib/core.d/bh-9935-pr-records-fields.js`, run by `ensureColumns`). `GET /api/pr-records?repo=&number=` returns the four, parsed; `PUT /api/pr-records` takes them (checks in `worker/jobs/src/lib/pr-record-fields.js` `fieldValues`; a bad one is 400 that names it). The list read does not return them. Webhook writes (`worker/jobs/src/lib/pr-record-intake.js` through `fieldWritesOf`): `status` merges `{state, description, sha, at}` per context into every record whose `head_sha` is the status sha (`STATUS_MERGE_SQL`); an `issue_comment` from exactly `mergify[bot]` with the payload markers stores `{state, code, draft_pr, failing_checks, left_sha, comment_id, at}`, newest by (created_at, id) (`MERGIFY_SQL`, the body is never stored); a `push` to a non-default branch stores `head_commit {sha, at}` on the open records of that head ref, ordered by push time (`HEAD_PUSH_SQL`). Client `bin/lib/pr-record.sh`: `pr_record_statuses <repo> <n> [head]`, `pr_record_mergify <repo> <n>` (record only, rc 1 + `statuses\|mergify <repo>#<n> miss=<word>`), `pr_record_head_commit_time <repo> <n> <head>` (one `commits/<head>` read on a miss), `pr_record_files <repo> <n> <head> <out-file>` (one `pulls/<n>/files` read per head sha; a 30-full-page list is printed, never stored), `pr_record_label_list <repo> <label> <out-file> [state]`. Each GitHub read writes one `head-commit\|files <repo>#<n> reason= gh_rc= … put=` line to `logs/pr-record.log`.
