# Sweep modules (`bin/lib/ms/`)

**What it is:** the start of the split of `bin/merge-sweep.sh` into one file
per concern under `bin/lib/ms/`. It follows the same pattern as `bin/lib/mc/`
(the conductor) and `bin/lib/br/` (the resolver): the script becomes a driver,
and each concern lives in one module. Two builds that touch two unrelated
concerns of the sweep then edit two different files.

**One module. It is cut.**

| module | what it owns |
|---|---|
| `bin/lib/ms/terminal.sh` | the terminal-skip cache helpers (BH-710): `sweep_record_fp` (the record fingerprint), `sweep_terminal` (the cache writer), `sweep_relog_line` (the re-logged cause lines) |

The three bodies moved byte for byte (BH-5242 slice C0). The driver has no
inline copy, so `terminal.sh` is load-bearing.

**The cache STATE stays in the driver.** `TERM_CACHE`, `NOW`, the
`declare -A _TERM` map and its load loop are still in `bin/merge-sweep.sh`.
`mm_load` (`bin/lib/module-map.sh`) sources a module at function scope, so a
top-level `declare -A` in a module would be local to `mm_load` and lost.
`bin/module-map-build.sh --check` refuses such a line.

**How the driver loads it.** The `# >>> sweep modules` block in
`bin/merge-sweep.sh` sources `bin/lib/ms/load.sh`, which runs `mm_load` over
`bin/lib/ms/` in the order of `bin/lib/ms/MODULES`. The block tries
`lib/ms` next to the script first, then `$HARNESS/bin/lib/ms`. It runs after
the lane gate and before the lock, the `EXIT` trap and any GitHub call.
`bin/lib/ms/MODULES` is generated by `bin/module-map-build.sh --write bin/lib/ms`
from each module's `# module:` header.

**A missing module is a REFUSAL.** A box mid-sync can see the driver new and
`bin/lib/ms/` missing or incomplete. Then the tick exits 1, sweeps no PR, and
writes one line to `logs/merge-sweep.log` (`refusing the tick`) and one line to
`logs/ALERTS.log`:

```
<stamp> SWEEP MODULE MISSING: bin/lib/ms/ is missing or unusable on <box> — the box's bin/ is half-synced; no PR was swept this tick
```

An off lane (`lane-off-merge-sweep`, `all-off`) exits 0 before the block, with
no alert.

**How an operator reaches it:** there is no new lane and no new cron line. It is
the hub's `*/10` sweep (`cron/hub.cron`), loading one more directory on startup.

```sh
ls /root/harness/bin/lib/ms/
cat /root/harness/bin/lib/ms/MODULES
```

**How to drive it:**

| what | how |
|---|---|
| the layout contract: headers, one module per function, the map both ways, the driver defines no mapped name, the `fns` ceiling, a real tick sources the module, the refusals | `bash tests/ms-split-layout.bh-5242-test.sh` |
| the move is pure: the bodies of the mapped names are unchanged | `MS_SPLIT_BASE=origin/main bash tests/ms-split-layout.bh-5242-test.sh` prints `bodies: identical` |
| the terminal cache still writes, caches and re-logs through the real sweep | `bash tests/merge-sweep-order-cache-test.sh` (section C) |
| the module map is valid and `MODULES` is current | `bin/module-map-build.sh --check` |

**Ownership and ceiling.** `tests/ms/expected-map.tsv` names the module of
each moved function. `tests/ms/driver-ceiling.tsv` caps the column-0 function
definitions in the driver (`fns`, 18 after slice C0). There is no line ceiling.

**Fixtures:** a suite that copies the sweep into a scratch `bin/` must put
`bin/lib/ms/` beside it, or the copy refuses its own tick. Either copy the whole
directory with `cp -rL` (the `-L` turns the `module-map.sh` symlink into a real
file):

```sh
mkdir -p "$T/bin/lib" && cp -rL "$DIR/bin/lib/ms" "$T/bin/lib/" || exit 1
```

or install the sweep's closure with `scratch_install_closure bin/merge-sweep.sh "$T"`
(`tests/lib/scratch.sh`), which lists the `bin/lib/ms/*.sh` files.
