# Scheduler owns dispatch in enforce (BH-6979)

**What it is:** with the settings row `scheduler.mode=enforce`, the pool and
triage dispatch read the scheduler's ready set and start only the tickets it
calls ready. Any other mode is today's path. Details:
[the note](../notes/2026-10-17-BH-6979-scheduler-enforce.md).

- Gate lib `bin/lib/sched-gate.sh`: `sched_gate <project> <KEY>` answers
  `SCHED_READY` (rc 0), `SCHED_WAIT ... reason=` (rc 3) or `SCHED_PASS` (rc 2,
  today's path).
- Route (harness-jobs, `worker/jobs/src/routes/scheduler.js`, bearer-gated):
  `GET /api/scheduler/ready?project=` 200 `{ok, project, at, mode, candidates,
  complete, verdicts:[{ticket, ready, reason}]}`; no tick: `at:null`.
- Writer: `bin/scheduler.sh` posts `verdicts` with each tick
  (`POST /api/scheduler/diffs`, table `sched_ready`).
- Run-build: block `# >>> scheduler enforce gate (BH-6979)` in
  `bin/lib/rb/gates.sh`. Pool: gate 0c of `pool_spawn_decision` in
  `bin/fly-pool.sh`. Triage prompt: `bin/lib/rt/scope.sh` (also the shard
  SOP) and `bin/overlap-schedule.sh --key`.

## How to verify

1. Read the set: `. /root/harness/bin/jobs-client.sh; _jobs_req GET
   '/api/scheduler/ready?project=cromford' | jq '{at, mode, complete,
   n: (.verdicts | length)}'`. Expect `complete: true` and `n` equal to
   `candidates`.
2. In shadow, a gate call passes:
   `HARNESS=/root/harness bash -c '. /root/harness/bin/lib/sched-gate.sh;
   sched_gate cromford BH-1'` prints `SCHED_PASS BH-1 not enforced`.
3. After a flip to enforce, `logs/fly-pool.log` shows `SCHED_READY` or
   `SCHED_WAIT` lines and a deferred build's RESULT reads
   `BUILD_DEFERRED scheduler: <KEY> waits — <reason> (tick <at>)`.
4. Rollback: set `scheduler.mode` back to `shadow`; the lines stop.
