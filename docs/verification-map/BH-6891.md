# blocked-resolver on Fly: one batch dispatch per tick (BH-6891)

**What it is:** the hub cron runs `bin/blocked-resolver.sh --dispatch` every
10 minutes. The dispatch arm calls `pl_dispatch blocked-resolver`
(`bin/lib/project-lanes.sh`). With `lane_placement.blocked-resolver=fly` the
tick must make ONE `POST /api/lane-runs/batch` for the whole fleet and start
no hub process. With the lane on the hub, the tick starts one
`bin/project-lane-run.sh` per project, as before.

- The batch route and the batch branch of `pl_dispatch` come from #6886, which
  is on main. This change adds no code. On a base without #6886 the suite's
  D1, D3 and D4 batch counts are red (13 single `POST /api/lane-runs`, 0 batch
  calls).
- The flip row `lane_placement.blocked-resolver` is #6260's. It is not seeded.

**How to drive it:**

| what | how |
|---|---|
| the real dispatch arm over the real worker, 13 projects | `HARNESS_TEST_SANDBOX=1 bash tests/blocked-resolver-fly-dispatch.bh-6891-test.sh` |
| the placement on the hub | `HARNESS=/root/harness bash -c '. bin/lib/project-lanes.sh; lp_decide blocked-resolver; echo "$LP_PLACE $LP_WHY"'` |
| the last dispatch on the hub | `grep 'blocked-resolver dispatch:' /root/harness/logs/blocked-resolver.log \| tail -1` |

**Production probes (post-merge close-out, owed):**

Preconditions: the #6260 flip row is live, #6886 (merged) is deployed, and
the #6882 sampler writes `state/hub-load/*.tsv` for 24 h before the flip.

1. Per-project proof. Run on the hub:

   ```bash
   curl -s -H "Authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/lane-runs?lane=blocked-resolver&status=done" \
     | jq -r '.rows[] | [.project, .rc, .claimer, .prof_line] | @tsv'
   ```

   Pass: one row per project in `bin/fleet-conf.sh --projects` (13 on
   2026-10-15). Each `prof_line` starts `PROF `. Each `claimer` is a lane-run
   machine (`GET /api/lane-fleet/machines`).

2. Hub share. Run on the hub over the 24 h before and the 24 h after the flip:

   ```bash
   awk -F'\t' '{for(i=7;i<=NF;i++) if($i ~ /^blocked-resolver\.sh=/){split($i,a,"=");s+=a[2];n++}} END{printf "%.2f%% mean over %d samples (named in %d)\n", s/(NR?NR:1), NR, n}' state/hub-load/<days>.tsv
   ```

   The column layout is #6882's (`bin/hub-load-sample.sh`): columns 1-6 are
   the stamp, runnable, steal, forks_s, cpu and samples; the `name=share`
   pairs start at column 7. The sampler writes a name only when it is in the
   top 15 for that sample, so a sample without the name counts as 0 % and
   the mean divides by every sample line (`NR`), not only the lines that name
   the script. Pass: about 3.3 % before, under 0.3 % after.

3. Post both outputs on #6891 and #6881. Until then the status is "built,
   merged, measurement owed".

**What must never regress:**

- Placement fly: 0 hub starts and 0 single enqueues per tick (D1).
- Placement hub, or a `hub_only` row: one hub start per project (D2, D5).
- A held project gets no row (D3). A second tick adds no row (D4).
