# Docker-pool claim lease (BH-7300, slice C0)

**What it is:** the hub side of a pull-mode Docker host. A named box claims one
queued `target='fly'` build_queue row by key, beats a lease while it builds,
and releases it. A box that stops beating loses the row at the next
`jobs-watchdog` tick after `lease_until` (default 300 s), not after 6 hours.
No runner calls it yet (slice C1). Details:
[the note](../notes/2026-10-17-BH-7300-docker-pool-lease.md).

- Routes (harness-jobs, `worker/jobs/src/routes/docker-pool.js`, bearer-gated):
  - `POST /api/docker-pool/claim {project, key, box}`: 200 `{claimed:true,
    queued:{ticket_key, ticket_id, attempt}, lease_until}`, 404 `nothing
    queued`, or 409 `{refused:true, reason}` with `killed`, `off`, `full`,
    `lost` or `not_pool`. 400 for a missing or bad field.
  - `POST /api/docker-pool/heartbeat {project, key, box}`: 200
    `{lease_until}`, or 409 `{error:"lost", reason}` with `no_lease`,
    `expired`, `not_claimer` or `row_moved`; 409 `killed` with kill on.
  - `POST /api/docker-pool/release {project, key, box, status, reason?}`:
    `status` `queued` or `done`; 200 `{released:true, requeued}`, 409 `lost`.
  - `POST /api/docker-pool/sweep`: 200 `{expired:[{project, key, box,
    requeued}], requeued, backlog}`, at most 50 leases per call.
- Shell client: `bin/lib/docker-pool.sh` (`docker_pool_claim`,
  `docker_pool_heartbeat`, `docker_pool_release`, `docker_pool_sweep`); rc 0
  ok, rc 9 refused (reason on stderr), rc 2 nothing queued, rc 1 anything else.
- `bin/jobs-watchdog.sh` sweeps every hub tick: one `DOCKER POOL LEASE
  EXPIRED` ALERTS line per requeued row, one `docker-pool:` log line.
- Rows `docker_pool.max_concurrent` (0 = off), `docker_pool.max_concurrent.<box>`,
  `docker_pool.kill` (0), `docker_pool.lease_s` (300, 60..3600),
  `retention.docker_pool_leases.days` (30).

**How to drive it:**

| what | how |
|---|---|
| route decision rules, race, retention, EXPLAIN at 5,000 rows | `cd worker/jobs && node --test test/docker-pool.bh-7300.test.js` |
| shell client and the watchdog sweep, over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/docker-pool.bh-7300-test.sh` |
| a claim on a live worker with the seeded max 0 (writes nothing) | `. bin/jobs-client.sh; . bin/lib/docker-pool.sh; docker_pool_claim cromford PROBE-BH-7300; echo rc=$?` prints `docker-pool claim refused: off` and `rc=9` |
| a sweep on a live worker | `. bin/jobs-client.sh; . bin/lib/docker-pool.sh; docker_pool_sweep` prints `0	0	0` when no lease is due |

**What must never regress:**

- Two boxes racing for one row: exactly one claims it (C8, D2).
- The hub pool's keyed claim of a docker-held row claims nothing (C12, D2).
- Max 0, a bad max value or kill 1 claims nothing and writes nothing (C1, C2, C5, D3).
- A box never holds more than its max active leases (C6).
- An expired lease requeues its row once (S1, S3, W2).
- An old lease never requeues a newer claim of the same key (S4).
- A heartbeat never extends a lease whose row moved (H4).
- Every lease statement uses an index, never a scan (E1).
