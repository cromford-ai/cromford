# Scheduler ready set in shadow (BH-6978)

**What it is:** a hub lane that computes which open `ai-build` tickets are
ready to build, gives one reason for each one that is not, and compares that
with what triage, sibling-serial, overlap-schedule and STACKED_WAIT did. It
dispatches nothing. Details: [the note](../notes/2026-10-16-BH-6978-scheduler-shadow.md).

- Lane `bin/scheduler.sh [<project>|--all]`, lib `bin/lib/scheduler.sh`, cron
  `cron/lanes/733-scheduler.cron` (`*/5`, hub), switch `flags/lane-off-scheduler`,
  log `logs/scheduler.log`, state `state/scheduler/<project>.last`.
- Routes (harness-jobs, `worker/jobs/src/routes/scheduler.js`, bearer-gated):
  - `GET /api/scheduler/holds?project=`: 200 `{holds:[{ticket, state, by, at}]}`.
  - `POST /api/scheduler/diffs {project, at, mode, counts, partial?, diffs}`:
    200 `{ok, tick_written, diffs_written}`; 400 on a bad field.
  - `GET /api/scheduler/agreement?day=&project=`: 200 `{ok, day, from, to, projects}`.
- Settings rows `scheduler.mode` (shadow), `scheduler.projects`
  (cromford), `scheduler.parent_reads_max` (20).

**How to drive it:**

| what | how |
|---|---|
| the lane, its lib and the digest line, over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/scheduler-shadow.bh-6978-test.sh` |
| routes, idempotency, retention and EXPLAIN plans | `cd worker/jobs && node --test test/scheduler.bh-6978.test.js` |
| the last tick on the hub | `grep 'SCHED-TICK project=cromford' /root/harness/logs/scheduler.log \| tail -1` |
| one day's agreement on a live worker | `curl -s -H "Authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/scheduler/agreement?day=$(date -u +%F)"` |

**What must never regress:**

- The lane never dispatches: no call to run-build, fly-dispatch or the ready queue, no job write (S4).
- A parent whose PR merged clears its child even when its branch still exists; no branch is read (S2).
- Every ticket that is not ready has exactly one reason (S1).
- A retried tick writes no second row (S5, W1).
- An unreadable required input posts nothing; an unreadable lane input posts `compared=0` (X3, X4).
- Every statement uses its index, never a scan (W5).
