# Signal key store, slice C0 (BH-9800)

**What it is:** an encrypted store of per-project Sentry and PostHog keys on
the jobs worker. Slice C0 has no screen. The console "Signals" page (C1) and
the readers (C2) call these routes. Details:
[the note](../notes/2026-11-17-BH-9800-signal-keys.md).

- Routes (harness-jobs, bearer-gated): `POST /api/signal-keys/set`,
  `POST /api/signal-keys/clear`, `GET /api/signal-keys`,
  `POST /api/signal-keys/test`, `POST /api/signal-keys/read`,
  `POST /api/signal-keys/hub-read`. set, clear and test also need
  `x-web-vault-admin-token` or the BH-9262 owner proof. read needs the run
  token of a claimed run of a lane in `signal_keys.read_lanes`. hub-read
  needs `x-envelope-hub-token`.
- Crypto: the web vault's (`worker/jobs/src/lib/web-vault-crypto.js`, Worker
  secret `WEB_VAULT_KEY_<n>`, setting `web_vault.key_id`).
- Vendor seam: `worker/jobs/src/lib/signal-probe.js`. Mask:
  `worker/jobs/src/lib/token-mask.js`. Lane gate:
  `worker/jobs/src/lib/signal-lanes.js`.
- Tables: `signal_key_kinds` (seeds `sentry`, `posthog`), `signal_keys`,
  `signal_key_audit`. Settings rows: `signal_keys.read_lanes`,
  `signal_keys.test_timeout_ms`, `signal_keys.rotate_days`,
  `signal_keys.list_limit`, `signal_keys.value_max_bytes`,
  `retention.signal_key_audit.days`.
- Retention: rule `signal_key_audit.age` in the hourly `bin/d1-retention.sh` run.

## Preconditions

- Worker secrets `WEB_VAULT_KEY_1` and `WEB_VAULT_ADMIN_TOKEN` are set
  (BH-7595). Without the key, set answers 503 and writes one
  `refused:key_missing` audit row.
- `ENVELOPE_HUB_TOKEN` is set for hub-read (BH-7964). Unset, hub-read is 503.

## Check after deploy

```bash
curl -fsS -H "Authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/signal-keys"; echo "rc=$?"
```

Expected: `rc=0` and JSON with `kinds` `sentry` and `posthog` and `rows: []`
until an operator sets a key.
