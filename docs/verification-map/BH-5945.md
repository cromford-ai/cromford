# Hub project-loop ratchet, cron staggers, lead-review lock measure (BH-5945)

**What it is:** three small changes from wave 5 of #5938. Details:
[the note](../notes/2026-10-17-BH-5945-ratchet-and-staggers.md).

## The ratchet

- Run it: `bin/project-loop-lint.sh --base origin/main .`, or through the pack:
  `bin/rules-pack.sh --only project-loop`.
- It judges only a `catalog/lanes.d/<id>.json` the diff ADDS with `"scope": "hub"`
  or `"hub"` in `.boxes`. A finding line starts `<script>: new hub lane <id> loops
  over projects (S1|S2|S3 line <n>)`, and names the global lock when there is one.
- It passes when the script calls `pl_dispatch`, `pl_lane_dispatch` or
  `bin/project-lane-run.sh`, or carries `# project-loop-ok: <reason>`.

## The staggers

- `bin/render-crontab.sh <box>` writes merge-queue at `m,m+20,m+40` with
  `m = (6 + offset) % 20` and review-prs at `r,r+30` with `r = (7 + offset) % 30`.
  The offset is the fleet.conf cron offset column.
- When an earlier project on the same box (fleet.conf order) has that minute,
  the next free minute is used.
- Check: `bin/render-crontab.sh small | grep -E 'merge-queue|review-prs'`. Each
  project has its own minutes.

## The lead-review tick lock

- Each tick that took `locks/lead-review-tick.lock` logs
  `tick lock held <s>s started=<n>` when it releases it.
- A tick that finds the lock held logs
  `tick skipped: ... (a review is running) held <s>s (rerun owed)`; `held ?s`
  when `state/lead-review/tick-lock.since` is unreadable.
- Where: `logs/lead-review.log` on each board box.
