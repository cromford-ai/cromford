# The disprove pass (BH-9047)

**What it is:** after a lead review answers BLOCK, one model call per BLOCK
finding tries to prove the finding wrong from the code. In `shadow` it records
the outcome and changes nothing. In `enforce` a disproved finding becomes a
`[NOTE] disproved:` line. Details: [the note](../notes/2026-11-04-BH-9047-review-disprove.md).

## Where to look

- The code: `bin/lib/review-disprove.sh` (`dp_review`), called from the
  `# >>> disprove (BH-9047)` block of `review_one` in `bin/lead-review.sh`.
- The box log: `grep 'disprove' /root/harness/logs/lead-review.log` on a board
  box. Each pass has one line `lr-<pr>-<sha12>: disprove: <ran|skipped:<why>> (mode <m>)`
  and one count line `disprove: <owner/repo>#<pr> @<sha12>: mode <m>, ...`.
- The report: `state/lead-reviews/lr-<pr>-<sha12>.md` (the console shows it in
  the job detail of a lead-review job, artifact `lead_review_report`). When a
  pass ran, it has the header line
  `- disprove (BH-9047): mode <m>; <n> finding(s): <c> confirmed, <d> disproved, <p> kept (protected), <u> unchecked; verdict <before> -> <after>`
  and one indented line `  - disprove <OUTCOME> <class> <path:line>: <reason>`
  per finding, above `- pr body:`.
- The record: `GET /api/review-disprove?repo=<owner/repo>&pr=<n>&head_sha=<sha>`
  (or `?since=<iso>`) answers the `review_disprove_runs` rows, one per pass.

## The switch

- `bin/jobs-client.sh setting-get review.disprove.<project>.enabled`: `1` = on.
  The seed is `1` for cromford only. No row is off.
- `bin/jobs-client.sh setting-get review.disprove.mode`: `shadow` (the seed) or
  `enforce`. Any other value is shadow.
