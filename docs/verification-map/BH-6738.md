# List files grow through fragments (BH-6738)

**What it is:** `bin/list-file-lint.sh` refuses a PR that adds lines to a list
file named in `catalog/list-files.tsv` when the PR does not add its entry as a
fragment file. It is one step of the `lint` job (`Syntax + shellcheck + config
integrity`): `list files grow through fragments (BH-6738)`.

- Catalog: three tab-separated columns, `<path glob>`, `<input>`, `<note>`.
  A `*` in a glob never crosses a `/`.
- `<dir>/` (fragments): an append is green only when the PR ADDS a file under
  `<dir>/`. An edit to an existing file there does not count.
- `rendered <dir>/` (committed render): green when the PR adds or edits a file
  under `<dir>/`.
- `ignored <dir>/` (git-ignored render): any added line is red. The fix is
  `git rm --cached <file>`.
- An append is net growth in `git diff --numstat <base>...HEAD` (added >
  deleted), or any binary change. A value edit or a shrink is not an append.
- Without `--catalog` the rows are the union of the catalog at HEAD and at the
  base, so a PR that deletes a row is still checked against it.
- rc 0: no list file grew, or all grew through their input dir. No match
  prints nothing. rc 1: an append without its fragment; the output names the
  file, the catalog row and a `Fix:` line. rc 2: a malformed row (named by
  line), an unknown flag, or a base that cannot be diffed.

**How to drive it:**

| what | how |
|---|---|
| every case, scratch git repos, real script | `HARNESS_TEST_SANDBOX=1 bash tests/list-file-lint.bh-6738-test.sh` |
| this branch against main | `bin/list-file-lint.sh --base origin/main` |
| check a catalog edit | `bin/list-file-lint.sh --base origin/main --catalog catalog/list-files.tsv` |
