# pr-owner-sweep reads the PR record before GitHub (BH-8270)

**What it is:** `bin/pr-owner-sweep.sh` asks the fleet's PR record
(`pr_records`, BH-8067) first for the GitHub reads the record can answer with
the same data. `bin/lib/pr-owner/prr.sh` holds the read rule (the
`pr_record_get` rule of `bin/lib/pr-record.sh`, with no GitHub call in it). On
a miss the lane makes its old GitHub read, with its old status handling.

| Read | Now |
|---|---|
| `po_enroll` `GET pulls/N` | record `state head_sha draft mergeable_state`. A row that is not `open` declines, as a `closed` PR did. After a fallback read the answer is written back (`pr_record_put`, source `github`; not in a dry run). |
| stale rebase rung `GET pulls/N` (branch) | record `head_ref` (`_po_stale_branch`). |
| `gh pr list --state open` and `--state merged` | the record has no list route, so the pair is kept in `state/pr-owner-sweep/<owner>_<repo>/{openlist,mergedlist}.{json,meta}` and reused (see below). |

The list pair is reused only when all of these are true:

1. `bin/lib/wake-backstop.sh` is loaded and `WAKE_BACKSTOP` is not 0.
2. `PR_RECORD_MAX_AGE_S` (`pr_record_max_age`, default 900) is above 0.
3. All four files are there and both metas carry the same epoch.
4. The copy is no older than `PR_RECORD_MAX_AGE_S` and not stamped in the future.
5. `wb_cache_get` finds no `pr` wake for any PR of the repo since that epoch. A
   feed that cannot tell is a read.

A pair is stored only when both list reads answered rc 0. A failed merged read
is `[]` for that run only. `wb_gc` removes copies older than 3 days.

**The miss line**, one per fallback read, in `logs/pr-owner-sweep.log`:

```
<UTC> PRR_MISS <owner/repo>#<n|list> why=<no-row|stale|no-field|unreadable>[ field=<f>]
```

Count them: `grep -c ' PRR_MISS ' logs/pr-owner-sweep.log`.

**Reads left on GitHub:** the CI read of an enroll candidate (`mc_ci_state`,
`actions/runs`), the stale ladder's close-rung labels and commit-gone
`updated_at` reads, `commits/SHA`, comment and review bodies, `compare`, the
ticket issue and the shipped-file checks. The record has no such data, or a
copy that can differ from GitHub's answer for a guard.
