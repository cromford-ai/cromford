# Alert lines from lane-run machines, and the merge-conductor manifest (BH-6889)

**What it is:** a lane-run machine has no hub `logs/ALERTS.log`. With
`LANE_RUN_ID` set, `bin/alert-line.sh` posts its line to the jobs API, and the
hub's `bin/lane-snapshot-publish.sh` replays it into `logs/ALERTS.log` once.
The same ticket adds the `merge-conductor` lane manifest pair. Details:
[the note](../notes/2026-10-16-BH-6889-mc-manifest-alert-lines.md).

- Routes (harness-jobs, `worker/jobs/src/routes/alert-lines.js`, bearer-gated):
  - `POST /api/alert-lines {lane, project, line, stamp?, severity?, alertid?, run_id?}`:
    200 `{id, dup}`. The same lane, project, run and line twice is one row.
  - `GET /api/alert-lines?unapplied=1&limit=n` (1..500, default 200):
    200 `{lines:[...], truncated, as_of}`, oldest id first.
  - `POST /api/alert-lines/applied {ids:[...]}` (1..500): 200 `{applied}`.
    A repeat answers `{applied:0}`.
  - 400 for a bad field (the error starts with the field name), 503 when the
    table is not applied.
- Machine side: `bin/alert-line.sh` -> `alr_post` (`bin/lib/alert-line-remote.sh`).
  A failed post appends locally, as before.
- Hub side: `bin/lane-snapshot-publish.sh` step 3 -> `alr_apply`. Its stdout
  summary ends with one of:
  - `alert lines: <r> replayed, <s> already applied, ack ok|failed|none[, more]`
  - `alert lines: skipped (busy)`, `alert lines: off (not configured)`,
    `alert lines: read failed`
  - A read or ack failure raises `lane-snapshot-alert-lines` (warn); the next
    good tick resolves it. It does not change the exit code.
- Settings rows: `alert_lines.apply_max` (200), `retention.alert_lines.applied_days`
  (7), `retention.alert_lines.unapplied_days` (30).
- Manifest pair: `catalog/lane-run-inputs.d/merge-conductor.ro` and `.rw`.

**Drive it:**

1. Run `curl -s -H "Authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/alert-lines?unapplied=1&limit=5"`.
   It answers a JSON `lines` array.
2. Run `bin/lane-snapshot-publish.sh` on the hub. The last clause of its line
   starts with `alert lines:`.
3. Run `HARNESS_TEST_SANDBOX=1 bash tests/alert-lines.bh-6889-test.sh` and
   `cd worker/jobs && node --test test/alert-lines.bh-6889.test.js`.
