# orphan-reconcile reuses its open-PR list (BH-8271)

**What it is:** `bin/orphan-reconcile.sh` reads the open-PR list of its repo
from GitHub only when its stored copy cannot be used. The copy is
`state/orphan-reconcile/<owner>_<repo>/prlist.{json,meta}`, the raw answer of
the last rc 0 `gh_rest_pr_list_all` read and its epoch.

The copy is used when all of these are true:

1. `bin/lib/wake-backstop.sh` is loaded and `WAKE_BACKSTOP` is not 0.
2. `PR_RECORD_MAX_AGE_S` (`pr_record_max_age`, default 900) is above 0.
3. The copy is no older than `PR_RECORD_MAX_AGE_S`.
4. `wb_cache_get` finds no `pr` wake for any PR of the repo since the copy was
   read. A PR open, close, reopen or push rings one. A feed that cannot tell
   (rc 2) is a read.
5. The copy reshapes with the classifier's jq.

Else the lane logs one `PRR_MISS <owner/repo>#list why=<no-row|stale>` line in
`logs/<project>.log` (`no-row` = no copy files) and reads GitHub as before. A
read that fails keeps the old behavior: enqueue nothing, write no copy. The run
summary carries `pl=hit` or `pl=read` before `stranded=`.

A PR whose title or body is edited rings no wake, so the knob bounds that
staleness. The lane makes no per-PR read (`pulls/N`, reviews, checks), so
`pr_record_get` has nothing to replace here.
