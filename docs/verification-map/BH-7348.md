# Docker-pool result rows and App token rotation (BH-7348, BH-7300 slice C2)

**What it is:** the reap of a pull-mode Docker host. After the container
exits, the host pushes the build's cost rows, then posts one result row. The
hub reads the rows from the jobs worker every `jobs-watchdog` tick. While the
build runs, the host re-mints the GitHub App token before it expires. No
runner calls the host libs yet (slice C1). Details:
[the note](../notes/2026-10-17-BH-7348-docker-pool-results.md).

- Routes (harness-jobs, `worker/jobs/src/routes/docker-pool-results.js`, bearer-gated):
  - `POST /api/docker-pool/result {project, key, box, result, cost_box,
    cost_rows, unpriced_rows, cost_verified, job_id?, pr_url?, tier?,
    auth_account?}`: 200 `{recorded:true, claimed_at}`; 409 `{refused:true,
    reason}` with `no_lease`, `superseded` or `already_reaped`; 400 for a
    missing or bad field (`reason: auth_account_not_a_label` for a
    credential-looking account).
  - `POST /api/docker-pool/results/reap {limit?}`: 200 `{reaped:[...],
    backlog:0|1}`, at most 50 rows per call, each row returned once; 400 for
    a `limit` outside 1..50.
- Host libs: `bin/lib/docker-pool-reap.sh` (`docker_pool_cost_box`,
  `docker_pool_reap`: rc 0 prints `cost_rows unpriced_rows cost_verified
  claimed_at`, rc 9 refused, rc 1 anything else) and
  `bin/lib/docker-pool-token.sh` (`docker_pool_token_rotate`: always rc 0,
  prints `off <why>`, `no-expiry`, `not-due`, `no-fresher`, `keep <why>` or
  `rotated <expires_at>`).
- Hub client: `docker_pool_results_reap` in `bin/lib/docker-pool.sh`.
- `bin/jobs-watchdog.sh` reads the rows every hub tick: one `docker-pool
  result:` log line per row, one `docker-pool results:` summary line, and one
  `DOCKER POOL COST ROWS` ALERTS line per row with unpriced or unverified cost
  rows.
- Row `retention.docker_pool_results.days` (30); retention rule
  `docker_pool_results.age` deletes only rows the hub has read.

**How to drive it:**

| what | how |
|---|---|
| route decision rules, reap race, retention, EXPLAIN at 5,000 rows | `cd worker/jobs && node --test test/docker-pool-results.bh-7348.test.js` |
| host libs, client and the watchdog block, over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/docker-pool-reap.bh-7348-test.sh` |
| a read on a live worker | `. bin/jobs-client.sh; . bin/lib/docker-pool.sh; docker_pool_results_reap` prints `0	0` when no row is unread |

**What must never regress:**

- A result from an expired, killed or released lease is never recorded (P3, P4).
- A result from a box that does not hold the lease is never recorded (P6).
- A row the hub read is never changed by a re-post (P15).
- Two concurrent reads never return one row twice (Q4).
- The cost rows are pushed and verified before the result is posted (R1).
- `cost_verified` is 1 only when `cost-rows-push.sh --verify` answered rc 0 (R2).
- The host reap and the container use one cost-row box id (I1).
- The rotation never writes a token whose expiry is not later than the old one (T5, T6).
- The token is never on stdout, in argv, in a log or in the state file (T4).
- An unread result row is never deleted by retention (P16).
- Every result statement uses an index, never a scan (E1).
