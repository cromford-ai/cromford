# Saved browser session of a web-task run, slice C0 (BH-7597)

**What it is:** an encrypted, run-bound save and load of the Playwright
`storageState` of a web-task run, so a later run can skip sign-in and 2FA.
A lane run uses `wsess_save` / `wsess_load` from `bin/lib/web-session.sh`.
Details: [the note](../notes/2026-11-01-BH-7597-web-session.md).

- Routes (harness-jobs, bearer-gated): `POST /api/web-session/save`,
  `POST /api/web-session/load`. Both need the header
  `x-web-vault-run-token` of a claimed `web-task` run of the same project,
  held by the calling machine, and a site on
  `lane.web-task.<project>.allowed_domains`.
- Store: `web_vault` field `session_state` of `(project, site)`. One row per
  `(project, site)`; a save replaces it. `POST /api/web-vault/read` refuses
  that field (`use_session_load`).
- Age limit: settings row `lane.web-task.session_max_days` (default 14). An
  older session is refused `404 expired` and is not deleted.
- Size cap: settings row `lane.web-task.session_max_bytes` (default 262144,
  1024..1048576). The worker and `wsess_save` both read it. A larger value
  is `400 value must be 1..<cap> bytes`.
- `wsess_forget` removes only `storage-state.json` in a `web-session.XXXXXX`
  dir directly in the physical `$TMPDIR`. Any other path is rc 2.
- No screen. No production caller yet: slice C1 calls the client from
  `bin/lib/web-task/session.sh`.

## How to drive it

Preconditions: a claimed `web-task` run and the run token its claim returned
(`vault_token`), the site on the project's allow-list, and the Worker secret
`WEB_VAULT_KEY_<n>`.

1. In the run's shell, set `LANE_RUN_ID`, `WEB_VAULT_MACHINE` (or
   `FLY_MACHINE_ID`), `WEB_VAULT_RUN_TOKEN`, `JOBS_URL`, `HARNESS_SECRET`.
2. `. bin/lib/web-session.sh`
3. `wsess_save <project> <site> state.json` prints
   `web-session: saved <project> <site>`.
4. `p=$(wsess_load <project> <site>)` gives a mode-600 file; `cmp state.json "$p"` is 0.
5. `wsess_forget "$p"` removes it.
6. Rc 3 from `wsess_load` with `web-session: none (expired)` or
   `none (no_entry)` means the run signs in again.

Operator check: `bin/web-vault.sh audit <project>` lists the `session_state`
`set` and `read` rows, with no value.
