# PM agent data signals (BH-7244 slice 1, BH-7258)

**What it is:** each `bin/run-product.sh <project>` cycle runs
`bin/pm-signals.sh <project> $CYCLE_DIR/data-signals.json` before SIGNALS.
The file is `{snapshot_hash, generated_at, evidence:[{id, source, metric,
value, window, link, status}]}`. When the file is valid, the SIGNALS prompt
gets the line `DATA_SIGNALS=<path>`, and the project log summary line gets
`data_evidence=<n>` (the count of `status: "ok"` rows).

- Registry: `bin/pm-signals.d/`. Every `common-*.sh`, then `<project>.sh`.
  One `pms_<name>` function per file. Today: `common-alerts.sh` only.
- A failed adapter gives one `adapter.<name>` row with `status: "error"`.
  The runner still exits 0.
- A runner failure is one `pm-signals failed or missing` line in
  `logs/<project>.log`. SIGNALS then runs without the `DATA_SIGNALS=` line.
- Seams for later slices: `product_run_cap_check <stage>` (BH-7244.5) after
  MAP, SIGNALS, IDEATE and SYNTH; `pm_ideas_land <project> <cycle_dir>`
  (BH-7244.3) once after SYNTH. `pm_ideas_land` returns 0 today.
  `product_run_cap_check` is the per-run USD cap since BH-7262
  ([BH-7262.md](BH-7262.md)); with no `PRODUCT_RUN_USD_CAP` row it returns 0.

**Preconditions:** none for the runner. A cycle needs the stage prompts and a
model route; the suite stubs `agent-call.sh`.

**How to drive it:**

| what | how |
|---|---|
| runner, adapter and run-product wiring (stub agent-call) | `HARNESS_TEST_SANDBOX=1 bash tests/pm-signals.bh-7258-test.sh` |
| the product.pm route seed | `cd worker/jobs && node --test test/model-routes-pm.bh-7258.test.js` |
| one snapshot on a box | `bin/pm-signals.sh <project> /tmp/ds.json && jq . /tmp/ds.json` |
| the last cycle's file | `jq . /root/harness/products/<project>/<YYYY-MM-DD>/data-signals.json` |
| the summary line | `grep 'data_evidence=' /root/harness/logs/<project>.log \| tail -1` |
