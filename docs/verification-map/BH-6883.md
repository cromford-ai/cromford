# Project lease with a fence token (BH-6883)

**What it is:** one lease per `(lane, project)`. A holder acquires it, gets a
fence number, renews it before each write and releases it when done. A holder
whose lease ran out and was taken over gets 409 `lost` on renew, so it must
stop. Details: [the note](../notes/2026-10-15-BH-6883-project-lease.md).

- Routes (harness-jobs, `worker/jobs/src/routes/project-leases.js`, bearer-gated):
  - `POST /api/project-leases/acquire {lane, project, holder, ttl_s?}`: 200
    `{fence, lease_until, as_of}`, or 409 `{error:"held"}`.
  - `POST /api/project-leases/renew {lane, project, holder, fence, ttl_s?}`:
    200 `{fence, lease_until, as_of}`, or 409 `{error:"lost"}`.
  - `POST /api/project-leases/release {lane, project, holder, fence}`: 200
    `{released:true, fence, as_of}`, or 409 `{error:"lost"}`.
  - 400 for a bad `lane`, `project`, `holder`, `fence` or `ttl_s`.
- Shell client: `bin/lib/project-lease.sh` (`pjl_acquire`, `pjl_renew`,
  `pjl_release`); rc 0 ok, rc 3 held/lost, rc 1 anything else.
- Row `project_lease.ttl_s` (180, 10..900).
- No caller yet. BH-6881.3 (#6887) is the first.

**How to drive it:**

| what | how |
|---|---|
| routes, schema plan and shell client, over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/project-lease.bh-6883-test.sh` |
| one acquire, renew and release on a live worker | `. bin/jobs-client.sh; . bin/lib/project-lease.sh; f=$(pjl_acquire probe-bh-6883 cromford "$(hostname)"); pjl_renew probe-bh-6883 cromford "$(hostname)" "$f"; pjl_release probe-bh-6883 cromford "$(hostname)" "$f"` |

**What must never regress:**

- A second holder never acquires a live lease (case 1).
- A takeover after expiry always raises the fence (case 2).
- A stale fence never renews or releases (cases 3, 4, D4).
- A holder never renews its own expired lease (D2).
- The 409 never names the holder (case 1).
- An outage is rc 1 in the shell client, never rc 3 (S2).
- Every statement uses the primary key, never a scan (case 5).
