# Lane-run fleet: flyctl lookup and the fly-missing alert (BH-6697)

**What it is:** `bin/lane-fleet.sh tick` finds flyctl under cron's bare PATH,
and the fly-missing alert repeats once per UTC hour while flyctl is absent.
The fleet itself is in [BH-6126](BH-6126.md).

- Lookup: `LANE_FLEET_FLY` when set, else `fly_bin` from
  `bin/lib/fly-bin.sh`. `fly_bin` looks in PATH, then `$FLYCTL_INSTALL/bin`,
  `$HOME/.fly/bin`, then `${FLY_BIN_DIR:-/root/.fly/bin}`.
- No flyctl: the tick writes `flyctl not found (PATH, $HOME/.fly/bin,
  ${FLY_BIN_DIR:-/root/.fly/bin}); nothing done` to `logs/lane-fleet.log`
  and exits 0. It writes one `[lane-fleet] flyctl not found on <host> ...`
  ALERTS line per UTC hour. The flag is
  `flags/alerted-lane-fleet-fly-missing-<YYYYmmddHH>`; the tick removes the
  flags of earlier hours.
- Every other lane-fleet alert kind stays one line per UTC day.

**How to drive it:**

| what | how |
|---|---|
| lookup and alert cadence, real tick, bare PATH, stub flyctl | `HARNESS_TEST_SANDBOX=1 bash tests/lane-fleet-flybin.bh-6697-test.sh` |
| the not-found count on the hub | `grep -c 'flyctl not found' /root/harness/logs/lane-fleet.log` |
| the last ticks on the hub | `tail -n 3 /root/harness/logs/lane-fleet.log` |
