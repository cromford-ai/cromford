# web_vault credential store, slice C0 (BH-7595)

**What it is:** an encrypted store of web-task sign-in values. The operator
writes with `bin/web-vault.sh`. A lane run reads with `wv_read` from
`bin/lib/web-vault.sh`. Details: [the note](../notes/2026-10-19-BH-7595-web-vault.md).

- Routes (harness-jobs, bearer-gated): `POST /api/web-vault/set`,
  `POST /api/web-vault/read`, `GET /api/web-vault/entries`,
  `GET /api/web-vault/audit`. set, entries and audit also need the header
  `x-web-vault-admin-token`.
- Crypto: `worker/jobs/src/lib/web-vault-crypto.js` (AES-GCM 256, Worker
  secret `WEB_VAULT_KEY_<n>`).
- Tables: `web_vault`, `web_vault_audit`, `web_vault_run_token`. Settings rows:
  `web_vault.key_id`, `web_vault.retain_days`, `retention.web_vault_audit.days`,
  `retention.web_vault_run_token.days`.
- A read needs the run token that the claim of a `web-task` run returns
  (`vault_token`). Enqueueing a `web-task` run needs `x-web-vault-admin-token`.
- Retention: rules `web_vault_audit.age` and `web_vault_run_token.age` in the
  hourly `bin/d1-retention.sh` run.

## Preconditions

- Worker secrets `WEB_VAULT_ADMIN_TOKEN` and `WEB_VAULT_KEY_1` are set. Without
  them, set answers 503 (`vault key missing`) and every operator route 403.
- The hub env holds `WEB_VAULT_ADMIN_TOKEN` (the same value) for the CLI.
- A read needs the settings row `lane.web-task.<project>.allowed_domains`.

## Check after deploy

```bash
bin/web-vault.sh stale; echo "rc=$?"
```

Expected: `rc=0`. No output means no stale rows. `not-configured: <NAME>` with
rc 3 means the hub env lacks that name.
