# web-task human step, slice C0 (BH-7598)

**What it is:** a web-task run that meets a 2FA step it cannot do asks a
person. It calls `wh_request_human` from `bin/lib/web-human.sh`. The person
answers on Telegram or on the ticket. Details:
[the note](../notes/2026-10-23-BH-7598-web-task-human.md).

- Routes (harness-jobs, bearer-gated): `POST /api/web-task/human/ask`,
  `POST /api/web-task/human/poll` (both also need the run token
  `x-web-vault-run-token` of the claim) and `POST /api/web-task/answer`.
- Seams: `bin/lib/web-human/telegram.sh` (Bot API; `TELEGRAM_BOT_TOKEN`) and
  `bin/lib/web-human/board.sh` (`gh api` issue comments).
- Table: `web_task_human_step`. Settings rows: `web_task.human_wait_s`,
  `web_task.human_poll_s`, `web_task.human_answer_ttl_s`,
  `web_task.human_logins`, `retention.web_task_human_step.days`. The Telegram
  chat is `lib.lane-alert.lane_alert_dm_chat`. Lib knobs:
  `lib.web-human.web_human_timeout_s`, `lib.web-human.web_human_connect_timeout_s`.
- Retention: rule `web_task_human_step.age` in the hourly `bin/d1-retention.sh` run.
- Markers: the hold comment's first line is
  `NEEDS-HUMAN: web-task <kind> on <site>: <prompt>`; a person answers with a
  comment whose first line is `HUMAN-STEP-DONE: <code|done>`.

## Preconditions

- Worker secret `WEB_VAULT_KEY_1` is set (a code is stored with the vault
  key). Without it a code answer is 503 and nothing is written.
- The run is a claimed `web-task` run with the run token of its claim, and the
  site is in `lane.web-task.<project>.allowed_domains`.
- For Telegram: `TELEGRAM_BOT_TOKEN` in the run's env, the chat row set, and
  the console forwarding `wt:` updates to `/api/web-task/answer` (slice C1).

## Check after deploy

```bash
printf '%s' '{"callback_query":{"data":"wt:1:AAAAAAAAAAAAAAAAAAAAAA:d"}}' \
  | curl -sS -K <(printf 'header = "authorization: Bearer %s"\n' "$HARNESS_SECRET") \
      -H 'content-type: application/json' --data-binary @- "$JOBS_URL/api/web-task/answer"
```

Expected: `{"error":"refused","refused":"bad_nonce"}` with HTTP 403. The route
is live and refuses an unknown nonce. `web_task_human_step schema not applied`
(503) means the schema fragment did not apply.
