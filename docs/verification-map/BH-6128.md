# blocked-resolver off the hub (BH-6128)

**What it is:** `blocked-resolver` runs on Fly lane machines. The hub publishes
each project's inputs as a snapshot through the jobs worker, the machine
fetches it before the run and writes its changes back after every candidate,
and the hub applies the write-backs with compare-and-set. No ssh.
Details: [the note](../notes/2026-10-12-BH-6128-blocked-resolver-offhub.md).

- Placement: settings row `lane_placement.blocked-resolver` (not seeded; the lane stays on the hub until a later PR sets `fly` after BH-6125 and BH-6126 are live).
  Once set to `fly`, the value `hub` or a `lane_placement.blocked-resolver.hub_only` text moves it back.
- Publisher: `bin/lane-snapshot-publish.sh`, cron `2,12,22,32,42,52`. One line:
  `lane-snapshot-publish: <n> published, <u> unchanged, <a> write-backs applied, <c> conflicts, <r> rejected, <f> failed (<why>); blocked-resolver placed <fly|hub> (<reason>)`.
- Machine: `logs/lane-run-worker.log` says
  `inputs: snapshot <sha12> + <k> write-backs, age <s>s` per run. A row `done`
  rc 66 means the fetch failed and nothing ran; rc 75 means a write-back failed.

**How to drive it:**

| what | how |
|---|---|
| fetch, run, write-back and apply, over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/blocked-resolver-offhub.bh-6128-test.sh` |
| the routes alone | `cd worker/jobs && node --test test/lane-snapshots.bh-6128.test.js` |
| one project's snapshot on a live worker | `curl -sS -H "authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/lane-snapshots/blocked-resolver/<project>" \| jq '{sha,age_s,pending,truncated}'` |
| the publisher on the hub | `tail logs/lane-snapshot-publish.log` |
| apply one project's write-backs by hand on the hub | `HARNESS=/root/harness bash -c '. bin/lib/lane-run-inputs.sh; lri_apply_pending blocked-resolver <project>'` |

**What must never regress:**

- A machine never runs on empty or stale inputs: no snapshot, an old one, a
  truncated write-back list or a sha mismatch is rc 66 and no run (O3, O5).
- A write-back never writes outside the rw allow-list (`env/`, `flags/`,
  `logs/ALERTS.log`, another project's records are refused) (O2, O6).
- The hub keeps its own copy when it changed a file after the machine's
  snapshot (O6).
- A run whose write-back failed is reported 75, never 0 (O7).
- The machine run takes the same rungs as a hub run and makes no ssh call (O9).
