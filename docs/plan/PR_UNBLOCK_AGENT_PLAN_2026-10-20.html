PR Unblock Agent: "Tackler"

cromford fleet, plan of 2026-10-20. Author: Mac planning session. Status: for the operator's review. No ticket is filed.

In a Lancashire mill the tackler was the worker who freed a stopped loom and kept the floor running. This agent does that for the fleet: when a PR, a batch, a build, a box or a lane stalls on a decision, Tackler decides from the operator's written guidelines, acts through the harness, writes one ledger row with the rule it cited, and sends the operator a one-screen card only when no rule covers the case or the action is in a never-auto class.

TL;DR

The answer is yes

  • On 2026-10-19/20 one Mac session made 36 hand decisions under the operator's standing approval in 43 hours (hub logs/merge-conductor-backstop.log). Each one is derivable from data the harness already holds.
  • The stalls had real cost: one BLOCK stayed comment-only for 80 minutes with no fix round (#7556); four innocent PRs sat ejected after batch #7699; the project-6-os box hung 9 hours; a respawn loop cost $77.54 in one day.
  • The fleet already has the parts: the staff roster and agent-core (decide(level, cap, action), never lists, delegation by streak), dequeue-watch, the queue doctor, the blocked-resolver ladder, lead verdict rows, settings rows, and the alert path to Telegram.
  • Tackler composes those parts. It adds a rulebook, a decision ledger, an escalation card and one act layer. It does not replace a lane.

Shape in one screen

  • Hub lane bin/unblock.sh, cron every 10 minutes, registry row catalog/lanes.d/unblock.json.
  • Staff agent tackler in staff_agents; classes in staff_classes; never-auto classes carry never_delegable=1.
  • Deterministic collectors and a JSON rulebook decide first. A model call happens only after the ledger row is claimed, and only for judgment the rules name.
  • Model routes stage.unblock and unblock.judge are DB rows seeded from model_prices (Fable or Opus per current routing). No model string in code.
  • Ledger table unblock_decisions: who, rule cited, evidence, action, outcome, override. Indexed per query. Archived after 180 days.
  • Escalation card to the operator's Telegram DM through bin/lane-alert.sh --critical. Answer grammar Tackler <id> <option>. On silence it waits and re-declares once a day.
  • Ships dark: UNBLOCK_ACT=0 (shadow). The flip to act is a settings row on cromford only. Other projects opt in by row.
  • 11 AI coding sessions in 7 slices. Slices 1-3 build in parallel.

What the engine guarantees

  • One rule per file. A new rule is a new file. The loader refuses two files with one id (lists are folders).
  • A predicate that errors or reads null is unknown, and unknown never matches. The stall goes to U12 with the predicate named.
  • key builds the decision key: sha256 of the named fields plus the rule id. The same stall on the same head can never buy two actions.
  • cites must exist in catalog/unblock-rules.d/_cites.json. A rule with no cite fails the lint (a decision with no rule behind it is a guess).
  • judge names a prompt file under catalog/prompts/ and a composition from the manifest. A judge answer is one of a closed set; anything else is UNSURE.
  • A rule edit is a PR on this repo. The lane reads the rendered catalog of the harness commit it runs. No rule is ever a settings row.

Ledger rules

  • Claim before spend. The row is inserted with outcome claimed before any model call or write. A conflict on decision_key means another tick owns it: stop (G10, G18).
  • Who. agent, plus actor on every settings row and verdict row it writes (tackler:<key12>). Every GitHub comment and review carries <!-- tackler:<decision_key> -->; the collectors drop anything that carries it (G6).
  • Rule cited. rule_id and rule_cites are NOT NULL except on a U12 row, where the cite is the parked class.
  • Evidence. The stall record as judged, capped at 8 KB, redacted by the same scrub mcp/lib/console.mjs uses. No secret value ever lands.
  • Outcome. Three outcomes for a paid judge call: an answer (ok), an empty answer (billed, terminal, treated as UNSURE), a failure (retry at most 2) (G10).
  • Override. S6 fills override_* when a person reverses the action inside 24 h: a human verdict row with the opposite verdict on the same head, a dequeue by a person after a Tackler queue, a settings row set back by a non-agent actor. One override demotes the class to ask_first (agent-core).
  • Retention. Rule unblock_decisions.age in worker/jobs/src/routes/retention.js: rows older than retention.unblock_decisions.days move to the archive store, retention.dry_run applies. Never a delete.
  • Routes. POST /api/unblock/decisions/claim, POST /api/unblock/decisions/record, GET /api/unblock/decisions?project=&subject=&outcome=, POST /api/unblock/decisions/:id/answer, GET /api/unblock/metrics (S6).

Card rules

  • One screen. At most 900 characters, plain text, no markup. tests/unblock-card asserts the cap and the five fields.
  • Five fields, always. What, options (2 to 4, numbered), recommendation with one reason, default if no answer, deadline. The default is always the safe state the subject is already in. The agent never acts on silence (the operator: "waits, never guesses").
  • Delivery. bin/lane-alert.sh --critical --id unblock-<key> --severity critical: the existing alert state machine sends it once to the operator's Telegram DM and suppresses repeats. The daily re-declaration is one REMIND through the same id (G6: declare the wait).
  • Answer paths. Telegram: bin/orchestrate.sh intercept calls bin/unblock-reply.sh intercept <text> (grammar Tackler <id> <option|hold note>), the same shape as Archie's intercept. Console: POST /api/staff/chat to agent tackler with the same text. Both land in POST /api/unblock/decisions/:id/answer, keyed on the command id, so a re-delivered message counts once.
  • After an answer. The keyed tick runs at once with the chosen option as a rule override for that subject and head only. The ledger row goes answered; the action it caused is a new row that cites the answer (cites: ["OPERATOR:u-3f9a2c"]).
  • Expiry. After UNBLOCK_CARD_TTL_H (72) with no answer the row goes expired, the subject stays parked, and the weekly report lists it. Nothing else happens.
  • Never on a card. A secret value, a client's data, a model string. The scrub runs before the send.

Safety

Kill switch and modes

  • Settings row unblock.enabled=0, flag lane-off-unblock, staff-kill-tackler (the console's /staff kill button): each one stops the tick before any read.
  • Mode per project: unblock.project.<p>.mode = off | shadow | act. Missing row = off. Only cromford is seeded, at shadow.
  • Registry knob UNBLOCK_ACT default 0. Shadow mode writes nothing outside the ledger and logs WOULD_<ACTION>, the dequeue-watch pattern (BH-3859). The lane never flips itself.
  • Rollback of any act-mode effect is a row: the verdict row is superseded by a newer row, a setting by its noted old value, a queue by a dequeue.

Budgets and tripwires (G3, G17)

  • Per call: UNBLOCK_LLM_MAX_USD (0.6) through AGENT_CALL_BUDGET_USD. Per day: LLM_USD_CAP_DAY registry default 0 (unlimited), like every LLM lane; the dedup key guards spend.
  • Tripwires alert and never stop: actions of one class in a day above 3x the 7-day baseline; the same subject claimed on 3 heads in a day; judge calls above 20 a day; a card re-declared more than 3 times. Each is one lane-alert.sh --severity warn with a stable id.
  • Hard limits that stay hard: the per-call dollar budget, 2 model attempts per decision key, the GitHub quota budget (gh-budget skip, as dequeue-watch), one knob change per key per day, one box restart per box per hour.

Dedup and idempotency (G6, G10)

  • The decision key is the condition's permanent address: no timestamp, no counter.
  • Before any GitHub write the act layer re-reads the head and refuses on a moved head (the lead-verdict.sh rule, exit 3).
  • Before a comment or review it searches for its own marker on that head; found = done, no second write.
  • A requeue goes through mc_requeued_mark and mc_requeued_record, so the conductor and Tackler share one once-per-(PR, sha) memory.
  • Collectors drop every item that carries a tackler: marker or a staff: label. Its own ledger is read only for the last 5 rows of the same subject, as context, never as a finding.

Audit

  • Every decision is one ledger row. Every write names the row in its actor or marker. The Mission Control page (S6) lists rows newest first with the rule cite and the evidence, sortable.
  • Every tick posts a staff_ticks row (phase, counts, rc) through the staff activity route, so a silent lane shows as silent.
  • The daily digest carries one Tackler line: decisions, acts, cards open, overrides. Archie's weekly report carries precision per class and any promotion to approve.
  • Tests run with stubs for gh, the jobs API and agent-call: every test counts calls, and a second tick on the same fixture must make 0 writes.
