## Executive summary

1. **The lane that "went wild" is the project-5 external-PR review lane (`bin/review-prs.sh`, box 10.0.0.5, cron 7,37).** Its dedup ledger `state/project-5.pr-reviews.json` became a 0-byte / non-object file, the pre-call check `.[num].sha == head` read "never reviewed" for every open PR, and every tick re-bought a Fable review of every unchanged head: **460 verdicts on 122 distinct PR+head (3.77x) in the surviving log window 09-18 04:41Z → 09-19 14:20Z; PR #229 @553a9e0 got 52 identical REQUEST_CHANGES reviews in 32 h, #2551 @0222cd8 got 37, twelve more PRs 12–19 each.** project-5 review-stage spend was $367 (09-17, 132 calls), $548 (09-18, 341 calls), $591 (09-19, 428 calls) = **$1,506 over 3 days, of which roughly $1,100 bought nothing new** (a fresh head costs ~$2.4 on Fable). The loop stopped ~14:20Z on 09-19 when the ledger was repaired; the code fix is BH-977 (#978, merged 09-19 16:36Z, deployed 18:29Z), which refuses a jq write that produced no object.
2. **Three more loops with the same shape are still running.** Triage shards re-buy an unchanged "still waiting on PR #X" conclusion for every queued ticket 3–6x per hour (project-4 TK-1673 97 sessions in 43 h; project-4 1,008 shards on 68 tickets on 09-18; cromford $896 on 09-18 for 936 calls on 187 tickets). Pre-plan drops and re-buys a $4 Fable plan every time `main` moves in a planned file (project-4 152 PREPLAN_STALE re-plans on 09-18, $1,037; TK-1847 ~50 re-plans in 3 days). Review-autopilot throws away a paid review whenever `gh pr comment` fails and buys it again next hour (156 of 372 spends in 3 days, project-4 #1541 @d8a5ba0 bought 16 times).
3. **The merge conductor's head-bound re-review re-buys fallback-lane reviews it then rejects.** When the Claude lane is down, `agent-call.sh` serves the review on fireworks/openrouter, the conductor marks it LANE FAILED on provenance, and spawns again (cromford #818 @d5e8152c: 8 spawns, 5 paid kimi reads, parked, re-armed, spawned again). 421 spawns on 305 heads in 3 days, 157 with no verdict.
4. **$3.5K (est) of the 3-day spend is invisible in the ledgers**: 123 review calls on `anthropic/claude-fable-5.1` via OpenRouter (72.9M input tokens, 0 cache reads, ≈$728), fable-via-OpenRouter triage on project-1/project-5/project-7/project-3/responder (≈$1,730), codex `gpt-6-astra` triage (≈$260), fireworks kimi (≈$330). Same cost-capture gap as the August grok incident; the fallback rung bills at API rate with no prompt cache, ~10–40x the subscription lane per call.
5. **Fleet total for the window: ≈$13.1K priced + ≈$3.5K est unpriced ≈ $16.6K in 3 days**, of which roughly $4–5K is repeat purchases of an unchanged input (project-5 reviews ~$1.1K, triage shards ~$2K, preplan ~$1.5K, autopilot ~$0.4K, conductor fallback re-reviews ~$0.3K).

The project-1 "213 identical comments on TK-88" is **not in this window and not our loop**: ALERTS.log dates it 2026-08-12 → 08-16 and attributes it to the partner fork harness ("Harness" actor on collaborator-1's box), one comment/min. ## Ranked fixes worth a ticket (most $ saved first; acceptance tests in the fleet's test-first shape)

1. **Per-ticket dedup for triage shards** (site 4) — est. $1,000–1,500/day. `bin/lib/rt/shards.sh` computes `state/triage-shards/<project>/<key>.fp` = sha256(queue line with ISO timestamps and free prose after the status word stripped + referenced PR numbers' `state` + this ticket's RESULT/COMMENTED set + result-rows for the key) and skips the shard when it equals the stored value and the stored stamp is <4 h old; the tick-level `queuefp` brake stays as backstop. Tests (`tests/triage-shards-ticket-fp-test.sh`, red first): (a) two RUN ticks over an identical queue line whose "Re-checked <ts>" and hold prose differ → the second tick dispatches 0 shards for that key and writes no cost row; (b) a referenced PR flipping OPEN→MERGED → the shard dispatches; (c) a new RESULT dir for the key → dispatches; (d) 4 h elapsed → dispatches once and restamps.
2. **Cap and terminalize pre-plan re-plans** (site 6) — est. $800–1,200/day. `bin/preplan-tick.sh` counts PREPLAN_STALE per `<project>/<key>` in `state/preplan/<p>-<key>.replans`; after 2 in 24 h it writes `PREPLAN_DEFER_TO_BUILD` (terminal until the ticket's queue line or plan inputs change) and stops calling; the build stage plans from scratch as it does today. Tests (`tests/preplan-stale-cap-test.sh`): (a) main moved three times in a planned file → exactly 2 re-plan launches, then a DEFER marker and no `agent-call.sh` invocation (stub agent-call counts calls); (b) the ticket's queue line changes → marker cleared, one more launch; (c) a merge that does not touch planned files → 0 launches.
3. **Make the review-prs dedup survive a wiped ledger** (site 1) — prevents recurrence of $500–600/day. Before `agent-call.sh review`, `bin/review-prs.sh` asks GitHub (free) whether a review authored by the harness identity carrying `of <sha>` already exists on the PR (and/or the D1 jobs ledger row for `<slug>#<num>@<sha>`); if so, it rehydrates `state/<project>.pr-reviews.json` from that and skips the call. Tests (`tests/review-prs-gh-dedup-test.sh`): (a) ledger reseeded to `{}` + stub `gh` returning an existing harness review for the head → 0 agent-call invocations, ledger entry restored; (b) same but the existing review is for an older sha → 1 call; (c) gh read fails → 1 call (fail-open) and one log line.
4. **Review-autopilot: cache before posting, never re-buy a failed post** (site 2) — est. $150–250/day. Write `state/review-autopilot/<key>` with `status=reviewed-unposted` and the review body BEFORE `gh pr comment`; on the next tick, a key in that state re-posts from the cached body with no model call; an empty review twice → `status=empty-terminal`. Tests (`tests/review-autopilot-post-retry-test.sh`): (a) stub `gh pr comment` fails → key file exists with the body, agent-call count 1; next tick with `gh` succeeding → posted, agent-call count still 1; (b) empty model output twice → terminal marker, third tick makes no call; (c) the daily cap still counts the first spend.
5. **Conductor re-review: no fallback buys the Claude lane will reject** (site 3 + 13) — est. $250/day when OpenRouter-Fable serves, plus the loop. `mc_rereview` passes a claude-only intent to `agent-call.sh` (env `AGENT_CALL_RUNNERS=claude`) so an outage returns rc=2 with no vendor call; a provenance/lane failure is recorded once per (head, lane-health epoch) and the head is not re-spawned until `claude-auth-check` reports the lane up; the BLOCKED_HUMAN → HEAD_MOVED reconciliation only re-arms when `head != reviewed` **and** the head sha changed since the park. Tests (`tests/merge-conductor-rereview-lanefail-test.sh`): (a) stub agent-call that serves "fireworks" → 0 vendor rows written, one `lanefail` attempt row, no second spawn while the lane-down marker is present; (b) lane marker cleared → exactly one spawn; (c) a park re-derived to HEAD_MOVED with an unchanged head → no spawn.
6. **Cost-capture parity for openrouter / fireworks / codex rows** (site 13) — makes $1.2K/day visible. `bin/lib/cost-row.sh` prices every row at write time from `catalog/model-prices.json` (fable via openrouter at API rate with `cache_read` as reported), and `cost-reconcile.sh` alerts when any runner writes >20 blank-cost rows in an hour. Tests (`tests/cost-row-priced-test.sh`): a synthetic openrouter row with tokens → `cost_usd` non-empty and equal to the catalog product; a grok row with zero tokens → `UNPRICED` note, not a silent blank. Also worth deciding in the same ticket: whether `RUNNER_*_FALLBACK=openrouter` with an `anthropic/` slug (no prompt cache, 40x the per-call price of the subscription lane) should be opt-in per stage rather than the fleet default.
7. **Consume a failing single-session triage after 3 attempts** (site 5) — small $, removes the 1,168 rc≠0 project-5 triage rows/day shape. Test: three consecutive rc≠0 sessions on the same gate fingerprint → the fourth tick consumes the pending fingerprint and alerts once.
8. **Age out post-merge QA requeues** (site 16) — no model spend, but 30,698 requeue lines in 3 days is a dead-feed: after N hours of "prod not yet serving sha" write terminal state and one alert.
