**The shape of the problem.** The DB layer was built additively over eight phases with the explicit rule "the file stays the ledger of record, the row is a mirror" (`docs/DB-COORDINATION-SPEC.md:1399`). That rule was right for landing the layer dark; it now means every lane has two answers to every question and a precedence rule per lane that differs from its neighbour's: merge-sweep reads file-then-DB and back-fills the file; migration-autopilot reads file-then-DB and does not back-fill; the conductor reads DB only on an empty file; pause flags reconcile DB→file apply-once; build_queue is row-first on the watcher and file-first on the pool; the reviewed sha has six homes and no rule at all. The wake loop (`wakes` table) already carries the GitHub events that would let eleven polling lanes stop polling (`docs/EVENTS.md §8`), but the cron lines were kept "as the safety argument" and never removed, so the fleet pays both.

**Drift finding (unrelated to the plan, but load-bearing for it).** The live hub crontab carries `* * * * * hub-lease.sh renew` and `# BEGIN hub-lanes` gating on 40+ lines; the committed `cron/hub.cron` has zero `hub-lease` mentions. The hub's own checkout `/root/harness-checkout` sits at a local merge commit (`7266ec54 Merge remote-tracking branch 'origin/main' into HEAD`) that carries BH-432 (`origin/ticket/bh-432-r2`, PR #785, not on main) and renders 53 hub-lease lines. So the hub is rendering its crontab from a branch that main does not have, and `tests/cron-fleet-parity-test.sh` cannot see it. The last crontab apply on the hub was 2026-09-13 (`state/crontab.bak-202609130010`). Land BH-432 or revert the checkout before any cron-line removal in this plan, or the parity test will fight every slice.

## 3. Migration plan — ticket-sized slices

Ordering: (a) split-brain risk today, (b) polling/spend saved, (c) size (in AI sessions). Every slice is additive on the schema (`IF NOT EXISTS`, new nullable columns or new tables), lands dark behind a flag row, and keeps the file as a write-through cache for one full cycle before the file read is deleted. Acceptance tests are `tests/<name>-test.sh` in the fleet's shape (`HARNESS_TEST_SANDBOX=1`, scratch tree via `tests/lib/scratch.sh`, a fake worker via the existing `tests/lib/jobs-fake.sh` pattern) and are written RED first.

### Slice 0 — Land the hub-lease gating on main and close the epoch gap
*Risk today: two hubs for 60–600s; the live crontab is rendered from a branch. Saves: nothing. Size: ~0.5 session.*
- Merge or re-cut BH-432 (`origin/ticket/bh-432-r2`, PR #785) so `cron/hub.cron` carries `hub-lease.sh renew` and the `# BEGIN hub-lanes` markers; re-point `/root/harness-checkout` at `origin/main`.
- `hub-lease.sh check` compares the cached `epoch` against the row whenever the cache is used from the grace path, and `renew` writes the epoch it was granted; a `promote` on the worker bumps `epoch` and the next `check` on the old holder fails even inside the 60s window.
- Tests: `tests/hub-lease-epoch-test.sh` — RED: cache says held, worker row has epoch+1 → `check` must exit 1; `tests/cron-fleet-parity-test.sh` passes on the rendered hub file.

### Slice 1 — One home for the reviewed sha and the verdict
*Risk: the highest split in the fleet (§2.3 #1). Saves: duplicate paid re-reviews, head-bound parks of approved PRs. Size: ~1 session.*
- `job_artifacts(verdict)` becomes the ONLY authority for `{verdict, reviewed_sha, tier, served_by}`. `review-prs.sh` writes it via `job_artifact_put verdict` (today it never does); every rebinder (`rebase-train.sh:247`, `merge-conductor.sh:355,:379,:753`, `lib:3005,:3159`, `blocked-resolver.sh:2185`) calls `job_verdict_rebind` and the file write becomes cache-only.
- Add a `verdict_history` table (or reuse `job_phases`) so a second review round does not overwrite the first (schema.sql:293).
- Delete the `apverdict` lines from `attempts.txt` (they become "the verdict artifact's `reviewed_sha` == head"); delete the sha from `state/<p>.pr-reviews.json`; `review-autopilot.sh:92` and `merge-sweep.sh:701` read the artifact.
- Tests (RED first): `tests/verdict-single-home-test.sh` — a rebase that moves the head must move the artifact; a merge-sweep run with a stale `reviewed-sha` file and a fresh artifact must NOT park; review-autopilot must skip a head the artifact already covers; an external PR reviewed by `review-prs.sh` must be visible to `job_verdict`.

### Slice 2 — Conductor state and attempts become rows; the tick is keyed to the PR that woke

### What stays on the filesystem, on purpose
- **Build worktrees, `builds/<record>/` artifacts, `plans/` contents, `/root/repos/*`** — the work itself; the DB holds pointers and verdicts, not the tree.
- **Logs as logs** (`logs/*.log`, `cost.csv` as write-ahead, `ALERTS.log` as the local audit trail) — kept append-only and hardened; what changes is that nothing *reads* them to decide.
- **`locks/*.lock` for in-process mutual exclusion on one box** (`flock -n` dedupe of a cron tick against itself). What must NOT remain is a lock file as a fleet-wide claim or as a liveness probe (`resume-dead-builds.sh:112`, `jobs-watchdog.sh:234`).
- **Identity and credentials**: `state/box-id`, `state/box-name`, `env/*`, `state/gh-app-tokens/`, `state/quota/` account files, `state/auth-accounts.local.json`, `~/.claude/*` — bootstrap material that must work with no DB.
- **Caches with a TTL** whose loss is a cache miss, not a fact loss: `state/hub-lease.json`, `state/gh-budget/`, `state/overlap-guard/*-prs.json`, `state/model-prices.json` (once the table is the source), the triage gate fingerprints (until Slice 8 makes them a row set).
- **Legitimately clocked lanes**: `watchdog-ping`, `state-backup`, `harden-state`, `clock-sync`, `disk-clean`, `healthcheck` (prod liveness half), `extra-usage-track`/`quota-poll`/`vendor-spend-pull` (meter polls), `security-scan`, `run-product`, `alert-digest`, `locks-mint-digest`, `update-model-prices`, `claude-auth-check` (the probe half), `outcome-metrics` (the recheck window), `rule-miner` (weekly review). These keep their cron lines; they should write rows, not files, but nothing about their cadence changes.
- **Operator scratch in `state/`** (`*.sh`, `.done`, `.bak-*`) — not state at all; a `disk-clean` rule to move it under `state/scratch/` is a hygiene ticket, not a migration.
