The short answer

  1. Builds open PRs they did not verify. On project-6, 36% of builds (353 of 982) could not run their own suite, and the PR opened anyway. CI is the first real test.
  2. The builder gate does not run the tests that fail later. project-6 has no pre-push gate file. On cromford the whole-repo ratchet suites are outside the gate.
  3. The recovery ladder repeats failures. It rebuilds a ticket on the same red checks, and it abandons after one failed fix round with no re-plan.
  4. Gates park true work on false signals. The iron-law scan parked 79 PRs, and review accepted 65 of 65. A parser fault mislabelled 138 queue ejections as "unknown".
  5. Parallel builds start with no file list. On project-6 and project-3, 100% of sibling holds are blind, and most conflicting PRs conflict within 1 hour of opening.

Causes, with evidence

1. The builder's own tests do not run

  • project-6: 353 of 982 builds (36%) recorded HARNESS_EXIT: could-not-run. 173 had ENOSPC.
  • The pool Postgres has no pgvector since migration 20261028194822_knowledge_chunk.sql. A full run fails 967 to 1,325 of about 2,500 test files, so builders narrow the scope.
  • project-6 has no bin/prepush-gate.sh. "PREPUSH-GATE mode=block" ran nothing on 54 of 54 builds read.
  • Unit shards failed on 29 of the 32 red project-6 PRs that name their checks. Example: #3802 failed tenancy-class.dt-1 because a new migration had no -- tenancy: header.

2. A red or unfinished verify does not stop the PR

  • REBASE_VERIFY_FAILED is in the result of 58 of 159 project-3 builds (36%) and 47 of 356 project-6 builds (13%).
  • Of 34 project-6 rebase typechecks, 13 ran out of memory (tsc exit 134) and 6 were red. All 19 PRs opened on the old base.
  • The PR self-check refused twice on 11 builds, and each PR was still queued.
  • EVIDENCE_GATE_ENFORCE is 0.

3. Whole-repo ratchets fail only in the queue (cromford)

  • 114 of 303 queue batch runs were red. Each batch held 1 PR. 39 of 48 PRs stayed red after the rerun, so the failures are deterministic.
  • no-state-files failed in 37 red runs and no-flag-files in 12. Neither is in catalog/test-impact-always.txt.
  • In all 8 red batches with a readable gate log, the builder gate had not run the failing suite.
  • Prequeue red parked 36 PRs: green alone, red when merged with main (lanes-registry on 10 PRs).

4. The recovery ladder repeats the failure

  • Rebuild-fresh does not compare failing checks. project-14 #17, #18, #19 (TK-16): 3 rebuilds in 3 hours, all red.
  • Fix rounds: "agent rc=0, verify rc=1, no verified commit" 41 times; timeout 7 times. The cap is 1 round in practice, 2 in the docs.
  • After the cap, a review block goes to ABANDONED. No re-plan is tried ("adjudicate 0, rebuild 0").
  • project-4#2205 ran 156 iron-law fix rounds on a false positive.

5. Gates fire on false signals

  • Iron-law: 79 PRs parked; 65 of 65 accepted on review. The 4 samples read were all false: a test fake, a single-org admin route, a printed secret name, a parameterized SQL template.
  • checks/client-id-trust/WHY.md lists cron and webhook routes as known false positives. check.sh does not apply the list. 11 of 16 project-4 hits are in those routes.
  • 138 of 182 eject events read "unknown" because Mergify changed its comment format. BH-9229 fixed the parser on 11-08. 61 "ejected twice" parks used the wrong label.
  • 506 of 921 HEAD_MOVED events are not head moves. They are the first look at a PR before its verdict binds.

6. Parallel builds collide

  • 28 of 42 project-6 conflicts and 22 of 31 project-3 conflicts appear within 1 hour of PR open. Main moved during the 1.5 to 2.6 hour build.
  • Sibling holds on project-6 and project-3: 100% say "(no pre-plan list)". The plan's file list stays on the Fly machine.
  • The overlap guard has made 0 decisions since 2026-09-19. Sibling-serial logged "prs=unread" 7,035 times.
  • The 360-minute ceiling released 279 holds. On project-6, 6 of 24 released tickets conflicted, 4 with the exact ticket they had waited for.
  • Shared append files: project-3 docs/RECENT-CHANGES.md hit 14 PRs; project-6 list-everything tests hit 5.

7. The in-build review misses spec gaps

  • Lead BLOCK classes by ticket: wrong-data 88, red-build 59, core-flow-broken 41, data-loss 25, auth-bypass 16.
  • Example, project-6#3322: the ticket asked for time in a state, and the code measured time since createdAt.
  • 20 of the 36 "findings outlasted the fix round" PRs are large, median about 2,900 lines. TK-1506 had 4,166 lines in 59 files.

8. New repos had no working CI

  • project-12, project-13 and project-14: 0 merged, 16 closed. The failing checks were the E2E jobs on every rebuild.
  • That points at repo or CI setup, not at the tickets.

Decisions for the operator

Size limits

Large diffs are the common factor in abandoned PRs (median about 2,900 lines). The size gate has been 1,200 lines and 30 files since 2026-10-14 (#6025), and #8739 asks for the fewest tickets. Both pull against the abandon data. Decision 2026-11-10: the gate stays at 1,200 / 30. #9441 now carries a re-measure step that posts abandon counts by diff size on #6025, 14 days after #9441 and #9437 merge.

project-3 RECENT-CHANGES.md

This hand-appended file conflicted on 14 PRs. The fix is a fragment directory or merge=union in the project-3 repo. Filed on the project-3 board on 2026-11-10 as an internal engineering ticket.

Direct commits on project-3

25 of 41 conflict pairs were against a client developer's direct commits to main (105 of about 280 commits). #9440 makes those commits count as file owners. A branch rule for that developer is a separate choice.

Method

  • Window: 2026-10-27 00:00Z to 2026-11-10 21:52Z. Source host: the hub, bh-hub-2.
  • Counts are distinct PRs unless the row says events. A PR can be in more than one class.
  • Sources: logs/merge-conductor.log (673,543 lines in the window), state/merge-conductor/pr-state.tsv, eject-cause/, state/ci-batch-red/, logs/blocked-resolver.log, logs/findings.log, build RESULT and review files, and about 75 GitHub REST calls.
  • Four agents read one failure class each: closed PRs, CI red and ejections, review and policy gates, conflicts. Their work files are in /tmp/agentA to /tmp/agentD on the hub.
  • Conflict files come from git merge-tree of each PR head against main at its first DIRTY event.
  • The class splits for conflicts (generated file, hot file, sibling slicing) are rule-based and approximate.
  • Code claims that were checked in the local checkout: no bin/prepush-gate.sh in project-6; bin/lib/rb/pr.sh:411-430 ships on a failed rebase verify; EVIDENCE_GATE_ENFORCE defaults to 0; check.sh for client-id-trust has no cron or webhook rule; the ratchet suites are not in catalog/test-impact-always.txt; POOL_AFTER_MAX_MIN defaults to 360; BR_MAX_FIXROUNDS defaults to 1.
